## 修复：设备ID诊断页黑屏（工具 → 设备ID诊断，/pages/device-id-diagnosis）
- 现象：打开「工具」里的「设备ID诊断」页面导致 app 黑屏
- 根因（新增页面不符合项目既有规范）：
  1. `.page` 用 `flex: 1` 且**缺 `width/height: 100%`** → 页面高度坍塌 → 黑屏（项目其他页都写满宽高，如 device-info、black-screen-check 的 `.page-root`）
  2. `overflow: scroll`（CSS 属性）—— **全项目仅此页这么写**；Vela 的滚动应使用 `<scroll scroll-y="true">` 组件（参考 schedule-manager.ux 用 `<scroll class="page" scroll-y>`）
  3. `box-sizing: border-box` 项目其他页未用
- 修复（commit f2507e5）：
  - `.page` 改为 `width: 100%; height: 100%; flex-direction: column;`（去掉 flex:1 / box-sizing）
  - 列表由 `<div class="list">` 改为 `<scroll class="list" scroll-y="true">`
  - `.list` 移除 `overflow: scroll`
- 备注：该页本身是「逐项测试 device API 是否会崩」的诊断工具，自带崩溃恢复（`PROGRESS_KEY=diag_progress_v2`、`crashedAt`、崩溃项下次自动跳过）；若打开正常但测某个 API 时仍黑屏，属该工具的设计行为（用于定位哪个 API 会崩）
- 该页为新增未跟踪文件，连同 `tools.ux` 入口 + `manifest.json` 注册 + 两个新 docs 一并入库

## 项目规范提示（本次踩坑得出）
- 快应用页面**根容器必须写满宽高**：`width: 100%; height: 100%`（不要用 `flex: 1` 当页面根）
- **滚动一律用 `<scroll>` 组件**（`scroll-y`/`scroll-x`），不要用 CSS `overflow: scroll`
- 新增页面须同步 `manifest.json` 的 `router.pages` 与 `_groups`（本页已注册到「实验室工具」组）

## 修复：设备ID诊断页"拿到一个就提前终止"（用户发现，commit ec55357）
- 用户问："能检测出来没有支持的情况吗，还是遇到一个合格的后面就不管了？" → **确实是 bug**
- 原逻辑：`startTests` 调 `runSafeAPIs(finish(gotID))`，`gotID = results.some(r=>r.ok)`，一旦为真就 `finish(true)` 整体终止
- 问题：安全组第一项 `testLocalUUID`（本地生成/读缓存 UUID）**几乎必然 ok** → 立刻判定"已拿到 ID" → `testGetInfo`/`testGetUA` 以及危险组 `getDeviceId`/`getSerial`/`getMac`/`getId` **全都不会跑**，等于除了本地 UUID 什么都测不出
- 修复：安全组**全部跑完** → 危险组**全部跑完**；末尾加"完成"汇总项
- 结果含义：绿=拿到值；红=空/获取失败/API不存在/异常/已跳过-上次崩
- 备注：`results.push` 触发视图更新在本项目 OK（device-info.ux 也用 `infoList.push` 且正常显示），无需改 concat

## 重构：设备ID诊断页改为「每次只测一个 API」（commit d996567）—— 纠正上一轮"全部跑完"
- 用户贴的分析指出真凶：**一键连续调用 7 个 device API（安全3+危险4）→ binder 打满 → 黑屏 → 设备重启**；若重进页面又自动跑则死循环
- 注意：分析里"onInit 自动跑"前提**已过时**（上轮已改手动）；但"连跑 7 个"仍成立——**上一轮我把提前终止去掉改成全跑 7 个，反而加剧了风险**
- 本次重写 `device-id-diagnosis.ux`：
  - 7 个独立按钮（`testList`），`runOne($idx)` 每次只调 1 个 API，出结果后再点下一个
  - 每次点击：先 `storage.set(diag_progress_v2=key)` 落盘 → 延时 350ms → 调 API → 正常返回后清除进度（崩溃则记录保留）
  - `onInit` 仅 `loadProgress()`（显示"上次崩在 X"），绝不自动跑
  - 危险项(getDeviceId/getSerial/getMac/getId) 点击时 `prompt.showDialog` 二次确认（try/catch 兜底：无该 API 则直接执行）
  - 结果行改竖排（label 上 / value 下）适配窄屏
- 后续判断：若**单次调用仍崩**，说明 Vela 在 Band 9 上封了硬件标识符读取，应放弃客户端方案、改服务端兜底（与 `docs/手环9胶囊屏设备ID为NA分析.md` 结论一致）
