## 导出改为按域（scope）可控 + 白名单模型
- 用户问：请求数据是单独分别给还是打包全放开？不开放的数据（如钉首页）对方是否读不到改不掉？
- **核心回答：手环侧是守门人，采用白名单模型**。插件只能通过 interconnect 请求，我们决定读什么、回什么：
  - 不在白名单的域（如授权 `auth`）→ **永远拿不到、也改不掉**
  - 在白名单但非默认的域（如 `pinned`）→ **不显式请求就拿不到**
  - `update_settings` 只处理白名单字段，其余一律忽略 → **改不掉**
- **已实现**（`src/app.ux`）：`export` 支持 `scopes`（数组）或 `scope`（单字符串简写）
  - `SYNC_DEFAULT_SCOPES = ["schedule","profile","homepage","appearance"]` —— 不传时返回这些
  - `SYNC_ALLOWED_SCOPES = [...,"pinned"]` —— 白名单；`pinned` 需显式请求才返回
  - 响应新增 `scopes` 字段回显实际使用的域
- **钉首页数据位置**：`src/data/pin-helper.js`，KEY `pinned_pages`，结构 `[{name, uri}]`；导出 `getList` / `isPinned` / `pinPage` / `unpinPage`。**注意 `pinPage`/`unpinPage` 会弹 Toast**，同步写入若要静默须直接用 storage 写 `pinned_pages`
- 单测验证：`pinned` 不在默认域 ✅ / `pinned` 在白名单可显式请求 ✅ / `auth` 不在白名单 ✅；`node --check` 通过、ES6+ 0
- 文档已更新：新增 3.4「作用域（scopes）与开放边界」章节
- 边界诚实说明：以上针对 **interconnect 通道**；若 AstroBox 绕过 interconnect 直读设备存储则不在守门范围（已写入文档）

## 反思：为什么这次对接显得"难"（教训）
- 用户问："对接这么难吗？是否我们做错了哪里？" 诚实结论：**对接不难（一个 JSON 通道 + 3 个 action），难在通道是"哑"的**——无 schema 校验、无 ACK 语义、send 失败静默，双端只能靠日志隔空猜
- 我们的错/不足：①`syncReply` 发对象（真错，且与接收端"按字符串解析"自相矛盾）②协议改动没端到端跑通就标"已落地"③没用最小路径验证通道（应先 ping→pong 再叠业务）④失败静默（catch 只 dlog，手环日志用户取不到）⑤文档重业务轻传输层
- 对方的问题：①昵称传 change 事件对象（未取 .value）②日志只记 TX 不记 RX
- **可复用的排错约定（以后照做）**：a. 传输层唯一约定 `{data:"<json字符串>"}` 双向 b. 联调第一步先 ping，通了再验业务 c. 协议改动必须真机 ping 通才算完成 d. 双端都要打印 TX/RX
- 待办（用户未拍板）：可加 `{"action":"ping"}` → `{"ok":true,"pong":true,"versionName","versionCode"}` 自检 action

## 诊断：插件侧报 "Plugin thread dropped the response"（关键）
- 对方日志：`[TX] register=Ok(()) send=Ok(())` 正常，但**全程无 `[RX]`**，最后报 `Plugin thread dropped the response [modules/pluginsystem/src/lib.rs:326]`
- **定性：这是 AstroBox 宿主(Rust 插件系统)的报错，不是手环侧问题**。含义=宿主拿到本该回传插件的响应，投递时发现**插件线程已结束(drop)**，响应无处可送被丢弃 → 所以插件永远看不到 RX；不是"手环没回"
- **根因在插件侧调用模型**（三选一）：①请求-响应式调用没 await/发完即返回 ②一次性执行模型（UI 事件跑完线程即退）③宿主等待超时后 drop 通道，设备慢回包才到
- **与之前"回包发对象"是两个独立问题**（那个已修 022dbf0）
- **二分定位法**：先做 ping——ping 也 dropped ⇒ 插件模型问题；ping 通仅 export dropped ⇒ 手环 export 太慢/太大触发宿主超时 ⇒ 手环侧优化
- 手环侧可优化点：export 走 syncCollectScopes 串了 getAllCourses/getNickname/getHomepageSettings/getBaseFontSize 多个异步 storage 回调，链路偏长 → 可加**回包超时兜底**（回调不返回也要回）

## 落地：ping 自检 + export 超时兜底 + 提前回包 bug 修复（已 commit）
- 新增 `ping` action（src/app.ux onmessage）：`{"action":"ping"}` → 同步立即回 `{ok:true,action:"ping",pong:true,versionName,versionCode}`；**跳过异步、最快往返**，联调第一步用它判定通道双向通

  - 修复：加 `registered` 标志，**全部任务注册完毕后才判定完成**；结束后再补 `if (done===pending) complete()`
