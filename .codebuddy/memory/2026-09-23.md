## 单元测试方法（手环 / 快应用场景）
- 用户问：单测怎么弄的？手环场景一般怎么做？课程增删改能测吗？会留冗余数据吗？
- **三种套路（本项目适用，均已验证）**：
  1. **纯函数** —— 正则从 `.ux` 提取 `<script>`，再截取目标函数片段 → 拼接测试代码 → 写 `/tmp` → `node` 跑。零依赖、零副作用。本次 `syncNormalizeDay` / `syncBuildTime` / `syncExtractCourses` / `syncToFormatA` 即用此法
  2. **依赖 storage 的逻辑** —— 劫持 `Module.prototype.require`，把 `@system.storage` 换成**内存 fake**（get/set/delete 走一个 `{}` 对象），再 `require` 真实的 `database.js` 跑 CRUD
  3. **页面方法** —— `new Function("require", script + ";return page;")(require)` 注入 mock（注意 `new Function` 作用域内没有 require，必须显式传入）
- **实测（课程增删改，fake storage）**：初始星期一 4 门 → 添加后 5（PASS）→ 改名生效（PASS）→ 删除后 4（PASS）；内存 keys = `migration_v2_done, allCourses_0, allCourses_dirty`
- **会不会留冗余数据**：**不会**。fake storage 全在内存，进程退出即销毁；测试脚本放 `/tmp`，不进工作区、不进 git。只有真机测试才会落盘（需 cleanup）

## 导出改为按域（scope）可控 + 白名单模型
- 用户问：请求数据是单独分别给还是打包全放开？不开放的数据（如钉首页）对方是否读不到改不掉？
- **核心回答：手环侧是守门人，采用白名单模型**。插件只能通过 interconnect 请求，我们决定读什么、回什么：
  - 不在白名单的域（如授权 `auth`）→ **永远拿不到、也改不掉**
  - 在白名单但非默认的域（如 `pinned`）→ **不显式请求就拿不到**
  - `update_settings` 只处理白名单字段，其余一律忽略 → **改不掉**
- **已实现**（`src/app.ux`）：`export` 支持 `scopes`（数组）或 `scope`（单字符串简写）
  - `SYNC_DEFAULT_SCOPES = ["schedule","profile","homepage","appearance"]` —— 不传时返回这些
  - `SYNC_ALLOWED_SCOPES = [...,"pinned"]` —— 白名单；`pinned` 需显式请求才返回
  - 响应新增 `scopes` 字段回显实际使用的域
- **钉首页数据位置**：`src/data/pin-helper.js`，KEY `pinned_pages`，结构 `[{name, uri}]`；导出 `getList` / `isPinned` / `pinPage` / `unpinPage`。**注意 `pinPage`/`unpinPage` 会弹 Toast**，同步写入若要静默须直接用 storage 写 `pinned_pages`
- 单测验证：`pinned` 不在默认域 ✅ / `pinned` 在白名单可显式请求 ✅ / `auth` 不在白名单 ✅；`node --check` 通过、ES6+ 0
- 文档已更新：新增 3.4「作用域（scopes）与开放边界」章节
- 边界诚实说明：以上针对 **interconnect 通道**；若 AstroBox 绕过 interconnect 直读设备存储则不在守门范围（已写入文档）

## 权限表收口 + 新增 version 只读域（已落地代码，未 commit）

- **重构内容**（src/app.ux）：
  - 删除 SYNC_DEFAULT_SCOPES/SYNC_ALLOWED_SCOPES，改为 **SYNC_ACCESS 权限表**（read/write 双维）+ SYNC_FIELD_DOMAIN（字段→域映射）+ SYNC_ALL_SCOPES + syncGetPolicy/syncCanRead/syncCanWrite + syncCollectVersion(require ./data/version.js)

  - `update_settings` 每个字段加 `syncCanWrite(field)` 守卫 → 传 version 字段被忽略（只读生效）
- **单元测试（真跑）10 项全 PASS**：version=只读、profile=读写、默认可读含 version、nickname 可写=true、version 可写=false、未知字段不可写=false、不传 scopes version 可读=true、pinned 不显式=false/显式=true、auth 不可读=false
- 校验：`node --check` 通过、ES6+ 高危语法 0、lints 0
- 文档更新（docs/同步器对接协议文档.md）：3.2 响应加 versionName/versionCode、3.4 表加 version 行、新增 4.2 版本号只读对接 + 4.3 昵称读写对接示例
