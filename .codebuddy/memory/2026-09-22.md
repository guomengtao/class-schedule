## 数据分层结论（回答用户）
- 本项目**不存在真正的数据库**：`src/data/database.js` 用的是 `@system.storage`（键 `allCourses`）+ 内存缓存 `_cache` 自实现的 CRUD；假期数据是另一个键 `holiday_data`
- `holidays-2026.js` 不是数据库，而是**打包进 App 的内置种子数据源**（只读常量）；流程：启动时 `ensurePreset()` 把种子补齐进 storage → 页面只读写 storage → 「恢复内置数据」用种子覆盖内置日期但保留用户自定义
- 校验脚本套路：`node -e` 里劫持 `Module.prototype.require` 注入 fake `@system.storage`，可本地跑通 storage 逻辑

## Git 安全边界（已向用户说明）
- 已 commit 的内容：对象进 `.git/objects`，后续删除/修改都不影响历史版本，可用 `git log -- <path>` / `git checkout HEAD~1 -- <path>` 取回
- 残余风险点（必须在常识上提醒）：本地未 push 时仓库物理损坏；`--force push` 或删远程分支；悬空对象（只 add 未 commit）会被 `git gc/prune` 在默认 90 天后回收；`.git` 被 rm
- 真正高危的始终是：**从未 add/add 后被 reset 出来的未跟踪文件**，`git clean -fd` 一次清空且无回收站
