## EvNotifier（app-auth 仓库）：禁止「退出后自动重启」（commit a4d8895，已推送）
- 现象/需求：菜单栏点「退出」→ 进程刚退出，launchd 因 `KeepAlive=True` 立刻把它拉回来，等于退不掉。
- 修复位置：`app-auth/tools/ev-notifier/ev_notifier.py`
  - 新增 `stop_launchd_job()`：只做 `launchctl bootout gui/$UID/com.evnotifier.agent`（**保留 plist**）；
  - `quit_app()` 在 `_mark_clean_exit("menu_quit")` 之后、`NSApp.terminate_` 之前调用它。
  - 与既有 `disable_auto_start()` 的区别：后者还删 plist（取消开机自启偏好）；**退出路径只摘本次 job**，下次登录 RunAtLoad 仍起来。
- 设计取舍：没有改成 `KeepAlive={"SuccessfulExit": False}`——那会把 `launchctl kickstart -k`（运维手册与 git 日志里反复用的重启手段）一起废掉。bootout 方案只影响「退出」这一条路径，崩溃自愈不受影响。
- 验证（本机生产实例，PID 7922→8114→8570）：`bootout` 后进程退出且 **10s 无新进程**，`plist` 仍在；`launchctl bootstrap gui/$UID ~/Library/LaunchAgents/com.evnotifier.agent.plist` 立刻复活。**bootstrap 是退出路菜单退出后的手工复活命令**。
- 版本 `tools/ev-notifier/version.json` 2.3.42 → 2.3.43；README「退出」小节补了行为说明与复活命令。
- ⚠️ 仓库协作：app-auth 有用户并行未提交改动（user-guide.html / version.json / `api/notify/` / `_test_write.html`），**只 add 自己这 3 个文件**；推送被拒（远端 ee91d93 只改 `ev/update-ev.json`）→ `git pull --rebase --autostash` 后推送成功，用户脏工作区原样保留。

## EvNotifier 打包成正规 Mac App（方案 A 精简版，commit c0cb470，已推送）
- `tools/ev-notifier/build_app.sh` 重写：`./build_app.sh` 构建、`--install` 安装到 `/Applications/EvNotifier.app`。
  bundle 结构 = `Contents/{Info.plist(LSUIElement=1, 版本取 version.json), MacOS/EvNotifier(相对 $0 解析的 sh 启动器), Resources/{venv, ev_notifier.py, version.json, EvNotifier.icns}}` + ad-hoc `codesign --force --deep --sign -`。实测 66MB。
  依赖放 `requirements.txt`（rumps / pywebview / redis / edge-tts，edge-tts 是 import 包不是外部 binary）；旧产物 mv 到 /tmp/trash、venv 缓存到 /tmp/evnotifier-venv-cache 复用。**bundle 里是拷贝 ⇒ 改完代码必须重新 build+install。**
- **启动路径自动移交**（`handover_to_launchd()`，在 `__main__` 拿到 PID 锁之后、load_env 之前）：双击 App/手动跑脚本时，若自己不是 "launchd 正在托管的那个"，就 rewrite plist 指向当前 `sys.executable`+脚本 → **延迟 2s bootstrap → 自己退场**，最终只剩一个受托管实例。
- 🔴 **踩坑1：`os.getppid()==1` 不能用来判断"是否被 launchd 拉起"** —— Finder/LaunchServices 双击启动的进程 ppid 也是 1！首版用 ppid 判定导致 App 实例跳过移交直接跑成野进程。正解：`launchctl list <label>` 取 job 的 PID 与 `os.getpid()` 对比。
- 🔴 **踩坑2：`ensure_auto_start()` 里的 `bootstrap` 必须删掉** —— 本进程已经在跑，注册 job 会让 launchd 立刻再拉一个实例 → 抢不到 PID 锁就退出 → KeepAlive 补位 → **"秒退秒起"重启死循环**（实测 stdout 刷屏 "Another instance"）。现在 `ensure_auto_start()` 只写 plist，job 注册统一交给 handover。
- 重复实例由静默退出改为 `notify_macos("Ev Notifier 已在运行")` 提示（双击最容易踩到）。
- 移交加了防呆：`~/.ev_launch_handover.stamp` 15s 内不再重试（bootstrap 系统性失败时至少能裸跑）；`auto_start` 偏好为 OFF 时不写 plist。
- 验证：一次 handover 落到单边状态 —— 进程数 1、argv 无 `-u`（说明是 plist 那条线拉起的）、`launchctl list` PID 一致、v2.3.44、30s 后无重启循环；随后 `open` 两次与直连 venv python 均只 leave 1 个进程（重复路径 exit=0）。
- 用户协作：用户一度误选 "B PyInstaller 可分发包"，随即纠正为 **A 精简版**。

## EvNotifier 迭代路径（日常改代码要多麻烦）+ 修第三个坑（commit 0f4b8d4，已推送）
- 结论给用户：**日常改功能只需 `./build_app.sh --sync`（≈2.2s，拷贝源码进 bundle + `kickstart -k` 重启）**；想要更快可 `--link`（bundle 脚本软链到仓库源文件，改完只要重启客户端，但仓库挪走 App 就废）；**只有依赖/图标/版本号变了才需要完整 `--install`**（~40s，venv 缓存 /tmp/evnotifier-venv-cache）。
- 🔴 **踩坑3：`launchctl list <label>` 打印的是 plist 字典（无 PID）**，要 PID 必须用**不带参数的** `launchctl list`（输出 `PID\tStatus\tLabel`）。接坑1：我第一版 `_launchd_job_pid()` 就是这么写错的 → 恒返回 None → 每次启动都误判"自己没被托管"，靠 15s 防重 stamp 才没炸。同理 shell 里要用 `launchctl list | awk -v l=$LABEL '$3==l{print $1}'`（`-F'\t'` 在 BSD awk 上不稳 → 用默认 FS）。
- 当前线上：job 指向 `/Applications/EvNotifier.app/Contents/Resources/venv/bin/python` + 同名 `ev_notifier.py`；实例 v2.3.45 / PID 25161 单实例健康。
- 顺带发现（未处理，先记）：启动自检时 `notify_macos` 的 `osascript` 偶发 5s 超时（`notify_macos EXCEPTION ... timed out after 5 seconds`），不影响后续流程。
- **操作手册已落盘**：`app-auth/tools/ev-notifier/EvNotifier桌面App与日常迭代手册.md`（commit 6353419）——含现状表、三条命令（--sync/--link/--install）、核心机制（退出不复活 / handover 移交 / PID 锁）、四个踩坑、运维命令速查、排障清单、相关文件。**下次改 EvNotifier 先读它**。

## EvNotifier 可分发版：portable App + dmg（commit 1fb0024，已推送）
- 新命令：`./build_app.sh --dmg` → `dist/EvNotifier-v{版本}-macos-arm64.dmg`（92MB）；`--portable` → `dist/EvNotifier.app` 可直接拷走。
- **运行时选型（关键）**：不能用 Homebrew Python——`otool -L` 实测其 lib-dynload 依赖 openssl@3/mpdecimal/sqlite/xz/zstd 外部 dylib，主 dylib install_name 也是绝对路径。改用 **python-build-standalone（本机 uv 已托管 3.12.14）**，官方设计可重定位：`cp -RL` 拷贝 + **隐藏原始目录**后仍正常 import ssl/sqlite（决定性验证）。
- 依赖装进运行时自身 `lib/python3.12/site-packages`（launchd 用裸 `sys.executable` 也能找到，无需 PYTHONPATH）；uv 运行时带 PEP 668 `EXTERNALLY-MANAGED`，缓存副本里删除后才可 pip。
- **运行时放 `Contents/Resources/python/` 而非 Frameworks/**：codesign 把 `Frameworks/*` 当嵌套代码扫描，python 目录非合法 bundle → "bundle format unrecognized"；Resources 只哈希密封，`--verify --deep --strict` 全绿。
- 运行时缓存 `/tmp/evnotifier-portable-runtime`（requirements.txt mtime 变化才重装依赖）。
- `handover_to_launchd()` 加 `/Volumes/` 守卫：从挂载 dmg 直接跑绝不写 plist（卷一弹出就失效）。
- 验证：原位置跑 ✅ → `mv` 换路径跑 ✅（exit=0 重复实例路径，全依赖可导入）→ dmg 挂载后运行 ✅；本机 venv 版同步到 v2.3.46 单实例健康。
- 下载 python-build-standalone 时 GitHub release 被 HTTP2 framing 卡死（curl -16），`--http1.1` 也极慢被用户取消 → 最终用**本地 uv 已托管的运行时**零下载解决；`uv python list` 可看已有版本。
- ⚠️ uv 的 `~/.local/share/uv/python/cpython-3.12-macos-aarch64-none` 是**软链**（真目录带完整版本号 3.12.14），`du` 为 0B 是因为没跟随软链；拷贝要用 `cp -RL`，"斩断测试"必须针对真实目录。
- ⚠️ 提醒过用户：PUB/SUB 广播 → 多机同时在线会重复弹窗+语音；要彻底解决需消息定向过滤（未做）。
