## 新增文档：跑道屏设备输入法打不开差异分析

- 产出：`docs/跑道屏输入法打不开分析.md`
- 现象：真机测试中手环 11 / 手环 9（跑道屏）进中文输入页键盘出不来；手环 10 Pro（方屏）正常
- 核心结论（静态分析）：
  - 键盘能否渲染 = `device.getInfo().screenShape` → `screenType` → `InputMethod.ux` 三个严格等值 `if` 分支（circle / rect / pill-shaped）。**三分支无 else 兜底**，未命中即键盘全空 = "打不开"
  - 10 Pro 是标准 `rect`，走方屏分支（唯一纯 flex 相对布局，不依赖 screenWidth、竖直余量宽裕），所以它对三类风险全免疫 —— **它的正常不能反证胶囊分支没问题**
  - 9/11 走胶囊分支，是唯一「固定 305px 高 + 外置 28px 拼音行 + 绝对定位 + `(screenWidth-192)/2` 居中」的分支
- 根因候选排序：R1 屏型值未命中（含 `|| "circle"` 误兜底、别名只转 `capsule`）；R2 `screenWidth` 取值链三处风险（初始值 336 是方屏基准 / fail 兜底也写死 336 / 不校验物理 vs 逻辑像素、undefined 会产生 NaN padding）；R3 竖直空间不足 + 组件根 `.page{position:absolute;bottom:0}` 放在外层 scroll 中被推出可视区；R4 顶层 `import vibrator` 模块不可用导致组件模块解析失败
- 澄清两条已失效的历史结论：输入法链路 ES6 箭头函数**已全部移除**（grep `=>` 零结果）；`chinese-input-full.ux` **已删除**，现只剩唯一入口 `src/pages/chinese-input/chinese-input.ux`。故旧 QA 报告里的这两条不能再解释本次现象
- 发现的口径矛盾：`chinese-input` / `index` / `week-view` 都认识 `capsule`，但 `device-info.ux` 的 `screenShapeMap` 只映射 `rect`/`circle`/`pill-shaped`（不认识 `capsule`）→ 取证时会误判，修复建议里已列出
- 建议修复方向：新建 `src/data/screen.js` 统一 `normalizeScreenShape(shape, screenWidth)`（未知值用宽度 ≤240 判胶囊）；组件三分支加兜底（非 circle/rect 一律按 pill 渲染）；居中量改脚本预算 `pillPadX` 并对 NaN 免疫；取消组件根绝对定位、键盘高度自适应；`getInfo` 补 fail 回调
- 后续：需真机按文档第五章取证（先读 device-info 三组参数 → 埋一行日志 → 四次二分），确证后再改代码

## 真机数据回填后的结论修订（同日追加）

用户提供了手环 11 / 手环 9 的激活 URL 参数（字段含义见 `src/pages/activation/activation.ux:429-440` 的 `fetchDeviceInfo()`）：

| 字段 | 手环 11 | 手环 9 |
|---|---|---|
| product | Xiaomi Smart Band 11 | Xiaomi Smart Band 9 |
| deviceType `t` | **band** | **band** |
| screenShape `s` | **pill-shaped** | **pill-shaped** |
| screenWidth `w` | **212** | **192** |
| screenHeight `h` | **520** | **490** |
| platformVersionCode `v` | 1200 | 1200 |
| osVersionCode `o` | 0 | 198145 |
| APILevel `a` | 2 | 2 |
| versionName `r` | **1.6.59** | **1.6.100** |
| channel `c` | `g` | `t-9p-d` |

修订后的结论（已写入文档「补充：真机数据回填与结论修订」一节）：
- **R1 屏型不命中 → 实测排除**（两台都返回 `pill-shaped`，组件胶囊分支必定命中）
- **R2 居中量算错 → 排除**（`(192-192)/2=0`、`(212-192)/2=10`，正确；仅剩首帧 `screenWidth:336` 导致 72px 偏移待确认）
- **R4 vibrator 顶层导入 → 间接排除**（`activation.ux` 同样顶层 import vibrator 且成功跑完取参）
- **R3 竖直高度不足 → 上升为首要怀疑**：胶囊键盘 305px + 常驻 28px 拼音行 = 333px；页面固定占用按 content-box 算 198px（padding-top 30 + header 56 + input-display 70 + done-row 42）→ 手环 9 可用 **292**（缺 41px）、手环 11 可用 **322**（缺 11px）、10 Pro 方屏 282 vs 需 283（≈够）。方向性与现象一致
- **结构性放大项**：组件根 `.page{position:absolute;left:0;bottom:0}` 挂在外层 `<scroll>` 内，绝定位不参与 scroll 内容高度 → 溢出被 `bottom:0` 推到可视区上方
- 新台账：①`w=212` 是项目首次出现的胶囊宽度（所有胶囊规范按 192 定标）②`t=band` 与 manifest `deviceTypeList:["watch"]` 不符（不阻断安装，运行时影响待验证）③手环 11 `o=0` 说明新 ROM 字段不全，不能假设字段必存在
- 已用 `git show 805adbc:src/pages/chinese-input/chinese-input.ux` 核对：1.6.59 与当前的输入法页面结构基本一致，版本差异大概率非主因，但**三台设备版本未统一仍是未控变量**
