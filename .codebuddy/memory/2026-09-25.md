## 新增文档：跑道屏设备输入法打不开差异分析

- 产出：`docs/跑道屏输入法打不开分析.md`
- 现象：真机测试中手环 11 / 手环 9（跑道屏）进中文输入页键盘出不来；手环 10 Pro（方屏）正常
- 核心结论（静态分析）：
  - 键盘能否渲染 = `device.getInfo().screenShape` → `screenType` → `InputMethod.ux` 三个严格等值 `if` 分支（circle / rect / pill-shaped）。**三分支无 else 兜底**，未命中即键盘全空 = "打不开"
  - 10 Pro 是标准 `rect`，走方屏分支（唯一纯 flex 相对布局，不依赖 screenWidth、竖直余量宽裕），所以它对三类风险全免疫 —— **它的正常不能反证胶囊分支没问题**
  - 9/11 走胶囊分支，是唯一「固定 305px 高 + 外置 28px 拼音行 + 绝对定位 + `(screenWidth-192)/2` 居中」的分支
- 根因候选排序：R1 屏型值未命中（含 `|| "circle"` 误兜底、别名只转 `capsule`）；R2 `screenWidth` 取值链三处风险（初始值 336 是方屏基准 / fail 兜底也写死 336 / 不校验物理 vs 逻辑像素、undefined 会产生 NaN padding）；R3 竖直空间不足 + 组件根 `.page{position:absolute;bottom:0}` 放在外层 scroll 中被推出可视区；R4 顶层 `import vibrator` 模块不可用导致组件模块解析失败
- 澄清两条已失效的历史结论：输入法链路 ES6 箭头函数**已全部移除**（grep `=>` 零结果）；`chinese-input-full.ux` **已删除**，现只剩唯一入口 `src/pages/chinese-input/chinese-input.ux`。故旧 QA 报告里的这两条不能再解释本次现象
- 发现的口径矛盾：`chinese-input` / `index` / `week-view` 都认识 `capsule`，但 `device-info.ux` 的 `screenShapeMap` 只映射 `rect`/`circle`/`pill-shaped`（不认识 `capsule`）→ 取证时会误判，修复建议里已列出
- 建议修复方向：新建 `src/data/screen.js` 统一 `normalizeScreenShape(shape, screenWidth)`（未知值用宽度 ≤240 判胶囊）；组件三分支加兜底（非 circle/rect 一律按 pill 渲染）；居中量改脚本预算 `pillPadX` 并对 NaN 免疫；取消组件根绝对定位、键盘高度自适应；`getInfo` 补 fail 回调
- 后续：需真机按文档第五章取证（先读 device-info 三组参数 → 埋一行日志 → 四次二分），确证后再改代码

## 症状修正：手环 9 是「点进输入法页面直接重启手环」（同日二次追加）⚠️ 方向性推翻

用户补充：手环 9 的实测症状**不是"看不见键盘"，是根本进不去 —— 点这个页面就导致手环重启**（系统级复位）。

**布局类根因全部作废**（溢出/偏移只会显示不全，不可能重启设备）。根因重排为两条：

- **W1（首因）进页面即同步全量初始化**：`dicUtil.js:490-491` 注释承诺"由 `InputMethod.ux` 在 onInit 中 **setTimeout 延迟**到首帧渲染后调用"，但实现是**同步直调** —— `InputMethod.ux:417-421` `if (!this.hide) { this.keyboardCreated = true; this._ensureDictInit() }`，`_ensureDictInit()` → `SimpleInputMethod.initDict()`（无 setTimeout）。而 `chinese-input.ux:35` 传 `hide="{{ false }}"` → 进页面即同步跑完整初始化。
  - `initDict` 同步构建 5 张大对象：`py2hz`(6763)、`romaji2kanji`、`syllableSet`(~6763)+`py2hz2`、`words`(~3000)、`initialsIndex`(815 行)；**只有 `_buildForwardIndex` 是分片的**
  - 叠加同帧模板首建（200+ 节点 / 60+ PNG）→ 主线程阻塞（看门狗复位）或堆峰值（OOM）
  - 同时解释两点：为什么"点页面就重启"（重活在 onInit 干完）、为什么 10 Pro 免疫（RAM/CPU 余量大）
- **W2 `progress type="arc"` + 非法负角度**：`InputMethod.ux:231` 胶囊分支独有的 `<progress ... type="arc" ... total-angle:-48deg>`；方屏是普通线性 progress、圆屏无 progress → **严格只影响跑道屏**，与现象吻合

验证方案（各 2 分钟，建议都做，二者不互斥）：V1 把 `hide` 临时改 `true`；V2 把 arc progress 套 `if="{{false}}"`；V3 给 `_ensureDictInit` 加 `setTimeout(…, 800)`；V4 抓 logcat 崩溃前日志。

修复方向：①`_ensureDictInit` 改异步+分片（兑现注释承诺，最好把 `initDict` 内部也分片）②`chinese-input` 错峰（先 `hide=true` 再短延时展开），把"词典初始化"与"模板首建"分开 ③替换 arc 进度条、去掉负 `total-angle` ④加"上次崩在输入法页"埋点闭环验证 ⑤三机回归含"重启后再进"

**技术债记录**：`dicUtil.js:490-491` 的注释与 `InputMethod.ux` 实现不一致（承诺 setTimeout 延迟、实为同步），属文档漂移，后续任何"懒加载/延迟初始化"的说法都要以代码为准复核。
