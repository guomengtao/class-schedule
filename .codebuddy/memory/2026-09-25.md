# 2026-09-25 工作日志

## 新增文档：跑道屏设备输入法打不开差异分析

- 产出：`docs/跑道屏输入法打不开分析.md`
- 现象：真机测试中手环 11 / 手环 9（跑道屏）进中文输入页键盘出不来；手环 10 Pro（方屏）正常
- 核心结论（静态分析）：
  - 键盘能否渲染 = `device.getInfo().screenShape` → `screenType` → `InputMethod.ux` 三个严格等值 `if` 分支（circle / rect / pill-shaped）。**三分支无 else 兜底**，未命中即键盘全空 = "打不开"
  - 10 Pro 是标准 `rect`，走方屏分支（唯一纯 flex 相对布局，不依赖 screenWidth、竖直余量宽裕），所以它对三类风险全免疫 —— **它的正常不能反证胶囊分支没问题**
  - 9/11 走胶囊分支，是唯一「固定 305px 高 + 外置 28px 拼音行 + 绝对定位 + `(screenWidth-192)/2` 居中」的分支
- 根因候选排序：R1 屏型值未命中（含 `|| "circle"` 误兜底、别名只转 `capsule`）；R2 `screenWidth` 取值链三处风险（初始值 336 是方屏基准 / fail 兜底也写死 336 / 不校验物理 vs 逻辑像素、undefined 会产生 NaN padding）；R3 竖直空间不足 + 组件根 `.page{position:absolute;bottom:0}` 放在外层 scroll 中被推出可视区；R4 顶层 `import vibrator` 模块不可用导致组件模块解析失败
- 澄清两条已失效的历史结论：输入法链路 ES6 箭头函数**已全部移除**（grep `=>` 零结果）；`chinese-input-full.ux` **已删除**，现只剩唯一入口 `src/pages/chinese-input/chinese-input.ux`。故旧 QA 报告里的这两条不能再解释本次现象
- 发现的口径矛盾：`chinese-input` / `index` / `week-view` 都认识 `capsule`，但 `device-info.ux` 的 `screenShapeMap` 只映射 `rect`/`circle`/`pill-shaped`（不认识 `capsule`）→ 取证时会误判，修复建议里已列出
- 建议修复方向：新建 `src/data/screen.js` 统一 `normalizeScreenShape(shape, screenWidth)`（未知值用宽度 ≤240 判胶囊）；组件三分支加兜底（非 circle/rect 一律按 pill 渲染）；居中量改脚本预算 `pillPadX` 并对 NaN 免疫；取消组件根绝对定位、键盘高度自适应；`getInfo` 补 fail 回调
