## 产品概述
为 Ev课程表（v1.6.4 / versionCode 833，小米手环 9 Pro / 10 Pro 平台）撰写一份 Markdown 评分文档，对象为「标准版」——独立于付费高级版，只提供课程表基础能力：添加、编辑、删除课程。高级版能力（数据备份恢复、多套课程表、首页自定义、多套主题）以弹窗形式呈现，需解锁后使用。

## 核心内容
1. **版本分界说明**：明确标准版可用范围与高级版弹窗拦截边界，依据 `store.isPremiumUnlocked()` 与 `auth-store.js` 的 `standard` 状态判定。
2. **胶囊屏专项分析（重点）**：胶囊屏物理宽 192px、规范内容区 160px，需逐页核算实际内容区宽度与字号，确认文字清晰、不被遮挡、不被截断。
3. **字号控制评估**：依据 `docs/Ev课程表_手环字号规范_v1.md` 的 20px 护栏、40/36/34/32/28/24/20 档位、行高 1.2 倍字号。
4. **布局与触控评估**：按钮高度规范 48px，重点核查添加课程的时间选择是否简洁高效、星期按钮是否易点准。
5. **用户操作视角三性评估**：从添加、编辑、删除三条主流程出发，评估稳定性（数据不丢不错）、安全性（误删防护、二次确认）、流畅性（首屏加载、页面跳转、无卡顿）。
6. **UI 清晰度检查**：是否存在文字截断、横向溢出、边界跳动、同类操作表现不一致、用户无法正常使用等混乱情况。
7. **最终结论**：百分制综合评分 + 分维度得分 + 按收益成本排序的改进方向。

## 约束
- 评估基准为**当前（本轮修复后）代码状态**，需体现已修复项带来的提升。
- 需引用真实文件路径、行号与宽度算式作为扣分依据。
- 文档落盘至 `docs/`，沿用既有中文命名与「结论 + 分数 + 表格 + 总结」风格（对齐 `docs/项目完善度分析.md` 的 85/100 评分范式）。
- 静态走查未真机运行，凡需实机确认处须显式标注。

## Agent Extensions
### Skill
- **lsp-code-analysis**
  - Purpose: 在撰写文档前精确定位被引用符号与行号（如 `store.isPremiumUnlocked`、`computeFontSizes`、`insertCourseStorage`、各页面 `@media (shape: capsule)` 块边界），避免文档中出现错误的路径与行号引用。
  - Expected outcome: 报告中每一处「文件 + 行号 + 代码位置」引用均经过校验，可被检索复现。

### SubAgent
- **code-explorer**
  - Purpose: 复核剩余问题清单的真实性与覆盖面——五页面胶囊屏 padding 取值、按钮高度低于 48px 的全部位置、`console.log` 残留分布、`isPremiumUnlocked` 拦截点是否遗漏标准版核心页、`course-manager-v2` 是否确无入口。
  - Expected outcome: 产出一份经核实的「剩余问题清单」，每条附带文件路径、行号、实际数值，作为扣分依据。
