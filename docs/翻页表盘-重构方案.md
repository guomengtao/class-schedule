## 一、现状诊断（重构前 = v1）

| 项 | 现状 | 判定 |
|---|---|---|
| 名字 vs 实物 | 叫「翻页」，实现是 `scrolltop` 跳到目标值 | ❌ 见下条：**这条路在当前引擎上根本不生效** |
| 数字根本不显示 | 日志 `domUpdate type:0 is error, kid:19999` 每秒列各一次（6 列 = 6 次）；截图只有两个冒号和「返回」 | ❌ **v1 是坏的，不是"体验差"** |
| 每帧写入量 | `tick()` 无条件写 `y0…y5` | ❌ 只有秒个位真变了，5 次 setData 白跑 |
| 尺寸常量 | JS `ITEM_H = 56` 与 CSS 高度双真源 | ❌ 改一处必崩 |
| 交互 | 整页 `onclick` 直接退出 | ❌ 一碰就走；无上下滑切表盘 |
| 生命周期 | `onInit` + `onReady` + `onShow` 三处 `refresh()` | ⚠️ 重复建 interval |
| 秒的相位 | `setInterval(…,1000)` 起始点随机 | ⚠️ 跳秒最多慢 1s |
| 信息量 | 无品牌、无日期 | ⚠️ 像 demo 不像表盘 |

**根因一句话**：这是一份「验证 `scrolltop` 能改数字」的实验代码，实验本身没成立。

### 黑屏与不可渲染的硬约束（历史标定，改本文件前必读）

1. Vela **禁用群组选择器** `.a, .b {}` —— 整张样式表被丢弃 → 黑屏。
2. **`transform` 用 `{{}}` 数据绑定会黑屏**；本页完全不用 transform。
3. 根容器显式 `width/height:100%` + `flex-direction: column`；`.page` **不加** `justify-content` / `align-items`。
4. **`scroll + scrolltop` 定位内容在该引擎上无效**（`domUpdate type:0 is error, kid:19999`）——别再用它做视口。
5. **absolute 子元素定位不到无定位上下文的盒子**：`.card` 内套 absolute 的 `.di`/`.seam` 会全部相对页面左上角叠成堆。卡片样式必须直接放在最终节点上，别做嵌套定位。

## 二、目标与边界

**要做的**

1. 数字真的显示出来（对齐 v1 的真实状态说一句：这是本次最硬的验收项）。
2. 用时下可行的最接近「翻页」的形态：**分片翻页卡**（一位一张卡 + 深底 + 圆角 + 居中大数字）。
3. 脏检查：正常每秒只写 1 位（秒个位），分/时按需。
4. 先 `setTimeout(1000 - now%1000)` 对齐整秒再起 `setInterval(1000)`；`onHide`/`onDestroy` 全清并把 `shown` 打回 `-1`。
5. 补齐品牌 `EV 翻页表盘` 与日期 `MM-DD 周X`。
6. 交互对齐系列：单击回目录、**上滑 → `watch-face-landscape`**、**下滑 → `watch-face-animated`**（Y 位移 ≥40px 手算 + `suppressTap`，同 `evpointer`）。

**不做（边界）**

- ❌ 不改 `watch-face-list.ux` 及任何其他 `watch-face-*`。
- ❌ 不改 `router.entry`（锁 `pages/welcome`）。
- ❌ 不读写课表/storage；无 12h 制式开关。
- ❌ 不做真 3D 翻页（无 `preserve-3d`/`rotateX`，且 `transform` 绑定会黑屏）。
- ❌ **不再尝试 `scroll`/`scrolltop` 数字视口**（有日志证据，§五.1）。

## 三、最终实现的形态

```
.page（100%×100%，#0b0d12，flex 列）
├── EV            top 56  font 20
├── 翻页表盘       top 80  font 11
├── .clock        top 150 left 8  width 176（flex 行）
│   ├── .di ×6   26×64，#151924，radius 5，font 34 line-height 64
│   └── .c ×2    10×64 分隔冒号，color #4a5265
└── .date        top 250 font 13  10-20 周二
```

宽度核算：`6×26 + 2×10 = 176`，左起 8 → 右缘 184，右侧留 8，全部在 192 内。
安全区核对：所有 `top` ∈ {56, 80, 150, 250}，全部落在 [40, 450]。

### 3.1 为什么不是"4 帧滚动"

初版方案（v2）设想：`scrolltop` 从 `a*H` 分 4 帧走到 `b*H`，中间值是小数所以看起来在滚。
**实测不成立**：引擎对 scroll 的 domUpdate 直接报错（§一），连静态显示都做不到，
所谓"缓动中间态"更无从谈起。故 v3 起废弃滚动路线，改为即时换字 + 卡片造型。

真翻页钟的观感本来也是「一秒啪一下换一张卡片」，而不是持续滚动——分片卡比假滚动更诚实。

### 3.2 脏检查与秒对齐

```js
tick() {
  const d = [H/10, H%10, M/10, M%10, S/10, S%10]   // 按位取
  if (d[i] === this.shown[i]) continue             // 没变 → 不写
  this.shown[i] = d[i]                              // 显式写六个字段，不用 ['y'+i]
}
```
六个字段必须显式写：动态属性名在 Vela 的 data 观测里不保证生效（本项目多次踩过）。

## 四、验收

| # | 项 | 方法 | 判据 |
|---|---|---|---|
| 1 | 数字真的显示 | 模拟器单帧截图 | 6 位数字 + 冒号 + 日期全部可见，无重叠、无裁切 |
| 2 | 脏检查 | `node test/watch-face-flip.test.js` | 同秒再 tick → 0 次写；下一秒只有秒个位被写 |
| 3 | 日期 | 同上 | `dateText === "10-20 周二"` |
| 4 | 秒对齐 | 同上 | 首个 `setTimeout` 延迟 == `1000 - now%1000` |
| 5 | 生命周期 | 同上 | `stopAll` 后 `shown` 全 -1、interval 已停 |
| 6 | 手势 | 同上 | 上滑 landscape / 下滑 animated / 29px 不跳 |
| 7 | 安全区 | 同上 | 所有 `top` ∈ [40,450]；`.di` 26×64 且字号 ≤ 34（防数字溢出卡片） |
| 8 | 禁用机制回归 | 同上 | 页面内**不得出现 `<scroll`**；不得有群组选择器、`transform` 绑定 |
| 9 | 真机出图 | `vela-loop.py --page watch-face-flip --avd xiaomi_band --entry --build --scroll 0` | 192×490 单帧，内容即 §三 |

**第 9 项必须带 `--scroll 0`**：默认 4 次上滚会触发本页 40px 上滑手势，直接跳到 `watch-face-landscape`，截图就全是别人的表盘了（本次返工两次都是这个原因）。

## 五、踩坑记录（可复用的结论）

| # | 现象 | 结论 |
|---|---|---|
| 1 | `domUpdate type:0 is error, kid:19999` ×6 | **`<scroll>` + `scrolltop` 在该引擎无效**，数字视口方案整体作废 |
| 2 | 6 张卡 + 6 个数字全叠在左上 | absolute 子元素找不到定位上下文；卡片样式要落在最终节点上 |
| 3 | 字号 46 塞 26px 卡宽 | 数字溢出并互相覆盖、右侧被屏切 → 34px 才贴合 |
| 4 | 截图非黑即隔壁表盘 | 页面带 ≥40px 上滑手势 → 长图工具 drag 会误触发；单帧必须 `--scroll 0` |
