# 胶囊屏返回按钮位置分析

> 问题：胶囊屏顶部弧形，返回按钮位置偏下，弧形空间被浪费，手感也不对。

---

## 1. 胶囊屏的物理现实

```
                    ┌──────────┐
                   ╱            ╲    ← 弧顶，物理屏幕在此收窄
                  │              │
  返回按钮 ──→  │  ◀ 备份V2    │   ← 当前 Y≈26px，在平直区
                  │              │
                  │  已有备份     │
                  │              │
                  │  ...         │
                  │              │
                   ╲            ╱    ← 弧底
                    └──────────┘
```

关键事实：
- 胶囊屏宽 198px，屏幕顶部是**弧形收窄**的
- 弧形区域（顶部 ~20-30px）因为物理收窄，**不能放置内容**，天然是"留白区"
- 当前 `header padding-top: 24px`（base）或 `26px`（≥200px），返回按钮圆心在 Y≈26+22=48px
- **结果：返回按钮在平直区偏下位置，弧形空间上方 ~24px 完全空置**

---

## 2. 为什么"尴尬"

### 2.1 视觉层面

弧形顶部留白 + 返回按钮再往下 = **双重浪费**：

```
弧形留白：  ~20px  ← 物理必须
header 上 padding： 24px  ← 可以缩小
─────────────────
返回按钮顶部： Y≈26px
```

用户感觉"按钮太靠下"。因为弧形本身已经撑开了顶部视觉空间，不应该再叠加 24px padding——这等于在弧形下面再空一段，按钮被"挤"到更下方。

### 2.2 操作层面

- 返回是**最高频操作**之一，应该放在最容易够到的位置
- 拇指自然活动范围在屏幕上半部，越靠上越好点
- 当前 Y≈48px（圆心）已经偏离最佳热区

### 2.3 与系统惯例对比

大多数手环系统应用（设置、闹钟等）的返回按钮**贴顶**放置，利用弧形空间作为天然的安全距离，不会在弧形下面再额外留白。

---

## 3. 方案对比

### 方案 A：压缩 header 上 padding（最小改动）

```
header { padding: 8px 8px 24px 8px; }   ← top 从 24→8px
```

| 项目 | 改前 | 改后 |
|------|------|------|
| 返回按钮顶部 Y | 26px | **10px** |
| 弧形浪费空间 | 24+20=44px | 8+20=28px |
| 按钮圆心底 Y | 48px | **32px** |
| 代码改动 | — | 1 行 |

**优点**：极简，零风险，按钮上移 16px。
**缺点**：上 padding 缩到 8px 后跟弧形很近，视觉上可能略拥挤（但系统应用也是这么干的）。

### 方案 B：header 上 padding 归零 + 弧形不要额外留白

```
header { padding: 0px 8px 24px 8px; }
```

| 项目 | 改前 | 改后 |
|------|------|------|
| 返回按钮顶部 Y | 26px | **2px** |
| 按钮圆心底 Y | 48px | **24px** |

**优点**：按钮最大化上移，贴合弧形顶部。
**缺点**：0px 上 padding 可能让内容紧贴弧形边缘，风险略高（不同手环型号的弧形起始位置可能有偏差）。

### 方案 C：仅在胶囊屏（≥200px）上移，手环 9 不动

```css
/* base: 手环 9 保持原样 */
.header {
  padding: 24px 8px 24px 8px;
}

/* ≥200px: 胶囊屏上移 */
@media (width >= 200px) {
  .header {
    padding: 8px 10px 26px 10px;   /* top 从 26→8px */
  }
}
```

**优点**：手环 9（矩形屏）不受影响，胶囊屏精准优化。
**缺点**：需要维护两套 padding。

### 方案 D：返回按钮独立上移（absolute 定位）

```css
.back-btn-wrapper {
  position: absolute;
  left: 8px;
  top: 4px;
}
.header {
  padding-top: 48px;   /* 给按钮让出空间 */
}
```

**优点**：按钮精确控制位置，不受 header 布局影响。
**缺点**：破坏 flex 对齐，需要重新算 header 高度。个人觉得过度设计。

---

## 4. 推荐

**推荐方案 C**：仅在 ≥200px 胶囊屏断点将 header `padding-top` 从 26px 缩到 **8px**。

理由：
1. 手环 9（矩形屏）没有弧形问题，保持原样不动
2. 胶囊屏弧形空间 ~20px + 8px padding ≈ 28px 视觉间距，足够舒适
3. 返回按钮上移 18px，离拇指更近
4. 改动仅 1 个 CSS 值，零风险
5. 符合触底自适应原则：base 不动，大屏断点增量调整（这里"增量"是减小 padding，本质一样）

### 推荐值

```css
@media (width >= 200px) {
  .header {
    padding: 8px 10px 26px 10px;
  }
}
```

| | 改前 | 改后 |
|------|------|------|
| padding-top | 26px | **8px** |
| 按钮圆心 Y | 26+18=44px | **8+18=26px** |
| 上移 | — | **18px** |
| 视觉间距（弧顶→按钮） | ~46px | **~28px** |

---

## 5. 注意事项

- 如果标题字号较大（当前 26px），上移后标题仍居中在 header 行内，不受影响
- 底部 padding 保持 26px 不变，header 整体高度缩小 18px，不影响下方内容
- 手环 9（base）完全不受影响
