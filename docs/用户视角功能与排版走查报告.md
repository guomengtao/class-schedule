**由此产生两个"看起来是 bug"的事实：**

1. `add_course_day` 被首页写入，但正式添加页 `add-course.ux` **从未读取** → 添加时不会预选你正在看的那一天。
2. `course-manager-v2` 注册在 manifest 里，但全项目**没有任何页面跳转指向它**（添加页/详情页跳的都是 `/pages/course-manager`）→ 该页属"无入口页面"。

### 2.3 字号机制（问题的根因）

- 字号由 `store.getBaseFontSize()` 提供，档位为 **`[20, 28, 36, 48, 62, 76]`，默认值 48**。
- 首页把该值直接当"课程名字号"用（`index.ux` L242-246）：

```242:246:src/pages/index/index.ux
store.getBaseFontSize(function(size) {
  self.displaySize = size
  self.metaFontSize = Math.round(size * 0.71)
  self.dayTitleSize = size
```

- 而规范档位是 **40 / 36 / 34 / 32 / 28 / 24 / 20**，首页课程名应为 **32px**、星期标题 **36px**。
- 结论：**默认 48px 既不是规范值，也大于规范最大档 40px**，而且这个值是通过内联 style 写进模板的（`index.ux` L71/73/74/9），会**击穿所有媒体查询里的降级字号**。这是首页排版的根本病因。

## 三、逐条链路走查

### 3.1 打开课程表（首页）—— 能打开，但默认状态下文字重叠

**链路**：`welcome` → `index` → `database.getAllCourses` → `loadDayClasses`（按 `currentDay` 过滤）→ 渲染 `currentClasses`。
链路本身完整：有骨架屏、有"今天没有课"空态、有"数据加载失败 + 点击重试"兜底。**能正常打开。**

**问题（P0）：课程名/时间的行高远小于字号，文字互相压**

首页课程卡是三行结构（名字 + 时间 + 地点），字号由内联决定，行高写在 CSS 里，两者不匹配：

| 元素 | 实际字号（内联） | 行高（CSS） | 差值 | 位置 |
|---|---|---|---|---|
| 课程名 `.grid-item-name` | `displaySize` = **48**（默认） | **32px** | 行框小 16px | `index.ux` L71（内联）、L678 |
| 时间 `.grid-item-time` | `metaFontSize` = **34** | **28px** | 小 6px | `index.ux` L73（内联）、L691 |
| 同上，方屏 rect 降级 | 仍是 48 / 34 | **25px / 21px** | 小 23px / 13px | `index.ux` L1210-1215、L1222-1227 |
| 同上，胶囊屏 | 仍是 48 / 34 | 继承 32px / 28px | 小 16px / 6px | `index.ux` L1005-1010、L1017-1021 |

后果：
- 行框高度只有 32px 却塞 48px 字形 → 字形的上下各溢出约 8px，而课程名下方只有 `margin-bottom: 6px`（L674）→ **课程名的下半部分会压到"时间"那一行**，肉眼看到的是"课程名和时间黏在一起/被裁掉一截"。
- 卡片本体 `overflow: hidden`（L649），溢出部分一旦越界会被硬裁。
- 方屏（336×480）降级更激进：CSS 作者本意是名字 17px / 行高 25px、时间 13px / 行高 21px，但 **font-size 被内联 48/34 覆盖，只剩行高生效** → 溢出 23px，视觉上几乎必然重叠。

**问题（P0，关联）：胶囊屏首页只能看到 1 个字**
胶囊屏卡片为横向布局（`.class-card-body { flex-direction: row }`，L1000-1004），名字 `flex: 1`、时间列 `flex-shrink: 0`。屏宽 192 − padding 24 = 168px，减去"08:00"（34px 字号，约 85px）后名字只剩 ~77px，而字号是 48px → **只能放下一个字**，其余被 `text-overflow: ellipsis` 截断。规范场景 2 要求课程名 32px，胶囊屏单行 5 字，此处差距明显。

**问题（P2）：CSS 冲突写法**
`.grid-item-name` 同时写 `max-lines: 2` 与 `lines: 1`（L675-677），语义冲突，建议只留一处。

**问题（P2）：星期标题也被内联击穿**
`.day-title` 在方屏/胶囊屏分别被降级为 24px / 26px（L1061-1066、L919-924），但模板内联 `font-size: {{ dayTitleSize }}px`（L9）恒为 48px（默认）→ 降级失效。"星期一"3 字 × 48px = 144px，与两侧箭头、圆钮同排（`index.ux` L7-21），方屏勉强、胶囊屏（单字）偏挤。

### 3.2 添加课程 —— 能添加，但有三处让人困惑

**链路**：首页"+ 添加课程" → `openAddCoursePage`（`bottom-buttons.js`）→ `add-course` → 选课程/时间/地点/星期 → `database.insertCourse` → 返回首页刷新。**能添加成功**，且 `id` 自增（初值 100）与快速添加的 `Date.now()` 不冲突。

**问题 1（P1）：不预选"你正在看的那一天"**
`bottom-buttons.js` L7 写入 `add_course_day`，但 `add-course.ux` 里没有读取这个键，日期靠 `setDefaultDay()` 取"今天"。用户在首页翻到"星期三"再点添加，表单默认仍停在今天 → **很容易把课加到错误的星期**（尤其周五晚上给下周排课的场景）。

**问题 2（P1）：不能直接输入新课程名**
课程名只能从"课程预设库"里选，想加一门新名字必须先点"管理"跳到 `course-manager` 建名字，再回来选。这是一条"添加课程要跨两个页面"的隐性成本，且两个页面的**返回态**没有把新课程自动选中（`add-course` 回到前台只刷新列表，未重映射当前选中索引，排序变化后高亮可能与实际选中项不一致——待真机确认）。

**问题 3（P2）：方屏（rect）没有字号适配，控件被压缩**
`add-course.ux` 只有 `@media (shape: capsule)` 一套媒体查询（L743），**没有 `rect` 和 `circle`**。所以方屏走默认值：

| 元素 | 当前字号 | 规范值 | 位置 |
|---|---|---|---|
| 页面标题 `.title` | 30px | 36px | L476-480 |
| 分节标题 `.section-title` | 26px | 32px | L516-520 |
| 课程名 `.course-name` | 26px | 36px | L547-551 |
| 时间值 `.time-val` | 32px | 32px（合规） | L584-589 |
| 星期文字 `.weekday-text` | 24px | 28px | L705-709 |
| 输入框 `.input-text` | 26px | 32px | L668-679 |

另外两处宽度超框（方屏内容区 304px）：
- 星期行 7 个 `.weekday-btn` 固定 48px = **336px > 304px**（L691-694）→ 被 flex 压缩到约 43px，"一周七天"并排没有间距。
- 底部按钮 `.cancel-btn 120px + .save-btn 240px = 360px > 304px`（L719-741）→ 两个按钮都会被强制收缩变形。

> 备注：`UI审计清单.md` 声称添加页已改到"标题 36 / 课程名 36"，与当前代码（30 / 26）**不符**，属文档与代码漂移，建议以代码为准修正清单。

### 3.3 查看总课程（总课表）—— 能打开，但"看不清"

**链路**：首页"总"圆钮 → `goToWeekView` → `week-view` → `renderScheduleData` 生成 `timeSlots`/`cells`。默认隐藏周末（`hideWeekend`），显示周一~周五。**能打开、能点击格子进入详情。**

**问题（P0）：默认模板每格只显示 1 个字，字号 20px**

`onInit` 默认套用 `minimal-char`（L294-296、L354）：

```137:146:src/pages/week-view/week-view.ux
var TEMPLATE_CONFIGS = {
  "minimal-char": {
    showRowNum: false, showRoom: false, showTeacher: false, showTime: false,
    showDayCount: false, showTotal: false,
    nameDisplay: "char",
    ...
    nameFontSize: 20, nameLineHeight: 28, nameFontWeight: "bold", infoFontSize: 0,
    useColorScheme: true, denseMode: false, cellWidth: 50
  },
```

`nameDisplay: "char"` 在 `getDisplayName` 里等价于 `name.charAt(0)`（L544-545）→ **"大学英语"显示"大"、"高等数学"显示"高"**。用户打开总课表，几乎无法判断哪一格是什么课。

对照规范场景 5（`Ev课程表_手环字号规范_v1.md` L96-123）：
- 方屏课程格应为 **28px、最多 2 个汉字**；实测配置是 **20px（护栏档，规范明确"日常不用"）、1 个字**。
- 表头应为 24px，格宽 5 列铺满 304px（≈57.6px/格）；实测 `cellWidth: 50` → 5 × 50 = 250px，右侧留白约 54px，网格整体偏左（`gridContentWidth = rowNumWidth + 天数 × cellWidth`，L378）。
- `showRowNum: false` + `rowNumWidth: 0` → **没有节次/时间轴**，用户看不出这是第几节课。

**问题（P1）：所有内置模板的课程名都是 20px**
`minimal-char / minimal-en / standard-block / compact-grid / color-pastel` 五个模板的 `nameFontSize` 全是 20（L137-182），即"总课表永远低于规范 28px"，无论换哪个模板都看不清。

### 3.4 编辑课程 —— 能编辑，但有"改不了星期"和"错改名"两个坑

**链路**：首页点课程卡 → `class-list.js` 写入 `detail_classId`/`detail_day` → `detail` 加载 `loadExistingCourseData` → 四步（选课程 → 时间 → 地点 → 确认）→ 更新存储 → 返回。**能编辑并保存。**

**问题 1（P1）：没有修改星期的入口**
`detail` 的四步里只有"课程名、时间、地点"，**没有星期选择**（对比 `add-course` 有 `.weekday-row`）。用户想把周三的课挪到周四，只能删掉重加。

**问题 2（P1）：课程名不在预设库时，会被静默换成"第一门课"**

```391:397:src/pages/detail/detail.ux
if (foundIndex >= 0) {
  self.courseIndex = foundIndex
} else {
  self.courseIndex = 0
  self.courseName = self.presetCourses[0].name
  self.courseTeacher = self.presetCourses[0].teacher
}
```

触发路径：在"课程管理"里重命名/删除过某个预设名（已排进课表的旧课程仍保留旧名字）→ 再编辑这门课时 `foundIndex = -1` → **页面显示的是预设库第一门课的名字，用户点"更新"后会把这门课真的改成那门课**，属静默数据损坏。

**问题 3（P2）：字号设置对编辑页完全无效**

```306:315:src/pages/detail/detail.ux
applyFontSizes(s) {
  this.titleStyle = "font-size: " + s.title + "px"
  this.labelStyle = "font-size: " + s.label + "px"
  ...
```

`titleStyle / labelStyle / hintStyle / inputStyle / btnStyle / pickerValueStyle` 这 6 个变量在脚本里被赋值，但**模板中一处都没有引用**（全文件搜索仅出现在 L184-191 与 L306-315）→ 用户在设置里调大字后，编辑页纹丝不动。属死代码，同时是一致性缺陷。

**问题 4（P2）：胶囊屏出现 18px 文字**
`.course-index-hint` 在胶囊屏为 18px（L1073），低于规范 20px 护栏。

### 3.5 删除课程 —— 能删除，但语义与提示容易误解

**两条删除路径：**

| 路径 | 入口 | 实际删掉什么 | 二次确认 | 提示 |
|---|---|---|---|---|
| 删课表里的课 | 详情页第 4 步"删除"或顶部垃圾桶 | 课表数据中的这门课 | 需点两次，按钮文字变化 | 无文字引导 |
| 删"课程" | `course-manager` 行内"删除"（L21）| **只删课程名预设，不动已排课表** | 5 秒内点两次"删除→确认"（L237-255） | toast「课程已删除」 |

**问题 1（P1）：命名误导**
用户在"课程管理"里删掉"大学英语"，回到首页发现周三的"大学英语"还在。这不是 bug（预设库与课表是两套数据），但**界面语言没有说明**，用户只会判定"删除没生效"。

**问题 2（P1）：第一次点击没有任何文字提示**
`course-manager` 的"清除全部"给出了「再次点击确认」文案（L10），但单条删除只有按钮文字从"删除"变成"确认"（L21），颜色变化也偏弱 → 用户容易以为"点了没反应"而放弃，或误以为已删除。

**问题 3（P2）：无撤销**
两处删除都是立即落盘（`saveCourses()` / `database` 写），误删后只能靠备份恢复。

## 四、字号与排版问题汇总（对照规范）

规范档位：40 / 36 / 34 / 32 / 28 / 24 / 20，**正文基准 32px，禁止低于 20px**。

| 页面 | 元素 | 当前值 | 规范值 | 问题类型 | 位置 |
|---|---|---|---|---|---|
| 首页 | 课程名 | 48（内联，随设置变） | 32 | 超档 + 行高 32 冲突致重叠 | `index.ux` L71、L678 |
| 首页 | 时间 | 34（内联 `0.71×`） | 32 | 行高 28 冲突 | `index.ux` L73、L691 |
| 首页 | 地点 | 34（内联） | 28 | 同上 | `index.ux` L74 |
| 首页 | 星期标题 | 48（内联） | 36 | 击穿 24/26 降级 | `index.ux` L9、L919、L1061 |
| 首页 | "+ 添加课程" | 17（方屏） | 28 | 低于护栏 20 | `index.ux` L1184-1189 |
| 首页 | "今天课程已排满" | 17（方屏） | 24 | 低于护栏 20 | `index.ux` L1180 |
| 总课表 | 课程格 | 20（5 个模板全部） | 28 | 低一档 + 只显示 1 字 | `week-view.ux` L137-182 |
| 总课表 | 表头 | 未显式设（随模板） | 24 | 缺显式值 | `week-view.ux` L33 |
| 添加课 | 标题 | 30（方屏） | 36 | 非档位值 | `add-course.ux` L476-480 |
| 添加课 | 分节标题 | 26 | 32 | 非档位值 | `add-course.ux` L516-520 |
| 添加课 | 课程名 | 26 | 36 | 非档位值 | `add-course.ux` L547-551 |
| 添加课 | 输入框 | 26 | 32 | 非档位值 | `add-course.ux` L668-679 |
| 编辑课 | 卡片课程名 | 36 / 胶囊 28 | 36 | 合规 | `detail.ux` L722、L1061 |
| 编辑课 | 索引提示 | 18（胶囊） | 20 | 低于护栏 | `detail.ux` L1073 |
| 编辑课 | 字号设置 | 不生效 | — | 死代码 | `detail.ux` L306-315 |
| 课程管理 | "编辑"按钮 | 实际=重命名 | — | 文案与行为不符 | `course-manager.ux` L20、L155 |

**行高规范（规范 §5.2）**：单行正文/标题 = **1.2 × 字号**，且"不要依赖默认值，必须显式设置"。
→ 32px 正文应为 **38px** 行高；当前 48px 字配 32px 行高属于反向错误（行高小于字号）。

## 五、问题优先级与修复建议

### P0（必须修，直接影响"能不能用"）

1. **首页课程卡文字重叠 / 胶囊屏只显示 1 字**
   - 让"字号"回归规范体系：在 `loadDayClasses` 生成 `currentClasses` 时把 `displaySize` 收敛到 `min(baseFontSize, 32)`，`metaFontSize` 收敛到 `min(..., 28)`。
   - 行高改为跟着字号走：内联同时写 `line-height: {{ item.lineHeight }}px`（= 1.2 × 字号），不要只靠 CSS 固定值。
   - 去掉 CSS 里"被内联覆盖"的假降级（L1005-1010、L1210-1215 的 `font-size`），改为在脚本里按屏型算好最终值再内联，避免两份真值互相打架。
2. **总课表默认模板看不清**
   - 默认模板由 `minimal-char` 改为 `standard-block`，或把 `minimal-char` 的 `nameFontSize` 提到 28、`cellWidth` 提到 60（5 × 60 = 300 ≈ 内容区 304），并打开 `showRowNum` 提供节次轴。
   - 五个模板的 `nameFontSize` 统一 ≥ 28。

### P1（应该修，影响"用得顺不顺"）
