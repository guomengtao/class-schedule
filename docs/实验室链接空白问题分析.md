# 实验室栏目链接空白问题分析

## 一、问题概述

用户从 设置页 → 功能实验室 → `/pages/lab` 进入实验室列表后，点击某些链接项，目标页面显示为空白（白屏或内容不渲染）。

## 二、涉及文件清单

| 文件 | 作用 | 状态 |
|------|------|:---:|
| [src/pages/lab/lab.ux](../src/pages/lab/lab.ux) | 实验室列表页 | ✅ 正常 |
| [src/data/lab-list.js](../src/data/lab-list.js) | 实验室数据源（5 个条目） | ⚠️ 存在风险 |
| [src/data/pin-helper.js](../src/data/pin-helper.js) | 钉首页辅助模块 | ✅ 正常 |
| [src/pages/countdown-manage/countdown-manage.ux](../src/pages/countdown-manage/countdown-manage.ux) | 倒数日页 | ⚠️ 存在风险 |
| [src/pages/course-manager-v2/course-manager-v2.ux](../src/pages/course-manager-v2/course-manager-v2.ux) | 课程管理V2(胶囊) | ⚠️ 存在风险 |
| [src/pages/add-course-v2/add-course-v2.ux](../src/pages/add-course-v2/add-course-v2.ux) | 添加课程V2 | ⚠️ 存在风险 |
| [src/pages/lab-add-course/lab-add-course.ux](../src/pages/lab-add-course/lab-add-course.ux) | 添加胶囊版 | ⚠️ 存在风险 |
| [src/pages/lab-edit-course/lab-edit-course.ux](../src/pages/lab-edit-course/lab-edit-course.ux) | 编辑胶囊版 | ⚠️ 存在风险 |

## 三、根因分析

### 3.1 `lab-list.js` 数据源被大幅裁减

当前 `src/data/lab-list.js` 的 `ALL_PAGES` 只有 **5 个条目**：

```javascript
var ALL_PAGES = [
  { name: "倒数日", uri: "/pages/countdown-manage" },
  { name: "课程管理V2(胶囊)", uri: "/pages/course-manager-v2" },
  { name: "添加课程V2", uri: "/pages/add-course-v2" },
  { name: "添加胶囊版", uri: "/pages/lab-add-course" },
  { name: "编辑胶囊版", uri: "/pages/lab-edit-course" }
]
```

而此前旧版 `home-module-demo/modules/lab-list.js` 曾包含 **37 条** 完整条目。大量历史实验室页面（如设备信息、震动实验室、二维码生成、中文输入法等）缺少入口。

**影响**：虽然条目少不是直接导致空白的原因，但说明文件经过大幅重构，可能在此期间引入问题。

---

### 3.2 `init()` 函数依赖链长，任一环节失败导致空白

`lab-list.js` 中的 `init()` 函数依赖链：

```
init(instance, callback)
  └─ getStorage()          ← 读取 lab_settings（可能失败）
       └─ pinHelper.getList()  ← 读取 pinned_pages（可能失败）
            └─ instance.labItems = items   ← 只有这里才赋值
```

**关键代码** [lab-list.js:L67-L101](../src/data/lab-list.js#L67-L101)：

```javascript
function init(instance, callback) {
  var pinHelper = require("./pin-helper.js")

  getStorage(function(settings) {
    // ... 构建 items ...
    pinHelper.getList(function(pinnedList) {
      // ... 标记 pinned ...
      if (instance) {
        instance.labItems = items       // ← labItems 赋值
        instance.labStatus = "ok"
      }
      if (callback) callback(items)
    })
  })
}
```

**风险**：
- 如果 `getStorage()` 的 `fail` 回调未被触发（如某框架版本 bug），则 `instance.labItems` 永远为空数组 `[]`
- 如果 `pinHelper.getList()` 回调未执行，同上
- ✅ 好在两个函数都正确处理了 `success` 和 `fail` 回调，风险相对可控

---

### 3.3 `countdown-manage.ux` 缺少全局主题同步（低风险）

`countdown-manage.ux` **没有导入 `store.js`**，不调用 `store.getTheme()`，而是使用硬编码主题：

```javascript
// 脚本部分只导入了以下模块：
import router from "@system.router"
import prompt from "@system.prompt"
var storage = require("@system.storage")
// ❌ 没有 const store = require("../../data/store.js")
```

虽然这不是导致空白的直接原因，但主题无法与全局设置同步，页面可能显示风格不一致。更严重的是，如果框架在构建时检测到缺失依赖会报错（视构建工具而定）。

---

### 3.4 `lab-add-course.ux` 模板空数组访问风险（高风险 ⚠️）

**这是最可能导致空白页面的原因。**

在 `lab-add-course.ux` 的 `onInit()` 中，`presetCourses` 初始值为空数组 `[]`：

```javascript
export default {
  private: {
    presetCourses: [],      // ← 初始为空！
    courseIndex: 0,
    step: 1,                // ← 初始就显示 step 1
    // ...
  },
  onInit() {
    var self = this
    store.getTheme(function(t) { self.theme = t })
    this.loadCourses()      // ← 异步填充 presetCourses
    // ...
  }
}
```

模板中第一步（`step === 1`）直接访问数组元素：

```html
<div class="form-body" if="{{ step === 1 }}">
  <div class="course-card" onclick="swipeNext" style="...">
    <text class="card-name" style="...">
      {{ presetCourses[courseIndex].name }}
      <!--                       ^^^^
           如果 presetCourses 为空数组，
           presetCourses[0] 是 undefined，
           访问 .name 会抛出 TypeError！ -->
    </text>
  </div>
</div>
```

**触发条件**：
- 在 `onInit()` 的异步 `loadCourses()` 回调完成之前，模板就进行了渲染
- 此时 `presetCourses === []`，`presetCourses[0]` 为 `undefined`
- 访问 `undefined.name` 抛出 `TypeError: Cannot read property 'name' of undefined`
- 在 QuickApp/HarmonyOS 快应用框架中，**模板表达式抛出异常可能导致整个页面白屏**

---

### 3.5 `lab-edit-course.ux` 也存在类似风险（低风险）

```javascript
private: {
    demoCourses: demoCourses,   // ← 有初始值（8 门课程）
    courseIndex: 2,
    step: 1,
}
```

模板：
```html
{{ demoCourses[courseIndex].name }}
```

虽然 `demoCourses` 在脚本顶层定义了 8 个课程，但如果 `private` 中的赋值方式存在变量提升问题（`var demoCourses` 先声明后赋值），可能在极端情况下导致 `demoCourses` 为 `undefined`。

**实际风险**：低，因为 `var demoCourses = [...]` 在脚本顶层已赋值，`private.demoCourses: demoCourses` 引用的是已赋值的变量。

---

### 3.6 `course-manager-v2.ux` 和 `add-course-v2.ux` 依赖 `store` 异步加载主题

两个页面都使用了：

```javascript
onInit() {
    var self = this
    store.getTheme(function(t) {
        self.theme = t       // ← 异步赋值主题
    })
    this.loadCourses()       // ← 同步开始加载课程数据
}
```

**风险**：如果 `store.getTheme()` 的回调因某种原因未执行：
- `self.theme` 保持初始值（硬编码的默认主题）
- 页面仍能渲染，不会空白

**实际风险**：低。

---

### 3.7 两个 V2 页面（`course-manager-v2` 和 `add-course-v2`）依赖 `database.js`

```javascript
var database = require("../../data/database.js")
```

`database.js` 内部导入了 `schedule.js`，并有复杂的异步初始化流程：

```javascript
// database.js
var scheduleData = require("./schedule.js")

function ensureReady(callback) {
  if (ready) { callback(); return }
  pendingCallbacks.push(callback)
  if (pendingCallbacks.length > 1) return
  initStorage()     // 复杂异步链路
}
```

但这两个页面仅在 `saveCourse()` 时调用 `database.insertCourse()`，不在 `onInit` 时调用，因此**数据库初始化不会阻塞页面渲染**。

## 四、综合结论

| 风险等级 | 问题 | 涉及页面 |
|:---:|------|------|
| 🔴 高 | `presetCourses` 空数组时模板访问 `[index].name` 抛出 TypeError，导致页面白屏 | `lab-add-course.ux` |
| 🟡 中 | `lab-list.js` 条目仅 5 个，大量历史实验室页面入口丢失 | `lab-list.js` |
| 🟡 中 | `init()` 依赖链（storage → pinHelper）任一环节失败导致 labItems 为空 | `lab-list.js` |
| 🟢 低 | `countdown-manage.ux` 未集成全局主题 | `countdown-manage.ux` |
| 🟢 低 | `course-manager-v2.ux` / `add-course-v2.ux` 依赖 `store` 异步主题 | 两个 V2 页面 |
| 🟢 低 | `lab-edit-course.ux` 模板数组访问 | `lab-edit-course.ux` |

## 五、修复建议

### 5.1 修复 `lab-add-course.ux` 模板空数组访问（优先）

在模板中增加安全访问判断，或者确保 `presetCourses` 在模板渲染前已有默认值：

**方案 A：在 `private` 中设置默认课程数据**

```javascript
// 不要在 onInit 异步填充后才赋值，直接在 private 中初始化
private: {
    presetCourses: defaultCourses.slice(),  // 直接用默认值
    // ...
}
```

**方案 B：模板中增加长度判断**

```html
<div class="form-body" if="{{ step === 1 && presetCourses.length > 0 }}">
  <!-- ... -->
</div>
<text if="{{ step === 1 && presetCourses.length === 0 }}" class="loading-text">
  加载中...
</text>
```

### 5.2 恢复实验室条目

将 `lab-list.js` 的 `ALL_PAGES` 恢复到至少包含全部有效实验室页面，确保用户在实验室中能找到所有功能入口。

### 5.3 增加 `init()` 失败兜底

在 `lab-list.js` 的 `init()` 中增加超时/失败兜底逻辑，防止依赖链中断导致永远不渲染。

### 5.4 统一主题加载

所有实验室页面统一使用 `store.getTheme()` 加载主题，避免硬编码主题，保证视觉一致性。

### 5.5 建议全局排查

建议对所有通过 `lab-list.js` 引用的页面，逐一检查是否在 `onInit` 之前模板就依赖了异步数据，避免类似问题。
