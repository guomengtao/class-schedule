# 方形机械表盘（watch-face-vibrate）双屏适配方案

> 一句话：这块**不是占位实现**，是已经做到像素级拟真的方表。它的双屏难点不在「画得不够好」，而在 **140 个绝对定位节点全部焊死在 192 屏坐标系**，而两屏宽高比不同（1.75 : 0.98），整页等比缩放不成立。

- 目标屏：手环 9 `192×490`（保持现状）+ 手环 10Pro `336×480`（本次新增）
- 母题：拟真方表（Tank / Reverso 观感）—— 无圆轮廓、四边不等亮、45° 倒角、方表零件
- 原设计依据：`docs/方形仿真机械表盘-方案.md`（本方案只解决双屏，不改设计语言）

---

## 1. 现状盘点

### 1.1 体量

`watch-face-vibrate.ux` 共 1156 行。其中 CSS 里 120 档 `.rN`（`rotate(180 + 3N)deg`）占约 90 行 —— 这部分是**纯角度、与尺寸无关**，双屏零改动。

真正的负担在 template：盘内约 **140 个节点，全部 absolute + 像素字面量**。

### 1.2 坐标系（192×490 基准）

| 元素 | 定位 | 尺寸 / 字号 |
|---|---|---|
| `.brand` | left 0 · top 52 · 宽 192 | 10px |
| `.brand-sub` | left 0 · top 69 · 宽 192 | 8px |
| `.dial-wrap` | **left 10 · top 112** | **172×172** |
| `.case-outer` | 0,0 | 172×172 · radius 9 |
| `.dial-face` | 16,16 | 140×140 · radius 3.5 |
| 刻度方框半径 `r` | — | **65**（= 86 − 21） |
| `.date-line` | top 338 | 13px |
| `.hint` | top 362 | 13px |
| `.panel` | 居中 | 宽 240 · 字号 15/22/18/13 |

表壳四级下沉全部靠「**错位同心方框**」造倒角：`case-outer 172 → bezel 三层 → dial-face 140`，内缩 16px。

盘内节点构成：
`7 层表壳 + 4 edge + 8 rail + 8 screw + 2 glare + 60 mtick + 12 tick + 12 lume + 11 num + 3 mark + 5 日期窗 + 9 指针 + 3 hub ≈ 140`

### 1.3 刻度几何（从现有坐标反推，已验证）

页头注释给的公式是 `R(θ) = half / max(|sinθ|, |cosθ|)`，但**实际使用的 half 是 65，不是盘半宽 86**。用现有坐标逐项验证：

| 时点 | θ | 公式 R | 相对盘心 (x, y) | 模板实测 | 结论 |
|---|---|---|---|---|---|
| 12 | 0° | 65 | (0, −65) | `left:85, top:21` → (0, −65) | ✅ |
| 1 | 30° | 65/0.866 = 75.1 | (37.5, −65) | `left:122.5, top:21` → (36.5, −65) | ✅ 差 1 = tick 宽 2 的外端对齐 |
| 2 | 60° | 65/0.5 = 130 | (65, −37.5) | `left:150, top:48.5` → (64, −37.5) | ✅ |
| 3 | 90° | 65 | (65, 0) | `left:150, top:86` → (64, 0) | ✅ |

**结论：刻度贴在「半径 65 的方框边界」上**，1/2/10/11 因此自然落到角部、呈 45° 斜向 —— 这正是真方表的观感来源。适配时**不能**退化成圆环刻度，否则方表立刻变「圆表塞进方框」。

### 1.4 功能面（改动必须零丢失）

震动默认开、每 30s 一次（`VIBRATE_INTERVAL`）、长按 600ms 开面板、轻触返回、面板内可开关震动并显示倒计时。

## 2. 核心矛盾：宽高比不同，等比缩放不成立

```
192×490 → 336×480
宽度比 1.75        高度比 0.98
```

- 盘体在 192 屏占宽 `172/192 = 89.6%`，几乎顶满 → 按同比例，336 屏应是 `301`
- 若整页 `scale(1.75)`：纵向 `490 × 1.75 = 858`，远超 480 → 直接爆屏
- 若整页 `scale(0.98)`：横向只到 188，白白浪费 148px

**因此只能「盘内等比放大 + 盘外重新排布」，两件事分开处理。** 这也决定了路线选择：缩放只作用在盘内绘制层，不动盘外信息层。

---

## 3. 三条路线

### 路线 A：`scale` 包裹盘内层（改动最小，首选）

给 `.dial-wrap` 加宽屏 class：

```css
.w-dial-wrap { transform: scale(1.674); }
```

布局盒仍是 172，视觉放大到 288，靠 `left/top` 补偿：`(288 − 172) / 2 = 58`。

- **改动量**：约 +10 行（1 个 class + 2 个定位值）
- **优点**：140 个节点一个不动；120 档指针角度不受影响；刻度几何天然保持正确（因为整体缩放，比例不变）
- **风险**：Vela 对 `transform: scale` / `transform-origin` 的支持**未验证**。若 `origin` 默认不是 `50% 50%`，补偿量要重算
- **有利证据**：`.rN` 的静态 `rotate` 已在实机跑通 120 档，`scale` 同属 transform 函数族

### 路线 B：刻度几何改 JS 生成（彻底，备选）

把 `mtick / tick / lume / num` 共 95 个节点换成 4 个 `for` 循环：

```js
// r 与 half 都从盘径派生 → 换屏只改一个常量
const half = dialSize / 2
const r = half - 21 * s                    // 刻度方框半径
R = (th) => r / Math.max(Math.abs(Math.sin(th)), Math.abs(Math.cos(th)))
x = half + R(th) * Math.sin(th)
y = half - R(th) * Math.cos(th)
```

- **改动量**：template −95 行，script +40 行
- **优点**：两屏精确、可维护、以后加屏零成本；顺带把「65 这个隐式常量」变成显式派生
- **风险**：动态 `style="left:{{x}}px; top:{{y}}px"` 绑定需验证（背景表盘已验证 `background-color` 可绑，`left/top` 未验）

### 路线 C：双份静态坐标（兜底，不推荐）

`.dial-wrap` 与 `.w-dial-wrap` 各写一套 140 个节点。

- 零技术风险，但文件 1156 → 约 2300 行，两份坐标必然失同步
- 只作 A/B 探针全挂时的兜底

### 推荐

**A 优先**：风险集中在一个 CSS 属性，探针一验即知；A 挂则上 B（B 本身也有独立价值，即路线 B 可以顺带干掉 95 行硬编码）。C 仅在 A/B 都不通时启用。

## 4. 探针设计（一次部署，验 4 个假设）

临时页 `src/pages/_probe/_probe.ux`，单机 `emulator-13000` 跑。**192 屏即可** —— `scale` 的行为与屏宽无关，不必占用大屏实例。

| # | 构造 | 判读标准 | 服务于 |
|---|---|---|---|
| P1 | 40×40 色块 + `transform: scale(1.5)` | 视觉 60×60 = 生效；仍 40 = 不支持 | 路线 A |
| P2 | 同上 + `transform-origin: 0 0` | 左上角不动 = origin 生效；中心不动 = 不生效 | 路线 A 补偿量 |
| P3 | `<div style="left:{{sx}}px;top:{{sy}}px">`，`sx=120 sy=200` | 落在 (120,200) = 动态 px 绑定可用 | 路线 B |
| P4 | 父 100×100 `scale(1.5)`，内含子块 `left:20px` | 子块偏移是否跟着放大到 30px | **决定性**：盘内 140 个绝对定位子元素能否被父级 scale 带动 |

P4 最关键 —— 路线 A 成立的唯一前提。一次截图看四个方块位置即可判完，无需交互。

## 5. 两屏排版数值（探针后微调）

| 项 | 192×490（保持） | 336×480（目标） | 依据 |
|---|---|---|---|
| 盘体 | 172×172 @ left 10 · top 112 | **288×288 @ left 24 · top 108** | 288/336 = 85.7%，比原 89.6% 略让，避免宽屏顶满的压迫感 |
| 缩放系数 `s` | 1 | **1.674** | 288 / 172 |

| `.brand` | top 52 · 10px | top 30 · 14px | 装饰铭文，比 24 小是刻意的质感 |

```

盘体      108 – 396                     （288）
```

## 8. 验收标准

1. **指针对位**：三针在 12/3/6/9 及任意档位均指向刻度中线，放大后不偏移 —— 这是缩放路径正确的最硬指标
2. **刻度几何不退形**：12 整点外端落在方形边界上，1/2/10/11 呈 45° 斜向；**不得**退化成圆环
3. **不裁切**：盘体 + 表冠在 336 宽内完整，不被屏边切
4. **ev-six**：面板与底部两行 ≥ 24px，分隔用 1px 线不用符号
5. **功能零丢失**：震动默认开、30s 一次、长按开面板、轻触返回、倒计时刷新
6. **192 零回归**：除面板/底部字号提升外，盘内像素不变

## 10. 实施回填（2026-10-25 实做）

### 10.1 探针结果：四条全中（一次部署，单机 192 屏）

| # | 构造 | 实测 | 判读 |
|---|---|---|---|
| P1 | 40×40 + `scale(1.5)` | 59×60 @ 原左上 | scale 生效，**默认原点是左上角** |
| P2 | 同上 + `transform-origin: 0 0` | 59×60 @ 原左上 | 与默认一致，确认原点就是左上 |
| P3 | `style="left:{{sx}}px"` | 30×30 @ (120,150) | 动态 px 绑定可用 |
| P4 | 父 100×100 `scale(1.5)` + 子块 `left:20` | 父 151×150，子 30×30 @ 相对 (30,30) | **父级 scale 带动子块，子块偏移按比例缩放** |

P4 是决定性的 → **路线 A 成立**：盘内 140 个节点一个坐标都不用改，刻度几何天然正确。P1/P2 还省掉了中心补偿量的计算。

### 10.2 与原估的数值差异

| 项 | 原估 | 实做 | 原因 |
|---|---|---|---|
| 盘 top | 108 | **96** | 288 高 + 底部两行 24px 字在 480 里放不下（396+90 > 480），整体上移 12px |
| 日期 / 提示 top | 412 / 440 | **392 / 424** | 同上 |
| 日期 / 提示 height | 未提 | **16/14 → 28** | 字号抬到 24 后原高度装不下，字被裁掉上半 |
| 提示文案 | 「长按设置 · 轻触返回」 | 「长按设置 · 返回」 | 9 字 × 24 = 216 > 192 宽会截断；缩文案不缩字号 |
| 表冠 | 单独给宽屏坐标 | **移进 `.dial-wrap`** | 进缩放层后随盘自动缩放，宽屏零代码 |

### 10.3 三个没料到的 Vela 渲染限制（本轮真正的成本）

1. **不支持后代选择器。** `.w-page .dial-wrap {}` 退化成 `.dial-wrap {}` → 宽屏样式套到所有屏。现象是「192 屏只是看起来变大了」，极难一眼看出；实测盘心从 96 跑到 167 才定位到。**宽屏规则必须全部用单类选择器。**
2. **纯动态 class 不行。** `class="{{ pageCls }}"` 会让 `.page` 的 `position:relative` / `100%` 全丢，子元素失去定位基准。必须混写 `class="page {{ pageCls }}"`（项目内 `class="hand hour {{hourCls}}"` 有先例）。
3. **同步 `device.getInfo()` 取到错误宽度。** 同步形式在 192 屏读到 ≥300，把小屏误判成宽屏。必须用异步回调 `device.getInfo({ success: ... })`。

这三条叠加，使实际部署 **7 次**（原估 3 次）：探针 1 + 迭代 4 + 终验 2。若把这三条写进任何新页面的开工检查表，同类任务可回到 3 次。

### 10.4 未闭环

面板未实机截图：模拟器 shell 无 `input` 命令（`adb shell input swipe` 报 `input: command not found`），600ms 长按门槛无法触发。面板只改了字号与宽度，尺寸已推算（24px × 最长 8 字 = 192 < 240；高度约 200 < 480），真机需补一张。
