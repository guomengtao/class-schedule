# 首页(index)截图误含「课程表管理」页 · 根因分析

- 单号：evtask-D-evclass-sche-261021-4rrpyy
- 日期：2026-10-21
- 现象来源：`tools/vela-loop.py --page index --build --entry --scroll 6` 一次首页验收（产物 `/tmp/vela-loop/index-long.png`，192×984，3 帧）

---

## 1. 结论

**这不是首页的渲染缺陷，而是截图自动化的缺陷。**

vela-loop 的翻页拖拽使用固定坐标 `(96, 430) → (96, 120)`，该起点恰好落在首页「⇄ 课程表1」切换条上。拖拽的 mouse-down 被 Vela 兑现为一次点击，触发 `openScheduleManager()` 跳转到课程表管理页；于是第 1 帧拍的是首页、第 2/3 帧拍的是管理页，拼图器又把两个不同页面的帧拼进了同一张「首页长图」。首页自身渲染完全正常。

---

## 2. 现象与证据

### 2.1 截图内容

长图上半部为正常首页（日期栏「10-21 周三」、上课中卡片、下节课程、快速添加、添加/设置按钮、「⇄ 课程表1」条）；下半部为课程表管理页（返回栏、课程表单选列表、新增课程表、固定到首页）。

### 2.2 运行日志中的异常信号（当时已出现，未被消费）

```
[  53.2s] 画面已出且稳定（nz=20000, vapp=2）
[  58.4s]   第3次 drag 无位移，重试 1/3
[  61.8s] 第 3 次滚动重试仍无位移 → 判定到底
[  61.8s]   固定 header 35 行（每帧重复，只保留一次）
[  61.8s]   帧2 重叠0行(差152.2) 裁掉35行 → 新增455行
[  61.8s]   帧3 重叠416行(差0.0) 裁掉451行 → 新增39行
```

关键点：

| 日志行 | 含义 |
|---|---|
| `帧2 重叠0行(差152.2)` | 第 1 帧与第 2 帧**零重叠**——正常滚动必有部分重叠，零重叠只可能是**换了页面** |
| `第3次 drag 无位移 → 判定到底` | 第 1 次 drag 后已在管理页；第 2 次 drag 滚动管理页；第 3 次到管理页底部 |
| `固定 header 35 行` | 拼图器假设每帧顶部有 35 行重复 header，跨页场景下该假设失效，管理页顶部 35 行被误裁 |

屏幕为 192×490 胶囊屏，首帧（前 490 行）底部有两条亮带：

拖拽起点 `(96, 430)`：x=96 ∈ [58,133]，y=430 ∈ [429,443]——**精确落在切换条触摸区内**。

## 3. 根因链（代码级证据）

1. **固定拖拽坐标**：`tools/vela-loop.py:469`
   ```python
   drag(a.port, 96, 430, 96, 120, 8)
   ```
   `drag()`（185–195 行）先以 button=1 在 `(96,430)` 按下，分 8 步移到 `(96,120)` 再抬起。

2. **首页该坐标上的元素是可点的导航控件**：`ev/class-schedule/src/pages/index/index.ux:158`
   ```html
   <div class="schedule-indicator" onclick="openScheduleManager" ...>
     <image class="schedule-swap-icon" .../>
     <text class="schedule-name" ...>{{ currentScheduleName }}</text>
   </div>
   ```

3. **点击即跳转**：`src/pages/index/modules/class-list.js:174-177`（`week-indicator.js:16-19` 有同名实现）
   ```js
   instance.openScheduleManager = function() {
     var router = require("@system.router")
     router.push({ uri: "/pages/schedule-manager" })
   }
   ```
   全仓枚举确认：除该入口外，首页没有任何其他路径能到达 `/pages/schedule-manager`（其余 push 目标为 week-view / workday-info / course-manager / detail）。

4. **首页结构决定了底部拖拽不可能滚动**：`index.ux:82-115` 唯一的纵向滚动区是中部课程列表 `<scroll class="class-list" scroll-y="true">`，页面根节点为普通 div（模板 163 行收尾），「⇄ 课程表1」条位于滚动区之外（150–161 行，页面最底部）。内容总高约 443px < 490px，首页本身一屏放得下——在首页上执行"滚动拖拽"只能命中 UI 元素。

5. **Vela 事件语义**：mouse-down 落在切换条上后，引擎将其兑现为对该元素的点击（拖拽终点 `(96,120)` 位于课程列表区，若按终点归属应跳 detail 页；实际落在管理页，证明点击归因于**按下点**的元素）。

6. **拼图器无跨页保护**：`vela-loop.py:148-169` `concat_png()` 对 `best_overlap` 返回 `k=0`（零重叠）没有任何中止/告警逻辑，仅按「固定 header」假设继续拼接，产出混合长图。

**完整链条**：
固定拖拽起点 (96,430) → 命中首页 schedule-indicator → onclick 触发 router.push → 第 1 次 drag 后屏幕变为管理页 → 帧 1=首页、帧 2/3=管理页 → 拼图器零重叠仍拼接 → 「首页长图」里出现课程表管理页。

## 4. 为什么此前未暴露

1. ev-page-job 流程此前在 device-info 等页面验证过，那些页面在 (96,430) 处没有可点元素，或该点本就位于滚动容器内。
2. 首页是该固定坐标**第一个命中导航控件**的页面（指示条是 2026-10-18 两次提交 009602d / 07877d1 刻意改成独立行并置于最底部的）。
3. ev-page-job 方案 §3 已封存「坐标连点导航」类盲操作风险（30 分钟时间黑洞），但**滚动起点沿用了同一盲坐标思路**，未纳入页面级感知——本次是同一类风险在滚动方向上的首次实例。

---

## 5. 判定：不应改首页代码

| 检查项 | 结果 |
|---|---|
| 首页渲染 | 正常：字段齐全、无截断折行、布局符合 §5 规范 |
| 指示条点击跳转 | 设计行为（切换课表入口），两次提交刻意为之 |
| 课程表管理页 | 自身渲染正常（列表/新增/固定到首页均在位） |

缺陷位于**验收工具链**（vela-loop.py），不在应用代码。修 `index.ux` 属于修错对象。

---

## 6. 修复建议（按优先级）

| 级别 | 措施 | 说明 |
|---|---|---|
| P0 | 拼图器跨页保护 | `concat_png` 中 `k==0` 或 overlap 差值低于阈值时**中止拼接并告警**，绝不产出跨页混合长图。本次日志 `帧2 重叠0行(差152.2)` 已是充分信号 |
| P1 | 拖拽起点页面化 | 为每个页面配置「安全拖拽原点」：必须落在该页滚动容器内、且不覆盖任何可交互元素。index 页建议 `(96, 150)`（class-list 滚动区中部） |
| P2 | 不可滚动页识别 | 拖拽后既无位移、又无跳转（屏幕内容不变）→ 判定为单屏页，直接单帧收尾，不做无效重试 |
| P3 | 交互元素避让 | 条件允许时用 uiautomator dump 取可点区域，再选起点；彻底消灭盲坐标 |

配套：ev-page-job 方案 §3 的封存表建议补一行「固定坐标滚动起点误触导航控件（index 页实例，2026-10-21）」。
