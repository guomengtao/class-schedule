> 目标页面：`src/pages/detail/detail.ux`（manifest 中的「编辑课程」页）
> **状态：已实施**（2026-09-20 落地到 `detail.ux`；行号以改动前的版本为准，改动已生效）

## 二、改动 1：第一步「管理」→「删除」，顶部垃圾桶移除

### 2.1 为什么顶部垃圾桶要一起去掉

需求给的理由是"上面的删除按钮没地方放"——胶囊屏 192px 宽，header 要塞下
`返回 48 + 标题 + 垃圾桶 48`，标题被压到只剩十几 px，所以历史上把 header 改成两行（L1177-L1211）。
把删除功能下移到第 1 步后，header 只剩「返回 + 标题」两个元素，两行的理由消失，可以恢复单行。

> 若不移除顶部垃圾桶，会出现**两个删除入口**，属于 UI 一致性问题，不建议。

## 三、改动 2：切换图标换成返回键同款 + 三个一行

```html
<div class="swiper-wrapper">

         style="background-color: {{ theme.cardLight }}" />
  <div class="course-card" if="{{ courseIndex < presetCourses.length }}" onswipe="onCardSwipe" onclick="swipeNext"

         style="background-color: {{ theme.cardLight }}" />
```

### 3.2 三个强制一行

**根因**：胶囊屏 L1238-L1259 给 `.swiper-wrapper` 加了 `flex-wrap: wrap`，并用 `order` 把两个箭头排到第二行
（当时的取舍是"箭头 48×2=96px 会把卡片压到 56px"，于是换行保箭头尺寸）。
现在要求一行，就必须把箭头宽度压下来、卡片变为弹性宽度。

**基础样式（替换 L830-L853）**：

```css
.swiper-wrapper {
  flex-direction: row;
  flex-wrap: nowrap;          /* 强制单行 */
  align-items: center;
  justify-content: center;
  margin-bottom: 12px;
}

.swipe-arrow-icon {
  width: 48px;
  height: 48px;               /* 高度达标，与 .back-btn-wrapper 一致 */
  border-radius: 10px;        /* 同返回按钮 */
  flex-shrink: 0;             /* 不被卡片挤压 */
}

.course-card {
  flex: 1;                    /* 吃掉剩余宽度 */
  min-width: 0;               /* 允许收缩，否则长课名会撑破一行 */
  flex-direction: column;
  align-items: center;
  justify-content: center;
  border-radius: 14px;
  padding: 12px;
  margin: 0 8px;
  border: 3px solid #7ec8e3;
  min-height: 80px;
}
```

**胶囊屏（替换 L1238-L1259 整块 wrap/order 规则）**：

```css
@media (shape: capsule), (shape: pill-shaped) {
  .swiper-wrapper {
    flex-direction: row;
    flex-wrap: nowrap;        /* 删除 wrap + order，回到一行 */
    align-items: center;
    justify-content: space-between;
  }
  .swipe-arrow-icon {
    width: 36px;              /* 受 192px 物理宽度限制，高度保持 48 */
    height: 48px;
    border-radius: 18px;
    flex-shrink: 0;
  }
  .course-card {
    flex: 1;
    min-width: 0;
    width: auto;              /* 删除 flex: 0 0 100% */
    height: 72px;
    padding: 6px;
    margin: 0 4px;
  }
  .card-course-name {
    font-size: 22px;
    font-weight: bold;
    line-height: 30px;
    lines: 1;
    text-align: center;
    text-overflow: ellipsis;
  }
}
```

**胶囊屏宽度核算**（全宽 192px）：

| 项 | 值 |
|:---|:--:|
| 页面左右 padding | 16 × 2 = 32（若仍偏窄可降到 12 × 2 = 24） |
| 可用宽度 | 160 |
| 箭头 36 × 2 | 72 |
| 卡片左右 margin 4 × 2 | 8 |
| **课程卡实际宽度** | **80px**（padding 6×2 后文字区 68px ≈ 22px 字号 3 字） |

> 取舍：胶囊屏箭头宽度 36px < 48px。项目守护手册把"胶囊屏 192px 物理宽度"认定为硬约束，
> 且**高度仍保持 48px**，与历史上 `.swipe-arrow capsule 36×44` 的处理一致（本次顺带把高度从 44 提到 48）。
> 若不接受宽度 36，唯一替代是回到两行——但与"三个一行"的需求冲突，故按需求执行。

**rect / circle**：两个屏型宽度充足，保持箭头 48×48、卡片 `flex: 1` 即可，无需额外规则
（circle 下卡片约 394-96-16 = 282px，rect 下约 316-96-16 = 204px，均远大于现在）。

## 四、改动 3：课程名左右滑动切换

### 4.1 主方案：`onswipe`（快应用通用手势事件）

在 `.course-card` 上绑定（见 3.1 模板），JS 新增：

```js
onCardSwipe(e) {
  var d = e.direction
  if (d === 'left') {
    this.swipeNext()      // 左滑 → 下一门
  } else if (d === 'right') {
    this.swipePrev()      // 右滑 → 上一门
  }
},
```

"+"卡片同样建议绑定（在该卡片上也加 `onswipe="onCardSwipe"`），这样滑到末尾再右滑能退回最后一门课。

### 4.2 风险与兜底

**风险**：全项目目前 **零** `onswipe` / `touchstart` 先例，`docs/vela-unsupported-reference.md` 也未明确 Vela 是否支持 swipe 事件。
**必须先真机验证**；若不触发，改用 touch 位移兜底：

```js
onCardTouchStart(e) {
  var t = e.touches && e.touches[0]
  if (t) { this.touchStartX = t.clientX; this.touchStartY = t.clientY }
},

onCardTouchEnd(e) {
  var t = e.changedTouches && e.changedTouches[0]
  if (!t || this.touchStartX === undefined) { return }
  var dx = t.clientX - this.touchStartX
  var dy = t.clientY - this.touchStartY
  // 横向位移 > 30px 且明显大于纵向，才判定为左右滑，避免与纵向滚动冲突
  if (Math.abs(dx) > 30 && Math.abs(dx) > Math.abs(dy)) {
    if (dx < 0) { this.swipeNext() } else { this.swipePrev() }
  }
  this.touchStartX = undefined
},
```

模板对应改为 `ontouchstart="onCardTouchStart" ontouchend="onCardTouchEnd"`（两个方案二选一，不要同时绑）。

### 4.3 与纵向滚动的冲突

页面根节点是 `<scroll class="edit-course-page" scroll-y="true">`。横向手势理论上由 `direction` 区分，
但兜底方案必须加 `Math.abs(dx) > Math.abs(dy)` 判定，否则上下滑会被误判成切换。

### 4.4 行为一致性

滑动触发的仍是现有的 `swipePrev` / `swipeNext`（L474 / L480），
因此 `course-index-hint`（L38 "3 / 12"）与课程名会自动同步，无需额外处理。
点击卡片前进（`onclick="swipeNext"`）的既有行为保持不变。

## 十、第三轮：删除后首页不刷新 + 编辑页白屏（已实施 2026-09-20）

### 10.1 症状

1. 编辑页删除课程 → 返回首页，**列表里还留着已删除的课程**（不是慢一拍，是不刷新）
2. 此时再点那门残留的课程进编辑页 → **白屏**
   （旧逻辑是 `toast("课程已删除或不存在")` + 1.6 秒后 `router.back()`，这 1.6 秒里所有 `form-section`
   都不渲染，页面只剩 header 和步骤点，观感就是白屏）

### 10.2 首页立即刷新：写盘版本号机制

原有链路 `onShow → loadScheduleData(idx, true) → getAllCoursesWithIndex(forceRefresh) → invalidateCache`
本身是对的，但 `_skipNextShow` 与跨页面写盘的时序无法保证，所以补一层**与 UI 无关的硬信号**：

| 位置 | 改动 |
|:---|:---|
| `src/data/database.js` | 新增 `markDataDirty()`，在统一写入口 `saveToStorageWithIndex()` 的 success 里写 `allCourses_dirty = Date.now()`。<br>所有增删改（insert/update/delete/updateAcrossDays）都经过这里，天然全覆盖 |
| `index.ux` `onInit` | 启动时读一次版本号存进 `_lastDirty` 作为基准（避免首次进入被误判成"已变更"） |
| `index.ux` `onShow` | 改为先读版本号，再调新增的 `resumeRefresh(dirtyVal)` |
| `index.ux` `resumeRefresh()` | 版本号不一致 ⇒ `dataChanged = true`：<br>① **即使 `_skipNextShow` 还没消耗也必须重读**（原来会被直接 return 掉）<br>② 刷新延迟由固定 50ms 改为 `dataChanged ? 0 : 50`<br>③ 追加 **400ms 二次兜底刷新**，消除跨页返回与写盘落地的竞态 |

> 关键点：`_skipNextShow` 原本无条件 return，是"删除后回首页不刷新"最可能的漏点；
> 现在只有"数据没变且是启动后首次 onShow"才跳过。

### 10.3 编辑页课程失效：友好状态页替代白屏

- 新增状态 `courseMissing`，`loadExistingCourseData()` 查不到课程时置 `true` 并**停留在页内**
- 模板新增 `.missing-state`：标题「这门课已经不在了」+ 两行说明 + 两个按钮
  - 「返回首页」→ `goBack()`
  - 「去添加课程」→ 新增 `openAddCourse()` 跳 `/pages/add-course`（已确认 manifest 注册）
- 4 个 `form-section` 的条件统一改为 `if="{{ !courseMissing && step === n }}"`
- **删掉了**原来的 `toast + setTimeout(router.back, 1600)` —— 白屏就是它造成的
- 样式：背景/描边由内联绑定 `theme.card` / `theme.border`；按钮 48px 高（主按钮实心、次按钮描边）；
  胶囊屏单独降字号适配
