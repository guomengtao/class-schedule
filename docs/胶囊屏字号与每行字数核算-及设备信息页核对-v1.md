# 胶囊屏可读性核算：字号、每行字数上限 —— 先定标准，再核对设备信息页设计

> 2026-10-05 · 背景：用户要求「必须核实胶囊屏实际需要多大字号能看清、一行最多多少字能放下」，然后回过头核对设备信息页设计稿。
> 机型基准：小米手环 9 标准版，192 × 490 px AMOLED，对角线 1.74 英寸。

---

## 一、物理事实（计算，待官方规格核实项已标注）

### 1.1 像素间距

```
对角线像素数 = √(192² + 490²) = √276964 ≈ 526.3 px
对角线长度   = 1.74 in ≈ 44.2 mm
像素间距     = 44.2 / 526.3 ≈ 0.084 mm/px（≈ 302 PPI）
屏幕宽（物理）≈ 192 × 0.084 ≈ 16.1 mm
屏幕高（物理）≈ 490 × 0.084 ≈ 41.2 mm
```

> ⚠️ 待核实项①：官方资料若给出不同 PPI/英寸数（有资料标 336 PPI），以官方为准重算；
> 差异 ≤10%，不影响下文结论的档位划分。

### 1.2 观看距离与可读阈值

手环实际观看距离约 **25–30 cm**（抬腕看表）。按人眼舒适阅读标准（字符高度 ≥ 20 角分）：

```
25 cm：舒适字高 ≈ 25 × tan(20′) ≈ 1.45 mm
30 cm：舒适字高 ≈ 1.75 mm
及格下限（15 角分，勉强看清）：≈ 1.1 mm @ 25cm
```

### 1.3 换算成像素（1 px = 0.084 mm）

| 字号 | 物理字高 | 25cm 评级 | 30cm 评级 | 结论 |
|---|---|---|---|---|
| 20 px | 1.68 mm | 舒适 | 及格偏紧 | **标题档（推荐）** |
| 16 px | 1.34 mm | 及格偏上 | 偏小 | **标题下限 / 大字段** |
| 14 px | 1.18 mm | 及格线 | 偏小 | **正文下限** |
| 12 px | 1.01 mm | 勉强 | 不合格 | 仅限极短辅助词 |
| ≤11 px | ≤0.92 mm | **不合格** | 不合格 | **禁用**（含 9px 标签） |

> ⚠️ 待核实项②（最重要）：以上是光学计算。**必须实拍核实**——把同一段文字用 20/16/14/12px 渲染进包里，装模拟器按 1:1 屏幕截图，再在真机/近距离肉眼对比确认「及格线」落在哪一档。计算只能定档位，最终以实拍为准。

## 二、一行最多多少字（宽度逐项加总）

### 2.1 可用宽度链（胶囊屏 192px）

```
192（整屏宽）
− 左右弧形收窄余量 ~6px（胶囊左右是全弧，直边区更窄）
− 页面左右边距 2×12 = 24px
− 卡片内边距 2×14 = 28px
────────────────────────────
= 单行文字安全宽度 ≈ 140px
```

### 2.2 每行字数上限（140px ÷ 字宽）

汉字宽 ≈ 字号 px；西文/数字 ≈ 0.5–0.6 字号：

| 字号 | 汉字上限 | 西文/数字上限 | 备注 |
|---|---|---|---|
| 20 px | **7 字** | ~13 字符 | 标题/型号名 |
| 16 px | **8 字** | ~15 字符 | 大字段 |
| 14 px | **10 字** | ~19 字符 | 正文 |
| 12 px | **11 字** | ~21 字符 | 辅助（慎用） |

### 2.3 行内「k + v」结构的最宽公式（键值对行）

```
k（键，≤4 字）× 字号 + v（值）× 字号 + 键值间距 8px + 内边距 28px + 页边距 24px ≤ 192
→ 14px 时：k ≤ 4 字 且 v ≤ 6 字（56+84+8+52=200 超了 → k ≤3 字 或 v 换行）
→ 结论：14px 键值行放不下「4字键 + 6字值」，必须二选一收，或长值整行换行
```

## 三、回过头核对：设备信息页设计稿 v1（自纠）

### 3.1 ❌ 不合规 —— 共 3 处

| 位置 | 设计稿 v1 | 核算结果 | 修正 |
|---|---|---|---|
| 分组标签 | **9px**（SCREEN / SYSTEM…） | 0.76mm，**远低于及格线，禁用档** | 改 12px 中文短标签（「屏幕」「系统」「标识」），或干脆删掉英文装饰标签 |
| 键值行正文 | **11px** | 0.92mm，**不合格档** | 正文全部升到 **14px**；值列 11→14 |
| 键值行宽度 | 「平台 Vela 1.0.3 (API 3)」k=2字+v=~11西文字符 | 14px 时 28+~90+8+52=178 > 192−? 边缘；「1.0.3 (API 3)」这种**混合值**最容易爆宽 | 长值拆两行或去掉括号附录（API 并入调试组） |

### 3.2 ✅ 合规

| 位置 | 设计稿 v1 | 核算 |
|---|---|---|
| 身份卡型号 | 16px「Xiaomi Smart Band 9」 | 1.34mm 及格；西文 19 字符 ≈ 149px，在 140px 边缘 —— **收紧：改两行或字号 18px 只留「Band 9」主字** |
| 长值换行 | 序列号整行换行不省略 | 合规，且是唯一正确处理方式 |
| 内容垂直避弧 | top:46 / bottom:44 | 合规 |

### 3.3 修正后的字号档（v2 将采用）

```
标题/型号：18px（唯一大字）
正文键值：14px（k 3字上限 / v 超宽整行换行）
辅助说明：12px（≤6 字，如「点击复制」）
装饰性英文分组标签：删除（既不合规也无信息量）
```

### 3.4 ⭐ 键值行布局铁律：值默认独立成行（2026-10-05 用户指定）

设备信息是**外部数据，内容长度完全不可控**（设备型号名、序列号、OS 版本串都可能超长）。
因此 v2 起**放弃「k 左 v 右同行」布局，统一改为上下两行式**：

```
┌──────────────────────────┐
│ 序列号（12px，次要，≤6字）│   ← 键行：短、弱化色
│ WSDF48219XQZ-XXXX-XXXX   │   ← 值行：14px，独占整行 140px，
│ （超长继续换行，禁省略）  │      可换行到 3 行，行高自适应
└──────────────────────────┘
```

**为什么更保险**：
1. 值独占 140px 整行 = 容量从「同行剩余宽度 ~80px」翻倍到 140px，10 汉字 / ~25 西文字符；
2. 无论值多长都只有「换行」一种行为，**不存在爆宽分支**，宽度核算从逐行枚举退化为一行公式；
3. 键行永远短（≤6 字），永不换行——两行各自职责单一。

垂直预算影响：每条信息从 ~30px 变为 ~52px（键 18 + 值 34 一行），一屏约容 4 条——
配合分组滚动完全够用；超长值（3 行）时该组自动伸高，scroll 吸收。
