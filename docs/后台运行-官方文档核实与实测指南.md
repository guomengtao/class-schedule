# Ev 课程表快应用「后台运行」官方文档核实 + 手环实测指南

> 核实时间：2026-10-12 08:11 · 会话：后台钉子户📌
> 对象：`ev/class-schedule`（包名 com.application.watch.classschedule，v1.8.258）

## 一、官方文档核实结论

### 1. 手机快应用（doc.quickapp.cn）— `system.resident` 有完整文档
- **入口**：https://doc.quickapp.cn/features/system/resident.html 与「后台运行」框架文档 https://doc.quickapp.cn/framework/background-running.html
- **平台要求**：1050+（本应用 `minPlatformVersion: 1050`，满足）
- **机制**：快应用切后台默认**暂停运行**；要保活需三条件同时满足：
  1. manifest `features` 声明 `system.resident`；
  2. 调用 `resident.start({ desc })` 启动后台模式；
  3. 当前至少有一个已在 manifest 声明的后台接口在运行（audio / record / request / geolocation，配在 `config.background.features`）。
- **行为**：后台接口全部结束后 **20s 倒计时**，无新调用则退出后台模式；通知栏显示常驻通知，文案取**最后一次 `start` 的 `desc`**，用户可点「结束」强退。
- ⚠️ 官方参数名是 **`desc`**。

### 2. Vela 手表快应用（iot.mi.com/vela/quickapp）— 没有 resident 专页
- `features/system/resident.html` 路径不存在（被重定向到指南首页）⇒ **Vela 官方文档未收录 `system.resident`**。
- Vela 官方给出的后台能力是**微服务**：https://iot.mi.com/vela/quickapp/zh/features/other/serviceclient.html
  - manifest 声明 `services`（name / path / autoStart）；
  - `serviceclient.connect({ policy: "always" })` ⇒ **应用关闭后服务不关闭**，脱离应用生命周期后台运行；
  - service 侧用全局 `serviceManager`，生命周期 onCreate / onConnect / onDisConnect / onDestroy。
- 社区实测（米坛 bandbbs）：Vela 快应用**熄屏时 JS 会暂停执行**；有后台能力的官方应用极少（目前仅见腕上管 Pro 离腕锁定一例）。

### ⚠️ 发现一个配置键不一致（潜在 bug）
- `src/data/app-defaults.js:60` 默认配置是 `{ enabled: false }`；
- `app.ux:1183` 判断的是 `config.running !== false`；
- 键名对不上（`enabled` vs `running`）⇒ 判断恒为 true ⇒ **常驻实际默认开启且没有任何 UI 开关能关掉它**（store 的 `setBackgroundRunningConfig` 无任何页面调用）。
- 注释说"默认开启保持开箱即常驻"——如果这是有意为之，建议把键名统一并补一个实验室开关；如果不想默认常驻，这里就是 bug。

## 三、手环实测清单（你自己来）

**安装包**：`dist/ev-v1.8.258-t-9p-d.rpk`（2026-10-12 08:04 构建，与源码 manifest 1.8.258 一致）

安装后按顺序验证：

1. **通知栏常驻**：打开应用 → 退出到表盘/息屏 → 看手机通知栏是否出现「课程表后台运行中」（验证 resident.start 在 Vela 端是否真的生效，以及 `message`/`desc` 参数名哪个被采纳）。
2. **定时任务存活**：设一个倒计时/上课提醒 → 息屏或切到别的表盘 → 观察是否继续走动（Vela 熄屏可能暂停 JS，这是最大不确定点）。
3. **同步通道存活**：手机端改课表 → 看手环是否收到（验证常驻的初衷：后台收 interconnect 同步消息）。
4. **恢复性**：手动杀 Ev 课程表 → 重新打开 → 确认 onCreate 又把 resident 拉起来（冷启动恢复）。
5. **耗电观察**：常驻一夜，对比掉电（官方建议：审慎使用后台运行）。

## 四、结论

- 「后台运行」在代码层面**已经打开**（冷启动即 `resident.start`，且因键名 bug 默认关不掉）。
- 但 Vela 官方文档**不背书** `system.resident`，官方后台方案是微服务（`policy: "always"`）——**resident 在 Vela 端是否真保活，必须以你手环实测为准**。
- 若实测 resident 无效：备选路线是把同步接收逻辑搬进 Vela 微服务（services + serviceclient），这是官方唯一文档化的后台方案。
