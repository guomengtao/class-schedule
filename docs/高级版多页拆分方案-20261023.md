## 一、结论先行

上一轮方案A 的拆分方向没错，但**拆法失效**，三处硬伤：

1. **首页仍然溢出首屏**——「历史 · 设备信息」入口落在屏外，标题被压成「高...」；
2. **代码量反而膨胀 69%**——1116 行拆成 1886 行，每页重复主题/header/deviceId/二维码逻辑；
3. **步骤 2 与步骤 3 合并在 `activation-guide`**——两个独立动作挤一页，滚动照旧，等于没拆干净。

本轮改为 **「一屏一动作」**：每个步骤独占一屏、二维码放大到可扫、首页只做导航。核心是把上轮的两类缺陷（布局超预算、逻辑重复）从结构上消除，而不是再调一次尺寸。

## 三、上一轮方案A 的失败实证

### 3.1 体量数据

| 文件 | 行数 | 承载 |
|---|---|---|
| `activation.ux` | 437 | 状态卡 + 购买卡 + 3 入口 |
| `activation-code.ux` | 702 | 步骤 4 |
| `activation-guide.ux` | 394 | 步骤 2 + 过渡卡 + 步骤 3 |
| `activation-info.ux` | 353 | 历史 + 信息 |
| **合计** | **1886** | 对比老版 1116 行，**+69%** |

### 3.2 界面实证（192×490 实拍）

- 顶部标题渲染为 **「高...」**，应为「高级版」——header 内 back 按钮 + title + placeholder 三者争宽，title 被省略号截断；
- 第二个入口按钮渲染为 **「激活步骤指...」**，应为「激活步骤指南」；
- 「历史 · 设备信息」入口**完全在首屏之外**，必须滚动才可见——与方案A §五「首屏三入口完整可见」的验收目标直接冲突。

### 3.3 根因归纳

| 现象 | 根因 | 性质 |
|---|---|---|
| 首页溢出 | 购买卡（146px）+ 状态卡（68px）+ 3 个 52px 入口 + 间距，实测 > 434px 可用高；预算表把 52px 写成 50px、漏算 margin 累加 | 预算失真 |
| 标题/按钮截断 | 容器用了省略号截断（`lines`/宽度不足），违反 §5 规范「长值一律不截断，超宽换行」 | 规范违背 |
| 代码膨胀 | 每页各自复制 theme、header、deviceId 获取、二维码拼接，无共享层 | 架构缺陷 |
| guide 页仍需滚动 | 步骤 2 与步骤 3 是两个独立动作，合并必然超一屏 | 切分粒度错 |

## 四、本轮拆分原则

1. **一屏一动作**：每页只承载一个需要用户动手的动作（扫码 / 输入 / 查看），单页内容高度 ≤ 一屏，不滚动。
2. **首页零滚动**：首页只放状态 + 四步导航，任何情况下不产生滚动条。
3. **文案零改动**：§2.1 的标题与说明原样搬入，不重写、不精简、不改语序。
4. **逻辑下沉**：deviceId、URL 拼接、状态读取抽为共享模块，各页只做展示与跳转。
5. **二维码优先可扫**：单页独占时二维码可放大到 140px（老版/方案A 为 80px，扫码距离偏紧）。
6. **返回路径唯一**：任一子页返回都回到首页，不产生多级 back 链。

### 5.2 首页（P0）结构

```
[←]  高级版

┌ 高级版 · 永久有效 ─────────┐
└────────────────────────────┘

1  购买兑换码          ›
   ───────────────────
2  快速激活            ›
   ───────────────────
3  获取激活码          ›
   ───────────────────
4  输入激活码          ›
   ───────────────────
   历史 · 设备信息      ›
```

- 四步为**清单式行**（每行 44px 热区，label 18px + 序号徽标），不是卡片；卡片只在各步页内出现。
- 已激活的步骤行显示状态徽标（`已完成` / `待完成`），不隐藏行，保持步骤序号连续可读。

### 5.3 备选方案 B（五页，步骤 2+3 合并）

若用户认为六页翻页过密，可保留 `guide` 一页承载步骤 2 + 3，但必须满足：

- 用**分屏锚点**：进入时定位到步骤 2，页面底部「下一步」滚动到步骤 3 而非跳页；
- 两段各自 ≤ 一屏内容，滚动只在页内发生，且必须有滚动提示；
- 代价：二维码无法放大到 140px（两屏共用 80px），扫码成功率不提升。

**建议采用主方案 A**。备选方案作为退路，仅在验收反馈「翻页太频繁」时启用。

### 6.3 标题不截断的实现约束

- `.header-title` 字号 28px（pil 屏），`max-width` 不设、`lines` 不设，靠 `flex: 1` 让出空间；
- 去掉 `header-placeholder`（它为对称留白占位，是标题被挤的元凶），改为 back 按钮绝对定位或 `flex-shrink: 0` + 标题 `flex: 1`；
- 长度校验：`高级版` 3 字 × 28px ≈ 84px，可用宽 192 − 14×2 − 44（back）= 120px，**放得下，不应出现省略号**。

## 七、共享层设计

新增 `src/pages/activation/shared/activation-context.js`，把四页重复的逻辑收口：

```js
// 唯一出口，各页只 require 这个文件
module.exports = {
  getDeviceId(cb),        // @system.device → 回落本地 UUID，带内存缓存
  getStatus(cb),          // authStore.getFullStatus 归一化
  buildAfdianUrl(id, params, channel),
  buildActivationUrl(id, channel),
  buildApkUrl(id),
  applyTheme(vm)          // 主题 + iconTheme，onInit/onShow 各调一次
}
```

约束：

1. `deviceId` 在模块内做**内存缓存**，跨页复用，避免每页各调一次 `@system.device`（老版每页一次，是膨胀主因之一）；
2. 三条 URL 的拼接规则只在共享层出现一次，页面内不得重复拼接；
3. 页面只保留 `private` 状态与 `onclick` 跳转，单页目标 ≤ 180 行（现有 code 页 702 行需在 S4 内瘦身，键盘与结果框抽为组件）。

## 八、导航与返回契约

| 动作 | 实现 | 说明 |
|---|---|---|
| 首页 → 任意步 | `router.push` | 可从任意步直接进入，不强制顺序 |
| 步骤页「下一步」 | `router.replace` | 顺序推进不堆栈，避免 back 逐级回退 |
| 任一子页返回 | `router.back` / 回首页 | 统一回 P0，不出现 P4→P3→P2 长链 |
| 激活成功 | 停留 P4 展示结果 → 返回 P0 | P0 的 `onShow` 必须重读状态，徽标即时刷新 |

## 十一、验收口径

1. **零滚动**：六页各自 `shot --full` 输出高度均为 **490**（等于单屏），无拼接帧（无 `-long` 溢出）；
2. **零截断**：标题显示完整「高级版」，所有按钮文字完整，无省略号。判据：OCR 文本包含完整词条；
3. **首屏全见**：P0 的 4 步行 + 历史入口在 490 内全部可见；
4. **可扫性**：P1/P2/P3 二维码实测边长 ≥ 140px，用手机在正常距离扫出正确 URL（三条 URL 分别校验 `deviceId` 参数存在）；
5. **文案一致**：§九 清单逐条 diff，零差异；
6. **热区合规**：`python3 scripts/audit-hitbox.py --strict` 0 处不达标；
7. **状态刷新**：P4 激活成功后返回 P0，状态卡与步骤徽标在 1 秒内更新；
8. **回归**：从设置页「高级版」入口进入、以及任意子页直接进入，均能正常渲染与返回。
