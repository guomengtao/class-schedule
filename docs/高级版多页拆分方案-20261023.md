## 一、结论先行

上一轮方案A 的拆分方向没错，但**拆法失效**，三处硬伤：

1. **首页仍然溢出首屏**——「历史 · 设备信息」入口落在屏外，标题被压成「高...」；
2. **代码量反而膨胀 69%**——1116 行拆成 1886 行，每页重复主题/header/deviceId/二维码逻辑；
3. **步骤 2 与步骤 3 合并在 `activation-guide`**——两个独立动作挤一页，滚动照旧，等于没拆干净。

本轮改为 **「一屏一动作」**：每个动作独占一屏、二维码放大到可扫、首页只做导航。核心是把上轮的两类缺陷（布局超预算、逻辑重复）从结构上消除，而不是再调一次尺寸。

### 1.1 v2 修订：四步线性编号是结构性错误

v1 沿用了老版的 `1 → 2 → 3 → 4` 连续编号 + `▼` 箭头串联。**这个编号系统本身就是错的**，原因不在措辞，而在语义：

```
真实流程                              v1 呈现
购买（两条路都必经）                    1 购买兑换码
   ↓                                    ▼
   ├── A 扫码激活（限安卓，装完自动激活）  2 快速激活
   │        └ A 到此结束                  ▼
   └── B 手工激活（全平台，不装 App）      3 获取激活码
            ├ 扫码取码                     ▼
            └ 手环输码                   4 输入激活码
```

第 2 步与第 3、4 步是**互斥分支**，却被编进同一条序号序列，于是产生两个具体伤害：

1. **误读为「必须走完四步」**——走 A 的用户完成第 2 步后看到 3、4 未打勾，会怀疑「是不是还没弄完」；
2. **A 路径用户的界面里有一半是无效信息**——步骤 3、4 与他无关，却占据首屏 50% 的纵向空间。

这不是「感觉」问题，而是**用线性序列表达非线性流程**的必然结果。v2 的修正不是改文案，是换模型。

**新模型：1 次购买 + 二选一激活**

| 层 | 内容 | 编号策略 |
|---|---|---|
| 前置 | 购买兑换码（两条路都必经，只做一次） | 唯一编号 `①` |
| 分支 | 选择激活方式：A 扫码（限安卓） / B 手工（全平台） | **分支内各自重新编号**，并显式标注「全程 N 步」 |

三条硬约束：

1. **A 与 B 平级，只按适用条件区分，不按优劣区分**。文案用「限安卓 / 全平台」，**禁用**「兜底」「备用」「次选」等贬低 B 的措辞——B 是 iOS / 鸿蒙 / 同步器不可用场景的唯一通路，写成退路会让这部分用户觉得自己被降级。
2. **每条路径必须自报步数与终点**：「全程 2 步」「全程 3 步」「装完即激活，无需其他操作」。用户随时知道「我还差几步」。
3. **分支内部编号从 1 重新开始**（A1/A2、B1/B2/B3），不延续全局序号，避免出现「第 3 步」这种需要回头数前面几步的表达。

## 四、本轮拆分原则

1. **一屏一动作**：每页只承载一个需要用户动手的动作（扫码 / 输入 / 查看），单页内容高度 ≤ 一屏，不滚动。
2. **首页零滚动**：首页只放状态 + `① 购买` + A/B 二选一，任何情况下不产生滚动条。
3. **文案零改动**：§2.1 的标题与说明原样搬入，不重写、不精简、不改语序。
4. **逻辑下沉**：deviceId、URL 拼接、状态读取抽为共享模块，各页只做展示与跳转。
5. **二维码优先可扫**：单页独占时二维码可放大到 140px（老版/方案A 为 80px，扫码距离偏紧）。
6. **返回路径唯一**：任一子页返回都回到首页，不产生多级 back 链。

## 五、新拆分映射

### 5.1 主方案：六页，按「1 前置 + 两分支」组织

| 页 | 路由 | 角色 | 一屏内容 |
|---|---|---|---|
| **P0** | `pages/activation` | 总览 + 选择方式 | 状态卡 + `① 购买兑换码`行 + A/B 二选一卡 + 历史入口 |
| **P1** | `pages/activation/step-purchase` | 购买（A/B 共用） | 标题 + 说明 + 140px 二维码 + `扫码购买` |
| **A1** | `pages/activation/path-a-sync` | **A 路径唯一页** | `扫码下载 Ev课程表同步器` + 140px 二维码 + 「装完自动激活」说明 |
| **B1** | `pages/activation/path-b-redeem` | B 第 1 步 | `设备ID` 行 + 140px 二维码 + `扫码兑换` |
| **B2** | `pages/activation/path-b-input` | B 第 2 步 | 18 格输入 + 12 键键盘 + 验证 + 结果框（复用 `activation-code`） |
| **I** | `pages/activation/info` | 历史与设备信息 | 复用 `activation-info` |

**页数与 v1 相同（6 页），但导航深度完全不同**：

| 路径 | v1 需翻页 | v2 需翻页 |
|---|---|---|
| A 扫码（主推） | 购买 → 同步器 → 取码 → 输码 = **4 跳** | 购买 → A1 = **2 跳** |
| B 手工 | 购买 → 同步器 → 取码 → 输码 = **4 跳** | 购买 → B1 → B2 = **3 跳** |

v1 让 A 路径用户白走两跳（取码、输码），这是「以为要走四步」的直接来源。v2 把 A 路径的跳数砍到 2，与用户认知的「两步」完全对齐。

> 现有 `activation-code.ux`（702 行）与 `activation-info.ux`（353 行）**直接改路由沿用**，不重写；`activation-guide.ux`（394 行）拆成 A1 与 B1 两个文件后下线。

### 5.2 P0 结构

**未激活态（主形态）**

```
[←]  高级版

┌──────────────────────────────┐
│ 未激活                        │
│ 激活后解锁全部功能 · 永久有效   │
└──────────────────────────────┘

①  购买兑换码                  ›
    ──────────────────────────
选择激活方式 · 二选一即可完成

┌ A  扫码激活          [推荐] ┐
│ 限安卓 · 装完自动激活 · 全程2步 │  ›
└────────────────────────────┘
┌ B  手工激活                ┐
│ 全平台 · 不装 App · 全程3步    │  ›
└────────────────────────────┘

历史 · 设备信息                 ›
```

**已激活态**

```
┌──────────────────────────────┐
│ 高级版 · 永久有效              │
│ 已激活 · 2026-12-31 到期      │
└──────────────────────────────┘
历史 · 设备信息                 ›
```

已激活后**购买行与二选一区域整体收起**，不留置灰入口——已激活用户不需要再看到「购买」和「选择方式」，否则又会产生「我是不是还要再走一遍」的疑问。

**设计要点**

- `①` 是**页面上唯一的全局序号**，只用在购买行，明确「这件事只做一次」。
- A/B 用字母前缀而非数字，视觉上与 `①` 区分开，读作「方式 A / 方式 B」而不是「第 1 步 / 第 2 步」。
- 两张卡都是 2 行：主标题 + 一行属性（机型 / 是否装 App / 步数）。属性行用 `textSecondary`，`[推荐]` 徽标只在 A 上。
- 卡片高度 64px，整卡可点（≥44px 热区），不做内嵌小按钮。

### 5.3 分支内部导航

| 路径 | 页序 | 「下一步」行为 | 终点 |
|---|---|---|---|
| A | `P1 购买` → `A1 扫码` | A1 无「下一步」，只有「完成」回 P0 | 同步器自行完成激活，页面提示「装完自动激活，无需其他操作」 |
| B | `P1 购买` → `B1 取码` → `B2 输码` | B1 → B2 用 `router.replace`；B2 成功后停留展示结果 | B2 内 `authStore.verify` 成功即终态 |

- A1 页底部不放「下一步」——放一个指向 B 路径的按钮会把 A 用户误导入 B，这正是 v1 「过渡卡（不下载同步器？）」的残留伤害。
- **「不下载同步器？」句式在 v2 中退役**。它原本的职责是「走不通 A 的人可以改走 B」，但在 v2 里 P0 已把 A/B 并列展示、并各自标注「安卓」「全平台」，非安卓用户在入口处即可自选，这个过渡句式变成多余的绕路。故 P0、A1、B1 三处均不再出现该文案——**这是删掉一个绕弯的提问，不是删功能**。
- 从 P0 的 A/B 卡进入后，返回一律回 P0，不出现 A1 → B1 这类跨分支回退。
- **v1 的「五页备选方案（步骤 2+3 合并）」作废**：分支重构后 A 路径已是 2 跳，无需再为减少翻页而合并两屏，合并只会把两类动作挤回一页。

## 七、共享层设计

新增 `src/pages/activation/shared/activation-context.js`，把四页重复的逻辑收口：

```js
// 唯一出口，各页只 require 这个文件
module.exports = {
  getDeviceId(cb),        // @system.device → 回落本地 UUID，带内存缓存
  getStatus(cb),          // authStore.getFullStatus 归一化
  buildAfdianUrl(id, params, channel),
  buildActivationUrl(id, channel),
  buildApkUrl(id),
  applyTheme(vm)          // 主题 + iconTheme，onInit/onShow 各调一次
}
```

约束：

1. `deviceId` 在模块内做**内存缓存**，跨页复用，避免每页各调一次 `@system.device`（老版每页一次，是膨胀主因之一）；
2. 三条 URL 的拼接规则只在共享层出现一次，页面内不得重复拼接；
3. 页面只保留 `private` 状态与 `onclick` 跳转，单页目标 ≤ 180 行（现有 code 页 702 行需在 S4 内瘦身，键盘与结果框抽为组件）。

## 八、导航与返回契约

| 动作 | 实现 | 说明 |
|---|---|---|
| P0 → P1 购买 | `router.push` | 买完后 `router.back` 回 P0，再选方式 |
| P0 → A1 / B1 | `router.push` | 直接进入所选分支，**不经过对方分支** |
| B1 → B2 | `router.replace` | 分支内推进不堆栈 |
| A1 返回 | `router.back` → P0 | A1 无后继页，不存在跨分支前进 |
| B2 返回 | `router.back` → P0 | 不出现 B2→B1→P0 长链 |
| 激活成功 | 停留 B2 展示结果 → 返回 P0 | P0 的 `onShow` 必须重读状态，未激活/已激活两态即时切换 |
| 已激活后进入 P0 | 收起购买行与二选一 | 不显示置灰入口 |

**禁止**：任何让 A 路径用户看到 B 路径页面的导航路径（v1 的「过渡卡 → 步骤 3」就是这种越界）。

## 十一、验收口径

1. **零滚动**：六页各自 `shot --full` 输出高度均为 **490**（等于单屏），无拼接帧（无 `-long` 溢出）；
2. **零截断**：标题显示完整「高级版」，所有按钮文字完整，无省略号。判据：OCR 文本包含完整词条；
3. **首屏全见**：P0 的 `① 购买兑换码`行 + A 卡 + B 卡 + 历史入口在 490 内全部可见；
4. **无四步误读**（v2 新增，一票否决）：P0 截图 OCR 文本中**不得出现** `2` `3` `4` 作为并列序号；不得出现「步骤」字样连排成线性序列；必须能读到 `二选一` 与 `全程2步` / `全程3步` 两个步数标注；
5. **路径独立性**（v2 新增）：A 路径从 P0 到 A1 全程 **≤ 2 次翻页**，且 A1 页面及其后续不出现 B 路径的任何入口（含 `不下载同步器？` 按钮级呈现）；
6. **可扫性**：P1/A1/B1 二维码实测边长 ≥ 140px，用手机在正常距离扫出正确 URL（三条 URL 分别校验 `deviceId` 参数存在）；
7. **文案一致**：§九 清单逐条 diff，零差异；
8. **热区合规**：`python3 scripts/audit-hitbox.py --strict` 0 处不达标；
9. **状态刷新**：B2 激活成功后返回 P0，页面在 1 秒内切换为已激活态（购买行与二选一区域收起）；
10. **回归**：从设置页「高级版」入口进入、以及 A1/B1/B2 任一子页直接进入，均能正常渲染与返回。
