# 「添加课程」胶囊屏模块 —— 全新重新规划方案

> **对象**：`src/pages/add-course/add-course.ux`（胶囊屏 / pill-shaped，192px 物理宽度）
> **版本**：v1.6.4 · 规划日期 2026-09-19
> **目标**：围绕 **UI 界面 / 架构设计 / 操作流畅度**，以**滑动滚轮选时间**为核心，重新规划一个「100 分」的添加课程体验
> **配套**：[标准版100分评分标准.md](./标准版100分评分标准.md)（红线清单）、[标准版完善度综合评分.md](./标准版完善度综合评分.md)

## 一、目标与定位

### 1.1 设计目标

在胶囊屏（160px 内容区、约 490px 高）上，"添加一门课程"要做到：

| 目标 | 量化指标 |
|:---|:---|
| **少点击** | 设定一次上课时间 ≤ **5 次点击**（当前典型 15 次） |
| **少输入** | ≥ **80%** 的场景无需唤起中文输入法 |
| **少滚动** | 单屏内完成一个子任务，理想状态**零滚动** |
| **点得准** | 所有可点元素 ≥ **48px**，滚轮行高 ≥ 48px |
| **不迷路** | 分步推进，任何时候都知道"在第几步、还差什么" |

### 1.2 定位

把"添加课程"从当前的**单页堆叠表单**，重构为胶囊屏下的**分步向导（wizard）+ 全屏滚轮选择**：

- 桌面/大屏思维 → 手环思维（一次只做一件事）
- 输入优先 → **选择优先，输入兜底**
- 步进微调 → **滑动滚轮 + 快捷时段**

### 1.3 非目标（明确不做）

- 不做全局字号联动（会破坏已满分维度，见评分标准 §0.11）
- 不引入新的第三方组件（沿用 `scroll` / `list` 自定义实现）
- 不改变存储结构（仍为 `{id, day, name, time, teacher, location, notes}`，`time` 格式 `HH:MM - HH:MM`）

## 二、现有问题分析

### 2.1 时间选择：效率是当前最大短板

现状（`add-course.ux` L45-64）：点击「开始 / 结束」时间盒 → **同页内联展开**「时 − 数值 +」「分 − 数值 +」两组步进器 → 点「确定」。

| 问题 | 具体表现 |
|:---|:---|
| **步长过小** | 小时 ±1（`increaseSelectedHour` L399-406）、分钟 ±5（L407-414）。从 08:00 调到 15:30 需 **+7 次时 + 6 次分 + 展开 + 确定 = 15 次点击** |
| **循环无边界感知** | 小时 23 → 0 循环（`if <23 +1 else 0`），用户容易滑过头，且没有"到头了"的反馈 |
| **内联展开挤压竖向空间** | 展开后页面变高，胶囊屏需滚动才能看到「确定」按钮；确定按钮在下方，易被误判为"没反应" |
| **分钟粒度固定 5 分** | 多数场景够用，但无法设 08:02 这类精确值（取舍：保留 5 分档，不做分钟级自由输入） |

### 2.2 表单堆叠：胶囊屏需要滚动

当前一页内自上而下排列：课程名（横向滚动条）→ 上课时间（展开步进器）→ 上课位置 → 星期（横向滚动）→ 取消 / 保存。胶囊屏约 490px 高，**展开时间选择器后必然超出一屏**。

### 2.3 中文输入：路径长

`showKeyboard()`（L425-432）`router.push` 到 `/pages/chinese-input`。手环上输入"教学楼A301"成本高：

- 跳页 → 输入 → 确认 → 返回，路径长且**中断当前填写流**
- 地点是高频重复值（同一教室反复出现），却每次都要重新输入

### 2.4 已有基础（需保留）

| 能力 | 位置 | 说明 |
|:---|:---|:---|
| 时间冲突检测 | `database.checkDayConflict` | 保存前检测同天重叠，二次确认 ✅ 保留 |
| 保存防重入 | `isSaving` 锁（L436-437） | ✅ 保留 |
| 预设课程库 | `presetCourses`（内置 9 门 + 用户课程） | ✅ 保留并强化 |
| 主题体系 | `store.getTheme` → `theme.*` | ✅ 沿用 |

## 三、UI 界面重设计

### 3.1 总体结构：分步向导（胶囊屏专属）

非胶囊屏保持单页表单；**胶囊屏启用分步**，每屏只做一件事：

```
┌────────────────────────────┐
│ ①●●○○  课程名        (顶栏)│  ← 进度点 + 标题，高度 34px
├────────────────────────────┤
│                            │
│       [ 本步核心内容 ]      │  ← 内容区（滚轮 / 列表 / 选择）
│                            │
├────────────────────────────┤
│  上一步      │     下一步   │  ← 底部固定操作栏，48px
└────────────────────────────┘
```

| 步骤 | 内容 | 交互 |
|:--:|:---|:---|
| 1 | 课程名 | 预设课程**纵向列表**选择（替代横向滚动条）+「管理」入口 +「自定义名称」兜底 |
| 2 | 上课时间 | **全屏滚轮**（时 / 分两列）+ 上方**快捷时段**一行 |
| 3 | 星期 | 七天单列列表（替代横向滚动），大按钮 48px |
| 4 | 上课位置 | **常用地点选择优先**，「其他…」才唤起输入法 |

底部操作栏固定，不随内容滚动，避免"按钮找不着"。

### 3.2 关键改动点

| 项 | 现状 | 改后 | 理由 |
|:---|:---|:---|:---|
| 课程名 | 横向滚动条（120px/条，滑动找） | **纵向列表**（一行一条，160px 全宽，课名完整显示） | 横向滚动在小屏上难定位；纵向列表一屏 4~5 条，课名不截断 |
| 时间 | 内联步进器 | **全屏滚轮弹层** | 独立空间，不与表单争抢竖向空间；滑动一次到位 |
| 星期 | 横向滚动 | **纵向列表 7 项** | 七天是有限集，纵向一屏可放下（48×7 = 336px，可滚动） |
| 位置 | 直接跳输入法 | **选择优先 + 输入兜底** | 80% 场景免输入 |

### 3.3 视觉规范（沿用项目 theme 体系）

```
内容区      160px（192 − padding 16×2）
主文字      24~28px / 行高 1.2×（≥29~34px）
次要文字    20px / 行高 24px        ← 规范下限
可点元素    高 ≥48px，圆角 24px
滚轮行高    48px（3 行可见 = 144px）
选中态      theme.accent 高亮 + 字号加粗
分隔        8px
```

## 四、架构与交互流程

### 4.1 状态设计

```js
private: {
  // 分步（胶囊屏启用）
  capsuleWizard: false,   // 屏型探测后回填，复用已有 isCapsule 机制
  step: 1,                // 1 课程名 / 2 时间 / 3 星期 / 4 位置
  // 表单数据（与现状一致，保证存储结构不变）
  courseName: "", courseTime: "",
  startHour: 8, startMin: 0, endHour: 8, endMin: 45,
  dayIndex: 1, day: "",
  courseLocation: "",
  // 滚轮
  pickerVisible: false, pickTarget: "start",
  wheelHour: 8, wheelMin: 0,
  isSaving: false, timePicker: false   // timePicker 内联模式保留给非胶囊屏
}
```

### 4.2 交互流程

```
进入页面
  └─ device.getInfo 探测屏型（复用，不重复调用）
       ├─ 胶囊屏 → capsuleWizard = true，进入 step 1
       └─ 其它   → 沿用现有单页表单

step 1 课程名
  ├─ 选预设（列表点击）→ courseName → 下一步
  ├─ 「管理」→ /pages/course-manager（返回后刷新列表）
  └─ 「自定义…」→ /pages/chinese-input（返回带回名称）

step 2 时间
  ├─ 快捷时段（一行标签）→ 一键填入（开始 + 自动结束）
  ├─ 或 点「开始 / 结束」→ 全屏滚轮 → 滑动 → 确认
  └─ 结束时间联动：改开始后，结束自动 = 开始 +45min（可单独覆盖）

step 3 星期 → 纵向列表选一天

step 4 位置
  ├─ 常用地点（历史 + 已有课程地点去重）→ 点击
  └─ 「其他…」→ chinese-input
  └─ 可跳过（位置非必填）

保存
  ├─ 校验 courseName / courseTime 非空
  ├─ database.checkDayConflict(day, newCourse, null) → 冲突则二次确认
  └─ database.insertCourse → toast → router.back()
```

## 五、时间选择器方案（滑动选择）—— 核心

### 5.1 技术前提

项目**无原生 `picker` 组件**（全量检索 `<picker` 零结果）。可用的是 `<scroll>`（支持 `scroll-x` / `scroll-y` / `onscroll`，项目内已大量使用）与 `<list>`。

因此滚轮基于 **`<scroll scroll-y="true">` + 固定行高 + 吸附** 自定义实现。

> ⚠️ **需真机验证的点**：`scroll` 的定位能力（如 `scrollTo` / `scrollTop` 绑定）与 `onscroll` 回调频率，不同固件可能有差异。**建议第一步先做最小验证**：一个 3 行高的 scroll，验证能否读取滚动偏移并程序化定位。

### 5.2 结构设计

```
┌──────────────────────────────┐
│ 快捷时段                      │  ← 一行横向标签，48px
│ [08:00][08:45][10:00][13:30] │
├──────────────────────────────┤
│          ┌────┐ ┌────┐       │
│          │ 08 │  00  │       │  ← 上一行（渐隐）
│   选中 → │ 09 │ : 30 │       │  ← 选中行（accent 高亮，加粗）
│          │ 10 │  45  │       │  ← 下一行（渐隐）
│          └────┘ └────┘       │
│         时列     分列         │  ← 两列 scroll，各 76px 宽
├──────────────────────────────┤
│   取消        │      确定     │  ← 48px
└──────────────────────────────┘
```

| 参数 | 值 | 依据 |
|:---|:--:|:---|
| 容器宽 | 160px | 内容区 |
| 列宽 | 76px ×2（间隔 8px） | 160 − 8 = 152 ÷ 2 |
| 行高 | **48px** | 触控规范下限 |
| 可见行 | 3 行（144px） | 上下各留一行做滚动暗示 |
| 时列数据 | 00~23（24 项） | 与现状一致 |
| 分列数据 | 00/05/…/55（12 项） | 与现状步长一致，保留 5 分粒度 |
| 选中态 | 居中行 accent 高亮 + 加粗 | 明确反馈 |

### 5.3 吸附逻辑（关键）

```js
// 伪代码：onscroll 节流 → 计算选中项 → 停止滚动后吸附
onWheelScroll(e) {
  // 1) 节流：滚动中不做重计算，仅记录偏移
  if (this.wheelThrottle) return
  this.wheelThrottle = true
  setTimeout(() => { this.wheelThrottle = false }, 80)

  var offset = e.scrollTop            // 需确认固件返回的字段名
  var idx = Math.round(offset / ROW_H)   // ROW_H = 48
  idx = Math.max(0, Math.min(this.wheelData.length - 1, idx))
  if (idx !== this.selectedIdx) {
    this.selectedIdx = idx            // 只更新索引，不做重渲染
  }
},
// 停止滚动后（scrollend 或定时器判定）对齐到 idx * ROW_H
snapTo(idx) {
  this.$element('wheelScroll').scrollTo({ top: idx * ROW_H, behavior: 'smooth' })
}
```

**要点**：

- **节流 80ms**：避免每像素触发 setData（否则手环卡顿）
- **松手才吸附**：滚动过程中只更新 `selectedIdx`，停止后（无新 onscroll 事件 ~120ms）再定位，避免"跟手打架"
- **惯性交给系统**：不自己实现惯性，依赖 `scroll` 自带惯性

### 5.4 快捷时段（把 15 次点击降到 1 次）

滚轮上方常驻一行快捷标签，按中小学/大学常见作息预置：

```
08:00  08:45  10:00  13:30  15:00  19:00
```

- 点击即填入**开始时间**，并**自动带出结束时间**（开始 +45min）
- 数据可写入 `store` 并支持用户自定义（后续版本）
- 这是把"典型 15 次点击"降到 **1 次**的关键

### 5.5 结束时间联动

- 修改**开始**时间后，结束时间自动 = 开始 + **45 分钟**（中小学课时），若用户手动调过结束则不再自动覆盖（用 `endTouched` 标记）
- 结束 < 开始时，自动改为开始 +45 并 toast 提示（见 §9）

## 六、中文输入优化

### 6.1 原则：选择优先，输入兜底

手环中文输入成本高，把"输入"降级为**次级入口**。

### 6.2 课程名（步骤 1）

| 来源 | 说明 |
|:---|:---|
| 内置预设（现有 9 门：语文/数学/英语/物理/化学/生物/历史/地理/政治…） | 保留 |
| **从已有课程同步** | 读取当前课表已有课程名去重，用户加过的课一定在列表里 |
| 「管理」 | 跳 `/pages/course-manager` 批量维护 |
| 「自定义…」 | 兜底跳 `/pages/chinese-input` |

列表改为**纵向**（160px 全宽一行一条），课名 24px 可显示约 6 字（8 字以上 ellipsis），彻底解决"横向滚动条只显示 4.5 字"的定位困难。

### 6.3 上课位置（步骤 4）

| 来源 | 说明 |
|:---|:---|
| **历史地点** | 从已有课程的 `location` 去重提取，存 `storage` |
| **内置常用** | 教室 / 实验室 / 操场 / 图书馆 / 机房 |
| 「其他…」 | 兜底跳 `/pages/chinese-input` |
| 可跳过 | 位置非必填（现状 `courseLocation || ""`） |

预期：**≥80% 的场景无需唤起输入法**。

### 6.4 跳页返回的状态保持

跳 `chinese-input` 属于跨页，需保证返回后**已填内容不丢**：

- 进入输入法前把当前 `step / courseName / time / dayIndex` 写入 `storage`（如 `add_course_draft`）
- 返回时 `onShow` 读取草稿恢复
- 输入结果通过 `storage`（如 `input_result`）带回，读取后清理

## 七、胶囊屏适配策略

### 7.1 尺寸基线

```
物理宽 192px，padding 16×2 → 内容区 160px
物理高 ~490px，减去上下 padding → 可用约 430px
```

### 7.2 逐项适配

| 元素 | 规格 | 达标校验 |
|:---|:---|:---|
| 顶栏（进度 + 标题） | 高 34px，标题 24px | 字号 ≥20 ✅ |
| 内容区卡片 | 宽 160px，圆角 12px | 不溢出 |
| 列表项（课程名 / 星期 / 地点） | 高 **48px**，文字 24px | 触控 ✅ |
| 滚轮行 | 高 **48px**，列宽 76px | 触控 ✅ |
| 快捷时段标签 | 高 **48px** | 触控 ✅ |
| 底部操作栏（上一步 / 下一步 / 保存） | 高 **48px**，两个按钮分列两端 | 触控 ✅ |
| 次要说明文字 | 20px / 行高 24px | 规范下限 ✅ |

### 7.3 分步带来的好处

- 每屏元素 ≤5 个 → **单屏可完成，无需滚动**
- 底部操作栏固定 → 不会出现"按钮在屏幕外"
- 进度点 ①●●○○ → 用户始终知道所处位置（对应"防混乱"要求）

### 7.4 屏型探测复用（重要）

沿用现有约定：**`device.getInfo` 全链路只调用 1 次**，屏型由首屏探测后回填。

- `add-course` 复用 `store` / 已有 `isCapsule` 机制，**不得自行再次调用 `device.getInfo`**（会拖慢首屏，属操作流畅性红线）
- 屏型是异步返回的，探测到胶囊屏后需**重新应用分步布局**（参考 `week-view` 的做法：探测后重新 `applyTemplate`）

## 八、操作流畅度与性能考量

| 项 | 措施 |
|:---|:---|
| **滚轮节流** | `onscroll` 节流 80ms；滚动中只更新 `selectedIdx`，不做列表重渲染 |
| **松手吸附** | 停止滚动 ~120ms 后定位一次，避免与惯性打架 |
| **分步渲染** | 每步只渲染当前步内容（`if="{{ step === n }}"`），避免整页重排 |
| **数据缓存** | 预设课程、历史地点读一次缓存（`_cache`），避免每次进入重读盘 |
| **日志** | 沿用 `DEBUG` + `dlog()` 包装，常态路径零日志开销 |
| **屏型探测** | 复用回填值，不重复 `device.getInfo` |
| **保存防重入** | 保留 `isSaving` 锁 |
| **写盘** | 单次 `insertCourse`，不在分步过程中写盘（草稿除外） |

**避免的做法**：滚动中频繁 `setData` 整个列表；展开/收起用大范围重排（改为分步切换）。

## 九、边界与异常处理

| # | 场景 | 处理 |
|:--:|:---|:---|
| 1 | 结束时间 ≤ 开始时间 | 自动改为「开始 +45min」并 toast「结束时间已自动调整」 |
| 2 | 跨天（23:30 → 00:30） | 允许保存，toast 提示「跨天课程」 |
| 3 | 同天时间冲突 | 保留 `checkDayConflict`：toast 提示与哪门课重叠，**再点一次确认才保存** |
| 4 | 课程名为空 | 保存按钮禁用 + toast「请选择课程」 |
| 5 | 滚轮滑动中点「确定」 | 取当前吸附值（先 snap 再取值），避免取到中间态 |
| 6 | 跳输入法后返回 | 草稿恢复（§6.4），已填项不丢 |
| 7 | 输入法返回结果为空 | 保留原值，不覆盖 |
| 8 | 写盘失败 | `isSaving = false` + toast「保存失败，请重试」，保留已填数据 |
| 9 | 快速连点「下一步」 | 步切换加 200ms 防抖，避免跳步 |
| 10 | 快捷时段与手动冲突 | 手动调过后 `endTouched = true`，不再自动覆盖结束时间 |
| 11 | 小时/分钟循环边界 | 滚轮采用**有限列表**（非无限循环），到头即停，避免"滑过头"（改进现状的 23→0 循环） |

## 十、评分标准 / 验收要点

### 10.1 对齐现有 8 维度（不得回退）

改动后必须复检 [标准版100分评分标准.md](./标准版100分评分标准.md) 的 13 条红线，尤其：

- 字号 ≥20px、行高 = 1.2×字号
- 可点元素 ≥48px（滚轮行、快捷标签、列表项、底部按钮）
- 胶囊屏不溢出（列宽 76×2 + 间隔 ≤160px）
- 不重复调用 `device.getInfo`
- 保留二次确认 / 撤销 / 冲突检测 / 原子写盘

### 10.2 「添加课程」专项验收（100 分标准）

| # | 验收项 | 达标标准 | 测量方式 |
|:--:|:---|:---|:---|
| 1 | **时间设定点击数** | 用快捷时段 **1 次**；用滚轮 ≤ **3 次**（滑动 + 确定） | 计数点击 |
| 2 | **典型课程添加时长** | 从进入到保存 ≤ **30 秒** | 计时 |
| 3 | **免输入率** | ≥ **80%** 场景无需唤起中文输入法 | 统计跳页次数 |
| 4 | **单屏完成率** | 每一步**无需滚动**即可完成操作 | 真机目测 |
| 5 | **滚轮吸附准确性** | 停止滑动后选中行居中，偏差 ≤ **半行（24px）** | 真机目测 |
| 6 | **滚轮跟手性** | 滑动过程无卡顿、无"回弹打架" | 真机手感 |
| 7 | **触控达标** | 所有可点元素高 ≥48px（含滚轮行） | 尺寸核对 |
| 8 | **课名可读性** | 列表项课名 ≥ **6 字**完整显示（160px 全宽 / 24px 字号） | 算式 + 目测 |
| 9 | **状态不丢** | 跳输入法返回后已填内容完整 | 实操 |
| 10 | **异常兜底** | 结束≤开始、跨天、冲突、写盘失败均有明确反馈 | 逐条验证 |
| 11 | **性能** | 滚轮滚动时无掉帧；页面进入 ≤ 现有耗时 | 真机 / 日志 |
| 12 | **无回退** | 8 维度复检仍全部 100 | 对照守护手册 |

### 10.3 落地顺序建议

1. **最小验证**（前置）：`scroll` 的滚动偏移读取与程序化定位能力 → 决定滚轮实现细节
2. **快捷时段**（收益最大、风险最低）：先上线，典型点击 15 → 1
3. **滚轮选择器**：替换内联步进器
4. **分步向导**：课程名 / 时间 / 星期 / 位置
5. **位置选择化**：常用地点 + 输入兜底
6. **真机验证**：按 §10.2 逐项验收，并回填评分文档
