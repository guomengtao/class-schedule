## 2. 结论速览（TL;DR）

| 项 | 结论 |
|---|---|
| 主因（候选 A） | **页面根容器是 `<stack>`，而内容层 `<scroll class="page">` 只写了 `height: 100%`，没有写 `width: 100%`。Vela 的 `stack` 子组件和 `scroll` 组件都不会自动撑满父容器，宽度退化为"内容撑开的宽度" → 页面只占屏幕左侧一部分** |
| 为什么是黑色 | `.page-root`（stack）**没有设置 `background-color`**，主题背景色只画在 `.page` 上。未被 `.page` 覆盖的右侧区域没有绘制内容 → 露出系统底色（黑色），即用户说的"黑板" |
| 唯一性证据 | 全项目 **177 个文件中只有 `schedule-manager.ux` 一个页面使用 `<stack>` 作为根容器**（`device-info.ux` 的 "stack" 只是注释文字）。它是唯一可能踩这个坑的页面，也正好是唯一报这个现象的页面 |
| 伴生因素（候选 B） | 标准版用户进入本页**必定弹出解锁弹窗**（`.overlay-modal`，`rgba(0,0,0,0.5)` 黑色遮罩）。若 `align-items: center` 在该组合下未生效，卡片偏左、右侧露出遮罩黑区，外观与候选 A 几乎一样 |
| 已排除 | `designWidth` 缩放、`192 vs 212` 宽度基线、`pill-shaped` 媒体查询未命中、输入法重启类崩溃、storage 并发 |
| 最小修复 | 1 行核心改动：`.page { width: 100%; }`；再加 1 行兜底：`<stack>` 上绑 `background-color`。**不动任何字号/尺寸/交互** |

## 4. 根因分析（候选 A：内容层宽度塌缩）

### 4.1 当前结构

```html
<!-- schedule-manager.ux:3-4, 107 -->
<stack class="page-root">
  <scroll class="page" scroll-y="true" style="background-color: {{ theme.bg }}">
    ... 页面全部内容 ...
  </scroll>

  <div class="overlay-sheet" if="{{ sheetIndex >= 0 }}" ...>...</div>
  <div class="overlay-modal" if="{{ showDialog }}" ...>...</div>
</stack>
```

对应样式：

```css
/* 有 width 的：根容器 */
.page-root { width: 100%; height: 100%; position: relative; }

/* 有 width 的：两个覆盖层 */
.overlay-sheet { position: absolute; left: 0; top: 0; width: 100%; height: 100%; ... }
.overlay-modal { position: absolute; left: 0; top: 0; width: 100%; height: 100%; ... }

/* ❌ 唯独缺 width 的：内容层 */
.page {
  flex-direction: column;
  padding: 44px 12px 12px 12px;
  height: 100%;        /* ← 只有 height，没有 width */
}
```

**三个兄弟元素里，两个 absolute 覆盖层都规规矩矩写了 `width: 100%; height: 100%`，唯一承载页面内容的 `.page` 却漏了 `width`。** 这正是症状来源。

### 4.2 为什么 `stack` 里的子元素必须显式声明宽度

Vela 官方文档（`iot.mi.com/vela/quickapp` 容器组件 · stack）对 stack 的定义：

> 基本容器，**子组件排列方式为层叠排列**，每个直接子组件按照先后顺序依次堆叠，覆盖前一个子组件。

官方示例中，stack 的每一个子 div 都**显式写了 `width`/`height`**（100px、200px），并用 `left`/`top` 做偏移。这说明在 stack 中：

- 子元素**不会**像普通 flex 容器那样被父容器拉伸撑满；
- 未声明尺寸时，尺寸退化为**自身内容撑开的大小**（wrap_content）。

再看 `scroll` 组件的官方说明：

> 滚动视图容器。竖向或水平方向滚动容器，**竖向滚动需要设置定高，水平滚动需要设置定宽**。

官方示例里的 scroll 同样都显式声明了 `width`/`height`。**`scroll` 没有"默认充满父容器"的语义。**

两个结论叠加：

```
stack 不拉伸子元素  +  scroll 不默认撑满  +  .page 未声明 width
        ⇒  .page 的宽度 = 内容撑开的宽度（远小于 192px）
```

### 4.3 宽度塌缩的推演：为什么只剩"左侧一竖条"

在 wrap_content 测量模式下，**只有固定宽度的元素能贡献宽度**；`flex: 1`、`width: 100%` 这类"依赖父容器剩余空间"的声明在测量阶段退化。逐行估算（手环 9 = 192px，`@media (shape: pill-shaped)` 生效，即 capsule 分支）：

| 元素 | 参与撑宽的部分 | 胶囊屏取值 | 贡献宽度 |
|---|---|---|---|
| `.header` | back-btn + title + placeholder | 40 + **title `flex:1`→退化** + 44 | ≈ 84px |
| `.item` | padding + indicator + name + more-hit | 14 + 2 + (16+12) + **name `flex:1`→退化** + 60 | ≈ **104px** |
| `.add-btn` | `width: 100%` | 循环依赖父宽 | ≈ 0 |
| `.empty-hint` | padding 40px 10px | 20 | ≈ 20px |
| `.pin-link` | padding 10px 24px | 48 | ≈ 48px |

取最大值 ⇒ **`.page` 实际宽度 ≈ 104 ~ 110px**。

屏幕宽 192px，于是：

```
┌──────────────── 192px ────────────────┐
│ ▒▒▒▒▒▒▒▒▒▒▒▒ │                        │
│ ▒ 页面内容 ▒ │   未绘制区域（黑色）    │
│ ▒ ~106px  ▒ │      ≈ 86px（45%）      │
│ ▒▒▒▒▒▒▒▒▒▒▒▒ │                        │
└───────────────────────────────────────┘
    左侧内容            右侧"黑板"
```

这与用户"页面被压缩在左侧 + 右侧一块黑色"的描述**逐字吻合**。

### 4.4 为什么右侧是黑色而不是主题色

```html
<stack class="page-root">                      <!-- 没有 background-color -->
  <scroll class="page" style="background-color: {{ theme.bg }}">  <!-- 背景只画在这里 -->
```

主题背景色 `#1a1a2e` 只画在 `.page` 上；`.page-root` 没有底色。`.page` 没覆盖到的右侧就是"没有任何绘制内容"的区域，手环（AMOLED）上呈现为纯黑 → 用户看到的"黑板"。

> 同类问题在本项目已有先例：`docs/position-fixed-手环渲染问题分析.md` 记录的"手环上只显示左上角一小块、其余全黑"，机理完全一致 —— **轻量渲染引擎下元素尺寸退化，未覆盖区域不绘制即黑屏**。

### 4.5 为什么只有这个页面出问题（强证据）

全文搜索 `stack`：

| 文件 | 匹配性质 |
|---|---|
| `src/pages/schedule-manager/schedule-manager.ux` | **真实的 `<stack>` 标签** |
| `src/pages/device-info/device-info.ux` | 仅注释里的 "stacked vertical layout" 一词 |

**全项目 177 个文件中，只有 `schedule-manager.ux` 用 `<stack>` 作根容器。** 其余所有页面根元素都是 `<div class="page">`，div 作为页面根天然占满屏宽，所以同样的"漏写 width"在别处不会暴露。

这不是巧合，而是"唯一用了不同布局容器的页面 = 唯一出现布局塌缩的页面"。

## 7. 修复方案（按优先级，改动面从小到大）

### P0-1（核心，1 行）：给内容层补 `width: 100%`

```css
/* schedule-manager.ux */
.page {
  width: 100%;          /* ← 新增：stack 子组件不会自动撑满，必须显式声明 */
  flex-direction: column;
  padding: 44px 12px 12px 12px;
  height: 100%;
}
```

> 注意：CSS 里**不能**写 `{{ }}`（那是模板语法）。这条是静态值，直接写 `width: 100%;` 即可。

### P0-2（兜底，2 行）：根容器也铺上主题底色 + 明确主轴

即使将来还有别的层塌缩，也不会露出黑底：

```html
<!-- 模板改一行 -->
<stack class="page-root" style="background-color: {{ theme.bg }}">
```

```css
.page-root {
  width: 100%;
  height: 100%;
  position: relative;
  flex-direction: column;   /* ← 新增：明确主轴，与旧分析文档 6.5 的建议一致 */
}
```

### P1-1（规范统一）：`scroll-y` 写法

```html
<!-- 现状（静态字符串） -->
<scroll class="page" scroll-y="true" ...>
<!-- 改为（全项目其它页面的统一写法） -->
<scroll class="page" scroll-y="{{true}}" ...>
```

全项目其它页面均使用 `{{true}}` 布尔绑定，本页是唯一例外，统一后可避免引擎对字符串 `"true"` 的解析差异。

### P1-2（清理死节点）：移除未使用的 `unlock-dialog`

```html
<!-- 现状：放在 <scroll> 内部，但代码里从未调用 this.$child('unlockDialog') -->
<unlock-dialog id="unlockDialog"></unlock-dialog>
```

该组件 `visible` 默认 `false`、从未被 `show()` 调用，是纯死代码。它位于 `<scroll>` 内部且 `.dialog-overlay` 用 `top/left/right/bottom: 0`（文档已记录手环引擎可能忽略 `right`/`bottom`），是潜在的风险节点。**直接删除这行。**

### P1-3（候选 B 兜底）：弹窗卡片改用显式居中

```css
.modal-card {
  width: 80%;
  align-self: center;      /* ← 新增：不依赖父容器 align-items */
  ...
}
```

同理给 `.sheet-card` 加 `align-self: center`。

### P2（复核，非必须）：胶囊屏尺寸复核

修复宽度后，按 192px 复核胶囊分支（内容宽 = 192 − 20 = 172px）：

| 元素 | 胶囊取值 | 余量 | 结论 |
|---|---|---|---|
| `.item` | indicator 16 + gap 12 + name(flex:1) + more-hit 60 + padding 16 | name 可得 ≈ 68px | 偏紧，靠 `text-overflow: ellipsis` 兜底，可接受 |
| `.more-hit` | 60 × 64px | ≥ 48px 触控 | ✅ |
| `.sheet-btn` | `flex: 1 1 45%` + `min-width: 45%` + `margin: 0 4px` | 45% + 8px margin 可能换行 | 建议改 `width: calc(50% - 8px)` |
| `.add-btn` | `width: 100%` × 44px | ✅ | ✅ |

修复前后各做一次，直接读数值：


```js
onShow() {

      success: function (r) {
        console.log('[diag] scroll width=' + r.width + ' height=' + r.height)
```

## 9. 防回退：建议写入守护手册的规则

在 `docs/标准版100分评分标准.md` 的胶囊屏红线清单中补一条：

> **凡使用 `<stack>` / `<scroll>` / `<swiper>` 作为容器或内容层时，子元素必须显式声明 `width`（根内容层写 `width: 100%`）。**
> 理由：Vela 中 stack 是层叠容器、不拉伸子元素；scroll 官方要求"竖向滚动需设定高、横向滚动需设定宽"，均无"默认撑满"语义。漏写 `width` 会让宽度退化为内容宽，未覆盖区域不绘制 → 手环上表现为黑色区域。
> 配套：所有 `stack` 根容器应同时绑定 `background-color`，避免任何一层塌缩时露出黑底。

另建议做一次全仓自检：搜索所有 `<stack` 与 `<scroll`，确认它们的样式里都有显式 `width`（当前全项目仅 `schedule-manager.ux` 一处 `<stack>`，成本极低）。
