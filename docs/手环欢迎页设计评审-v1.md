## 二、诊断 H1–H10

### H1 · 首屏 40% 是纯装饰，拇指要伸到屏幕中部
`y=0–194` 共 194px 只有标题 + 标语。手环 9 是 **192×490 的长条**，握持时拇指自然落在屏幕**下三分之一**；把唯一高频动作放在上 40%，等于每次都要"够一下"。

### H2 · 主次不分：三个按钮挤在同一重量级
- `进入首页` 160×48 vs `设置` 140×48 —— **只差 20px（12.5%）**，视觉上是"略大"而不是"主次分明"。
- `设置` 与 `退出` **完全同款**：同 140 宽、同 48 高、同 `cardLight` 底、同 `24px` 圆角、同 `20px` 字号。

三个按钮各占一整行 48px，**合计 48+13+48+13+48 = 170px（屏高 35%）**，却只承载三个"开始用"的入口。

### H3 · 「退出」是极低频 + 破坏性动作，却与导航动作并排等权
- 「退出」在一张**日更 5 次**的工具页里属于极低频动作，且会中断使用。
- 更要紧：`exitApp()` 在运行时不提供退出入口时只 `toast("请用系统手势退出应用")` —— **一个可能"点了没反应"的按钮，摆在主流程第三位。**
  代码注释已写明这是为了修「安装后无法退出」，**但这个兜底本身应该"可用才显示"，而不是常驻一个小号大按钮。**

### H4 · 版本徽章用强调色 → 跟主按钮抢焦点，且对比度在多主题下塌陷
徽章样式是 `color: theme.bg` + `background-color: theme.accent`。按 `data/store.js` 的 `THEMES` 逐主题算 WCAG 对比度：

| 主题 | 徽章底 = accent | 徽章字 = bg | 对比度 | 判定 |
|---|---|---|---|---|
| 深空蓝 | `#7ec8e3` | `#1a1a2e` | 9.1 : 1 | ✓ |
| **翡翠绿** | `#7ec8a0` | `#1a2e1a` | 7.4 : 1 | ✓ |
| 珊瑚红 | `#e37e7e` | `#2e1a1a` | 6.0 : 1 | ✓ |
| **晨光白** | `#4a90d9` | `#f0f0f0` | **2.9 : 1** | ✗ |
| **暖阳米** | `#c4a882` | `#f5f0e8` | **2.0 : 1** | ✗ |

**根因：把 `theme.bg` 当"反白色"用。** 深色主题下 `bg` 是深色 → 反白成立；浅色主题下 `bg` 变成了**亮灰色** → 反白变成"浅字压浅底"，且暖阳米主题的 accent 本身也是浅米色 → 字几乎消失。

### H5 · 主按钮文字同样中招（本页最严重的一条）
`.enter-btn` 同样是 `color: theme.bg` on `accent`：

| 主题 | 主按钮文字 on 底 | 对比度 | 22px 粗体（大字号门槛 3.0） |
|---|---|---|---|
| 翡翠绿 | `#1a2e1a` on `#7ec8a0` | 7.4 : 1 | ✓ |
| **晨光白** | `#f0f0f0` on `#4a90d9` | **2.9 : 1** | ✗ |
| **暖阳米** | `#f5f0e8` on `#c4a882` | **2.0 : 1** | ✗ |

**全页最重要的控件，在最亮的两个主题下最看不清。**

### H6 · 「退出」按钮文字对比度不足
`color: theme.textSecondary` on `cardLight`：翡翠绿 **3.4 : 1**、晨光白 **3.2 : 1**，均低于普通字号的 4.5 : 1 门槛。
作者的意图显然是"用低对比度表达次要"——**方向对，但量过头了，越过了可读性红线。**

### H7 · 浅色主题下按钮边界消失
「设置 / 退出」用 `cardLight` 填充：晨光白主题里 `cardLight #e8e8e8` vs 页面 `bg #f0f0f0`，**逐通道只差 (8,8,8)**。
按钮退化成一团"比背景稍灰的色块"，无边框可依。
> 与手机端设置页 `CARD2 #EAF0F8` vs `CANVAS #E9EAEF` 差 `(1,6,9)` 是**同一种病**：把"容器色"和"画布色"配得太近。

### H8 · 字号层级与重要性排序不一致
现状字号梯度：`30`（标题） > `22`（主按钮） **=** `22`（版本徽章） > `20`（次按钮） > `18`（副标题）。

**版本号是全页最不重要的信息，却与最重要的按钮同字号（22px），还比副标题（18px）更大。** 徽章本身又用最亮的强调色填充 —— 视觉重量与信息重要性完全反了。

### H9 · 副标题是 slogan，对日更 5 次的页面是纯噪音
「你的随身课程助手」占 17px 高 + 上下 12 / 22px 间距 ≈ **51px（屏高 10%）**。第一次是品牌，第二十次是垃圾。
**这是全页最该放有用信息的位置** —— 今天几节课、下一节是什么 —— 现在放了一句静态标语。

### H10 · 90% 的屏幕面积是死的，唯一必点按钮的热区只有 160×48
一次会话里「进入首页」是**必然且唯一**要点的东西，却只有 160×48 的热区；它周围的 700+ 像素点上去什么都不会发生。手环屏幕本来就小，**每一平方毫米都要挣得自己的位置。**

## 三、设计原则（本页专用）

| # | 原则 | 对应诊断 |
|---|---|---|
| **P1** | **一屏一个主角**：手环首屏的注意力预算只够一个主对象，其余一律降级 | H2 H3 H8 |
| **P2** | **拇指优先**：主对象放在屏幕下 1/2 | H1 |
| **P3** | **反白色不许来自 `bg`**：浅色主题下 `bg` 是亮色，必须显式声明 `onAccent` | H4 H5 |
| **P4** | **极低频/会失败的动作不进主流程**：退出、版本 → 降级或移出，且"可用才显示" | H3 H6 |
| **P5** | **静态装饰换动态信息**：屏小，每行都要挣得位置 | H9 |

## 四、改进方案

### 方向 A（推荐）· 一眼课表 + 一个按钮

1. **副标题 → 动态摘要**（P5）。`welcome.ux` 已经 `require` 了 `store`，直接读缓存拼一行：
   `今天 6 节 · 下一节 09:00 高等数学` / 假期 `今天放假 · 共 0 节` / 无数据 `还没有课程表 ›`。
   静态标语换掉，**信息量从 0 变成"打开就有用"**。
2. **主按钮满宽 + 下沉到拇指区**（P1 P2）。宽度 `160 → 168`（= 内容宽，两边各留 12px），高度 `48 → 52`，位置从 `y194–241` 移到 **`y322–374`（屏高 66%–76%）**。
3. **「设置 / 退出」压成一行两个次级按钮**（P1），各 `80 × 40`，放在主按钮正下方。解决 H2 的"三个等权"。
4. **「退出」去掉填充，改纯文字链**（P4），并且**只在 `utils.exitApp()` 可用时才渲染**（先探测再挂载，避免"点了没反应"）。解决 H3 H6。
5. **版本徽章 → 11px `textMuted` 纯文字**，移到最底部居中（或直接删，版本号归「设置」页）。解决 H4 H8。
6. **修主题反白**（P3）：给 `THEMES` 每项新增 `onAccent` 字段，徽章与主按钮改用 `theme.onAccent`：

   | 主题 | 现 `bg` 当反白 | 新 `onAccent` | 主按钮对比度 |
   |---|---|---|---|
   | 深空蓝 / 翡翠绿 / 珊瑚红 … | 深色，碰巧对 | = 原值不变 | 不变 ✓ |
   | **晨光白** | `#f0f0f0` ✗ 2.9 | **`#1a1a1a`** | **5.2 : 1** ✓ |
   | **暖阳米** | `#f5f0e8` ✗ 2.0 | **`#2b2018`** | **7.0 : 1** ✓ |

   **只改浅色两族的值，深色主题零变化** —— 最小改动、可逐主题验证。
7. **给浅色主题的次级按钮补 1px 描边**（H7）：`border: 1px solid theme.border`（晨光白 `#d0d0d0`）→ 按钮重新有边。

### 方向 B · 整屏可点（备选）
把欢迎页做成"闪屏"：**整屏任意位置点击 = 进入首页**（热区 192×490 全屏），设置/退出压成底部一行小字。
- 优点：零误触成本，拇指不用瞄准；**彻底解决 H1 H10**。
- 代价：「设置」被挤到首页去（或需要长按）。

### 方向 C · 自动进入（备选）
进页面 800ms 后自动 `router.replace`，欢迎页退化为初始化过渡。
- 优点：把 H1 H10 一次解决到位。
- 风险：与"看一眼摘要"的需求冲突；`store` 异步回调未返回时会闪。需"点击可取消"。

### D1–D8 决策表（以方向 A 为准）

| # | 决策 | 治 |
|---|---|---|
| **D1** | 副标题 → 动态摘要在（今天 N 节 · 下一节 …） | H9 |
| **D2** | 主按钮满宽 168×52，下沉到 y322–374 | H1 H10 |
| **D3** | 设置 / 退出 合成一行两个 80×40 次级按钮 | H2 H3 |
| **D4** | 退出改纯文字链，且 `exitApp()` 可用才渲染 | H3 H6 |
| **D5** | 版本徽章 → 11px `textMuted` 纯文字，移到底部 | H4 H8 |
| **D6** | `THEMES` 增 `onAccent`，主按钮/徽章改用它（只动浅色两族） | H4 H5 |
| **D7** | 浅色主题次级按钮补 1px `border` | H7 |
| **D8** | `padding` 不对称（60/30）→ 统一为 44/32 | 构图 |

> ⚠️ **D2 与断点的关系**：`welcome.ux` 有 `@media (width>=200px)` 与 `(width>=400px)` 两档，方法学是"base 只写手环 9 必须的值，大屏断点只做增量"。**D2 的 168px 是 base 值**（内容宽 = 屏宽 − 24px），大屏断点按现有写法继续覆盖即可，不要新造一套。

## 六、验收清单

- [ ] 「进入首页」按钮宽度 = 内容宽（192−24 = 168px）、中心 y ≈ 348（±6px），**像素扫描复核**
- [ ] 首屏不再出现 `你的随身课程助手` 字样；摘要行随数据变化（有课 / 假期 / 无课表 三态）
- [ ] 「设置」「退出」同一行、各 80±2px 宽、高 40±2px
- [ ] 「退出」为无填充文字链；`exitApp()` 不可用时**整条不渲染**（不是置灰）
- [ ] 版本号字号 = 11px、色 = `textMuted`、无填充底
- [ ] **晨光白主题**：主按钮 `#1a1a1a on #4a90d9` ≥ 4.5 : 1；**暖阳米主题**：`#2b2018 on #c4a882` ≥ 4.5 : 1
- [ ] **晨光白主题**：设置/退出 有可见 1px 描边（与背景色差 ≥ 24）
- [ ] 深空蓝 / 翡翠绿 / 珊瑚红 三主题**渲染结果与现状逐像素一致**（D6 不得误伤深色族）
- [ ] `@media (width>=200px)`、`(width>=400px)`、`(shape: circle)` 三档仍生效，手环 10 / 9 Pro / Watch 6 不回归
- [ ] `onBackPress()` 行为不变（退出可用才消费返回键）

## 七、附：取证方法（可复现）

```bash
# 1) 起 9 标准版独立无头实例（必须显式写型号；沙箱里 qemu 会 mprotect 失败）
cd ~/Documents/guomengtao/ev/ev-emu-cli
vela up band9 --rpk ../class-schedule/dist/com.application.watch.classschedule.release.1.7.98.rpk --wait

# 2) 截图：guest 无 screencap，唯一读法是 /dev/fb0
#    192×490 RGB565、stride 384B、2 帧双缓冲 → 每帧 188160B
adb shell "dd if=/dev/fb0 of=/tmp/fb.raw bs=188160 count=2"   # 别用 cat /dev/fb0，会永久阻塞
adb pull /tmp/fb.raw .

# 3) 点击：走模拟器控制台纯 TCP 文本协议（不是 adb emu event）
#    auth <~/.emulator_console_auth_token> → event mouse X Y 0 1 → event mouse X Y 0 0 → quit
#    坐标吃 LCD 坐标，不要加皮肤偏移

# 4) 量测：对 PNG 逐行扫描背景差分，得到每个视觉块的 y 范围 / 宽度 / 主色
```

**本轮踩到并值得记的两条：**

1. **`/bin/ps` 在工具会话里被 shim 屏蔽**，`vela up` 内部 `alive_pids()` 调它 → `PermissionError` 直接冒出来；
   `dangerouslyDisableSandbox: true` 也无效，`osascript -e 'do shell script "ps …"'` 同样拿空。
   `shot / tap / nav / down / ls` 不碰 `ps`，**只有 `up` 需要打补丁**（把那一行改成空字符串）。
2. **guest 里的旧 `.js` 会遮蔽新包**：本次点「主题配色」无任何反应（md5 前后完全一致），而返回键、设置按钮都正常
   → `vela push` 只覆盖 `.jsc`，guest 残留的旧 `pages/settings/settings.js` 仍在被引擎读取。
   **推论：在这台实例上做"交互级验证"不可靠**（只有"渲染级"可信）。浅色主题的结论因此改用 `THEMES` 源码值 + WCAG 计算给出。
