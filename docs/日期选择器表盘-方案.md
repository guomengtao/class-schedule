# 日期选择器表盘 · 重构方案

> 目标页：`src/pages/watch-face-pickdate/watch-face-pickdate.ux`（现 107 行）
> 列表条目：「日期选择器表盘」（`src/pages/watch-face-list/watch-face-list.ux` 第 90 行）
> 基线机型：小米手环 192×490（emulator-11000）

---

## 一、现状与问题

当前页面与「日期」毫无关系，只有三样东西：

| 元素 | 实现 | 问题 |
|---|---|---|
| 「分钟」标题 24px | `text` | 与页面名不符 |
| 分钟选择器 | 原生 `picker`，`range` 60 项 | 只选分钟，不选日期；样式只能靠 `selected-*` 四个属性 |
| 自动滑动动画 | `animation: translateY(-40px)` 每秒一次 | **每秒整页重绘一次**（`mIdx` + `animClass` 两个字段并发写入），必然闪 |

结论：**不是修补，是整页重写**。原生 `picker` 这条路要放弃——它的可视区域、行高、选中行背景都不可控，做不出"机械日期鼓"的质感；而且 `selected` 一变就整块重排。

---

## 二、产品定义

「日期选择器表盘」= 一块**日历表**，主视觉是一个**机械日期鼓（date drum）**：

- 中央大号显示**今天几号**，上下各露半个相邻日期 → 读者一眼看出"这是滚动鼓，不是文字"。
- 顶部一行月份 + 年份，底部一行星期。
- 交互：上下滑 → 前后翻日期（浏览模式，只改显示不改系统）；3 秒无操作 → 自动弹回今天；长按 600ms → 立即回今天并轻微震动回执。

明确**不做**的：
- 不做分钟选择器（与"日期"无关，且正是闪烁来源）。
- 不做课程信息（`watch-face-class` 已经承担，表盘保持纯粹）。
- 不做农历（无接口、无字体，硬凑会变成伪文字）。

## 三、三条实现路线比选

### 路线 A：继续用原生 `picker`，多加两列（月/日/星期）

- 优点：几乎不用写样式，滚动由引擎负责。
- 致命缺点：
  1. 三列 `picker` 在 192px 宽屏上每列只剩 ~60px，日期 2 位数挤成一坨；
  2. `picker` 无法设行高/居中偏移，**选中行永远在正中间**，顶部月份、底部星期没地方放；
  3. `onchange` 一次要写 `mIdx/dIdx/wIdx` 三个字段 → 3 次全屏重绘；
  4. 现有代码已经证明：`picker` 上叠 `animation` 会每秒重绘。
- **结论：否决。**

### 路线 B：自绘「三行窗口」鼓（推荐）

结构极简，只有一层窗口 + 三个文本：

```
鼓窗（clip）
 ├ 上一行  text  日-1   （14px，色 #4a5058）
 ├ 中行    text  日      （96px，色 #e9eef2）
 └ 下一行  text  日+1   （14px，色 #4a5058）
窗口切口：左右各一条 1px 竖线 + 上下各一块半透明遮罩
```

- 翻页动效**不用 transform**（Vela 红线：祖先 transform + 子孙 rotate 启动即退；`animation` 的 `translateY` 在 picker 上已证实会触发整页重绘）。
- 改用**字面量位移类**：预先写好 `.dy0 ~ .dy24`（每档 2px 的 `top` 偏移），翻页时只切一个 class → 一次重绘，且完全走已验证的"字面量类"机制（与 120 档 `.rN` 同源）。
- 缺点：要自己算 3 个日期的换行（月末/月初跨月），但逻辑只有 6 行。

### 路线 C：Canvas 绘制

- Vela 手表侧 `canvas` 支持不稳定，且本项目全部表盘无一处用过 canvas，风险高。
- **结论：否决。**

## 五、日期计算

```
now = new Date()
day = now.getDate()
month = now.getMonth() + 1
year = now.getFullYear()
weekday = now.getDay()
```

- 上下邻日用真日历算，不用 `day±1` 硬减：
  `prev = new Date(y, m-1, day-1).getDate()`，`next = new Date(y, m-1, day+1).getDate()`。
  这样 1 号显示上月最后一天（如 30/31），月末显示 1，跨年也对。
- 「第 N 天」：`Math.floor((now - new Date(y,0,0)) / 86400000)`。

## 六、性能：不闪的三条硬规则

1. **脏值判断**：`tick()` 每秒跑，但只在 `day/month/year` 变化时才 `setData`（其余字段直接 return）。稳态每天只重绘 1 次。
2. **翻页动效只切 1 个字段**：浏览模式下滑时只改 `dyCls`（位移档位类），不改数字，动画走完再写数字（两步各 1 次重绘）。
3. **不用 `vw`、不用动态 `transform`、不在旋转/变换父元素内嵌子元素**——三条都是本项目的启动即退红线。

## 七、交互

| 手势 | 行为 |
|---|---|
| 上滑 | 日期 +1（浏览模式），`dyCls` 走 `d1→d2→d3` 三档位移 |
| 下滑 | 日期 -1 |
| 单击 | 返回表盘列表（与原页面一致） |
| 长按 600ms | 立刻回到今天 + `vibrate` 短震回执 |
| 3 秒无操作 | 自动回到今天（视觉上滚回） |

浏览模式与系统日期**完全隔离**：只改页面内 `browseOffset`，不动 `Date`。

## 八、多机型

- 页面用「顶/中/底三段 flex 纵向分布」+ 百分比锚点，不写死绝对 `top`；鼓窗高度用 `flex-grow` 吃掉中间空间。
- 上下遮罩、切口竖线用百分比高度，避免 336×480 / 466×466 上错位。
- 已知全局问题：全 App 在 336 屏都靠左（`designWidth: device-width` + 192 基准），本页不解决，只保证自身纵向不塌。

### 12.3 本轮新踩的三个坑（比代码更值钱）
1. **把这个页面设成 `manifest.json` 的 entry 会整页白屏**（纯静态模板也一样白）。同一份 jsc 通过正常路由进入就完全正常。
   对照实验：把方形表盘的 jsc 覆盖到 pickdate 槽位 → 能出画，说明槽位与引擎没问题，是「作为 entry 加载」这条路径本身不适合本页。
   结论：**表盘页验收只能走真实路径（首页 → 设置 → 表盘目录 → 目标项）**，别再拿 entry 覆盖去验。
2. **`vela loop --entry` / `manifest-watch.json` 手工改 entry 全部无效**（引擎读打包内 manifest），已二次确认。
3. **`adb shell input` 在这台 NuttX 上不存在**（`input: command not found`），滚列表要用 `vela.py tap --drag X1 Y1 X2 Y2 --steps 8`。
4. 模拟器单实例在当前 8G 机器上约 2–3 分钟就会黑屏猝死（fb0 非零=0），验收动作必须压在一次上电内做完。

### 12.4 未闭环（下一轮第一件事）
- **3 秒自动回今天未验证通过**：两个实现（`setTimeout` 版、`getTime()` 轮询版）在实拍里都没能让画面回到今天，
  且连拍两帧完全相同 → 疑似该页的 `setInterval/setTimeout` 没有被引擎驱动（其它表盘页的秒针是动的，说明全局定时器可用，本页异常）。
  已补 `onShow()` 兜底：重新进入页面一定刷新到今天。
  下一轮建议：在 `onInit` 里先 `setInterval` 后立刻改一个可见字段做"心跳"探针，确认本页定时器是否真的注册成功。
- 长按 600ms 回今天 + 震动回执未实测。
- 336×480 / 466×466 未验（纵向布局用绝对 px，宽屏会靠左，属全局问题）。
