# 激活码子页「结果框入屏」遗留项修复记录（2026-10-21）

## 背景

evtask-D-sersannerocu-261021-mrkkh7 验收关单后的遗留项：子页「验证结果框」位于折叠下方，
用户输完码点验证后看不到结果详情（仅有 toast 短提示）。本轮将结果框收入一屏。

## 方案：验证后键盘退位、结果框上位

- 输入阶段（不变）：18 格码位 + 10 键键盘 + 验证按钮，一屏内完成输码→验证
- 结果阶段（新增）：键盘与验证按钮隐藏，结果框占据其位置；失败时附带「重新输入」按钮，
  一键清结果回输入态（键盘恢复、已输码位保留）
- 高度核算：结果阶段 ≈404px < 可用 434px

## 实施过程与踩坑（三轮构建 1.9.8 → 1.9.10）

### 坑 1：`show` 属性 false→true 恢复失效（1.9.8）

结果框用 `show="{{ verifyResult }}"`（重构前主页同款模式）。运行时键盘 `show="{{ !verifyResult }}"`
（true→false）正常消失，但结果框（false→true）始终不显示。改用 `if` 条件渲染指令后恢复。
结论：该引擎 show 属性「初始假值→数据驱动置真」不生效；if 指令（DOM 销毁/创建）可靠。

### 坑 2：if 动态节点 onclick 疑云（1.9.9）——实为坐标怪癖

1.9.9 用 if 指令后结果框与「重新输入」按钮渲染成功，但 tap(96,445/460) 无响应，
一度怀疑 if 动态创建节点事件绑定丢失，改为内联 display 绑定（1.9.10）。
最终诊断实验证明：**tap(96,430)（按钮上部热区）正常触发 onRetry，键盘完整恢复**——
按钮功能一直正常，是事件热区与视觉中心存在约 15px 向上偏移（该类引擎坐标映射怪癖，
与主页按钮「加载态/稳态位移」同源）。display 绑定版保留（DOM 恒在，语义更稳）。

### 坑 3：onRetry 遗漏 showRetry 重置

onRetry 清 verifyResult 但未重置 showRetry（if 版时期引入），display 版已补
`this.showRetry = false`。

### 其他修复

- 11 个验证结果分支抽取为 `setResult(success, result, detail)` helper，统一维护
  verifyResult/verifyDetail/verifySuccess/showRetry 四字段，杜绝逐分支漏改
- 结果框紧凑化：label 28→22px、code 32→24px、detail 24→20px（均 ≥18px 审计线）、
  padding 12→8、bottom-spacer 结果态隐藏，总高从 ≈490px 压到 ≈404px

## 流程教训（供后续会话）

1. **事件热区 ≠ 视觉中心**：该引擎上手环点击热区较视觉中心上偏约 15px，tap 视觉中心可能脱靶；
   脱靶时先上下试探 20-30px 再怀疑功能缺陷（本轮误判两轮）
2. **show false→true 不生效**：条件显示一律用 if 指令或内联 display 绑定，勿用 show 属性做
   「初始隐藏→数据驱动显示」
3. **二级页当 entry 冷启崩溃是概率性竞态**：单命令内 `am stop + vapp + sleep 45 + 探活重试`
   循环可破；切勿把「重启（后台任务）」与「稳态截图/点击」并行——am stop 延迟到达会杀应用
   （本轮撞车三次，黑图 md5 99b0bdd 是同一张杀应用黑图）
4. 冷启 45s 仍可能停留「加载中」态（状态卡异步），且双 vapp 会话会互相抢前台导致永久加载态；
   验收前用 md5 比对稳态页确认
