# 标准版对高级版控制方式

## 1. 概述

本项目采用"软拦截"策略，标准版用户**不是被挡在门外**，而是**可以进入页面，但看到半透明遮挡层+解锁提示**。这样做的目的是让用户先看到功能内容（模糊预览），产生"我想用这个功能"的期待感，然后再引导付费。

## 2. 核心架构

### 2.1 权限检查入口

所有高级版控制都通过 `store.isPremiumUnlocked()` 统一检查：

```javascript
// store.js 中的核心方法
store.isPremiumUnlocked(function(unlocked) {
  if (unlocked) {
    // 高级版用户：正常使用
  } else {
    // 标准版用户：显示拦截提示
  }
})
```

`isPremiumUnlocked()` 的判断逻辑（[store.js](file:///Users/Banner/Documents/guomengtao/tom/class/class/src/data/store.js#L609)）：

1. 先检查 `premium_unlocked` 标记（本地存储）
2. 再检查 `authStore` 的激活状态（`isActivated` 或 `isPermanent`）
3. 任一满足即返回 `true`

### 2.2 现有组件

| 组件 | 路径 | 用途 | 模式 |
|------|------|------|------|
| `unlock-dialog` | `src/components/unlock-dialog.ux` | 底部半屏抽屉解锁提示 | Bottom Sheet |
| `pro-card` | `src/components/pro-card.ux` | 页面内联 Pro 卡片 | Inline Card |

### 2.3 已接入高级版控制的页面

| 页面 | 控制方式 | 说明 |
|------|----------|------|
| `backup-restore.ux` | 操作拦截 | 点击备份/恢复按钮时检查，未解锁弹底部抽屉 |
| `homepage-settings.ux` | 页面内联卡片 | 页面底部显示 Pro 卡片 |
| `schedule-manager.ux` | 操作拦截 | 点击新建课表时检查 |
| `premium-test/index.ux` | 页面内联卡片 | 高级版功能预览页 |

## 3. 半透明遮挡方案（推荐）

### 3.1 方案描述

用户进入页面后，页面内容正常渲染，但上方覆盖一层**半透明遮罩**，遮罩上显示 Pro 解锁提示卡片。用户可以看到模糊/暗化的页面内容，但无法交互。点击"立即解锁"跳转激活页，点击"继续使用标准版"返回上一页。

<script>
import router from "@system.router"
const store = require("../../data/store.js")

export default {
  private: {
    isPremiumUnlocked: false,
    theme: store.DEFAULT_THEME
  },

  onInit() {
    var self = this
    store.getTheme(function(t) { self.theme = t })
    store.isPremiumUnlocked(function(unlocked) {
      self.isPremiumUnlocked = unlocked
    })
  },

  onShow() {
    var self = this
    store.getTheme(function(t) { self.theme = t })
    store.isPremiumUnlocked(function(unlocked) {
      self.isPremiumUnlocked = unlocked
    })
  },

  goBack() {
    router.back()
  },

  goToActivation() {
    router.push({ uri: "/pages/activation" })
  }
}
</script>

### 3.4 需求合理性分析

| 维度 | 评估 | 说明 |
|------|------|------|
| **用户体验** | ✅ 合理 | 用户能看到内容但无法交互，产生好奇心，比直接拦截页面更友好 |
| **商业转化** | ✅ 合理 | 模糊预览让用户看到价值，提高付费转化率 |
| **技术实现** | ✅ 简单 | 只需一个 `position: fixed` 的遮罩层 + 条件渲染 |
| **维护成本** | ✅ 低 | 复用现有组件和权限检查逻辑 |
| **行业惯例** | ✅ 常见 | 类似 App Store 的"先预览再购买"模式 |

## 4. 三种控制模式对比

| 模式 | 适用场景 | 用户体验 | 实现复杂度 |
|------|---------|---------|-----------|
| **半透明遮挡** | 整个页面都是 Pro 功能 | 能预览模糊内容，有期待感 | 低 |
| **底部抽屉** | 点击某个操作按钮时触发 | 保留上方背景，下滑可关闭 | 中 |
| **页面内联卡片** | 页面部分功能需要 Pro | 卡片嵌入页面流中，不遮挡 | 低 |

## 6. 注意事项

1. **遮罩层 z-index**：确保遮罩层在最上层，覆盖所有页面内容
2. **返回按钮行为**：标准版用户点击"继续使用标准版"应调用 `router.back()` 返回上一页
3. **主题适配**：遮罩卡片应使用 `theme` 变量，保持与整体风格一致
4. **onShow 中重新检查**：用户可能在激活页激活后返回，`onShow` 中重新检查可自动解除遮挡
5. **不要重复造轮子**：优先复用 `pro-card` 组件或 `unlock-dialog` 组件

## 7. 总结

半透明遮挡方案是**最推荐**的整页 Pro 控制方式：

- 需求合理，用户体验好
- 实现简单，约 35 行代码即可完成
- 复用现有基础设施，无需新建组件
- 已有多个页面采用类似模式，方案成熟
