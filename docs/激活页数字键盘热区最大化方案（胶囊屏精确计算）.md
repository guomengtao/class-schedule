# 激活页数字键盘：热区最大化方案（胶囊屏 192×490 精确计算）

> 问题：激活页（`pages/activation`）的 18 位激活码要靠页内自绘数字键盘逐位输入，
> 用户反馈**热区太小、点不准**。本方案给出精确几何计算 + 修改 + 眼睛验证。

---

## 一、现状（CSS 实测）

键盘是页内自绘（非 InputMethod 组件）：`.keypad` > `.keypad-row` ×4 > `.keypad-btn` ×3。

**基础样式（:944）**：`width:75px; height:50px; margin:0 12px`
**胶囊屏覆盖（:1042）**：`width:64px; height:50px; margin:0 4px`
**容器**：`.keypad { padding:8px }`，`.keypad-row { margin-bottom:4px }`

## 二、胶囊屏几何推导（精确计算）

```
屏幕            192 × 490（shape: pill-shaped，圆角 corner_radius ≈ 96）
.page 胶囊覆盖   padding: 30px 16px          → 内容宽 = 192 − 32 = 160px
键盘行需求       3 × (64 + 4 + 4) = 216px
供需差          216 − 160 = +56px（超需求 35%）
```

**后果（flex 默认 shrink=1，均匀压缩 160/216 = 0.74 倍）**：

| 项 | CSS 声称 | 实际渲染 |
|---|---|---|
| 键宽 | 64px | **≈47.4px**（64×0.74）|
| 键间距 | 8px | ≈5.9px（**死区**）|
| 键高 | 50px | 50px |
| 行间距 | 4px | 4px（**死区**）|
| **单键热区** | 64×50=3200px² | **≈47×50=2370px²（−26%）** |

> 即：**设计上以为 64×50，实际只有 47×50**，而且键与键、行与行之间全是点不到的死区。

## 三、为什么不能铺满 192px

胶囊屏**物理圆角 ≈96px**，屏幕最左/最右的上下区域会被圆角裁掉。
`.page` 的 16px 侧边距正是给圆角让位的 → **160px 就是安全可用宽度**，
键盘做成全屏宽（192px）会让最外侧键的边角被裁 → 不可取。

**结论：160px 容器内做到"零死区 + 键最大"，就是热区的物理上限。**

## 四、方案：零死区 + flex 均分

```css
/* 胶囊屏覆盖块内 */
.keypad {
  padding: 0;            /* was 8px —— 消除四周死区 */
}
.keypad-row {
  margin-bottom: 0;      /* was 4px —— 行间零死区（用 1px 边框做视觉分隔）*/
}
.keypad-btn {
  flex: 1;               /* 关键：自动均分，不再写死 64px（写死必被压缩）*/
  height: 56px;          /* was 50 —— 4 行 = 224px，触控更稳 */
  margin: 0;             /* was 4px —— 键与键无缝 */
  border-radius: 8px;    /* 保留小圆角（缝隙 <2px，可忽略）*/
}
.keypad-text {
  font-size: 32px;       /* 不变 */
}
```

### 改后几何
```
行宽 160px ÷ 3 = 每键 53.3px（flex 均分，不再被压缩）
键高 56px
```

### 前后对比
| 项 | 现状 | 改后 | 提升 |
|---|---|---|---|
| 单键宽 | ≈47.4px | **53.3px** | +12% |
| 单键高 | 50px | **56px** | +12% |
| 单键热区 | 2370px² | **2985px²** | **+26%** |
| 死区 | 键间 6px + 行间 4px | **0** | 整个键盘面 100% 可点 |

## 五、验证方法（眼睛）

1. `--start-page 'pages/activation'` 构建 + 只推 `app.jsc`，滚动到键盘；
2. 改前后各截一张同位置图，**对比键的宽度与间隙**；
3. `png-measure.js bands <图> <y0> <y1>` 量键的左右边界（改后应为 x≈2..190 均分，无边距）；
4. 逐键点一遍（`cseq`），确认 12 键全部响应。

## 六、实施（✅ 已落实 2026-09-28）

改 `activation.ux` 胶囊覆盖块（:1042 起），`.keypad` 规则增加 `width: calc(100% + 28px)` + `margin-left: -14px`（负 margin 突破 `.step-card` 的 `padding: 18px 14px`），**不动基础样式**（212×520 等宽屏不受影响——那边容器够宽，75px 键放得下）。

> 注意：原方案分析的键宽从 64px 压缩到 47.4px 是第一版实施前的旧状。第一版已将键改为 `flex: 1; margin: 0`。但漏算了 `.step-card` 的 14px 内边距——132px ÷ 3 = 44px/键，反比改前还小。本次 +2 行负 margin 将键盘恢复到 160px 容器，键宽 53.3px。

- `cell`（18 位激活码格子）热区 56px 高，暂不动。
