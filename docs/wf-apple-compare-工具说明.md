# AWF-Comp · 苹果表盘复刻量化对比器

> 工具脚本：`tools/wf-apple-compare.py`
> 代号：**AWF-Comp**（Apple Watch-face Comparator）
> 用途：把**我方表盘截图**与**苹果时钟小组件基准图**做可重复的像素级量化对比，输出"形状差"而不是"角度差"。

---

## 1. 一句话定位

它不是"整图差分"工具——因为钟表指针指向不同时刻，整图逐像素相减只会把**角度差**算成**形状差**，毫无意义。
所以它做的是**单根指针的径向宽度剖面对比**：自动识别每根针的角度，沿针轴每 1px 测一次垂直墨迹宽度，得到 `width(r)` 曲线，再比较我方与苹果在"细颈 / 肩部 / 针身 / 长度"上的差异。

---

## 2. 为什么不用整图差分（设计理由，务必先看）

| 思路 | 问题 |
|------|------|
| 整图逐像素差（ImageChops.difference） | 苹果基准图停在固定时刻（≈10:09:3x），模拟器是当前时刻，两图指针角度不同。**差分热图会把"角度漂移"全算成"形状漂移"**，根本分不清针画歪了还是针走动了。 |
| 对齐后再差分 | 需要把两图时针/分针/秒针都转到同一角度，等价于先识别角度再局部裁剪——那就回到"按针拆解"了。 |

结论：**对表盘这种"同一构图、不同时间"的图，唯一公平的比法是按单根指针拆解、沿轴线量宽度**。这就是 AWF-Comp 的设计内核。

---

## 3. 它实际做什么（算法）

1. **裁白卡**：`card_bbox()` 按行/列亮度覆盖率找白色卡片包围盒 → 裁成正方形 → 缩放到 `320×320`（`norm_card`）。
   - 苹果基准图是白卡，我方 10 Pro / 手环9 截图里白卡也居中，所以两边都用同一判据归一，天然消除了分辨率/缩放差。
2. **识别针角度**：`angular_peaks()` 在 `r∈[40,105]` 环带里按 0.5° 步进累计暗像素命中数，取局部极大作为指针角度。
   - 黑针（时/分）= 深色峰值；橙红秒针用 `is_reddish()` 单独识别（避免被黑针干扰）。
   - **分针 = 黑色第二峰**，**秒针 = 橙色峰**，时针 = 黑色第一峰。
3. **测宽度剖面**：`width_profile()` 沿某角度，对每个半径 `r`（步进 1px）在垂直方向 ±9px 采样，记录墨迹左右边界 → 得到 `width(r)`。
4. **输出**：并排图 + 中心放大图 + `profiles.txt` 数值表。

## 5. 用法

```bash
# 最简：用默认基准图 + 默认我方截图 /tmp/wf_v8.png
python3 tools/wf-apple-compare.py

# 指定我方截图（最常见）
python3 tools/wf-apple-compare.py --mine /tmp/wf_v9.png

# 指定基准图（可用其他苹果 widget 基准，见 docs/reference/apple-clock-widget/）
python3 tools/wf-apple-compare.py --ref docs/reference/apple-clock-widget/widget-analog-fullnums-white.png

# 调大中心放大倍数（默认 8）
python3 tools/wf-apple-compare.py --mine /tmp/wf_v9.png --zoom 12

# 改中心取景边长（默认 90px，卡片坐标系）
python3 tools/wf-apple-compare.py --box 110
```

### 参数表

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--ref` | `docs/reference/apple-clock-widget/widget-analog-numerals-white.png` | 苹果基准图（白卡数字版） |
| `--mine` | `/tmp/wf_v8.png` | 我方模拟器截图（白卡居中即可） |
| `--zoom` | `8` | 中心放大倍数（NEAREST，看细颈/环用） |
| `--box` | `90` | 中心取景边长（卡片坐标系 px） |

## 6. 输入要求

- 两张图都**必须有一张白色（或近白）卡片居中**，否则 `card_bbox()` 找不到区域会报错。
- 我方截图来源：Vela 模拟器 `shot` 命令的输出（10 Pro 是 336×480、白卡 320×320 居中；手环9 是 192×490 胶囊屏，白卡居中即可）。
- 基准图来源：`docs/reference/apple-clock-widget/` 下 5 张从 Tom 桌面裁切的图（源 2880×1800 @2x）：
  - `widget-analog-numerals-white.png`（默认，白卡 + 12 数字）
  - `widget-analog-fullnums-white.png`（白卡 + 全数字）
  - `widget-analog-dark.png`（暗卡）
  - `widget-digital-worldcup.png` / `widget-worldclock-4up-dark.png`

| 文件 | 内容 |
|------|------|

## 8. 怎么读 `profiles.txt`

每根针一段，格式：

```
=== REF-hour@107.5deg  全长=...  起始r=...  90%宽度在r=...  最宽=...
  r=  6.0  w= 3.50
  r=  7.0  w= 4.00
  ...
```

- `r` = 距盘心的半径（px，已归一到 320 坐标系）。
- `w` = 该半径处针的垂直宽度（px）。
- **细颈/尾部形状** = `r∈[0,30]` 这段 `w(r)` 的走势：苹果是"根部 4~5px 细线 → r≈21 处突然展开到 9~10px 肩部"的锥形过渡。
- **针身宽度** = `r≥26` 段的 `w`（应稳定在 9~10px）。
- **长度** = 最后一个 `w≥1` 的 `r`（除以卡片半径 160 即 R 比值）。

### 一次真实输出（v8 我方，节选）

```
[角度] 基准 黑色指针峰值: [(193.5, 131), (107.5, 103), ...]
[角度] 我方 黑色指针峰值: [(342.5, 131), (148.0, 60), ...]
[角度] 基准 橙色秒针峰值: [(324.5, 141)]
[角度] 我方 橙色秒针峰值: [(55.5, 142)]

  r=  6.0  w= 3.50
  r= 20.0  w= 6.00
  r= 21.0  w= 9.50     ← 肩部展开点
  r= 30.0  w= 9.25
  r= 40.0  w= 8.50     ← 针身稳定 ~9px
```

> 注意 v8 的 `r=10..19` 段宽度在 3.5~4.75 之间抖动（旧"白遮罩+黑线"结构留下的锯齿收腰），正是后续要修掉的形状缺陷——这就是工具的价值：把"肉眼觉得不对"变成"r=12 处 w 掉了 1px"这种可定点修的数值。

## 9. 验收标准（本项目表盘复刻用的阈值，非工具硬编码）

复刻苹果 macOS 时钟小组件时，AWF-Comp 输出的判定线（写进 `evtask-D-evclass-sche-261026-7xvn73` 验收项）：

- 时/分针根部 `r=10..21` 宽度 **5 ± 0.8px**（细颈，不是 0）；
- `r≥26` 针身宽度 **10.4 ± 0.8px**；
- `r∈[0,30]` 内**不允许出现 `w<3` 的凹口**（旧版遮罩锯齿造成的视觉收腰）；
- 长度：时针 ≈ **0.56R**、分针 ≈ **0.81R**、秒针穿过中心留 ≈25px 配重尾；
- 中心环：外径 ≈10px、孔径 ≈4px 的空心橙环（非实心点）；
- 模拟器截图**无黑屏**（走秒 class 注入正常）。

达到以上即判"一致 / 超越"，否则回到 `.ux` 改几何、再跑本工具闭环。

## 10. 已知限制

1. **依赖白卡居中**：两张图都必须有清晰白色卡片，否则归一失败。胶囊屏（手环9）边缘圆角区域若裁进黑边会干扰 bbox，必要时手动 `--box` 或先裁图。
2. **角度识别是启发式**：`angular_peaks` 阈值 `v<8` 和 `>12°` 去重是经验值；若两根针角度太近（<12°）会漏识别，此时可改 `rmin/rmax` 或手动指定。
3. **不替你判"像不像"**：工具只给数值，是否"一致/超越"由人 + 第 9 节阈值决定。
4. **无 numpy**：用纯 PIL 逐像素采样，图大时稍慢（320×320 量级秒级，可接受）。

## 11. 演进与踩坑（给未来自己）

- 初版想用整图 `ImageChops.difference` + 像素差分热图，实测被"角度差"污染，作废 → 改为径向剖面（本工具）。
- 量过苹果基准图确认：**黑针根部是一根细线（≈4~5px），向外到 r≈21 才展开成 9~10px 针身**；中心是**空心橙环**，不是实心点；指针**无反向配重尾**（反方向扫描 r≥8 全 0）。
- 我方 v1~v8 的演进：秒针 7px→2px、实心点→空心环、（白遮罩+黑线）细颈→0×0 嵌套旋转载体让针身从 r=21.5 圆底展开成肩部（消除 r=20 处白色收腰）。
- 几何标定坑：`card_bbox` 行/列覆盖率判据太宽松会让卡片半径缩水，导致量出的 R 比值偏小；标定苹果基准几何时改用了"橙心质心 + 白卡边界"双判据（见历史会话脚本）。
