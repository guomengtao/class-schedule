# Ev课程表（手环快应用）用户研究报告与可执行建议

**研究日期**：2026-10-07 ｜ **分析对象**：`ev/class-schedule` v1.7.123 (code 1125)，小米手环 9 标准版（192×490 胶囊屏）为主评机型
**方法**：静态产品走查（26 个路由页 + 源码）+ 已有设计评审/走查报告二次综合（三角验证：首页评审 v1、欢迎页评审 v1、用户视角走查报告、设计错误记录、QA 报告）。本研究基于代码与文档证据，未含真机用户访谈；建议中的指标为验证目标。

---

## 1. 研究概览

**核心问题**：一款功能面很宽（26 页、9 主题、6 档字号、多课表、商业化体系）的手环应用，在 192px 胶囊屏上是否真正"可用、耐用、愿用"？

**三项关键发现**：
1. **垂直空间是最致命的用户痛点**——首页固定栏吃掉 81% 屏高（348px），课程列表仅剩 47px，**一张课卡都放不下**。用户的核心任务"看今天有什么课"在首屏直接失败。
2. **可读性不达标**——教室名、状态胶囊在部分主题下对比度仅 2.0–3.4:1（WCAG 最低 4.5:1），浅色主题尤其严重；根因明确（THEMES 缺 `onAccent` token），可一次性修复。
3. **无任何行为数据**——没有埋点，渠道号已进包但转化漏斗不可见；所有 UX 决策靠截图评审而非用户行为证据，改进效果也无法度量。

## 2. 用户画像与场景（基于产品功能与反馈通道推断，待访谈验证）

| 画像 | 场景 | 核心诉求 | 当前体验风险 |
|---|---|---|---|
| **高中生**（主力） | 课间抬腕看"下节什么课、在哪个教室" | 1 秒内读到，无需操作 | 首屏课卡放不下；教室名对比度低；调休条折 3 行 |
| **大学生** | 周末/换课表切换多课表、看周视图 | 切表快、周视图每格可读 | 总课表每格只显示 1 个字（走查报告 P0） |
| **新用户** | 安装后 5 分钟内建好自己的课表 | 快速导入/添加 | 无配对向导但有预置示例数据（好）；4 步加课向导 + 3 个重复加课入口（选择过载） |
| **付费潜力用户** | 免费用爽 → 激活高级版 | 感知到高级版价值 | 激活码 16 位输入，手环上输入成本极高 |

**用户旅程断裂点**（首次启动 → 日常使用）：
```
欢迎页 ──进入──> 首页(列表仅47px!) ──点卡──> 详情/编辑
  │                  │
  │ 主按钮在39.6%屏高 │ 无课空态下100px纯空白
  │ (拇指区外)        │ 无"明天N节"引导
  └ 退出按钮常驻"点了没反应"
```
数据传递大量依赖 storage 键而非 URL 参数（如 `add_course_day` 只写不读 → **添加课程不预选当前查看日期**，P1 走查问题），是编辑流"改不了星期/日期"类 bug 的结构性根源。

## 3. 可用性发现清单（按严重度，均有文件佐证）

### P0 — 阻断核心任务
| # | 问题 | 证据 |
|---|---|---|
| A1 | 首页固定栏 81% 屏高，课程列表 47px，核心任务"看课"失败 | `docs/手环首页设计评审-v1.md` H2 |
| A2 | 假期日状态条显示"即将上课"与假期卡矛盾——**正确性 bug 比体验 bug 更伤信任** | 同上 H1 |
| A3 | 教室名/状态胶囊多主题对比度 2.0–3.4:1 不达标，浅色主题近不可读 | 同上 H8/H9；根因 THEMES 缺 `onAccent` |

### P1 — 高频摩擦
- 添加课程不预选当前日期（storage 键只写不读）；编辑课程改不了星期（走查报告）
- 3 个重复加课入口（首页评审 H12）→ 决策过载
- 调休条折 3 行、词被劈开；"今天"硬编码；无日期锚点"你在看哪天"（H3/H4/H5）
- 欢迎页：40% 纯装饰、主按钮在拇指区外、退出按钮常驻（欢迎页评审 H1–H10）
- 黑屏/白屏/输入法崩溃/SQLite 降级类稳定性问题（300+ 篇 bug 文档集中于此）——**稳定性是留存的第一道门槛**

### P2 — 机会点
- 无课空态 100px 空白可放"明天 3 节"类前瞻提示
- 欢迎页静态 slogan 改动态摘要"今天 N 节 · 下一节 数学 @302"
- 首屏 defer 异步"元素迟到"（骨架屏方案已有：`docs/analysis-skeleton-screen.md`）

## 4. 可执行建议（含验证指标）

### 第一批：P0 止血（预计 1 个迭代，纯前端小改）
1. **首页布局压缩**：按已评审的"方向 A"——固定栏 81%→32%，课程列表 47px→262px，底部三件套合一排图标。
   - 验证：模拟器 9 标准版实拍，首屏至少完整显示 2 张课卡 + 1 行状态。
2. **对比度一次修根**：THEMES 补 `onAccent` token，全主题按 WCAG 核算一遍（设计铁律文档已有方法）。
   - 验证：全部 9 主题 × 教室名/状态胶囊 ≥ 4.5:1。
3. **修 A2 假期状态矛盾**：状态条优先读假期/调休状态。
   - 验证：设一个假期日，状态条与卡片文案一致。

### 第二批：信任与流程（第 2 迭代）
4. **storage 键改 URL 参数/统一路由状态**，先修"加课不预选日期"和"编辑改不了星期"两个走查 P0/P1。
5. **欢迎页改造**：主按钮下沉满宽至拇指区；退出改"可用才显示"；slogan 改动态摘要。
   - 验证：首启到看到自己课表 ≤ 3 次点击。
6. **加课入口归一**：保留 1 个主入口 + 长按快捷。
7. **空态放前瞻信息**："今天没课，明天 3 节"。

### 第三批：建立度量闭环（与第二批并行）
8. **轻量行为埋点**（自研，经反馈通道/同步链路上报，不引第三方 SDK）：首启完成率、加课完成率、各页停留、崩溃/白屏计数。渠道号已进包，直接复用现有参数对接分析文档的方案。
   - 指标基线→目标：加课完成率 ≥ 80%；周留存数据跑 2 周后再定目标。
9. **错误日志持久化**（方案已有 `docs/error-log-persist-plan.md`）：崩溃日志随反馈二维码附带，让用户反馈"可诊断"。
10. **补一次 5 人真机任务测试**（任务：建课表→看明天课→切表→开振动提醒），记录完成率/耗时/出错点，验证第一批改动的真实收益——这是把"截图评审"升级为"用户证据"的最小成本做法。

### 长期
- 触底自适应改造按已有 P0–P2 排期推全（22 页面）。
- 实验诊断页（rect-c1~c7 等）继续摘除，减少包体与误入风险。
- 高级版价值前置：激活页直接演示高级功能而非 16 位码输入说明。
