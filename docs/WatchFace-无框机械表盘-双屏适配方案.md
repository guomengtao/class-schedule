# 无框机械表盘 watch-face-random · 336×480 双屏适配方案

- 单号：`evtask-D-class-schedu-261026-uufarb`
- 目标文件：`src/pages/watch-face-random/watch-face-random.ux`（639 行）
- 基线：192×490（手环 9），目标：336×480（手环 10Pro）
- 前提约束：192 屏观感零回归，仅「可读文字 ≥24px」允许例外

---

## §1 这块与前六块的根本差异：坐标已经自适应

前六块要么是 CSS 字面量坐标（evpointer / metal / gold → 父级 scale），要么是 JS 常量算坐标（animated → 改常量）。

random 第三种情况：**它在 `onInit` 里已经按真实屏宽高重算过一次**。

```js
onInit() {
  this.build(192, 490)                    // 先用基线出图，避免首帧空
  device.getInfo({ success: (ret) => {
    this.build(ret.screenWidth, ret.screenHeight)   // 拿到真机尺寸后重建
  }})
}
```

`build(W, H)` 内所有节点的 `left/top` 都由 `cx = W/2`、`cy = H/2`、`a`、`b` 推导，且全部走数据绑定实时落到 48 个分钟刻度 + 12 个整点时标 + 11 个夜光点 + 11 个数字 + 日期窗 + 铭文 + 三针 + 中轴。

**结论：位置一行不用改。问题全在「尺寸固定」的地方。**

## §2 336 屏代入后的两处几何冲突

```
192×490: a = min(84.5, 205.8) = 84.5    b = min(205.8, 114.1) = 114.1（1.35a 封顶）
336×480: a = min(147.8, 201.6) = 147.8  b = min(201.6, 199.5) = 199.5（1.35a 封顶）
```

`a` 放大 **1.75 倍**，`b` 同步 1.75 倍，盘等比放大 —— 但屏幕高度从 490 掉到 480，于是：

| | 192×490 | 336×480 |
|---|---|---|
| 盘点纵向 | 228（占屏高 46%） | **399（占屏高 83%）** |
| 顶部两行 | 品牌 103、副标 118（盘上沿 131，余量足） | 品牌 12.5、副标 27.5（盘上沿 40.5，**贴边**） |
| 底部三行 | JEWELS@367 / 日期@381 / 返回@460 | JEWELS@447.5 / **返回@450** / 日期@461.5 |

### 冲突 1：底部三行互相重叠

`jwT = cy+b+8`、`dlT = cy+b+22` 只隔 14px，而宽屏字号要放大到 18/24px。
`backT = H-30 = 450` 反而落在 JEWELS(447.5) 与日期(461.5) 之间 —— 三行交错压在一起。

### 冲突 2：盘心居中导致上下预算失衡

上下可用空间本来就不对称：顶部只要 2 行（品牌 + 副标），底部要 3 行（JEWELS + 日期 + 返回）。
`cy = H/2` 强行对半分，算下来：

- 顶部区需 46px、底部区需 90px，合计 136px，可用 480 − 344(盘) = 136 —— 恰好卡死，**但前提是盘心必须偏上 22px**。

`cy = 240` 时底部只剩 480−439.5 = 40.5px，装不下 90px 的三行。

## §3 解法：尺寸因子 S + 盘心上移

### 3.1 盘心与椭圆（`build` 内加宽屏分支）

```js
var wide = W > 300
var S = wide ? 1.75 : 1        // 尺寸因子：a 的实际放大倍数 147.84/84.5
var a = Math.min(0.44 * W, 0.42 * H)      // 不变，147.84
var b
if (wide) {
  b = 172                      // 固定纵径半轴：纵径 344，给底部留 90
  cy = 46 + b                  // = 218，盘 46–390
} else {
  b = Math.min(0.42 * H, 1.35 * a)        // 192 原逻辑，一行不动
  cy = H / 2                   // = 245
}
```

`b/a` 从 1.35 降到 1.16 —— 椭圆略扁，但本屏宽高比 0.70 本身比 192 屏的 0.39 方得多，视觉上仍是竖长盘。

### 3.2 纵向预算（480 高）

```
顶部 0–46      品牌 22px @6（高 26）+ 副标 10px @34（高 12）  → 间距 6，贴盘沿 46
盘区 46–390    纵径 344（b=172，cy=218）
底部 390–480   JEWELS 14px @392（高 18）
               日期   24px @414（高 28）
               返回   24px @446（高 28）  → 底余 6
```

底部三行由 `build` 直接给出（不再用 `cy+b+8/+22` 的紧贴公式）：

```js
this.jwT   = r1(wide ? 392 : cy + b + 8)
this.dlT   = r1(wide ? 414 : cy + b + 22)
this.backT = r1(wide ? 446 : H - 30)
```

### 3.3 尺寸表（盘内元素统一 ×S=1.75）

| 元素 | 192 | 336 | 备注 |
|---|---|---|---|
| 分钟刻度 `.mt` | 1×4 | 2×7 | |
| 整点时标 `.hm` | 2×11 | 4×19 | |
| 夜光点 `.lume` | 2×2 | 3×3 | |
| 数字 `.num` | 10px / 18×11 | 18px / 32×20 | 盘内时标，豁免 24px 下限 |
| 数字 `.num-big` | 13px / 16 高 | 22px / 28 高 | |
| 日期窗 `.dw` | 22×16 | 38×28 | 三处子元素同步 |
| 窗内数字 `.dw-num` | 11px | 19px | |
| 品牌 `.brand` | 15px / 60 宽 | 22px / 105 宽 | 顶部仅 46px，不能给到 26 |
| 副标 `.mark2` | 7px / 80 宽 | 10px / 140 宽 | |
| 日期行 `.dateline` | 10px / 90 宽 | **24px / 180 宽** | 可读文字，宽度必须同步加 |
| 返回 `.back` | 10px | **24px** | |
| 时针宽 | 6px（高光 1px） | 10px（高光 2px） | 内联 → 改绑定 |
| 分针宽 | 4px（高光 1px） | 7px（高光 2px） | 同上 |
| 秒针宽 / 配重 | 1px / 2px | 2px / 3px | 同上 |
| 中轴 | 5×5（环 3、点 1） | 9×9（环 5、点 2） | |

针长 `hh/mh/sh/sth` 由 `L0 = √(a·b)` 算出，随盘自动放大，**不用改**。

### 3.4 `build` 内的半宽常量必须乘 S

这些「减半宽」的偏移量是硬编码的数字，尺寸类放大后不跟随就会出现整体偏移：

```js
var BW = 60 * S, MW = 80 * S, DLW = 180 * (wide ? 1 : 0.5)
var NW = 18 * S, NH = 11 * S, DW = 22 * S
var HW = 6 * S, MW2 = 4 * S, SW = 1 * S, STW = 2 * S, HUB = 5 * S
```

对应替换：

| 原式 | 改为 |
|---|---|
| `nms.push({x: nx-8, y: ny-6})` | `x: nx - NW/2, y: ny - NH/2` |
| `dwx = cx + 0.66*a - 11` | `- DW/2` |
| `brL = cx - 30` | `cx - BW/2` |
| `brL2 / jwL = cx - 40` | `cx - MW/2` |
| `dlL = cx - 45` | `cx - DLW/2` |
| `hx = cx - 3`、`hxs/hxl = cx - 2` | `cx - HW/2`、`cx - HW/2 + 1` |
| `mx = cx - 2`、`mxs/mxl = cx - 1` | `cx - MW2/2`、`+1` |
| `sx = cx - 0.5`、`tx = cx - 1` | `cx - SW/2`、`cx - STW/2` |
| `hbx = cx - 2.5`、`hby = cy - 2.5` | `cx - HUB/2`、`cy - HUB/2` |

### 3.5 192 屏的两处必要修订

- `.dateline` 10px → **24px**，宽度 90 → **180**（"周一 10-26" 24px 约 115px，90 会截字）
- `.back` 10px → **24px**

`dlT = 381` 时 24px 文字占 381–409，与返回 460 不冲突，位置不动。

## §4 为什么不用父级 scale（否定路线记录）

`scale` 会连同 48+12+11+11 个**数据绑定的 left/top** 一起放大，圆心 (cx,cy) 也倍化 —— 与 animated 完全同因。且本页坐标已由 JS 按真实屏算好，scale 等于二次放大。

## §6 部署与验收

- 构建：`CODEBUDDY_SAFE_DELETE_BULK_THRESHOLD=99999 npx aiot release --enable-jsc`
- 部署：push rpk → unzip → **最后**覆盖 manifest（entry 指向本页），双机各一次
- 已知：每次 `vapp` 后首张截图必黑，`am stop` 重拉 + 等 26s 即可
- 验收量测：
  1. 336 盘心 (168, 218)、椭圆横径 295.6（x 20–316）、纵径 344（y 46–390）
  2. 三针角度直方图，与盘面时间误差 ≤3°（120 档量化步长）
  3. 底部三行 ink 分段互不重叠，日期/返回字高 ≥24px
  4. 192 与基线像素比对，仅 dateline/back 两处变化

## §7 风险

1. **`b` 从 1.35a 降到 172** → 椭圆变扁。若目视不可接受，退路是把 JEWELS 移到盘内或省略，把高度还给椭圆。
2. **18px 数字时标** 低于可读下限，但属盘内刻度（与 metal 罗马数字同口径豁免）。
3. `onReady` 在本仓曾出现不触发（watch-face-functional），本页 `onShow → refresh` 兜住计时，`build` 挂在 `onInit`，不受影响。

## §8 实施回填

**落地结果**（ux 639 → 714 行）

| 项 | 计划 | 实测 |
|---|---|---|
| 336 盘心 | (168, 218) | (168, 218) ✓ |
| 336 盘纵径 | 344（y 46–390） | y 46–390 ✓ |
| 336 三针 | 与盘面时间误差 ≤3° | 橙秒针 169°（配重尾 341°）、灰白针 298° / 230° |
| 192 三针 | 与基线一致 | 170° / 298° / 230° —— **与 336 完全同形** ✓ |
| 336 底部三行 | 互不重叠 | 盘+JEWELS 380–408、日期 419–440、返回 450–472（空隙 11/10）✓ |

**与方案的偏差两处**

1. **`DLW` 必须两屏统一 180**（方案写的是「宽屏 180 / 192 仍 90」）。实测只改 CSS 宽度而 `DLW` 留 90，`dlL = 96-45 = 51`、容器伸到 231，192 的日期行右端被屏边缘裁掉（ink 到 191 = 屏宽 192）。改为 `DLW = 180` 后 `dlL = 6`，文字居中回 96。
2. **顶部 `.w-brand` 22px → 20px，`brT` 6 → 2、`brT2` 34 → 32**。首版 EV(22px) 与 AUTOMATIC(10px) ink 连成一片（y 11–47 无间隙）。缩到 20px 并上移后：EV 7–23、AUTOMATIC 28–49，间隙 5px。AUTOMATIC 底沿 49 越过盘沿 46 共 3px —— 20px+10px 的 ink 高 42 加间隙已超 46px 预算，物理上放不进，且机械表铭文压盘缘是常规做法，予以保留。

**192 屏零回归核对**

`S=1` 时全部 `* S` 项与原字面等价（`cx - 3 * 1` = `cx - 3`），逐项对照无差。实际改动只有两处：
`.dateline` 10px/90 宽 → 24px/180 宽、`.back` 10px → 24px。其余像素零变化。

**部署账目**：2 次（计划 2）；构建 2 次（16.0s / 13.9s）。首版双机一次即出图（本次未黑屏），第二次改 `DLW`/顶部后全量重部署。
