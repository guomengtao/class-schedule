# 模拟器「还是黑屏」误报排查 —— vela-loop 端口与出画判据（2026-10-18）

## 现象

用户反馈「中文输入法页面，点击任意键黑屏」修复后（v0.5.179），**模拟测试还是黑屏**。

## 排查过程

### 第一层：连错设备（假黑屏之一）

`vela-loop.py` 默认 `--serial emulator-13000 --port 13000` 写死。而模拟器这次起在
**13002**（qemu 重启后端口会变，evemubuddy_watchdog 拉起的新实例占了 13002）：

```
$ adb devices
emulator-13002   device
$ adb -s emulator-13000 shell ps
adb: device 'emulator-13000' not found     ← 所有 adb 命令静默失败
```

表现：`shot()` 拉不到帧 → `ok=False` → `base_hash=""` → vapp 进程 0 →
「8s 无画面且无 vapp 进程 → 提前放弃」，连 retry 3 次全失败，看起来像页面写坏了。

### 第二层：稳定判据被闪烁动画卡死（真黑屏之主因）

改用正确端口（`--serial emulator-13002 --port 13002`）后，**vapp 进程起来了（进程数 2）**，
但等到 49s 仍判「未出画」。

写探针逐帧打点（`/tmp/probe_frame.py`），真相：

```
baseline ok=True nz=0
0 nz=20000 same_base=False hash=0206c710 vapp=2
1 nz=20000 same_base=False hash=15224514 vapp=2
2 nz=20000 same_base=False hash=fb7ce425 vapp=2
...
17 nz=20000 same_base=False hash=ecf70114 vapp=2
```

- **nz=20000（上限满值）= 屏幕是亮的**，2.5s 就出画；
- 但每帧 hash 都不同 —— chinese-input 页的**光标 blink 动画**
  （`.cursor { animation-duration: 1200ms; iteration-count: infinite }`）
  让 2.5s 采样间隔永远抓到不同的帧；
- 旧判据要求「连续两次哈希相同」→ **永远等不到「稳定」** → 白等 40s 判失败。

### 结论

「黑屏」是两个**工具层 bug** 的叠加误报，页面本身完全没有问题：
长图实拍显示「编辑昵称」标题、输入框「思考者」+光标、完成按钮、
中文键盘与候选词（镇/真/针）全部正常；点击 Q 键后 nz=20000 依旧正常。

## 修复（tools/vela-loop.py，commit 3cfa324）

1. **端口自动探测**：`--serial` 默认从 `adb devices` 里取第一个 `emulator-*`，
   `--port` 默认取 serial 里的端口号。模拟器换端口不再误判。
2. **出画判据改为「非黑即算」**：`nz>=3000 且 vapp 进程在`，连续 3 次满足即算出画；
   帧哈希相同只作日志提示（含"上一轮残留画面"提示），不再参与判定。
   带动画（光标闪烁、进度条）的页面从此不会误报。

## 验收

| 场景 | 结果 |
|------|------|
| chinese-input 冷启（不传端口） | 34.5s 出长图 192×1270，页面完整 |
| chinese-input 点击 Q 键补拍 | nz=20000 正常，无黑屏 |
| welcome 对照 | 36.1s 正常出画，无回归 |

## 教训（可复用规则）

1. **判黑屏不能只信一种信号**：`nz`（非零字节数）和「进程在不在」要一起看。
   nz 满值 + 进程在 = 亮屏，与帧是否变化无关。
2. **写死设备端口是隐患**：模拟器重启换端口时，adb 失败是静默的，
   报错信息（device not found）很容易被脚本的容错逻辑吞掉。
3. **「渲染稳定」判据对带动画页面不成立**：闪烁光标/动画会让帧哈希永不重复。
   稳定判据应该是「连续 N 次都满足非黑+进程在」。
4. 之前的结论「chinese-input 直启黑屏、welcome 正常」同样受这两个 bug 影响，
   应作废；APK 端 v0.5.179 的输入法修复本身有效（手环端实测正常），与此误报无关。
