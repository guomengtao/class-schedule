# 模拟器复现真机 REDMI Watch 6 问题——可行性分析与放弃结论

> 日期：2026-09-28　|　结论先行：**"克隆 5.0 镜像模拟器来复现真机崩坏"这条路判定为不可行（对本问题），立即换方式**。本文记录全部实验证据、三个硬障碍、以及根因论证为何不需要这个复现环境，最后给出替代方案。

---

## 一、我们要解决什么问题（回顾）

用户 REDMI Watch 6 真机（Vela **v=1200**，432×514 rect）三个页面崩坏：
1. 输入法键盘塌缩到左下 ~150px（`InputMethod.ux` rect 分支）
2. 首页设置行布局失效（标签与开关叠压）
3. 震动实验室标题与卡片挤同行

而 **pre-4.0 模拟器（包括 432×514 的 Watch 6 皮肤）全部渲染正常**。于是产生设想：换一个与真机更接近的模拟器运行时，把问题复现出来，供修复后本地验收。

## 二、实验时间线（每一步证明了什么）

| # | 动作 | 结果 | 证明/推翻 |
|---|---|---|---|

| 2 | pre-4.0 + Watch6 皮肤（8556）截图输入法页 | 键盘渲染完全正常 | **排除 432 宽度布局数学问题**，指向运行时差异 |
| 3 | 发现本地有 `vela-miwear-watch-5.0` 镜像 | 从未使用过 | 唯一可能更接近真机的运行时 |

第 11 步是压垮骆驼的最后一根稻草：连"读个存储"都不回调，意味着在这个实例上做自动化取证的地基不存在。

## 三、三个硬障碍（为什么继续烧下去不划算）

### 障碍 1：镜像 ≠ 真机系统（保真度不可证）

`vela-miwear-watch-5.0` 是 SDK 模拟器镜像，**没有任何证据表明它与 REDMI Watch 6 真机的 Vela v=1200 同源**。真机崩坏可能是厂商定制（字体、布局引擎补丁、显示服务）导致的——这些在公开镜像里大概率不存在。就算我们在这个实例上测出"一切正常"，也无法区分：
- A. 问题不在运行时，在我们的修复方向错了
- B. 镜像本来就不带真机的定制，天然复现不了

**复现成功才能证明可行，复现失败什么也证明不了**——这是一个不可证伪的实验设计，本身就是可行性红旗。

### 障碍 2：本地工具链与 5.0 存在代差（排查成本失控）

本轮实际踩掉的坑：`-semihosting`/`-smp` 参数不支持、端口转发冲突、缺 `userdata-qemu.img`、`pm install` 以文件名为包名、`/data/quickapp/app` 手推目录失效、`am stop` 后无法再启动、`--start-page` 失效、dmesg 环形缓冲 10 秒被 AT_RIL 重试刷掉、`storage.get` 回调不触发。**每一层基础设施都要重新发明**，且没有调试日志通道（真机 r 参数回传、模拟器 log 都缺失），等于在黑暗里装机。

### 障碍 3：即使复现，验收闭环也太慢太脆

每轮验证 = 构建 → 推 rpk → `pm install` → reboot(50s) → `am start` → 截图 ≈ **3-5 分钟/轮**，触摸注入未验证（不能点按钮），自动导航未跑通。对比 pre-4.0 实例的秒级截图巡航，这个环境不具备日常回归价值。

## 四、关键论证：修这个问题，真的需要"复现"吗？

**不需要。** 证据链已经闭环：

1. **根因有强代码证据**：三页崩坏全部命中本项目已知红线——"子元素无显式 width → Vela 宽度退化"、"div 默认 row"（`vibration-lab.ux` 里甚至有注释预言了这个故障形态）。
2. **反证支持**：首页在真机不崩——它的内容层全部显式 `width:100%`。同一个真机、同一次安装，显式声明的地方全部正常。
3. **修复是"做加法"**：补 `width:100%`/`flex-direction` 显式声明，在 pre-4.0 模拟器上已证明是 no-op（不会引入回归），在真机上大概率就是修复本身。**修复的正确性不依赖"先复现故障"**——这不是改逻辑、改交互，是把隐式行为显式化。
4. **最终验收标准本来就是真机**：项目铁律"模拟器通过 ≠ 真机通过"。真机往返是绕不开的最后一环，模拟器复现只是想给中间加一层保险——这层保险的成本已远超其价值。

## 五、结论与替代方案（新方式）

**判定：放弃 5.0 模拟器复现路线。** 改为：

| 优先级 | 方案 | 说明 | 成本 |
|---|---|---|---|
| **P0** | **直接出修复包 → 用户真机验证** | 补显式声明（IME rect 分支容器链、`.item-row`、`.style-block` 及父链）→ 出包 → 用户安装 → 以回传 r 参数核对版本。修复是显式化加法，模拟器已证 no-op，真机结果就是终审 | 半天 |
| **P1** | **真机诊断页** | 扩展 `input-crash-diag`：显示 screenShape/screenWidth/字体缩放 + 一个"无 width 中间层 + scroll-x"最小塌缩用例 + 三页入口，用户真机一键截图回传。一次真机数据 > 十轮模拟器猜测 | 半天 |
| **P1.5** | **pages.html 审核闭环** | 已有基础设施（app-auth 审核系统）：用户真机截图直接提交带标注，AI 按 pageId+box 定位修复后回写 resolved | 已建成 |
| 备份 | 保留 5.0 实例成果 | watch6-miwear5 实例、pm install/am start/部署坑知识已沉淀（附录），将来真要测 5.0 运行时行为可复用，**现在不再投入** | 0 |

## 六、清理项

- `src/pages/welcome/welcome.ux` 的巡航调试注入（`DBG:` 副标题 + storage 计数）已按"验证后必须删干净"红线恢复原状。
- 模拟器实例 `watch6-miwear5`（emulator-5558）保留但不再投入；不影响现有两台实例。

## 七、附录：5.0 实例搭建知识（沉淀备查）

1. **建实例**：`~/.vela/vvd/<名字>.ini` + `<名字>.vvd/config.ini`（复制现有 config，改 `AvdId`/`image.sysdir.1`/`ide.image.type`），需从镜像拷 `vela_system.bin`，并用 `vela_data.bin` 生成 `userdata-qemu.img`，否则启动报缺盘。
2. **启动**：`/Users/Banner/.vela/sdk/emulator/darwin-aarch64/emulator -vela -avd <名字>`（不支持 `-semihosting`/`-smp`；hostfwd 端口被 IDE 实例占用会报非致命错误）。
3. **安装**：只能走 `pm install /data/<包名>.rpk`（**文件名=包名**，安装到 `/data/app/<pkg>/`，带 hash 校验）；手推 `/data/quickapp/app/` 无效。
4. **启动应用**：`am start <包名>`；`am stop` 后 `am start` 失效，需 `reboot`（~50s）后再 start。
5. **日志**：`dmesg` 环形缓冲极小（~1KB），AT_RIL 每 10s 重试刷屏；要在同一 shell 会话内"动作+立即导出"才能抓到。
6. **已知残缺**：`storage.get` 回调不执行、`--start-page` 失效、aiot-toolkit pre-4.0 工具链产物兼容性存疑。

## 八、替代方案落地：布局诊断页（rect-diag）使用说明

> 历史依据：v1.4.50/51 手环 9Pro 左上角黑屏（同为"模拟器正常真机崩"）正是靠"逐项隔离结构 + 真机取证"定位的（`docs/index-band9pro-black-screen-analysis.md`、`band9pro-black-screen-fix-plan.md`）。本次把它升级为**单页 7 步累加**，一张截图=全部证据，比当年的多页跳转更快。

### 页面结构（工具 → 布局诊断）

顶部环境卡自证屏型/分辨率/版本；下面 7 格，**蓝格=容器（应满宽），黄块=被测元素（应铺满蓝格）**：

| 步骤 | 结构 | 对应嫌疑 |
|---|---|---|
| 1 | 单层 `width:100%` + 文本 | 基准：它都不满宽=页面级问题 |
| 2 | 无 width 中间层 ×2 嵌套 div | 宽度退化主嫌疑 |
| 3 | 无 width 层 + `scroll-x` 横滚 | 输入法 rect 分支同构 |
| 4 | `row + space-between` 标签+固定块 | 首页设置行同构 |
| 5 | `column` 父 + 48% 两格网格 | 震动实验室卡片同构 |
| 6 | `min-height:100%` 容器 | 历史 9Pro 根因结构 |
| 7 | `if` 条件渲染（可点击切换） | 重绘缺失坑（对照） |

### 用户操作（1 分钟）

1. 安装 `dist/ev-v1.6.155-t-9p-d.rpk`（r=1.6.155， activation 页/关于页核对版本）。
2. 工具 → **布局诊断**，滚动整页截 1-2 张图发回。
3. 判读规则：**哪一格黄块没铺满蓝格，根因就是那一格标注的结构**；若全部铺满，则问题在更上层的页面链（回到代码逐页排查）。

### 判读后动作

- 命中步骤 2/3 → 补齐 IME rect 分支容器链显式 `width:100%`；
- 命中步骤 4/5 → 对应页面行/网格容器补显式方向与宽度；
- 全部正常 → 优先怀疑厂商字体缩放/显示服务，转向诊断页增加字号缩放读数。
