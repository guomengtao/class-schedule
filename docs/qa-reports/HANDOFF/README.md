# HANDOFF 目录约定

QA（我）和作者（Tom）异步沟通的地方。**双方写不同文件，从根本上零 git 冲突。**

| 文件 | 谁写 | 说明 |
|---|---|---|
| `REPLY.md` | **作者** | 唯一的回复入口。不管回哪一轮，都改这一个文件。 |
| `2026-09-11-roundN.md` | **QA** | 每轮质检新建一份，只增不改不改旧。含本轮待办表 + 空的回复区。 |

## 作者怎么答复

三种，挑最省事的：

1. **commit 带编号**（推荐）：`git commit -m "fix(qa): P0-2 修了 xxx"` —— QA 下轮自动扫 git log 比对并复核代码，文档一个字都不用写。
2. **改 `REPLY.md`**：适合要解释、要反驳、要提问的。
3. **只改代码不说话**：也行，QA 会自己重新扫。但「认为不是问题」和「无法静态确认」这两类必须说一声，否则会一直报。

## QA 怎么读

每轮开始按顺序做：
1. `git fetch` + 比对 HEAD，扫 `git log 上轮HEAD..HEAD` 里的 `fix(qa):` 编号
2. 读 `REPLY.md`，把「已修」的编号记下来
3. **打开代码复核** —— 文档会过期，只有代码是真的
4. 复核结果写进新 round 文件的「与上一轮对比」

详见 `REPLY.md`。
