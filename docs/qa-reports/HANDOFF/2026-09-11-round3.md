## ⭐ 本轮最重要的一条：P0-2 根因已锁定，1 行就能修

之前我只说「add-course 绕过 database 直写 storage」，不够准。本轮把链路走完了：

1. `add-course.ux:551` 把课程**直接写进** `allCourses_<idx>` —— 数据**确实存下来了**（冷启动能看到，所以不是"保存丢失"）。
2. 返回首页 → `index-full.ux:210 onShow` 确实有完整重载，**逻辑没问题**。
3. 但重载调到 `database.getAllCoursesWithIndex` → `database.js:151-156`：

   ```js
   if (!_cacheDirty[index] && _cache[index] !== undefined) {
     callback(_cache[index])   // ← 直接返回内存里的旧副本，根本不读 storage
     return
   }
   ```

   而 `add-course` 直写 storage **没有清缓存**，且 `database.setScheduleIndex`（`:504-516`）**也不清缓存** → 首页拿到的是**加课之前的旧数组**。

**所以用户看到的就是"保存了但没生效"——这正是你反馈的「编辑课程失败」的真身。**

**最小修复（1 行）**：在 `add-course.ux:554` 的 `success` 回调里加 `database.invalidateCache(idx)`。
⚠️ 注意：`invalidateCache` 定义在 `database.js:141`，**目前没有导出**（`module.exports` 从 `:467` 开始，里面没有它），需要先把它加进导出。
更彻底的做法：改用 `database.insertCourse`（`database.js:482` 内部已经自带 `invalidateCache`），一劳永逸。
