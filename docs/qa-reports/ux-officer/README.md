# UX Officer（用户体验官）工作目录

> 本目录属于第二个 QA 角色——**用户体验官（UX Officer 自动巡检，每 6 小时一次）**。
> 与既有「主 QA」协同：主 QA 报告在 `docs/qa-reports/` 根目录、交接在 `../HANDOFF/`。本角色**只在 `ux-officer/` 目录内写文件**，不碰主 QA 的报告与 HANDOFF，不碰 `src/`。

## 三方零冲突分工（沿用主 QA 的物理隔离设计）

| 文件 | 谁写 | 其他人 |
|---|---|---|
| `../HANDOFF/REPLY.md` | **作者 Tom（唯一回复入口，P0/P1/U/UX 编号都写这里）** | 主 QA、UX Officer 只读 |
| `../HANDOFF/STATUS.md`、`../HANDOFF/roundN.md`、根目录 `class-schedule-QA-*.md` | 主 QA | 作者、UX Officer 只读 |
| `UX-STATUS.md` | **UX Officer（本角色缺陷台账）** | 作者/主 QA 只读 |
| `reports/UX-Report_*.md` | **UX Officer（只新增、不改旧报告）** | 作者/主 QA 只读 |

三个写者（作者 / 主 QA / UX Officer）各写各的文件，**git 冲突在物理上不可能发生**。

## 编号规则（关键：避免和主 QA 撞号）
- 主 QA 已占用：`P0-x`、`P1-x`、`U-x`（UI 类，已用到 U-12）。
- 本角色一律使用 **`UX-x`**（UX-1、UX-2…长期延续，不随每份报告重置）。
- 若发现的问题主 QA 已编号或已处理，**不另起炉灶**：在 `UX-STATUS.md` 与报告中交叉引用主 QA 编号，标注重叠与「剩余差距」，不重复推送主 QA 已验证修复的项。

## 每轮巡检开始做什么
1. `git fetch` 比对 HEAD，扫 `fix(qa):` / `fix(ux):` 编号 commit。
2. 读 `../HANDOFF/REPLY.md`（作者对 UX-x 的回复）与 `../HANDOFF/STATUS.md`（主 QA 台账，用于去重、了解已修范围）。
3. 对 main 最新代码做静态走查 + 量化统计（用户视角优先，见下方分级）。
4. 新增 `reports/UX-Report_YYYY-MM-DD_HHMM.md`，并更新 `UX-STATUS.md`；**只写这两类文件**。

## 优先级（用户视角优先，用户能直接感知的最重要）
- **P0** 用户操作直接失败/不可用（保存没反应、数据丢、白屏黑屏、进不去、误跳转）。
- **P1** 用户直接感知的错/乱（缺成败提示、返回不刷新、显示错乱/截断、字小看不见）。
- **P2** 可感知但不阻断的优化（间距/留白/行高/字号档位/占位文案）。
- **P3** 用户无感的内部工程问题（日志、临时文件、目录、版本配置），报告末尾简列。

## 作者怎么回复 UX-x（和回复主 QA 完全一样，不用学新流程）
- 最省事：commit 带编号，如 `git commit -m "fix(ux): UX-4 付费弹层字号"`，本角色下轮自动扫。
- 或写进唯一入口 `../HANDOFF/REPLY.md`，用同样三档（已处理给 commit / 处理中 / 不打算做），编号写 `UX-x`。
- 「认为不是问题」「无法静态确认需真机」两类请注明，否则会重复报。
