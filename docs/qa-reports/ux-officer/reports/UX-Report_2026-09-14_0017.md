## 一、基础用户操作稳定性（课程添加 / 编辑 / 删除，标准版重点）

### 🟥 UX-15【P1·本轮头号新增，真机或升 P0】删了 vibrator「声明」却没删「调用」，落在输入按键主路径
- **优先形态**：全部形态，胶囊输入场景尤甚（中文输入是添加/编辑课程的必经路径）。
- **代码事实**：
  - `0ae8ed1` 从 `manifest.json` 的 features 移除了 `system.vibrator`（现仅剩 router/storage/prompt/device/request/resident/app）；sqlite/alarm/calendar/configuration 已确认代码 0 引用、移除安全，**唯独 vibrator 仍被 3 处 import**：
    - `src/components/InputMethod/InputMethod.ux:341` import；`:789-792` `onVibrate(){ if(this.vibratemode!=""){ vibrator.vibrate({mode:this.vibratemode}) } }`——**无 try/catch**；该方法在 `:481/:515/:729/:744/:801` 五处按键流程被调用。
    - `src/pages/chinese-input/chinese-input.ux:20` 与 `src/pages/nickname-edit/nickname-edit.ux:22` **显式传入 `vibratemode="short"`**（非空，门控 `!= ""` 必然进入 vibrate 调用）。
    - `src/pages/activation/activation.ux:246-250` `doVibrate` **已用 try/catch 包住，安全**；`src/pages/vibration-lab/vibration-lab.ux` 为振动实验页（见 UX-9/UX-10）。
- **用户影响**：快应用使用某 system API 必须在 manifest 声明该 feature；声明被删后，未声明的 `@system.vibrator` 在部分 Vela 固件上为 undefined 或方法不可用。用户在「中文输入页 / 昵称编辑页」**每按一个键**都会执行到无保护的 `vibrator.vibrate`：若固件直接抛 TypeError，会中断当前按键 handler，可能表现为**按键无震动之外的上屏/候选词异常、甚至按键像失灵**——这是添加课程能否顺利打字的核心路径。
- **确定性说明（不臆断）**：不同 Vela 版本对「未声明 feature」行为不同（有的抛错、有的 noop 容错），静态无法 100% 定死，**真机进入中文输入连续按键即可一锤定音**；一旦复现按键报错/无法连续输入即升 P0。
- **修复建议（成本极低，二选一，让「声明」与「代码」一致即可）**：
  1. 若保留按键震动反馈 → 把 `system.vibrator` 加回 `manifest.features`；
  2. 若按产品决定删除振动（与 UX-10 一致，推荐）→ 删除 chinese-input/nickname-edit 的 `vibratemode="short"` 传参、移除 InputMethod/activation/vibration-lab 的 vibrator import 与调用、下线 vibration-lab 页。
  - 无论选哪个，都建议给 InputMethod.onVibrate 补一层 try/catch（activation 已有范本），做防御性兜底。
- **关联**：本项是 UX-10（删除振动不彻底）在 `0ae8ed1` 之后的**升级形态**——从「声明残留」变成「声明已删但仍调用」的硬不一致；关联主 QA P0-9（已删振动模块测试按钮）。

## 二、胶囊屏 UI（窄屏优先）

> 基准：标题 38 / 正文 32 / 辅助 26 / 底线 22，胶囊方屏统一、真机为准宁大勿小。胶囊水平宽仅 96~106dp，`designWidth=device-width` 等比缩小，小字风险更高。

### UX-4【P1】字号仍未向基准收敛（<22px 347→299，但标题档 38 全站 0 处）
- 全站仍 **24 种**字号（11~56px）；低于底线 22 的 **299 处**（较上轮 347 减少 48，本轮胶囊修复清掉一批小字，方向对）；但**基准标题 38px = 0 处、正文 32px 仅 45 处**，主力仍是 28(253)/24(248)/20(101)/18(52)。
- 即：极小字少了，但**整体仍比「正文 32」基准小一档**，叠加 device-width 缩放，胶囊真机「看得清」仍不达标。
- 建议维持：以 38/32/26/22 四档收敛，正文/菜单/可点列表回 32；胶囊高频页（首页、总课表、添加/编辑、设置列表）先行，真机复核。

### UX-5【P1·部分改善】付费转化弹层：unlock-dialog 已达标，pro-card / premium-overlay 仍有极小字
- `unlock-dialog.ux` 最小字号已由 12 提到 **20**（现 20/22/24/26/28/34），✅ 改善明显。
- 但 **`pro-card.ux` 仍有 12px×4、13px×1（共 5 处 <22）**；**`premium-overlay.ux` 仍有 12/13/14px（共 4 处 <22）**。
- 这两处是引导高级会员/爱发电转化的关键区域，胶囊上仍偏难读。建议标题≥32、正文≥26、底线≥22，精简文案换字号空间（范围已比上轮缩小，只剩这两个组件）。

### UX-6【P2·未变】顶栏组件字号偏小：`components/clock/index.ux:62`=18、`components/day-nav/index.ux:49`=20，胶囊高频观看区建议 22~26。

### UX-7【P2·略反弹】无效媒体值 `(shape: capsule)` 33→37 处
- Vela 官方形状仅 circle/rect/pill-shaped，`capsule` 是永假值，现靠并列的 pill-shaped 侥幸命中；本轮新增/改动页面又带入 4 处。建议统一只保留 pill-shaped，避免误导与死声明。关联主 QA P1-1。

### UX-8【P2·未变】显隐仍以 `if` 销毁为主：`if="{{"` 125 处 vs `display:none` 仅 2 处。项目曾因大量条件渲染触发局部黑屏，建议「仅暂隐」优先内联 `display:{{cond?'none':'flex'}}`，「永不再用」才用 if；胶囊判定可叠加运行时宽高比 <0.55 兜底。

### UX-16【P2·新增】12 个正式二级页根块缺 `width:100%`，仍依赖 `min-height:100%`
- **优先形态**：胶囊优先，其次方屏。
- **代码事实**：以下正式页根容器写了 `height:100%` 但**都没有 `width:100%`**，且冗余保留 `min-height:100%`：activation、backup-restore、chinese-input、chinese-input-full、device-info、donate、homepage-settings、nickname-edit、pinned-pages、reset-data、template-picker、vibration-lab（bs-demo1/3 为故意对照，不计）。
- **用户影响**：高度方向已兜住，水平方向靠 flex 默认 stretch「碰运气」；在对交叉轴 stretch 支持不一致的固件上，根块可能不铺满水平方向，是「局部渲染、其余空/黑」的残余诱因之一（与本仓库四份黑屏记录中的「根容器塌缩」路径同源）。当前非必然、故定 P2。
- **建议**：统一给这些页根块补 `width:100%; height:100%; box-sizing:border-box;` 并删除冗余 `min-height:100%`（真首页 index-full、welcome 已是正确范本）。纯样式、零逻辑风险。
