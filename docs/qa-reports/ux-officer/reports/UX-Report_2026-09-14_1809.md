## 二、本轮新增问题（从 UX-22 起编号）

### 🔴 UX-22 ｜ P1（胶囊优先，待真机确认溢出程度，严重可升 P0）
**标题：新「添加课程 V2」主链路在胶囊屏横排固定宽度必然超宽——双时间框、底部双按钮**

- 优先形态：**胶囊屏（米环9 物理 192、米环10 物理 212；左右 padding 各 16 → 内容宽仅 ≈160/180px）**，其次方屏。
- 位置：`src/pages/add-course-v2/add-course-v2.ux`
  - `.time-row`（基础 :540）内两个 `.time-box`，胶囊块（:755）仍各 **130px**：130×2 = 260，再加 `.time-sep`（margin 0 10 + 字宽 ≈ 44）≈ **304px**；
  - `.bottom-bar`（:679，flex-row + space-between）内 `.cancel-btn` 胶囊 **100px**（:810）+ `.save-btn` 胶囊 **200px**（:816）= **300px**。
  - 二者都远大于胶囊 ≈160px 内容宽。胶囊 @media 块（:710-821）只收了字号和单点宽度，**没有把这两组横排改成纵排或弹性宽度**。
- 用户影响：这是首页「+」现在唯一跳转的正式添加页（`bottom-buttons.js → /pages/add-course-v2`），**用户每次添加课程都会遇到**：开始/结束两个时间框横向挤出、底部「取消 / 确认添加」两个按钮被压缩或出屏，胶囊上可能出现点不准、点不到「确认添加」。属用户直接感知的布局错乱。
- 对照证据：同仓 welcome 胶囊主按钮的成熟做法是**单按钮 160px + `max-width:100%`、纵向排列**（welcome.ux 胶囊块 :271-279）；作者在 `29e6f1b` 修过旧页同类超宽（对应主 QA P1-12 / 本角色 UX-20），但新页 V2 又重现同类问题。
- 修复建议：在 `@media (shape: pill-shaped)` 块内——
  1. `.time-row { flex-direction: column; }`（开始、结束纵向堆叠）或两个 `.time-box { flex:1; width:auto; max-width:100%; }`；
  2. `.bottom-bar { flex-direction: column; }`，`.cancel-btn/.save-btn { width:100%; max-width:160px; align-self:center; }`（主按钮在下、全宽）；
  3. 改完在米环9/10 真机确认两组元素不横向出屏、「确认添加」可点。
- 关联：主 QA **P1-12**（超 192px 固定宽度，旧页已修、新页重现）、本角色 UX-20。

### 🔴 UX-23 ｜ P1（胶囊优先，待真机确认系统返回是否可靠；若硬件返回全机型顺畅可降 P2）
**标题：高级版/激活页移除固定 header 后，页面内已无任何返回入口，与全站二级页不一致**

- 位置：`src/pages/activation/activation.ux`（提交 `69c99af`「移除高级版页面顶部固定 header 栏」，本页 -56 行）。
- 现状：全页 template 已无返回按钮，script 无 `router.back`/`goBack`/`onBackPress`；对照其余正式二级页 settings/detail/add-course-v2/schedule-manager/donate **均有 5–7 个返回元素**，唯独激活页为 0。
- 用户影响：用户从设置进入「解锁/激活高级版」页后，**页面上找不到返回**，只能依赖手环硬件返回键/侧滑。这是付费转化页，"进得去、看不到出口"会放大被困感、也不符合全站一致的交互预期。
- 说明：移除占空间的固定 header 是合理方向（作者有《CAPSULE_HEADER_ANALYSIS》分析），但"去 header"不等于"去返回能力"。
- 修复建议：保留一个紧凑返回控件即可——胶囊可只放一个 48×48 的「◀」图标按钮（对齐 add-course-v2 的 back-btn），或显式实现 `onBackPress()` 兜底；并在米环9/10 真机确认硬件返回一定能 router.back。
- 待作者拍板：是否接受"激活页仅靠硬件返回"。若确认所有目标机型硬件返回稳定可靠，本条可降级关闭。

### 🟠 UX-24 ｜ P2（全形态）
**标题：添加课程 V2 缺「结束时间须晚于开始时间」校验，可保存时间倒挂的课**

- 位置：`add-course-v2.ux` `confirmTimePick()`（:357）、`updateTimeString()`（:386）、`saveCourse()`（:409）。
- 现状：开始、结束时间由两个调节器独立增减（小时 0–23 循环、分钟步进 5），保存前只校验"选了课程/设了时间/默认星期"，**不比较 start 与 end**；可存出如「10:00 - 09:00」的倒挂课程。
- 用户影响：课表网格按时间排序/渲染时出现顺序错乱或时长为负的卡片，属于用户可直接感知、但不阻断保存的数据合理性问题（旧 add-course 同样缺，V2 作为新主链路建议一并补上）。
- 修复建议：在 `saveCourse()` 提交前（或 confirmTimePick 选结束时间时）比较 `endH*60+endM > startH*60+startM`，不满足则 `prompt.showToast('结束时间需晚于开始时间')` 并拦截。

### 🟠 UX-25 ｜ P2（全形态，待真机）
**标题：添加课程 V2「选择课程」列表加载存在两套逻辑，onShow 走的 refreshCourseList 失败/解析异常时静默无兜底**

- 位置：`add-course-v2.ux`
  - `loadCourses()`（:274）健壮：catch 与 fail 都回退 `defaultCourses`；
  - 但 `onShow()`（:230）调的是 `refreshCourseList()`（:249），其 `catch(e){}`（:261）与空 `fail`（:264）**都静默、无 defaultCourses 兜底**。
- 用户影响：进入页面/从输入位置返回时若存储读取或 JSON 解析异常，顶部"选择课程"横向列表为空且无任何提示，用户无法点选已有课程（仍可走课程管理，但页面不自愈、无提示）。两套几乎重复的加载方法健壮性不一致是根因。
- 修复建议：让 `refreshCourseList` 复用 `loadCourses` 的 catch/fail 兜底（异常时回退 defaultCourses 并重选当前项），或直接合并为一个方法。
