## 1. 结论先说

现版本是**占位式实现**：5 个字符各绑一个颜色 + 两个按钮，**66% 的屏幕是空的**，且渐变只发生在字符之间、字符内部全是纯色。

所以这次分三层做：**视觉母题 → 信息层级 → 双屏适配**，并补专属开发文档。只加宽屏分支解决不了"单调"。

三页同构对比（同一份骨架复制，11 个 class 逐字相同）：

差异只在「哪个东西绑定颜色」：彩色 = 5 字符各一色，渐变 = 5 字符取色带 5 档，背景 = 整页底色 + 单色字。

### 2.1 为什么单调（四个根因）

1. **渐变是假的**：`c0..c3` 五个色值分给五个字符，字符内部仍纯色 → 看到的是"5 个不同颜色的字"，不是渐变。
2. **信息只有时间**：表盘定位是"抬腕看关键信息"（组级文档原话），现在没有日期、没有秒、没有层次，只有一个静态 HH:MM。
3. **没有垂直构成**：flex 居中把内容压在中段，上下各空 1/3，没有品牌行、没有视觉重心、没有分隔。
4. **不合字号规范**：按钮 22px、面板标题 22px 均低于 ev-six 24px 绝对下限；也没有任何宽屏分支，336 屏靠 60px 字号硬撑（左右各空 ~83px）。

## 3. 品质提升设计

### 3.1 视觉母题：让渐变真的"流"起来

四层叠加，每层只用项目内已验证能力（绝对定位 div + 纯色/opacity + border-radius）：

| 层 | 做法 | 解决什么 |
|---|---|---|
| 背景渐变 | 8 条等高横向色带，色值沿色带插值，相邻带重叠 8px + opacity 过渡消硬边 | 从"纯色底"到"整屏有色彩方向" |
| 逐字符连续取色 | 色带由 5 档加密到 7 档（含冒号），按位置线性插值 | 字符之间不再跳色 |
| 秒进度条 | 底部 4px 细条，宽度 = 秒/60 × 安全区宽，颜色取色带中段 | 画面"活着"（现在整分钟才动一次） |
| 氛围光 | 时间下方 200×90 圆角 div，opacity 0.10，取色带中间色 | 数字有发光感，不再是贴纸 |

**关键取舍**：`linear-gradient` 全项目 **0 处使用**、`text-shadow` 已被《字体表盘方案》判为「未验证 🚫 不做」，所以不赌。开工第一步做 **3 行探针**（1 次构建）：

- 探针通过 → 背景改用一条 `background-image: linear-gradient(...)`，比 8 带法更平滑
- 探针失败 → 走 8 带分层法（已在验证能力内，零黑屏风险）

两条路验收标准一致，只是实现不同。

### 3.2 信息层级：从"一个数"到"三层结构"

192 屏（不加课程数据，纯排版构成）：

```
        E V              24px  品牌行（letter-spacing 4）
     2 0 : 0 7           76px  主时间（七档渐变色）
    10-25 周六            24px  日期行
    ▁▁▁▁▁▁▁▁▁             4px  秒进度条（渐变色）
     渐变 │ 返回          24px  两按钮同排，1px 竖线分隔
```

336 屏同构放大（主时间 104px、其余走 24/28 档），纵向留白从 66% 降到 ~35%。

**明确不做：加课程信息。** `store` 课表读取属「课程表盘 / 功能表盘」职责；加进这三页会让三页重新同构，还引入空态与异常分支。表盘栏目已有课程表盘承担。

### 3.3 三页差异化（避免做成三个孪生）

| 页面 | 母题 | 时间呈现 | 独有元素 |
|---|---|---|---|
| **渐变** | 色彩流动 | 逐字符渐变色 | 背景分层渐变 + 秒进度条 + 氛围光 |
| **彩色** | 色块构成 | 单色高对比 | 科目色环 / 侧边色柱（几何），背景保持纯净深色 |
| **背景** | 场景氛围 | 单色 + 1px 描边 | 6→8 套场景背景（暗色为主）+ 面板色票预览 |

三页共用同一套骨架与适配分支，但**视觉母题不重叠**。这是"不再单调"的关键——不是三页都加满，而是三页各有一个别人没有的东西。

### 3.4 ev-six 合规

- 主时间以外全部文字用 24/28 两档（现 22 → 24），24 为绝对下限
- 主时间 76 / 104px = 表盘图形本体，豁免四档，样式注释写明理由（与前两块同一处理）
- 分隔靠排版（1px 竖线、间隙），不用 `|` `/` 符号（第 5 条）

## 4. 双屏适配

沿用已验证范式（经典 / 翻页表盘同一套）：

```js
device.getInfo → screenWidth >= 300 → wide = true
模板：<text if="{{ !wide }}" class="...">    原 192 版式，class 一个不改
      <text if="{{ wide }}"  class="w-...">  宽屏版式
```

| 项 | 192×490 | 336×480 |
|---|---|---|
| 主时间 | 60px（原值不动） | **104px** |
| 冒号间距 | margin 0 2px | 6px |
| 按钮 | 竖排两行（36 / 14 间距） | 横排一行 + 1px 竖线分隔 |
| 面板 | 240 宽 / 标题 22 / 项 26 | 284 宽 / 标题 24 / 项 28 |
| 秒进度条 | 新增，宽 140 | 宽 300 |
| 安全区 | 两侧各 10（胶囊圆角） | 两侧各 10，内容 ≤316 |

**主时间 104px 的来源**（沿用 landscape 最坏字宽 0.6F 反算）：

- 116px：`4×0.6×116 + 冒号 0.35×116 + 间隙 6×4 ≈ 278 + 41 + 24 = 343 > 316` ❌
- **104px**：`4×0.6×104 + 0.35×104 + 24 ≈ 250 + 36 + 24 = 310 ≤ 316` ✅

取 104（留 6px 防宽字形），构建后实测微调——这一步必须看截图，不能只算。
