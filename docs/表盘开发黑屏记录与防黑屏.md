## 一、TL;DR（防黑屏十诫）

新增表盘页面时，先过一遍这条清单，能挡掉绝大多数黑屏：

1. **`onInit` 里的 for 循环必须用 try-catch 包**——Vela 渲染引擎可能在 CSS 盒模型算完前执行 `onInit`，大 for 渲染一崩，页面直接整页黑。包了之后即使崩也降级不黑屏。
2. **`setInterval` 刷新间隔 ≥ 200ms**——Vela 帧率约 30fps，100ms 太密集会跑死渲染管道，页面无报错直接黑。200ms 视觉几乎不变，压力减半。
3. **`.page` 用纯 `position: relative` + 全部子元素 `absolute` 手写坐标**——不要在 `.page` 上叠 `flex-direction/justify-content/align-items` 又同时让子元素 absolute，两者冲突时 absolute 解析异常会黑屏。参考已验证正常的 `watch-face/watch-face.ux` 骨架。
4. **渲染元素宁少勿多**——`for` 一次性铺 60 刻度 + 12 时标（72 元素）每帧全量 `rotate` 重渲染会把管道压垮。能省则省，或分步加入并逐步真机验证。
5. **不要用不支持的 CSS 语法**——逗号分隔的 `@media ... , ...` 列表、`position: fixed` 等在部分手环上会导致布局规则全失配 / 渲染崩溃。
6. **`onShow/onHide/onDestroy` 完整启停定时器**——页面不可见时要 `clearInterval`，否则泄漏 + 后台空转。
7. **分清"代码黑屏" vs "部署/模拟器黑屏"**——多半时候黑屏是模拟器启动环节问题（App 进程没起来），不是页面代码问题。先排部署再排代码。
8. **验证时确认装的是新包**——设备/模拟器上的旧 rpk 缓存会骗你，改了代码却看的是旧包，容易被误导成"还在黑"。
9. **先做个"纯静态单帧版"确认能显示**——如果动态走时黑，先砍掉 `setInterval` 只画一次当前时间，确认背景/指针能显示，再一档档加回动画，定位到底哪步黑。
10. **加一个欢迎页调试入口**——开发期间在欢迎页放一个直达的临时入口，省去层层导航，快速反复验证。

## 二、本次表盘开发的黑屏排查实录

### 现象时间线

| 阶段 | 页面内容 | 结果 |
|---|---|---|
| 第 0 步 | 仅一个居中文字「hello」+ 一个圆盘 div | 🟢 能显示 |
| 第 1 步 | 双层表壳 + 盘面 + 60 刻度 + 12 时标 + 三针走时（72 循环元素）| ⚫ **黑屏** |
| 第 2 步 | 砍掉 60 刻度，只留 12 时标 + 三针走时（17 元素）| ⚫ 仍黑 |
| 第 3 步 | 全 static，砍掉 for / 只留 8 元素 + 三针走时，`.page` 改纯 relative | ⚫ 待确认 |

### 逐层排查的经验（逐步排除）

- **`for` 渲染量大**：第 1 步 72 元素是主要嫌疑。但第 2 步砍到 17 元素仍黑 → **不是单纯数量问题**。
- **`.page` 布局冲突**：前两版 `.page` 用了 `flex-direction:column + justify-content/align-items:center`，同时内部子元素全部 `position:absolute`。flex 容器 + absolute 子元素在 Vela 上可能解析异常 → 推断是重要嫌疑，第 3 步已改为随 `watch-face` 同构的 `pure relative`。
- **`onInit` 时序**：已在第 1 步就加 `try-catch`，若仍是这个根因也不该黑 → 排除（不是主因）。
- **高频 setInterval**：200ms 已低于危险阈值，与 `watch-face` 一致 → 排除为主因，但保留。

> **待确认**：第 3 步（纯 relative + 8 元素）是否在**新打入的 rpk** 上恢复正常，以此最终定位。若仍黑，下一步砍掉 `setInterval` 做纯静态单帧。

### 🔑 关键判断点（这在任何排查中都最重要）

1. **先确认"装的是新包"**——否则前两次黑屏可能都是旧包缓存，白改。
2. **先排部署/模拟器环节**——看 `emulator-black-screen.md`：模拟器黑屏 90% 是 `--jsdebugger` 挂起或 `&` 后台进程被 SIGHUP 杀，App 进程压根没起来，跟页面代码无关。
3. **分环节定位**——在欢迎页加调试入口直达表盘列表；列表若也黑 → 问题在列表页/路由；列表正常、仅点具体表盘才黑 → 才确认是该表脚本问题。

## 🔍 元凶锁定（2026-10-09 · 精确定位最终裁定）

**`setInterval` 高频动态刷新 `transform: rotate` = 黑屏元凶。**

一次加一项的精确定位过程（每一版都真机打包验证）：
- 纯文字版：✅ 正常
- **+ 一个静态绝对定位指针 div**（无 transform/无定时器）：✅ 正常
- **+ `transform: rotate(45deg)` 静态角度**（仍无定时器）：✅ 正常
- **+ `setInterval` 200ms 动态更新角度**（同代码只多这一步）：❌ **黑屏**

三版逐步确认：布局（多 absolute）、`transform` 静态旋转**都不是**元凶；唯独引入 `setInterval` 驱动动态重渲染后立即黑屏。

**实锤：Vela 渲染引擎对 `setInterval` 高频触发 transform 重渲染支持不佳，会整页黑屏且无报错。**

**规避对策（避免手指战场重蹈）**：
1. **不靠 setInterval 高帧驱动 transform**——`tick()` 改为由 `onShow` 触发一次即可，或拉长间隔到 10s/60s（分钟级刷新），不追求扫秒平滑
2. 若要秒针动：改用**最小侵入**（只用一个轻量 div 转秒针），避开整页数据更新遍历
3. 动态刷新前先 `hide()`/更新后再 `show()`，避免在渲染管道里连续转动
4. 首选**静态多指针分层**（预置每 5 分钟一档的角度），零定时器最稳

## 🔍 终极结论修正（2026-10-09 · 对照运行正常的 watch-face-gold 后推翻前面归因）

**真凶 = `.page` 上叠加 flex centering（`justify-content/align-items: center`）+ 内部 `position:absolute` 子元素**。

**决定性证据链**：项目里 `watch-face-gold`（运行正常）用了**完全相同**的
`transform: rotate({{hourDeg}}deg)` 数据绑定 + `setInterval` + 60 刻度 for 循环，
**却从不黑屏**。它与我的黑屏版唯一结构性差异就在 `.page`：
- gold：`.page { flex: 1; flex-direction: column; width: 100%; height: 100% }`（**无 centering**）
- metal 黑屏版：`.page` 额外加了 `justify-content: center; align-items: center`

**被推翻的中间结论**（曾经误判，现更正）：
1. ❌ "setInterval 高频重渲染致黑" → 错，gold 也用 setInterval 走时
2. ❌ "transform 数据绑定致黑" → 错，gold 也用 {{}} 数据绑定
3. ✅ 唯一成立：**flex centering 与 absolute 子元素叠加**会整页黑屏

**排查实验回顾**（为何曾绕远）：纯文字版能显示，是因为它虽带 centering，但子元素只有 dial/文字且无 transform；一旦加绝对定位的 transform 指针，centering + absolute 的组合被激活即黑。多轮误判源于我一直在减元素、换写法，却从没把 `.page` 的 centering 去掉。

**铁律（新表盘必遵）**：`.page` 一律用 `flex:1; flex-direction:column; width:100%; height:100%`，**绝不加 justify-content/align-items**；所有构件用**显式 `left/top` + 可选 `transform-origin`** 绝对定位（盘心坐标 CX/CY 手算）。有动机的实时走时（setInterval + 数据绑定 transform）在正确布局下是安全的。

## 🏁 最终裁定（2026-10-09 · 真机逐版实测定论）

**黑屏唯一元凶 = Vela 的 `transform` 使用 `{{}}` 数据绑定（`rotate({{angel}}deg)`）。**

一次加一项的真机定位（每版打包上真机验证）：
| 版本 | 内容 | 结果 |
|---|---|---|
| 纯文字版 | 圆盘+文字 | ✅ |
| +字面量指针 | `rotate(60deg)` 字面量 + transform-origin | ✅ |
| 完整静态版 | 12 时标 + 三针 + 轴帽，**全部字面量** | ✅ |
| 数据绑定角度 | `rotate({{hourDeg}}deg)`（值同样60） | ❌ 黑 |

**回归链式证据**：字面量静态（无论元素数量多少）→ 全稳定；键出唯一变量 = 数据绑定 transform → 键黑。连一直以为正常的 watch-face-gold 实测也黑，因为它的指针同样用 `{{hourDeg}}` 数据绑定。

**结论铁律**：
1. **Vela `transform: rotate` 禁止用 `{{}}` 数据绑定**，会整页黑屏无报错
2. 字面量静态 transform 完全安全
3. js 动态改角度 → 必然走数据绑定 → 必然黑。**要实时走针，唯一可行方向是 Vela 动画（`animation` 关键帧），不用 js 动态改写 transform**

**已验证稳定的写法模板**（真机确认不黑）：
- `.page { position:relative; width:100%; height:100%; flex-direction:column; justify-content:center; align-items:center }`
- 指针：`position:absolute` + 字面量 `transform: rotate(60deg)` + `transform-origin: 50% 100%`
- 全部构件静态定位，零数据绑定 / 零 for / 零 setInterval

## ✅ 最终成功经验（2026-10-09 · 真机验收通过并发布）

**Vela 表盘"实时走针"的正解 = `@keyframes` 动画，绝不用 js 数据绑定改 transform。**

实测通过：仿古青铜表盘（watch-face-metal）用动画实现三针走时，真机稳定不黑、指针转动正常。

**走针动画标准写法**（速率对齐真实时间）：

```css
/* 秒针：60s 转一圈（1分钟1圈） */
.hand-second {
  transform-origin: 50% 100%;
  animation-name: kf-second;
  animation-duration: 60s;
  animation-timing-function: linear;
  animation-iteration-count: infinite;
}
@keyframes kf-second { from { transform: rotate(0deg); } to { transform: rotate(360deg); } }

/* 分针：3600s 一圈 / 时针：43200s 一圈，写法同上，调 duration */
```

**三条铁律汇总**：
1. `transform: rotate` 禁止用 `{{}}` 数据绑定 → 黑屏（唯一实锤元凶）
2. 静态定位 + 字面量 rotate + 可选 `@keyframes` 动画 → 完全安全
3. js 定时器改角度 = 数据绑定 = 黑；**实时走针一律走 `@keyframes` 动画**

**已知取舍**：动画起始角是写死的固定值，进表盘时指针不追真人当前时刻，但从固定角匀速走、速率真实。后续要对真实时刻需另想办法（分层 + 短动画偏移），需实测防黑屏。

## 四、防黑屏规范（新表盘必做）

### 1. 页面骨架模板（已验证与 watch-face 同构）

```html
<template>
  <div class="page">
    <!-- 全部子元素 absolute，手写 left/top -->
  </div>
</template>
<style>
  .page {
    position: relative;   /* 不要叠 flex centering + absolute 子元素 */
    width: 100%;
    height: 100%;
    background-color: #141210;
  }
</style>
```

### 2. onInit + 定时器模式

```js
onInit() {
  try { this.buildDial() } catch (e) { /* for 渲染崩也不黑屏 */ }
  this.tick()
}
onShow() { this.startTimer() }
onHide() { this.stopTimer() }
onDestroy() { this.stopTimer() }
startTimer() {
  this.stopTimer()
  const self = this
  this.timer = setInterval(() => self.tick(), 200)  // ≥200ms！
}
stopTimer() {
  if (this.timer) { clearInterval(this.timer); this.timer = null }
}
```

### 3. 渲染量红线

- 循环生成元素量级控制在 **≤ 20 个**内起步，逐步加，每档真机验证。
- 每帧会动的元素（rotate 的指针）越少越好；静态刻度/时标可留，但别一次性全铺。

## 五、排查 SOP（遇到黑屏按此顺序做）

1. **确认新包**：重新打包，确认设备装的是最新 rpk。截图比对，别被旧缓存骗。
2. **排部署/模拟器**：模拟器先看 `adb shell ps` 有没有 App 进程；手机/手环看能否进其他页面。列表页能进 = 全局没问题。
3. **分环节**：欢迎页 → 表盘列表 → 具体表盘。定位黑在哪个环节。
4. **隔离变量**：
   - 砍掉 `setInterval` 做静态版 → 看背景能否显示（**排除动画/渲染频率**）
   - 砍掉 `for` 改手写少数元素 → 看能否显示（**排除循环渲染**）
   - `.page` 改纯 relative → 看能否显示（**排除布局冲突**）
5. **看日志**：连 USB 看 App/渲染日志，有 try-catch 时错误会打出来；纯黑无日志更多指向运行时崩溃——优先查 onInit 时序与渲染频率。
6. **记录**：把现象、版本、改动 commit、结论写进本文档，供团队共享。
