# 日期选择器表盘 → 自动走时时间表盘 改造方案

> 状态：方案草稿 · 2026-10-10
> 依赖：Vela 官方 picker 组件（`type="time"` + `type="text"`）已验证可用
> 任务单：evtask-D-class-schedu-261010-ewf8mj

## 一、目标

把当前「日期选择器表盘」(`watch-face-pickdate`) 从**手动选日期的静态交互**，改为**自动走时的时间表盘**：

- 时间自己走（秒/分跳动）
- 仍然可以上下滑动手动改时间
- 变成一个「活」的表盘，不是纯挑选工具

## 二、核心问题：picker 能不能自己走？

Vela 官方 picker 的 `selected` 属性支持数据绑定：

```html
<picker type="time" selected="{{ timeVal }}" onchange="onTimeChange"></picker>
```

如果 JS 里用 `setInterval` 每秒更新 `this.timeVal`，picker 会不会自动滚动到新值？

| 问题 | 分析 | 风险 |
|---|---|---|
| selected 动态更新后 picker 是否滚动？ | 官方未明确说明，需真机验证 | ⚠️ 中 |
| setInterval 每秒改 selected 是否触发 change 事件？ | 如果触发会导致死循环，需加标记位抑制 | ⚠️ 低（可解决） |
| picker 滚动动画是否流畅？ | `type="time"` 原生滚动应该平滑 | ✅ 低 |
| 每秒触发数据绑定是否导致性能问题？ | Vela 数据绑定轻量，经典表盘 1s 心跳已验证 | ✅ 低 |

## 三、方案设计

### 方案 A · 时间 picker 自动走（推荐）

**思路**：用 picker `type="time"` 作为主显示区，`setInterval` 每秒更新 `selected`，picker 自动滚动到当前时分。

```
┌──────────────────┐
│                   │
│   [ 时间 picker ] │  ← type="time"，selected 每秒更新
│   小时 : 分钟     │     picker 自动滚到当前值
│                   │
│   2026-10-10     │  ← 下方固定显示日期
│                   │
│  点击任意位置返回  │
└──────────────────┘
```

**JS 核心逻辑**：
```javascript
// 每秒走时
this.timer = setInterval(function() {
  self.suppressChange = true        // 抑制 change 事件
  self.timeVal = nowHour + ":" + nowMin
  // picker 看到 selected 变了，自动滚到新时间
}, 1000)

onTimeChange: function(e) {
  if (this.suppressChange) {
    this.suppressChange = false
    return                          // 自己的定时器触发，忽略
  }
  // 用户手动滑了 picker，更新显示
  this.timeVal = e.hour + ":" + e.minute
}
```

**优点**：
- 用户看到的是「活的时间」在 picker 里自动走
- 手动滑 picker 也能改时间（手动优先，改完继续走？还是停走？需确认交互）
- 体验新颖：picker 既是指针又是表盘

**缺点**：
- `selected` 动态更新是否驱动 picker 滚动，未在真机验证
- 每秒更新可能产生不必要的渲染开销

### 方案 B · 大号文字时间 + picker 只用于手动调

**思路**：经典表盘模式——大号文字显示时间，每秒刷新；picker 降级为「手动调时间」的辅助控件。

```
┌──────────────────┐
│                   │
│   14:35          │  ← 72px 文字，setInterval 每秒刷新
│   2026-10-10     │  ← 日期
│                   │
│   [选项：调时间]  │  ← 点击弹出 picker
│                   │
│  点击任意位置返回  │
└──────────────────┘
```

**优点**：零风险，经典表盘模式已验证，picker 不做自动滚动只做手动选择。

**缺点**：picker 没有「自己走」，不够新颖。

### 方案 C · 混合：时间 picker 走 + 年月日三列也走

**思路**：方案 A 的基础上，再加年月日三列 picker `type="text"`，也自动走。

```
┌──────────────────┐
│                   │
│  [ 年 picker  ]  │  ← 走年（慢，一年一变）
│  [ 月 picker  ]  │  ← 走月（一月一变）
│  [ 日 picker  ]  │  ← 走日（一日一变）
│  [ 时间 picker ] │  ← 走时分（每秒/每分钟）
│                   │
│  点击任意位置返回  │
└──────────────────┘
```

**优点**：整页都是 picker，都在自动走，视觉冲击力强。

**缺点**：
- 四个 picker 挤在 192×490 跑道屏上太密
- 年月日走得慢，大部分时间看起来不动，浪费空间
- 每秒更新 4 个 picker 可能性能吃紧

## 四、推荐：方案 A

### 交互细节待确认

| 问题 | 选项 |
|---|---|
| 用户手动滑 picker 改时间后，是否继续自动走？ | A. 停止自动走（手动优先，直到点击「恢复」）/ B. 继续自动走，覆盖用户选择 |
| 走时粒度：每秒还是每分钟？ | A. 每秒（更活）/ B. 每分钟（省性能，和经典表盘一致）|
| 是否同时显示日期？ | A. 显示（一行小字）/ B. 不显示（纯时间表盘）|

## 五、实现步骤

1. 复制 `watch-face-pickdate/watch-face-pickdate.ux` → 改造
2. 把三个 `type="text"` picker 替换为一个 `type="time"` picker
3. 加 `setInterval` 每秒更新 `timeVal`
4. 加 `suppressChange` 标记区分「自动走」和「手动滑」
5. 日期行保留（静态文字显示，每分钟刷新一次）
6. 编译 → 真机验证 `selected` 动态更新是否驱动 picker 滚动

## 六、风险

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| picker 不响应 selected 动态更新 | 中 | 方案 A 废，退回方案 B | 先验证 5 分钟即可 |
| 每秒更新导致渲染抖动 | 低 | 体验差 | 降到每分钟走 |
| 手动滑 picker 后自动走覆盖用户选择 | 高 | 体验差 | 加标记位：手动改后暂停自动走直到点击恢复 |
| 四列 picker（方案 C）跑道屏挤不下 | 高 | 不可用 | 不用方案 C |

- [ ] 不黑屏、不卡顿
- [ ] 点击返回正常
