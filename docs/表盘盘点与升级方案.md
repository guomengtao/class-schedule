## 二、诊断：三个真问题

### 问题 1：5 款是同一个东西（占 31%，1425 行）

`经典 / 字体 / 彩色 / 背景 / 渐变` 五款的模板骨架完全同构：

```
.page > text.clock + text.btn-color + div.mask > div.panel > text.p-item × N + text.p-cancel
```

差别只有"面板里换什么"：换字色 / 换字形 / 换配色 / 换背景 / 换渐变。四款换色加起来 20 套预设，
用户感知就是"同一块表盘换了几次颜色"，却占了目录 5 行、1425 行代码、5 套几乎重复的定时器与面板逻辑。

### 问题 2：护城河被埋在目录第 5 行

课程表盘是**唯一别人抄不走的东西**（依赖 `src/data/store.js` 的课程数据）。但它：

- 排在目录第 5 行，前面 4 行是换色和机械；
- 时钟 48px，**课名字号比时钟还小**，抬腕第一眼看到的是时间而不是"我现在上什么课"；
- 空档期只说"今日无课"，不说"下一节几点"；
- 有"剩余文字"却没有把"还剩多久"变成可视化的长度。

### 问题 3：机械系 5 款、3605 行，维护成本最高

`vibrate(1156) / gold(877) / random(639) / metal(511) / evpointer(422)` 五款都在画"刻度 + 三针"，
其中 vibrate 一款就占全项目 15% 的行数。四款的差异主要是表壳形状与配色，用户观感差异远小于代码差异。

## 三、先做减法（成本最低、收益最直接）

**动作**：目录页把 `经典 / 字体 / 背景 / 渐变` 四个入口收成 1 个「配饰表盘」，点击后进彩色表盘的
"模式切换"（字色 / 字形 / 背景 / 渐变 四页签，共 19 套预设）。

| 项 | 做法 | 风险 |
|---|---|---|
| 目录行 | 16 行 → **12 行**（一屏可见） | 无 |
| 路由 | `manifest.json` 里的 4 条**保留不删**（隐藏入口即可回滚） | 无 |
| 代码 | 只改 `watch-face-list.ux` 的入口行 + `watch-face-colorful.ux` 加页签 | 低 |
| 可逆性 | 4 个页面文件一行不改，随时恢复入口 | 可逆 |

先把入口收了，等新表盘验证成功再决定是否删文件——**不做一次性大重构**。

## 四、课程表盘（表盘目录里的瘦身版）

> **归属修正（2026-10-20 16:10）**：本节原写"课名 56px 当主角、时钟降到 30px"，
> 按 §九 的判据 1（谁的字最大谁是主角），那个版式**已经是课表首页、不是表盘**。
> 现修正为：①表盘目录里的课程表盘只做**瘦身版**（时间优先，课程压成一行）；
> ②"课名 56px + 宽 160 进度条"的设计稿**整段挪到更多首页**，作为第 8 种风格「课程大字」。
> 下面 §四 的原表格因此**同时是「课程大字」面板的施工图**，不要在表盘目录里实现它。

现状（670 行）已经有：时钟 + 阶段标（上课中/课间/午休）+ 当前课名 + 剩余文字 + 今日时间线 + 脚注。
方向不是重做，是**换主次**：让"我在上什么课、还剩多久"成为第一眼信息。

### 新版式（192×490）

| 区 | 内容 | 字号 | 说明 |
|---|---|---|---|
| 顶栏 | `08:15 周四` | 30 | 时钟降级为副信息，整分刷新 |
| 主区 | 课名（最多两行，每行 4–5 字） | **56** | 蓝色高亮，无课时显示"课间休息" |
| 进度 | 本节剩余进度条（满宽 160，高 8） | — | 纯色 div，`width` 数据绑定 |
| 次行 | `A301 · 第 3-4 节 · 剩 25 分` | 26 | 教室/节次/剩余合并成一行 |
| 底部 | `下一节 09:55 大学物理` | 22 | 永远给出"下一个动作"，没有"今日无课"这种死胡同 |

### 关键设计决定

1. **进度条不用 transform**：`width: {{ barW }}px`，从 0 到 160 线性映射本节已过比例。每 30s 刷新一次即可
   （1 秒刷毫无必要，反而费电）。
2. **"剩余"用相对量而非绝对时间**：`剩 25 分` 比 `至 08:40` 更符合抬腕场景。
3. **空档期三态**，不允许出现空白：
   - 课间 10 分钟 → `课间 · 距下一节 8 分`
   - 午休 → `午休 · 13:30 继续`
   - 全天结束 → `今天课已上完 · 明天 08:00 有课`
4. **无课日**（周末）→ 显示 `今天没课`，并给"明天第一节"。
5. 保留原时间线为**二级信息**（点击展开），不占主屏——现在它占了 40% 屏幕却只服务"查课表"这个低频动作。

### 验收

- 单测：三态判定（上课中/课间/课后）、无课日、跨天、进度条像素值（0 / 80 / 160）、定时器清理
- 实拍：上课中、课间、课后三种时刻各一张（可用假时钟喂数据）
- 回归：原时间线展开后仍可读，返回手势不被吞

## 五、两款新表盘提案（按性价比排序）

### P0 · 上课倒计时表盘

**解决**：上课前 30 分钟，抬腕只想知道"还剩几分钟"。
**版式**：150px 一个数字（剩余分钟）+ 下面 24px `分钟后上课` + 22px 课名。
**技术**：复用大字表盘的版式骨架（150px 两行已验证）；数据只读"下一节课的 start"；每分钟刷新。
**成本**：约 2 小时（含单测）。**风险**：低（无 transform、无 keyframes）。
**边界**：距下一节 > 12 小时显示"明天 08:00 有课"。

### P1 · 今日课表环

**解决**：一天的时间"用掉多少了"——时间线是列表，环是进度，抬腕一眼就懂。
**版式**：60 格环映射 08:00–20:00（每格 12 分钟）；已过=暗灰、当前=青绿、未到=深灰；
环心 `第 3 节` + `剩 2 节`。
**技术**：与动画表盘的 60 格秒环同一套坐标算法（`posOf(deg, size)` + `left/top` 绑定），
**纯色 div、零 transform**，已在本机验证过可渲染。
**成本**：约 3 小时。**风险**：中（节点数 60 + 60，需确认首帧耗时）。

### P2 · 考试/DDL 倒计时（暂缓）

目前 `store.js` 没有考试或作业数据源。**没有数据就不做**——先加"考试"数据模型，再上这款。
若要做，版式同"上课倒计时"，只是分母从"分钟"变成"天"。

## 六、机械系合并（唯一的重活，放最后）

| 动作 | 说明 |
|---|---|
| 保留 | `gold`（罗马刻度，最经典）、`metal`（仿古黄铜）、`evpointer`（十二时辰，有记忆点） |
| 合并 | `vibrate`（方形表壳）+ `random`（无框）→ 一款「现代机械」，表壳在页内切换 |
| 理由 | 两款的指针/刻度/走时逻辑本就是同一套，差异只在表壳与配色；合并可省约 800 行 |
| 风险 | **高**：两个文件各 1156 / 639 行，`transform` 用法密集，合并时容易碰"带文字节点必白屏"的坑 |
| 前置 | 必须先有机械系的像素级对照截图，合并后逐帧比对 |

| 批次 | 动作 | 成本 | 风险 | 验收 |

## 九、表盘目录 vs 更多首页：栏目边界

两个入口在设置页相邻，都在"换外观"，其中**课程表盘**和**更多首页的 7 种课表面板**做的是同一件事
（用不同版式展示当前课），这是当前唯一真实的重复。

### 一句话定位

> **表盘 = 时间的皮肤**（熄屏/抬腕层，时间为主）
> **更多首页 = 课程的仪表盘**（App 内首页，课程为主）

### 六维对照

| 维度 | 表盘目录（16 款） | 更多首页（7 种） |
|---|---|---|
| 载体 | 系统表盘层，**不打开 App 就能看见** | App 首页，必须先进入应用 |
| 使用时刻 | 抬腕 0.5 秒，扫一眼 | 打开应用 5–30 秒，查、点、翻周 |
| 主角 | **时间**：时钟必须存在且整屏最大 | **课程**：时钟可小、可无 |
| 回答的问题 | "几点？我是不是该上课了" | "今天上什么？这门剩多久？下一节在哪" |
| 交互 | 近零（轻触返回目录） | 可点课程进详情、可切周、可置顶 |
| 数量策略 | **少而精**，外观差异必须大 | 可以多，信息组织方式不同即可 |

### 三条判据（以后新增内容按这个卡）

1. **谁的字最大**：时钟最大 → 表盘；课名最大 → 课表首页。
2. **有没有"今天/本周结构"**：时间线、周视图、剩余节数 → 课表首页；只有"当前这一条" → 表盘。
3. **两者都想要时，做两个版本，不做折中版**——折中版两边都不像，现在的课程表盘就是折中版。

### 五步落地

| # | 动作 | 目录 | 成本 |
|---|---|---|---|
| 1 | 课程表盘**瘦身**：时钟回 52–56px 主位，课程压成一行 `现在 · 高数 · 剩 25 分`，不展开时间线 | 表盘目录 | 2 h |
| 2 | 把 §四 的「课名 56px + 进度条」做成**第 8 种风格「课程大字」** | 更多首页 | 3 h |
| 3 | `功能表盘`（电量/剩余空间）移出表盘目录 → **工具页** | 工具 | 0.5 h |
| 4 | 两栏互给入口：课程表盘底部 `看今日课表 ›` → 更多首页；更多首页顶部 `换表盘 ›` → 表盘目录 | 双向 | 1 h |
| 5 | 文案显性化：设置页 hint 改 `时间为主` / `课程为主 · 7 种` | 设置 | 0.2 h |

第 5 步零风险、当天可做；第 1–2 步是消除重复的实质动作；第 3、4 步是让用户不用回设置页二次决策。

## 十、结论

- 现有 **16 款 / 7467 行**，真正稀缺的是 **1 款**（课程表盘），冗余最重的是 **5 款换色**（1425 行）。
- 建议先"收入口"把目录从 16 行压到 12 行，再把课程表盘从"时钟为主"改成"课程为主"，
  然后补两款课程相关新表盘（倒计时 / 课表环），机械系合并在最后且允许放弃。
- 全程不引入 `transform` 旋转、不引入新的 `@keyframes`、不引入 `<scroll>`——这三样在本引擎上都踩过坑。
