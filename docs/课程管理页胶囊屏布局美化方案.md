# 课程管理页胶囊屏布局美化方案

> 适用页面：`src/pages/course-manager/course-manager.ux`（路由 `pages/course-manager`，栏目「课程管理」）
> 目标屏：小米手环 9 胶囊屏 **192×490**（兼容 pill-shaped / capsule 两种取值）
> 文档性质：实施方案（待评审 → 实施 → 模拟器验证 → 真机验收）

---

## 一、现状结构（胶囊屏当前渲染）

```
┌──────────────────────────────┐
│  [◀]   课程管理      (占位)   │  header ≈ 44px
├──────────────────────────────┤
│                 [+ 添加]     │  add-toolbar 48+4 = 52px  ← 右对齐，左侧整块空白
├──────────────────────────────┤
│  清除全部提示        [清除]   │  clear-bar ≈ 38+6 = 44px
├──────────────────────────────┤
│  ①  语文                     │  course-item（纵向两行）
│              [编辑] [删除]   │    行1: 序号30 + 课程名
│  ②  数学                     │    行2: 编辑56×48 + 删除56×48（右对齐）
│              [编辑] [删除]   │    单项 ≈ 106px + 8px 间距
│  ③  …（只能看到约 2.3 项）    │
└──────────────────────────────┘
```

**像素预算**（内容区 = 192−2×16 = 160 宽，490−30−56 = 404 高）：

| 区块 | 高度 |
|---|---|
| header | ≈ 44px |
| add-toolbar | 52px |
| clear-bar | 44px |
| **列表可视区** | **≈ 264px** |
| 单个课程项（两行） | ≈ 114px |

→ **一屏只能完整看到 2 个课程项、第 3 项露一半**，这是当前最大痛点。

---

## 二、问题清单（按严重程度排序）

### P1 竖向空间浪费：添加按钮独占一行
胶囊屏把「+ 添加」从 header 挪到了独立 `add-toolbar`（`justify-content: flex-end`），右侧 72px 按钮 + 左侧 ~80px 空白，整行 52px 只为一个按钮。

### P2 空态文案与实际不符
`暂无课程，点击右上角 + 添加` —— 胶囊屏上按钮根本不在右上角（在下方工具栏），新用户会被误导。

### P3 "编辑"按钮热区偏小
两行布局下"编辑"只有 **56×48**，紧贴"删除"（间距仅 10px），窄屏上极易误触删除。删除是危险操作，不应与编辑相邻等大。

### P4 样式重复定义
`.course-name` 在 502 行与 554 行**完全相同地定义了两次**（后续胶囊媒体查询只覆盖其中一处，维护时容易漏改）。

### P5 课程项视觉密度低
项内 padding `10px 12px` + 行间距 8px，序号徽章 30×30 与 22px 课程名比例失衡，第二行按钮右对齐后左侧大面积空白，视觉重心不稳。

---

## 三、方案设计

### 方案 A：纯样式收紧（改动面最小，仅动胶囊屏媒体查询块）

1. **合并工具行为一行**：删掉 `add-toolbar` 独立行，把「+ 添加」并入 `clear-bar` 改名 `toolbar-bar`，两端布局：
   ```
   清除全部(文字提示+清除)          [+ 添加]
   ```
   → 竖向省出 **52px**，列表可视区 264 → 316px。
   - 胶囊屏里 header 右侧的占位 `placeholder-cap` 保留（结构不动），非胶囊屏逻辑不变。
2. **课程项紧凑化**（仍两行）：
   - `padding: 10px 12px` → `8px 12px`；行间 `margin-top: 8px` → `6px`；
   - 单项 ≈ 114 → 106px；
   - 合计一屏可完整看到 **约 3 项**。
3. **修正空态文案**：改为按 `isCapsule` 切换——胶囊屏显示"暂无课程，点击上方 + 添加"。
4. **删除重复的 `.course-name` 定义**（保留一处）。

### 方案 B：交互热区重构（推荐，在 A 基础上追加）

遵循本项目红线「列表行 onclick 只放整行容器，行内子元素不绑 onclick」：

1. **点击整行 = 编辑**：`course-item` 容器绑 `onclick="startRename($idx)"`，热区从 56×48 扩大到 160×106，窄屏不再"点了没反应"。
2. **行内只保留一个「删除」**：
   - 默认态：第二行左侧显示课程名次行信息可留白，右侧单个红色「删除」按钮 72×48（热区更大）；
   - 二次确认态沿用现有 `deleteConfirmIndex` 逻辑（"再点确认"提示 + 按钮变确认色）；
   - 移除独立"编辑"按钮 → 每项少一个元素，视觉更干净。
3. **序号徽章弱化**：30×30 圆形 → 24×24，字号 20→18，让课程名成为视觉主体。
4. **删除按钮远离确认态**：确认态下"删除"变"确认"后整行高亮红边框（`border` 复用 `theme.deleteText`），强化危险语义。

### 两案对比

| | 方案 A | 方案 B |
|---|---|---|
| 改动范围 | 仅 `<style>` 胶囊块 + 文案 | A + 模板结构 + onclick 迁移 |
| 一屏可见项 | ~3 项 | ~3 项 |
| 误触删除风险 | 不变 | **显著下降**（删除独占、编辑是整行） |
| 回归风险 | 极低 | 中（需回归二次确认/撤销流程） |

**建议：先落地方案 A，真机确认后再评估 B。**

## 四、实施红线（必须遵守）

- 按钮/可点行高 **≥ 48px**（Vela 窄屏热区铁律）；
- 只改 `(shape: capsule), (shape: pill-shaped)` 媒体查询块，**不新增第二个同属性 capsule 块**（覆盖不稳定）；
- 根容器 padding 维持 `30px 16px 56px 16px`（底部 56px 为撤销条预留），不动非胶囊屏布局；
- 删除二次确认 + 5s 撤销逻辑**不得改动**（数据安全红线）；
- 所有颜色走 `theme.*`，不硬编码。

## 五、验证方案

1. **模拟器**（192×490，`xiaomi_band`）：
   - 构建 `npx aiot release --enable-jsc --start-page 'pages/course-manager'`，只推 `app.jsc` + `pages/course-manager/course-manager.jsc`；
   - 截图后用 `scripts/png-measure.js bands` 测量：工具行合并后按钮左右边距应对称 16px；课程项上下边界连续无重叠；
   - 用 `event` 注入或临时 start-page 直达验证滚动。
2. **单元级**：`deleteConfirmIndex` / `undoBackup` 相关纯函数逻辑若抽取过则跑单测；本次纯样式改动以模拟器为主。
3. **真机验收**（手环 9）：热区点击命中率、二次确认流程、撤销条遮挡。
4. **多屏回归**：圆屏（`shape: circle`）、矩形屏（`shape: rect`）各截图一张，确认未受影响。
