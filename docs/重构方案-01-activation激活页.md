## 二、病根：一页干了 7 件事

模板顺序（实测）：

```
1  header            返回 + 「高级版」
2  status-card       状态 / 有效期 / 版本 / 详情行
3  section-title     「激活软件」
4  step-card ①       购买兑换码      + 二维码
5  step-arrow ▼
6  step-card ②       下载同步器      + 二维码 + loading
7  step-card         不下载同步器？提示
8  step-arrow ▼
9  step-card ③       手工激活·获取激活码 + 设备ID + 二维码
10 step-header ④     手工激活·输入激活码
11 cells-grid        6 格码位
12 keypad            4 行 × 3 键
13 verify-btn        「验证」
14 result-box        验证结果
15 section-title     「激活历史」
16 history-list      历史条目 / 空态
17 section-title     「设备信息」
18 device-card       3 行设备信息
```

**7 类任务挤在一页**：查状态 / 买兑换码 / 下同步器 / 拿激活码 / 输激活码 / 看历史 / 看设备。

三者最致命：

1. **主任务被埋在第三屏**——用户来这页 90% 是想「输入激活码」，却要滚过 2 个二维码才看到键盘。
2. **键盘与码位是完整任务流，却和引导文案共处一页**——输入时操作区上方还压着 3 个二维码。
3. **3 个二维码全在首屏渲染**——`updateQrText` 要生成 3 张码，首屏成本与视觉噪音翻倍。

## 三、重构目标

一句话：**主任务（输入激活码）必须在一屏内可完成，其余任务各归其页。**

| 目标 | 判定 |
|---|---|
| 首屏无滚动即可看到「输入激活码」入口 | 截图验证 |
| 输入激活码全流程（码位 + 键盘 + 验证）在一屏内 | 截图验证 |
| 单页区块 ≤ 6 | 脚本统计 |
| 激活页首屏二维码数量 = 0 | 脚本统计 |
| 三维审计全绿（字号/热区/留白/余量） | `audit-hitbox.py --strict` |

## 四、拆法：1 页 → 4 页（按任务切）

### A. `activation`（主页面，保留路由）

```
[返回]  高级版
┌────────────────────────┐
│ ● 已激活 / 未激活       │   ← status-card 压到 2 行
│ 有效期至 2027-01-01     │      （版本号移到 info 页）
└────────────────────────┘
┌────────────────────────┐
│     输入激活码       →  │   ← 主按钮 168×56，首屏可见
└────────────────────────┘
┌────────────────────────┐
│     购买兑换码       →  │
└────────────────────────┘
┌────────────────────────┐
│     获取设备 ID      →  │
└────────────────────────┘
   激活历史 · 设备信息  →     ← 一行下拉入口（次级）
```

区块数：header + status + 4 入口 = **5**（达标 ≤6）。首屏 0 二维码。

### B. `activation-code`（新建）· 输入激活码

整段搬运：`cells-grid` + `keypad` + `verify-btn` + `result-box`。
**一屏内完成**。返回：验证成功后回 A 并刷新状态。

### C. `activation-guide`（新建）· 购买与获取

步骤 ① 购买兑换码（二维码）+ ② 下载同步器（二维码）+ ③ 获取激活码（设备 ID + 二维码）。
3 个 `step-card` 竖向排列，滚动承载。二维码**按需生成**（进页面才 `updateQrText`）。

### D. `activation-info`（新建）· 历史与设备

`history-list` + `device-card`。纯只读，长列表滚动。

## 六、验收标准

1. `python3 scripts/audit-hitbox.py --strict` → 0 命中，**四页均无命中**
2. 模拟器截图四张：主页首屏 / 输入码页 / 引导页 / 信息页，**首屏均无需滚动即见主操作**
3. 主页区块数 ≤ 6、首屏二维码 0 个（脚本统计 markup）
4. 激活码全流程走通：点 6 格 → 键盘输入 → 验证 → 回主页状态刷新
5. 构建产物 `jsc` 页数 = 现状 +3（**新增页不进 `router.pages` 会编译成空白**）

## 七、风险与对策

| 风险 | 对策 |
|---|---|
| 拆页后 `goBack` 错乱（子页返回应回主页而非设置） | 子页统一 `router.back()`；主页返回才回 `settings` |
| 二维码移到子页首次进入白屏等生成 | 子页 `onInit` 先渲染占位骨架，`updateQrText` 回调再替换（复用现有 `qr-loading`） |
| 新增 3 页导致产物体积/页数异常 | 构建后核对 `jsc` 数量（现 53 → 应 56） |
| 付费流程改坏 | 只搬 UI 与方法，不改校验逻辑；改完真机走一次全流程（未激活 → 输入码 → 已激活） |
