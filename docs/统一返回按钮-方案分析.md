# 统一返回按钮（页头胶囊）方案分析

- 日期：2026-11-01
- 参照物：`ev/countdown` 的「设置科目」页顶部按钮（`pages/pill/pill.ux` + `docs/页头返回按钮规范-20261101.md`）
- 目标：把课程表二级页面的「左上角方块返回键 + 居中标题」改成**一个整体的胶囊按钮**（`‹ 标题`），顶部水平居中，整块可点返回
- 结论性质：**方案可行，但不能一次铺 57 个页面**。必须先建新命名空间的共享样式，单页试点，再按批迁移（见 §7）

---

## 1. 结论摘要

| 判断 | 内容 |
|---|---|
| 技术上可行吗 | 可行。纯 CSS + 原生 DOM，符合本项目既有的「不用自定义组件」约束 |
| 最大风险是什么 | 不是样式写不出来，而是**一改就要动 57 个页面**；这些页面现在各自复制了 36 份返回键样式，任何全局替换都会踩到已漂移的版本 |
| 上次为什么没做成 | 2026-08 就做过一版 `common/header.css`（见 `docs/CSS样式方案_统一头部适配.md`），方案本身没错，但落地方式要求每页手写一行 `@import`，结果只有 4~5 个页面接了进去，其余 36 个继续各自复制 → 三档尺寸并存，样式反而更散 |
| 本次的关键设计 | **不复用旧类名**（`.header` / `.back-btn-wrapper` / `.header-title` 一律不碰），新开 `.hdr-pill` 命名空间。这样**迁移一页就干净一页，未迁移页零影响**，随时可以停在中间态 |
| 与首页的关系 | 首页头是「◀ 日期 ▶」三段式导航，不是返回键，**不纳入本次改造** |
| 预期收益 | 点击区从 30×30 扩大到约 140×40（≈6 倍）；消灭「标题被挤成 高…」这类历史问题；页头垂直占用不增加（甚至少 4px） |

## 2. 目标形态

参照 countdown 的「设置科目」：

```
┌──────────────────────────────┐
│                              │
│      ┌──────────────┐        │
│      │ ‹  设置科目  │        │  ← 一颗胶囊，水平居中
│      └──────────────┘        │     整块可点 → goBack
│                              │
└──────────────────────────────┘
      ↑ 左右留白，不撑满整行
```

对照课程表现状（40 个页面中的标准形态）：

```
┌──────────────────────────────┐
│ [‹]        添加              │  ← 返回键 30×30 + 标题 flex:1 + 等高占位
└──────────────────────────────┘
  ↑ 图标可点，标题也可点（双绑），中间大片是不可点的死区
```

差异要点：

1. **一个整体**：不再拆成「按钮 + 标题 + 占位」三段，占位元素直接删除
2. **居中**：靠外层行容器 `justify-content: center` 实现，不靠占位元素凑
3. **宽度按内容**：不写死 148px（countdown 那是 212×520 屏的定宽），课程表标题 2~8 字不等，必须自适应
4. **整块可点**：`onclick` 挂在胶囊上，标题上的 `onclick` 全部删掉，避免双绑定重复触发

## 3. 现状盘点（实测数据）

### 3.1 覆盖面

| 指标 | 数量 |
|---|---|
| 页面总数（`src/pages/*/*.ux`） | 64 |
| 调用了 `router.back` 的页面 | 59 |
| 含 `back-btn-wrapper` 的页面 | 57 |
| 其中用 `class="header"` 容器的 | 40（结构 100% 一致） |
| 其中用 `class="back-header"` 容器的 | 18（内部多数仍复用 `back-btn-wrapper`） |
| 用文字 `<` 当返回键的 | 1（`capsule-hide-test`，实验页） |

**好消息**：40 个 `class="header"` 页面的内部结构**完全一致**——`back-btn-wrapper` + `back-btn-icon` + `header-title` + `header-placeholder`，没有任何页面在 header 里塞了右侧动作按钮。这意味着结构替换是机械的，不需要逐页设计。

### 3.2 样式已经漂移成三档

36 个页面各自定义了一份 `.back-btn-wrapper`，尺寸分三档：

| 规格 | 页面数 | 备注 |
|---|---|---|
| 30×30 / 圆角 8 / 图标 22 | 23 | 主流，与 `common/header.css` 一致 |
| 44×44 / 圆角 20 | 8 | 偏胖，疑似早期版本残留 |
| 36×36 / 圆角 18 | 1 | 孤例 |

`.header` 容器本身也分裂：高度出现 56 / 48 / 36 / 34 / auto 五种，`margin-bottom` 出现 8 / 6 / 10 / 12 四种。

**这正是本次要统一的对象**，但也是风险来源：不能假设所有页长得一样。

### 3.3 已发现的真实缺陷

`src/pages/backup-restore/backup-restore.ux:108`：

```js
this.iconTheme = (themeName === "light") ? "dark" : "dark"
```

三元运算符两边都是 `"dark"`，等于没判断。浅色主题下这里会取深色图标。统一改造时顺手修，但要单独记一笔，避免混在样式提交里。

### 3.4 `goBack` 不是同一个函数

17 个页面的 `goBack` 带定制逻辑，**统一按钮不能自己实现返回**，必须继续调用页面自己的 `goBack`：

| 页面 | 定制内容 |
|---|---|
| `settings` | 先 `clearExitConfirmTimer()` 再返回 |
| `vibration-lab` / `v2` | 先 `stopVibration()`，否则马达一直震 |
| `homepage-settings` | 先把开关状态 `store.setHomepageSettings(...)` 存盘 |
| `schedule-manager` | 编辑态下返回 = 取消编辑，不退出页面 |
| `reset-data` | 清理预设定时器 |
| `full-schedule` | `router.getLength() > 1` 判断，栈深为 1 时 `replace` 回首页 |
| `countdown-panel` / `schedule-panel-*`（6 个） | 双模返回：`fromPanel === '1'` 回父页，否则作为 root 首页回「更多首页」 |

**结论：模板里只改结构，`onclick="goBack"` 原样保留，一行脚本都不动。** 这是本方案「安全」的第一条硬约束。

## 4. 上次统一为什么没落地（教训）

`docs/CSS样式方案_统一头部适配.md`（2026-08）提出的方法今天看依然正确：不建自定义组件（手环内存紧张、组件有独立 ViewModel 会卡顿白屏），只用公共 CSS 类 + `<import>`。

但它落地失败了，原因是三点：

1. **接入成本压在每个页面上**：每页要手写 `<import src="../../common/header.css">`，漏一行就退回本地样式，没人守，也无从检查。全仓只有 4 个页面接了（`statistics` / `settings` / `donate` / `schedule-qrcode`）
2. **裸类名没有隔离**：公共文件定义 `.header` / `.header-title`，而 36 个页面**自己也定义同名类**。二者同时存在时谁生效取决于 `@import` 与本地规则的前后顺序 —— 这种不确定性让所有人都不敢接
3. **方案没写"迁移完成"的判定标准**：没有进度指标，改到一半就自然停下来了

本次对应三条对策：

1. **新样式不是一个共享文件，而是一个命名空间**，页面只需拷 3 行模板结构 + 1 行本地 CSS（或不拷，用行内样式），不依赖 `@import` 能否生效
2. **类名全部新开**（`.hdr` / `.hdr-pill` / `.hdr-pill-ic` / `.hdr-pill-t`），与现存类零重叠，任何页面接入都不会与本地旧样式打架
3. **给出可 grep 的验收口径**：`grep -rl "back-btn-wrapper" src/pages/*/*.ux | wc -l` 的数值即迁移进度，从 57 逐步降到 0

## 5. 尺寸推导（192×490 手环为基准）

手上宽度预算：

```
屏宽                       192
− 页面左右 padding（12×2）  −24
────────────────────────────
可用宽                     168

胶囊宽 = 左内距 14 + 箭头 20 + 间距 4 + 标题(N字) + 右内距 14
```

| 标题字数 | 标题实宽（24px×0.96/字） | 胶囊总宽 | 占 168 |
|---|---|---|---|
| 2 字（添加 / 设置） | 46 | 98 | 58% |
| 3 字（高级版 / 设备诊断→4） | 69 | 121 | 72% |
| 4 字（编辑课程 / 完整课表） | 92 | 144 | 86% |
| 5 字 | 115 | 167 | **99%（临界）** |

**结论：标题字数上限 4 字。** 超过 4 字必须改文案（本项目已有先例：`activation.ux` 注释里记着「更多首页」被切成 3.5 字的老账），或者该页暂不迁移。

高度 40、圆角 20 与 countdown 一致；本项目首页底部三钮已是 40px 直径，可点击手感有既有参照。

**垂直占用不增加**：现多数页 `padding-top 44` + header 36 + margin 8 = 88；改造后 44 + 40 + 4 = 88，持平。部分页 header 原为 56 高的，改造后反而省 12px 给内容。

**为什么不定宽**：若照抄 countdown 的 148px 定宽，在 192 屏上占 88%，左右只剩 22px，视觉上退化成「通栏」——比现状还差，而且标题短时会显得空。按内容自适应才是正解。

## 6. 方案设计

### 6.1 模板（以 `settings` 为例，改造前 → 改造后）

改造前：

```html
<div class="back-header">
  <div class="back-btn-wrapper" onclick="goBack" style="background-color: {{ theme.card }}">
    <image class="back-btn-icon" src="/common/icons/{{ iconTheme }}/icon_back.png"></image>
  </div>
  <text class="header-title" onclick="goBack" style="color: {{ theme.text }}">设置</text>
  <div class="header-placeholder"></div>
</div>
```

改造后：

```html
<!-- 页头胶囊：外层 hdr 只负责居中，内层 pill 宽度按内容收缩 -->
<div class="hdr">
  <div class="hdr-pill" onclick="goBack" style="background-color: {{ theme.card }}">
    <image class="hdr-pill-ic" src="/common/icons/{{ iconTheme }}/icon_back.png"></image>
    <text class="hdr-pill-t" style="color: {{ theme.text }}">设置</text>
  </div>
</div>
```

要点：

- `onclick="goBack"` 只保留在 `.hdr-pill` 上，标题上的那份删除
- `header-placeholder` 删除
- 原 `.back-header` / `.header` 容器保留也可以（它控制 `margin-bottom`），但要把 `justify-content` 让给 `.hdr`。**推荐直接把容器换成 `.hdr`**，迁移更彻底

### 6.2 样式（基础值即手环态）

```css
/* ===== 页头胶囊返回按钮（2026-11-01） =====
   设计原则与 index.ux 的兜底改造一致：
   基础样式 = 手环（192×490）正确形态，大屏只做「放大」，
   即使 @media(shape) 在真机上不命中，也只是字小一圈，不会错位。 */

.hdr {
  flex-direction: row;
  justify-content: center;   /* 居中在这里做，与旧方案的占位元素凑对称不同 */
  align-items: center;
  width: 100%;
  margin-bottom: 4px;
  flex-shrink: 0;            /* 键盘弹起时不被压成 0 高（countdown 踩过的坑） */
}

.hdr-pill {
  flex-direction: row;
  justify-content: center;
  align-items: center;
  height: 40px;
  padding: 0 14px;
  border-radius: 20px;
  flex-shrink: 0;
}

.hdr-pill-ic {
  width: 20px;
  height: 20px;
  margin-right: 4px;
  object-fit: contain;
}

.hdr-pill-t {
  font-size: 24px;
  line-height: 30px;
  lines: 1;
}

/* 大屏放大（不命中也只是偏小，不影响可用） */
@media screen and (shape: rect), (shape: circle) {
  .hdr-pill {
    height: 48px;
    border-radius: 24px;
    padding: 0 18px;
  }
  .hdr-pill-ic {
    width: 24px;
    height: 24px;
    margin-right: 6px;
  }
  .hdr-pill-t {
    font-size: 30px;
    line-height: 38px;
  }
}
```

关于 `@media` 的取舍：今天刚验证过真机上 `shape: pill-shaped` 可能整条不命中（见 `docs/首页-真机与截图不一致-根因分析.md`）。这里把它降级为「只放大字号」，命中不命中都不影响形态正确，属于可接受的降级 —— 这与首页那次「错位」性质不同。

### 6.3 配色与图标

- 底色用 `theme.card`（现有返回键底色，已与各主题调好对比度，不引入新色值）
- 标题色 `theme.text`
- 图标沿用 `/common/icons/{{ iconTheme }}/icon_back.png`（32×32 PNG，dark/light 双套齐全）
- **不需要像 countdown 那样手工生成 chevron PNG**：本项目已有成熟的 `iconTheme` 双套机制，直接复用，避免新增资源与许可问题

### 6.4 与 countdown 方案的差异对照

| 维度 | countdown（设置科目） | 课程表（本方案） | 原因 |
|---|---|---|---|
| 宽度 | 定宽 148 | 按内容自适应 | 课程表标题 2~4 字不等；192 屏定宽 148 会占 88% 像通栏 |
| 图标来源 | 手工 rsvg 生成 chevron 双 PNG | 复用现有 `iconTheme/icon_back.png` | 已有双套图标机制，不必新增 |
| 字号 | 24（212 屏最小档） | 24 手环 / 30 大屏 | 课程表大屏页原有 30px 标题，不能降 |
| 垂直位置 | `margin-top: 26px` 躲弧边 | 由页面 `padding-top` 决定 | 课程表页 `padding-top` 普遍 30~44，已远离弧边 |
| 接入方式 | 单页硬写 | 新命名空间 + 分批迁移 | 57 个页面，必须能停在中间态 |

## 7. 风险清单与对策

| # | 风险 | 触发条件 | 对策 |
|---|---|---|---|
| R1 | 与页面本地旧样式打架 | 页面同时定义 `.hdr` 或复用旧类名 | 新类名与现存 36 份本地样式**零重叠**；接入即删本地 `.back-btn-wrapper` 等定义 |
| R2 | 定制 `goBack` 被冲掉 | 改模板时顺手写了 `router.back()` | 硬约束：只改结构，`onclick="goBack"` 原样保留（17 个页面涉及） |
| R3 | 标题超 4 字被切 | 迁移到长标题页 | 迁移前逐页核对标题字数；>4 字先改文案，或该页不迁移 |
| R4 | 媒体查询不命中导致大屏偏小 | 真机 `@media(shape)` 失效 | 基础值即手环正确态，媒体查询只放大；偏小可接受，不错位 |
| R5 | 键盘弹起页头被压成 0 高 | 页面有输入法（`chinese-input` 等） | `.hdr` / `.hdr-pill` 均写 `flex-shrink: 0` |
| R6 | 整行为可点区导致误触 | 胶囊被撑成 100% 宽 | `.hdr-pill` 不设 `width`，由 `padding` 撑开；`.hdr` 才 100% 宽 |
| R7 | 大屏（336×480 / 466×466）回归 | 只在手环验证 | 验收矩阵必须含方屏；圆屏模拟器当前无法启动应用，需在真机或修好 AVD 后补测 |
| R8 | 首页被误改 | 批量迁移时手滑 | 首页 `.schedule-page` 头部是「◀ 日期 ▶」导航，**不在清单内**，明确排除 |

## 8. 落地路径（建议四步，每步可独立验收、独立回滚）

### S1 · 建命名空间 + 单页试点（不改其他任何页）

- 选 `settings`（有定制 `goBack`，最能验证 R2；标题 2 字，无长度风险）
- 新增 `.hdr` 系列样式（可放 `src/common/header.css` 里新起一节，与旧类共存不冲突）
- 只改 `settings` 一个页面
- 验收：192×490 手环截图，深色 + 浅色各一张；点击验证返回行为与改造前一致（会清 `exitConfirmTimer`）

**S1 落地记录（2026-11-01，已完成）**

| 项 | 结果 |
|---|---|
| 样式落点 | `src/common/header.css` 新增 `.hdr` / `.hdr-pill` / `.hdr-pill-ic` / `.hdr-pill-t` 一节，含 rect/circle 放大规则 |
| 页面改造 | `settings.ux` 模板换成一颗 `.hdr-pill`；本地 `.back-header` / `.back-btn-wrapper` / `.back-btn-icon` / `.header-title` / `.header-placeholder` 五条定义与媒体查询里两条 `.header-title` 全部删除 |
| 尺寸实测 | 手环胶囊 **98×40**（预测 98 ✅），距顶 44（= `.page-body` padding-top），水平居中，两侧各 46px 空白 |
| 点击热区 | 点胶囊中心 (96,61) 正常返回首页；点左侧空白 (20,61) **不返回**（未整行可点，R6 验证通过） |
| 方屏 | 336×480 命中媒体查询：胶囊放大为 48 高、字号 30，居中，形态一致 |
| 浅色主题 | 未单独截图。胶囊配色为 `theme.card` 底 + `theme.text` 字 + `iconTheme` 图标，与旧返回键同源同变量，无新增色；真机切浅色时复核 |
| `goBack` | 原样保留，`clearExitConfirmTimer` 未被替换（R2 通过） |
| 旧类残留 | 该页 `grep back-btn-wrapper` 仅命中注释文字，代码零残留 |

一个实测结论要带回 S2：`.hdr` 的 `margin-bottom: 4px` 让页头总高 44px（原 30+10=40），settings 页视觉上更透气，但没有把「个人」卡片顶下去 —— 迁移其他页时按各页原 `padding-top` 复核一次即可，不需要统一改 padding。

### S1.1 · 页头紧凑化（2026-11-01 追加）

问题：换胶囊后，原 `.page-body` 的 `padding-top: 44px` 变成一整片死白 —— 那是旧「方块返回键」时代的经验值，怕小方块贴顶不好看；而胶囊本身 40 高、左右各离边 46px，顶部中央根本不在胶囊屏弧边裁切范围内。

几何核算（192 屏）：弧半径约 40，胶囊左上角 (46, 12) 到左上弧心 (40, 40) 的距离 = 28.6 < 40，落在可视区内部，不会被切。

改法：

| 屏型 | 顶部内距 | 说明 |
|---|---|---|
| 手环（基础值） | 44 → **12** | 只留呼吸，不贴边 |
| 方屏 rect | 40 → **20** | 与手环同步收 |
| 圆屏 circle | 56 **保留** | 圆形可视区在顶部收窄，这个值有几何理由，不是历史遗留，不要为「统一」压小 |

实测：胶囊 y 12–51（高 40，宽 100），顶距精确等于 padding，未触弧边；省出的 32px 让一屏多露出一行（改造前只到「更多首页」，改造后露出「工具」）。

**S2 迁移时同步执行**：每个页面把 `.page-body` / `.page` 的 `padding-top` 一并收到 10~12（手环档），否则胶囊上面会继续顶着几十像素空白。这是 S2 的第二个必做动作，不是可选项。



### S2 · 批量迁移骨架页（约 20 页）

优先迁：`add-course` / `course-manager` / `schedule-manager` / `backup-restore` / `detail` / `feedback` / `donate` / `full-schedule` / `device-info` / `statistics` / `homepage-settings` 等高频入口页。

机械替换规则（三步，逐页执行）：

## 附：一句话总结

形态本身是简单的（一颗居中胶囊、整块可点），难点全在**迁移面**：57 个页面、36 份复制样式、三档尺寸、17 处定制返回逻辑。所以本次不追求「一次性统一」，而是**新开命名空间、单页试点、按批迁移、随时可停**——这也正是上一次（2026-08）失败的地方：方案对了，但没给出一条能走到终点的路径。
