# 真机测试：编辑课程页黑屏重启分析

> **测试日期**：2026-10-04
> **测试设备**：手环 9（跑道屏/胶囊屏）、手环 10 Pro
> **测试版本**：基于 `cc181d0`（fix: 修复40个页面@media screen and导致手环9黑屏重启）

---

## 一、测试结果

| 页面 | 手环 9（跑道屏） | 手环 10 Pro |
|------|:---:|:---:|
| 首页（index） | 🟢 正常，不黑屏不重启 | 🟢 正常 |
| 编辑课程（detail） | 🔴 黑屏 + 重启 | 🟢 正常 |
| 实验编辑课程（lab-edit-course） | 🔴 黑屏 + 重启 | 🟢 正常 |
| 实验添加课程（lab-add-course） | 🔴 黑屏 + 重启 | 🟢 正常 |

**模式**：涉及"编辑/添加课程"的页面在手环 9 上统一黑屏重启，但首页和其他非课程编辑页正常。

---

## 二、CSS 是否为根因？——否

### 2.1 先澄清三个 CSS 相关事实

#### 事实 1：`@media screen and` 语法手环 9 完全支持

用测试页 `src/pages/media-test/media-test.ux` 实测：

| 测试项 | 语法 | 结果 |
|--------|------|:---:|
| 1 | `@media (shape: pill-shaped)` | 🟢 匹配 |
| 2 | `@media screen and (shape: pill-shaped)` | 🟢 匹配 |
| 5 | `@media screen and (width >= 100px)` | 🟢 匹配 |
| 7 | `@media (width >= 100px)` | 🟢 匹配 |

**`@media screen and` 不是黑屏原因**——此前将首页崩溃归因于 `@media screen and` 是误判。

#### 事实 2：逗号语法 `@media (shape: capsule), (shape: pill-shaped)` 不兼容手环 9

逗号分隔的媒体查询列表在快应用 CSS 引擎中**整体失效**，整条规则被忽略。

#### 事实 3：首页崩溃的真正原因不是 CSS

`cc181d0` 中修复首页的关键操作是**回退探针代码**（`onInit` 中的阻塞诊断逻辑），而不是 CSS 媒体查询改动。CSS 改动只是顺便修了逗号问题。

### 2.2 编辑课程页的 CSS 状态

当前三个编辑课程页的媒体查询状态：

| 文件 | 当前语法 | 手环 9 上是否生效 |
|------|------|:---:|
| `detail.ux` | `@media (shape: pill-shaped)` | 🟢 语法正确，应生效 |
| `lab-edit-course.ux` | `@media (shape: pill-shaped)` | 🟢 语法正确，应生效 |
| `lab-add-course.ux` | `@media (shape: pill-shaped)` | 🟢 语法正确，应生效 |

**对比首页**：

| 文件 | 当前语法 | 手环 9 上是否生效 |
|------|------|:---:|
| `index.ux` | `@media (shape: capsule), (shape: pill-shaped)` | 🔴 逗号导致整条失效 |

首页的胶囊屏样式其实是**失效的**（因为逗号），回退到了基础 fallback 样式，但**不黑屏不重启**。

编辑课程页的 CSS 语法完全正确，样式应该正常生效，但反而**黑屏重启**。

### 2.3 结论：CSS 不是根因

如果 CSS 格式是根因，那么：
- 首页（CSS 有问题/逗号）→ 应该黑屏 → 但实际**正常** ❌ 与假设矛盾
- 编辑课程（CSS 无问题）→ 应该正常 → 但实际**黑屏** ❌ 与假设矛盾

**CSS 媒体查询语法与黑屏重启之间没有因果关系。**

## 三、可能的真正原因

### 3.1 假设 A：编辑课程页的 JS 代码触发崩溃

- 首页崩溃被 `cc181d0` 通过**回退 JS 探针代码**修复，而非通过改 CSS
- 编辑课程页可能有类似的**重计算/重渲染逻辑**在手环 9 的 QuickJS 引擎上触发崩溃
- 对比：手环 10 Pro 性能更强，同样的代码不会崩溃

**排查方向**：回退编辑课程页最近的 JS 改动，二分法定位。

### 3.2 假设 B：某些 CSS 属性组合触发渲染引擎边界 bug

虽然媒体查询语法本身没问题，但 `.edit-course-page` 内的**某些 CSS 属性组合**可能触发 QuickJS CSS 引擎的 bug。

已知问题模式：
- `flex-direction: column` + `align-items` + 窄容器（160px）在某些版本可能有边界问题
- 嵌套 flex 层级过深可能触发渲染栈溢出

**排查方向**：对比首页和编辑课程页在 `@media (shape: pill-shaped)` 块内的 CSS 属性差异。

### 3.3 假设 C：页面组件加载链导致内存/栈溢出

编辑课程页比首页加载更多交互组件（stepper、picker、课程横滑条等），初始化时可能触发：
- 大量组件同时创建 → 内存峰值过高
- 组件生命周期钩子链式调用 → 调用栈过深
- `onInit` 中的同步数据操作阻塞渲染管线

**排查方向**：减少 `onInit` 中的同步操作，改为延迟/分帧加载。

---

## 四、下一步建议

1. **优先排查 JS**：在编辑课程页 `onInit` 中逐步注释代码，二分法定位崩溃点
2. **对比首页**：首页不崩溃，对比两者的 `onInit` 逻辑差异
3. **简化测试**：创建一个最小化的编辑课程页（只保留框架和基础 CSS），确认是否仍崩溃
4. **CSS 属性二分**：先在 `@media (shape: pill-shaped)` 块内清空所有样式，逐步加回，观察哪条属性触发崩溃
