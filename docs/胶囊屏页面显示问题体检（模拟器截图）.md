## 一、结论速览

| 项 | 结论 |
|---|---|
| 眼睛管用吗？ | **管用，但只能看"拍下来的那一帧"**。本次据此定位到 3 类真实观感问题（下节），同时**排除了 3 个假阳性**（见第五节）——说明它能用，但**必须配代码/尺寸复核**，否则容易误报 |
| 全项目"固定宽度溢出" | ✅ **干净**：192px 胶囊屏作用域内，**没有任何** `width/min-width` 超过内容宽度（50 个 `.ux` 全扫） |
| 本次发现的问题 | 集中在**输入法页**（键盘两侧裁切、候选面板压底边）与**首页纵向密度**（可视卡片仅约 1.5 张）；诊断页的截断问题**已随页面移除而消失** |
| ⚠️ 最大缺口 | 现有画面是 **212×520（手环10）与 336×480（Pro）**，**没有一张是 192×490（手环9）**；且只覆盖 **5 个页面**。所以本文结论对手环 9 只能算"**只会更紧**"的推断，需要一次采集（第六节给了照做清单） |

## 三、已发现的问题（有截图证据）

### 3.1 输入法键盘：左右两侧键位被屏边裁切 ⚠️

- 证据：`xiaomi_band_10-2026-09-25-22-34-09.png`（编辑昵称页，中文键盘，212×520）
- 现象：可见 `T Y U I / G H J / B N` 等键位，**左右两侧各有一列键位被屏幕边缘切掉**（只露出部分圆角键位），视觉上像"键盘比屏幕宽"
- 判定：**疑似缺陷，待复核**——可能原因：①该分支键盘按更宽屏设计，横向未自适应；②键盘支持横向滚动而当时停在中间位置
- 影响：最外侧列（Q/P、A/L 等）可能点不到或显示不全
- 注意：输入法组件 = 上游最新版逐字节零改动，如确认是缺陷，需**先查上游**是否有对应修复（本项目既有教训：先查上游 commit/diff）

### 3.2 输入法候选面板：下边缘压到胶囊屏底部圆弧区 ⚠️

- 证据：`xiaomi_band_10-2026-09-25-23-46-32.png`、`…-23-51-02.png`（编辑昵称页，候选面板「企 其 起 / 期 气 七 / 器 汽 奇」）
- 现象：候选面板底部**紧贴/进入屏幕底部圆弧与黑色区域**，最后一行候选几乎压边；键盘底部把手也在圆弧区
- 判定：**遮挡风险（贴边）**——胶囊屏上下是圆弧，肉眼可见"内容没有安全边距"
- 影响：末行候选在圆角区被视觉遮挡，且靠近边缘不易点

### 3.3 首页：纵向空间过挤，可视课程卡片仅约 1.5 张

- 证据：`xiaomi_band_10-2026-09-24-20-55-41.png`、`…-20-56-20.png`（212×520）
- 现象：从上到下依次是 日期行 → 左右箭头+星期 → 总/今/明 → 调休提示条 → 课程卡片…，**可视区只放得下约 1.5 张卡片**，第二张（「甘…」/「语文」）被列表容器下边缘裁切
- 判定：**这是列表容器的正常滚动裁切（不是遮挡）**，但**密度问题真实存在**：顶部 4~5 层 bar 挤占了专业列表空间，与既有分析 `docs/胶囊屏header布局与触控问题分析.md` 的结论一致（已知、未修）
- 影响：用户一屏看不到第二天/更多课程，需要频繁滚动

### 3.4 已随改动消失 / 不构成现行问题

| 现象 | 证据 | 现状 |
|---|---|---|
| 诊断页标题省略号截断（「第二轮·元…」）、正文截断（「v1.6.120 · pill-」「已通过：1,2,3,4,」） | `…-21-56-48.png`、`…-21-03-13.png`、`…-22-11-40.png` | 这些**输入法诊断/实验室页已从注册表中移除**（不随包发布）→ 不构成现行问题；但可作"宽度不足就截断"的取证样本 |
| rect 屏课程表管理页每行右侧仍有**三点按钮** | `xiaomi_band_pro-2026-09-27-11-46-16.png` | 今天已把 `.more-hit` 从模板与 CSS 全部删除 → **已消失** |
| 课程表管理页（胶囊屏）标题/行名/按钮 | `…-11-54-42.png`、`…-11-55-22.png` | **无截断、无遮挡**；面板 8 项内容完整（这页反而是当前的"健康样本"） |

## 四、静态尺子的结果（全项目）

| 检查 | 结果 |
|---|---|
| 胶囊屏块内 `width/min-width` > 内容宽度 | **0 处** ✅（50 个 `.ux`） |
| 全局 `width >= 200px` 的固定尺寸 | 4 处，**全部为假阳性**（见第五节） |

**解读**：本项目在"声明层面"没有明显的溢出/变形隐患，说明既往胶囊屏适配是做过工作的；剩下的问题更可能出现在**运行时表现**（键盘自适应、圆角安全区、密度），也就是**只有画面才能看到**的那一层——这正好说明"眼睛"的价值区间。

## 五、被排除的假阳性（方法论的收获，别踩第二次）

| 候选 | 表面结论 | 复核后 |
|---|---|---|
| 首页第二张卡片"被遮住一半" | 遮挡 ❌ | `.class-list { flex: 1 }` 是弹性分配，卡片只是**被滚动容器裁切**（正常机制）→ **不是缺陷**。教训：**"半截内容"要先分清"滚动裁切"还是"叠加遮挡"** |
| `welcome.ux .enter-btn { width: 220px }` | 溢出 192px ❌ | 胶囊屏块里已覆盖为 `width: 160px; max-width: 100%` ✅ |
| `detail.ux .course-card { width: 200px }` | 溢出 ❌ | 该规则在 `@media (shape: circle)` 块内（圆表 480px 用），胶囊屏另有定义 ✅ |
| `InputMethod.ux` 的 480/324px | 溢出 ❌ | 属于 **480px 圆表键盘分支**（`if screentype==='circle'` / `#full-keyboard`），且组件已有 `@media (min-width:230) and (max-width:235) and (shape:circle)` 专门适配 ✅ |
| `lab-edit-course.ux { width: 200px }` | 溢出 ❌ | 该页**未在 manifest 注册**，不随包发布 ✅ |

## 六、覆盖缺口与"采集清单"（补齐后即可出终版）

### 6.1 缺什么

- **分辨率不对**：手环 9 = **192×490**；现有画面 = 212×520（手环10）/ 336×480（Pro）。192 比 212 **窄 20px（-10%）、矮 30px** → 所有"贴边/裁切/密度"问题在 192 上**只会更紧**
- **页面太少**：只有 首页、编辑昵称（含键盘）、课程表管理（含面板）、两个诊断页 —— 全项目 30+ 页面里覆盖不到 1/5

### 6.2 采集清单（照做即可，约 5~10 分钟）

**第一步（关键）**：在 IDE 里启动 **192×490 的 `xiaomi_band`** 虚拟设备（本机已存在，`hw.lcd.width=192 / height=490 / shape=pill-shaped`），不要用 `xiaomi_band_10` 顶替。

**第二步**：按下面顺序截图，每页 1~2 张（文件名自带设备与时间，我按时间排序判读）：

| # | 页面 | 造数据要求（关键：要触发截断） |
|---|---|---|
| 1 | 首页（当日课表） | 课程名 6~8 个汉字、地点长（如"图书馆三楼西侧自习区"）、老师名长 |
| 2 | 首页 | 同一天排满 6 节课（看列表密度与滚动） |
| 3 | 总课表 / 周视图 | 三种模板各一张（极简/清爽/紧凑） |
| 4 | 课程表管理 | 课表名放到 8 个字（如"高等数学(下)"） |
| 5 | 课程表管理 → 面板 | 看 8 项按钮与「取消」是否贴底/被圆角切 |
| 6 | 课程管理（列表） | 长课程名 + 「编辑/删除」两按钮并存 |
| 7 | 添加课程 / 编辑课程 | 时间选择、地点输入框 |
| 8 | 编辑昵称 | 中文键盘 + 候选面板（本次问题集中区，重点） |
| 9 | 设置页 | 逐屏截全部设置项（含说明文字最长的那些） |
| 10 | 首页设置 / 主题设置 | 字号滑杆到最大（76）时的预览 |
| 11 | 统计页 | 课程数多、科目名长 |
| 12 | 导出二维码 | 长课表名 |
| 13 | 激活页 / 关于页 | 版本号长、说明段落 |
| 14 | 置顶管理 / 自定义内容 | 长标题 + 开关 |
| 15 | 假期与工作日信息 | 长节假日名 |

**第三步**：截完告诉我，我按"逐页 × 问题类型（截断/遮挡/贴边/变形/密度）"出一张终版体检表，并对每个问题给出**最小改动方案**。

## 七、体检结论的效力说明（务必一起读）

1. 本次 3 条问题里，**3.1 / 3.2 的截图来自 09-25 的旧构建**（v1.6.116~1.6.120），而输入法组件在 09-25 晚间换成了上游最新版 → **需在当前构建复核**；3.3 的首页布局结构未变，**大概率仍然存在**
2. **模拟器的"没问题"不能推出真机的"没问题"**（今天已被实证：模拟器点击正常 → 真机手环 9 打不开）；反之，模拟器看到的问题**通常是真的**（尤其是布局/裁切），但严重程度在 192px 真机上可能更重
3. 本项目的显示问题最终仍要在**手环 9 真机**上确认一遍，模拟器负责"提前发现 + 缩小范围"
