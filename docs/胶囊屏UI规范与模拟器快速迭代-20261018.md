# 胶囊屏 UI 规范与模拟器快速迭代（2026-10-18 实战总结）

> 来源：倒计时页「文字不截断 + 按钮热区 + 入口位置」两轮改造的实测记录。
> 用户当日两条明确指令：**① 编辑按钮热区加大；② 添加按钮移出头部，以后禁止头部标题加按钮**。
> 本文把这轮踩到的坑与提速方法固化下来，避免下次再从零试错。

---

## 1. 三句话结论

1. **手环 9 的头部只放「返回 + 标题」**，任何操作按钮、开关、图标都不准进头部（192 宽内容区只有 168，第三个控件必然出屏或被压成竖排）。
2. **Vela 会静默丢弃 `.父 .子` 后代选择器**——这是"改了 width 完全没反应"的真凶，不是缓存、不是打包、不是设备没刷。样式一律用单类选择器。
3. **一轮模拟器验收可以从 30 分钟压到 40 秒**：打包 20s 是天花板，其余全是冷启失败与人工往返，脚本里自动重试 + 同轮补拍即可消掉。

## 2. 胶囊屏头部铁律（用户指定，长期有效）

| 项 | 规定 |
|---|---|
| 允许出现 | 返回按钮（32×32）+ 标题（单行，20px） |
| 禁止出现 | 任何操作按钮 / 开关 / 多余图标 / 双行标题 |
| 新增与全局操作 | 下沉到**列表底部整行按钮**（168×44），随列表滚动，空态同样显示 |
| 空态文案 | 不再写"点击右上角添加"这类指向失效的引导 |

原因：192 屏扣掉 24 留白只剩 168，返回占 32、标题「倒数日」占 72，只剩 64 —— 放「添加」时按钮右半截被裁到屏外，同时标题被挤成两行。改前基线图见 `screenshots/倒计时-基线-改前-20261018.png`。

**判断口诀**：头部只要出现第三个控件，就一定出事。要么去掉，要么下沉。

## 3. 按钮与热区规范

### 3.1 尺寸

| 位置 | 尺寸 | 说明 |
|---|---|---|
| 列表卡片「编辑 / 删除」 | 72×40 | 卡片内容宽 152 = 72 + 8 + 72，热区相比旧版 68×28 **+51%** |
| 详情弹层「编辑 / 删除」 | 72×40 | 同基类，弹层内容宽 168，居中排 |
| ON / OFF 开关 | 52×28（列表）· 80×32（详情） | 旧 44×24 偏小，手指常点空 |
| 列表底部「+ 添加倒数日」 | 168×44 | 整行，圆角 22 |
| 返回按钮 | 32×32 | 保持 |

规律：**高度不低于 40，单侧宽度不低于 72**；两个按钮并排时按 `(可用宽 − 间距) / 2` 反算，别先定尺寸再硬塞。

### 3.2 必须 div + text，不能用 input

`input[type=button]` 在 Vela 里**宽度只跟文案走，`width` 写了也不生效**。实测把 `width` 从 68 改成 72，像素量出来始终是 40（两个字 + 内边距）。

```html
<!-- ✅ 宽高可控，onclick 一样能点 -->
<div class="action-btn edit-btn" onclick="startEdit(idx)" style="background-color: {{ theme.accent }}">
  <text class="btn-label" style="color: {{ theme.bg }}">编辑</text>
</div>
```

```css
.action-btn { width: 72px; height: 40px; border-radius: 20px;
              justify-content: center; align-items: center; }
.btn-label  { font-size: 20px; line-height: 24px; text-align: center; }
```

### 3.3 单类选择器（最省时间的规矩）

```css
/* ❌ 编译不报错，运行时静默失效 */
.cd-actions .edit-btn { width: 72px; }
.detail-actions .action-btn { width: 80px; }

/* ✅ 拆成单类，模板上直接挂 */
.action-btn { width: 72px; height: 40px; }
.del-btn { margin-left: 8px; }
```

排查口诀：**样式改了没反应 → 先看选择器里有没有空格**。同级选择器（`@media`）本身没问题，出问题的是"两个类名用空格连起来的后代写法"。

### 3.4 详情弹层

- 面板宽 **184**（屏宽 192 − 左右各 4），内容区 168，正好放 72 + 8 + 72。
- `justify-content: flex-start` + `padding-top` 定位，不要 flex 居中（会把底部操作排推出 490 屏）。
- 操作排拆两行：第一行编辑/删除，第二行开关。
- 遮罩层 `rgba(0,0,0,.6)` 在 Vela 上**看起来不生效**（背景卡片不变暗），功能不受影响，暂不追。

## 4. 模拟器迭代耗时实测（Vela / 手环 9 / 无头实例）

| 阶段 | 耗时 | 结论 |
|---|---|---|
| `aiot release --enable-jsc` | **14.8 – 22.7 s**（6 次取样） | 单项最大，但有上限，不是主要浪费 |
| `adb push` 整包 1.1 MB | 0.6 s | 基本免费 |
| `adb shell unzip` 269 个文件 | 3.2 s | 免费 |
| `adb push` app.jsc(75 KB) + 单页 jsc(22 KB) | **0.05 s** | 定向推送最划算 |
| 冷启 → 画面稳定 | 成功 11.4 / 27.6 / 27.9 / 32.3 s | 波动大，且**约一半会失败** |
| 失败早停（8 s 无画面 + 无 vapp 进程） | 8 – 16 s | 原来要等满 40–50 s |
| 滚动截图 + 拼长图（3 帧） | 7 – 8 s | 稳定 |
| **一轮完整验收（含打包）** | **38 – 42 s** | 无人值守，一次调用出一张长图 |

### 之前"改一下跑 30 分钟"的真实构成

不是打包慢，是四件事叠起来：

1. **冷启失败率高**（约 1/2），失败后我在对话层重新发一遍整条链 —— 每次多 50 s + 一次模型往返（往返本身比命令还贵）。
2. **保险起见整包重装**（push rpk → `mv pages pages_oldN` → unzip），多了 4 s，还引入"app.jsc 是新的、旧页面残留 → 启动即崩"的次生问题。
3. **每个状态单独冷启**：列表一次、详情一次、空态一次，等于 3 × 40 s。
4. **一次只改一个点**：按钮尺寸 + 入口位置 + 选择器三件事本该一轮验完，实际排了 5 轮。

### 提速四招（已落在 `tools/vela-loop.py`）

| 招 | 做法 | 省下 |
|---|---|---|
| `--retry N`（默认 2） | 冷启没出画就自己回收会话重来，不用回到对话层 | 每次失败 50 s → 10 s，且省一次往返 |
| 8 s 早停 | 3 次采样无画面变化且 `ps` 里没有 vapp → 立即判失败 | 失败损失 40 s → 10 s |
| `--tap x,y` | 截图循环后再点一次补拍（详情弹层这类要点击的状态） | 一次冷启（≈40 s） |
| 定向 push | 只推 `build/app.jsc` + 变更页的 `.jsc`，跳过 rpk/unzip | 3.8 s + 规避旧页面残留 |

```bash
# 日常一轮：打包 + 直达该页 + 滚 3 屏 + 顺便点开详情补拍
python3 tools/vela-loop.py --page countdown-manage --build --entry --scroll 3 --tap 96,150

# 已打过包，只重推 + 截图
python3 tools/vela-loop.py --page countdown-manage --scroll 2
```

## 5. 踩坑清单（本轮新增，都是"不报错但不对"）

| 现象 | 真因 | 处理 |
|---|---|---|
| 改了 `width: 68 → 72`，按钮纹丝不动 | `.cd-actions .edit-btn` 是后代选择器，被编译丢弃 | 改单类选择器 |
| 按钮文字竖排成「编/辑」 | 宽度实际只有 40（input 按文案自适应），又被我塞了高度 | 换 div + text，显式 width |
| `onInit` 里 `setTimeout(…, 1200)` 永远不触发 | Vela 页面里定时器不执行 | 放到数据回调里同步调用 |
| 点击卡片无反应，2 s 后 nz=0 | tap 只发 down/up 时 Vela 偶发不认这一下 | 中间补一个同点 move，按住 0.25 s |
| 冷启 47 s 超时、nz=0、`ps` 无 vapp | 保活会话与 `am stop` 打架 | 脚本内 kill 旧会话 + 重试 |
| 打包后首帧偶发全黑（nz=0） | 渲染管线未起 | 不能把 nz=0 当"出画"，必须重试 |
| 空态到有数据闪一帧 | `loadList` 异步 | 既有行为，已知不动 |

## 7. 复现命令

```bash
# 1. 打包（约 20 s）
cd ev/class-schedule && aiot release --enable-jsc

# 2. 一轮验证（约 40 s，产出 /tmp/vela-loop/countdown-manage-long.png）
cd ~/Documents/guomengtao && python3 tools/vela-loop.py --page countdown-manage --entry --scroll 3

# 3. 需要看详情：同轮补拍
python3 tools/vela-loop.py --page countdown-manage --entry --scroll 0 --tap 96,150

# 4. 模拟器起停（无头手环 9，端口 13000）
~/.vela/sdk/emulator/darwin-aarch64/emulator -vela -avd xiaomi_band \
  -no-window -no-audio -no-boot-anim -no-snapshot-save -port 13000 -qemu -smp 2 -semihosting
pkill -f "qemu-system-armel.*xiaomi_band.*-port 13000"
```

> 模拟器整包重装前务必 `mv pages pages_oldN` 再 unzip，否则新旧页面混装会启动即崩（老坑，见 §4 第 2 条）。
> 用定向 push 时反而不会踩这个坑 —— 只覆盖同名文件，没有残留。
