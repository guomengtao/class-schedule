## 一、一句话经验

> **模拟器的"眼睛"在 gRPC（`getScreenshot`），"手指"在模拟器控制台（`event mouse`）——两条通道都藏在"看起来像私有协议、其实只是没被认出来的标准协议"里。**

- 眼睛：`node scripts/emulator-eye.js shot <grpcPort> out.png`
- 手指：`node scripts/emulator-eye.js ctap <grpcPort> <lcdX> <lcdY>`（自动读 token + 自动加皮肤偏移）
- 拉起 App：`adb shell am start app/<包名>`（**不做这步会截到全黑**）

## 三、三个关键突破（每个都附"为什么之前没看出来"）

### ① 眼睛：模拟器内置 gRPC 控制服务

- **端口**：`gRPC = 控制台端口 + 3000`（`emulator-5554` → **8554**，`emulator-5556` → 8556）
- **服务**：`android.emulation.control.EmulatorController`
- **可用 RPC**：`getScreenshot` / `streamScreenshot` / `getStatus` /（`sendMouse`、`sendTouch` 等**存在但空实现**）
- **依赖零成本**：proto 与 `@grpc/grpc-js`、`@grpc/proto-loader` 都在 `node_modules/@aiot-toolkit/emulator/` 里，**不用装任何东西**

> ❓**为什么之前判错**：我连上 8554 后拿到一段服务端**主动先发**的二进制，第一反应是"这不是 RFB，是私有协议"，就放弃了。
> **教训：服务端先发的少量字节，先按"已知协议的前缀"去对号入座**——这里 `00 00 18 04` 正是 HTTP/2 SETTINGS 帧的头（length=24、type=4），一眼能认。

### ② 拉起 App：不做这步只能截到黑屏

```bash
ADB=node_modules/@aiot-toolkit/emulator/node_modules/@miwt/adb/bin/mac/adb
$ADB -s emulator-5554 shell am start app/com.application.watch.classschedule   # am <start|stop> <pkg>
# 等价： $ADB -s emulator-5554 shell vapp app/com.application.watch.classschedule
$ADB -s emulator-5554 shell ps | grep classschedule                            # 确认在跑
```

**判据**：截图**纯黑/极小体积**（1.5KB）＝ App 没在跑或屏幕没内容；正常首页约 **17~18KB**。

### ③ 手指：模拟器控制台 `event mouse`

```bash
T=$(cat ~/.emulator_console_auth_token)          # 控制台 token（文件权限 600）
( printf "auth $T\nevent mouse 178 439 0 1\nevent mouse 178 439 0 0\nquit\n"; sleep 3 ) | nc 127.0.0.1 5554
```

- **端口**：`控制台 = gRPC − 3000`（5554 / 5556）
- **语法**：`event mouse <x> <y> <device> <buttonstate>`（**必须 4 个整数**，`1`=按下，`0`=抬起）
- **坐标**：**皮肤窗口坐标** = `LCD + part2 偏移`；偏移读 `~/.vela/sdk/skins/builtin/<avd>/layout` 的 `part2 { name device; x N; y N }`
  - `xiaomi_band_10` = **(+30, +22)**（LCD 212×520 / 窗口 272×563）
  - `xiaomi_band` = **(+44, +154)**（LCD 192×490 / 窗口 281×820）
- **验证判据**（重要）：连点后**画面 md5 必须变化**；本次更强证据是键盘候选区从「阿企信书」相关变成了「**到 道 导**」——说明事件真的被 App 消费了

## 四、死路清单（写下来是为了以后别再走一遍）

| 死路 | 结论 | 判据 |
|---|---|---|
| `screencapture` 抓 IDE 窗口 | ❌ 无屏幕录制权限 | `could not create image from display` |
| 当成 VNC / 用 `aiot start --openVNC` | ❌ 不需要 | `emulator -help` 里**没有 `-vnc`**；5900 无监听 |
| gRPC `streamInputEvent` | ❌ 未实现 | **`12 UNIMPLEMENTED`**（最干脆的一句报错） |
| gRPC `sendMouse` / `sendTouch` | ❌ 返回成功但不生效 | 用"切换日期"做判据，前后截图 **md5 完全一致** |
| "坐标不对"的猜想（对 gRPC 而言） | ❌ 不是原因 | 按 `part2` 偏移试 6 个点，全部无变化 |
| "token 鉴权"的猜想 | ❌ 不是原因 | 读类 RPC 无 token 也通；`grpc.token` 在工具链里查无来源 |
| `/dev/utouch`、`/dev/input0` 直写 | ❌ 无可用实现 | 工具链与 IDE 扩展里**查无引用** |
| `--start-page` 绕开点击 | ⚠️ 可行但重 | 是**编译期**注入（`@aiot-toolkit/parser` 的 `startPage` 插件），每页一次构建 |

## 五、可复用方法论（下次遇到"黑盒通道"照这个顺序做）

1. **先看"谁已经在用它"**：IDE 是现成客户端。`grep -rli <关键字> ~/.aiot-ide/extensions/<相关扩展>/dist`、`node_modules/@aiot-toolkit/` —— 本次就是靠这一步从 "VNC 死路" 拐到 "gRPC 正路"。
2. **认领端口**：`lsof -nP -iTCP -sTCP:LISTEN | grep qemu`，注意**成对的端口**（5554/5556 控制台、8554/8556 gRPC、10055/10056 调试口、5555 adb）——`+3000` 是本模拟器的固定规律。
3. **认领协议**：把服务端先发的字节当"已知协议前缀"去对（HTTP/2 SETTINGS、RFB banner、gRPC 帧头），**别急着定义成私有协议**。
4. **最小可验证信号**：每次尝试都必须有一个"必然可见"的判据 ——
   - 截图类：文件大小 / md5
   - 点击类：选一个**操作必然改变画面**的目标（本项目的"切换日期箭头"最好用），比较前后 md5
   - 更强判据：找"只可能由输入产生"的副作用（键盘候选词变化）
5. **报错要读完**：`12 UNIMPLEMENTED` 一句就省掉后面十次瞎试。
6. **排除要成对**：怀疑坐标就扫坐标、怀疑鉴权就断鉴权、怀疑焦点就换拉法 —— 一次只否定一个变量。
7. **设备真身在文件里**：`~/.vela/vvd/<avd>.vvd/hardware-qemu.ini`（分辨率/屏型/密度）、`emu-launch-params.txt`（启动参数）、`skins/builtin/<avd>/layout`（皮肤偏移与圆角）。

## 六、命令速查（本次全部验证过）

```bash
# ---- 找设备与端口 ----
ps aux | grep qemu-system-armel | grep -v grep          # -avd <名字>、hostfwd 端口
lsof -nP -iTCP -sTCP:LISTEN | grep qemu                 # 5554/5556 控制台、8554/8556 gRPC
npx aiot getConnectedDevices

# ---- adb（NuttX NSH，不是 Android 那套）----
ADB=node_modules/@aiot-toolkit/emulator/node_modules/@miwt/adb/bin/mac/adb
$ADB devices -l
$ADB -s emulator-5554 shell am start app/com.application.watch.classschedule
$ADB -s emulator-5554 shell ps | grep classschedule
# 没有 wm / input / screencap / dumpsys（别浪费时间）

# ---- 眼睛（gRPC）----
node scripts/emulator-eye.js ports
node scripts/emulator-eye.js status 8554
node scripts/emulator-eye.js shot   8554 /tmp/x.png

# ---- 手指（控制台 event mouse，坐标自动加皮肤偏移）----
node scripts/emulator-eye.js ctap 8554 148 417                 # 点 LCD(148,417)
node scripts/emulator-eye.js cseq 8554 /tmp/out 40,64 148,417  # 逐点点击并各截一张

# ---- 规格反查 ----
grep -E 'hw.lcd.(width|height|shape|density)' ~/.vela/vvd/<avd>.vvd/hardware-qemu.ini
cat ~/.vela/sdk/skins/builtin/<avd>/layout                     # display 尺寸 + part2 偏移

# ---- 控制台 ----
T=$(cat ~/.emulator_console_auth_token)
( printf "auth $T\nhelp\nquit\n"; sleep 3 ) | nc 127.0.0.1 5554
```

## 八、教训（与项目既有红线呼应）

1. **"返回成功"≠"生效"**。必须找必然可见的判据；本次若只看 RPC 返回码，会误判成"输入已通"。
2. **别把不认识的协议当私有协议**。先对号入座已知帧头（本次就栽在 HTTP/2 SETTINGS 帧上）。
3. **报错信息是捷径**。`12 UNIMPLEMENTED`、`event mouse` 的 `KO: argument missing, try ...` 都直接给出了答案。
4. **同族不同尺寸不能互相背书**。212×520 的结论不能解释 192×490 的现象；**手环 9 必须用 `xiaomi_band`**。
5. **模拟器"通过"≠真机通过**（用户当天明确提醒）：同一份代码在 212×520 模拟器上点击正常，装到手环 9 真机却打不开。模拟器负责"提前发现、缩小范围"，**触摸命中/性能/机型差异只有真机说了算**。
6. **能自动化的先自动化**：单测毫秒级且能定位到函数（当天就是单测抓到 `openSheet` 越界静默失败）；模拟器截图负责画面类问题；两者覆盖层不重叠。
