# 临时调课

> 路由：pages/course-swap ｜ 源码：src/pages/course-swap/course-swap.ux

## 页面职责

手环端当场记录临时换课。中小学生不能带手机，老师在课堂上临时宣布「今天第二节调到明天第三节」时，学生点开对应课程、选另一节**已有**课程，两节课内容互换。只影响指定日期，基础周课表不改写，日期过后自动失效。

## 入口

首页点击某一节课 → `pages/detail` 编辑课程页 → 页头下方常驻「临时调课」按钮 → 本页。

## 界面结构（ev-six）

| 区块 | 内容 | 字号 |
|---|---|---|
| 头部 | 返回键 30×30 / 标题「调课」/ 占位 30×30 | 28 |
| 源课卡片 | 「这节课」+ 课名 +「今天 第2节」 | 24 / 28 / 24 |
| 日期切换 | 「今天」「明天」两个 tab | 24 |
| 提示行 | 「换到这节」或「已选 第3节」 | 24 |
| 候选列表 | 每行「第N节」+ 课名，仅列已有课程 | 24 / 28 |
| 底部 | 「确认换课」按钮，「撤销调课」 | 28 / 24 |

全页只用 28 / 24 两档字号，行高 38 / 34；页面左右 padding 12px、卡片左右 8px；无禁用符号、无徽标、无行内箭头。

## 核心方法

- `onInit()` 读取 `detail_classId` / `detail_dateStr` / `detail_period`，再载入基础课表与覆盖表。
- `setTab(i)` 切换今天 / 明天的候选列表，跨天选中态保留。
- `pickCourse(key)` 选中目标课，同一列表内单选。
- `confirmSwap()` 调用 `courseSwap.applySwap()`，一次写盘生成两条覆盖记录，提示后回首页。
- `clearSwaps()` 清掉今天与明天的覆盖，用于撤销。

## 数据字段

存储键 `course_swap_data`（`@system.storage`），结构与 `holiday_data` 同为「按日期索引」：

```
{
  "2026-11-09": {
    "<courseId>": { "name", "teacher", "location", "from", "fromId", "group" }
  }
}
```

- `name/teacher/location`：该格位当天实际显示的内容，来自交换的另一节课。
- `time` / `id` / 节次属于格位，不覆盖，避免跨节次时间串位。
- `group`：一次交换的两条记录共享同一 groupId，用于整次撤销。
- `from/fromId`：记录内容来自哪一天的哪一节，便于排查与回滚。

## 注意事项

- 只允许已有课程互换，页面不提供新增课程入口；晚课虚拟条目（`_rotation`）从候选中排除。
- 基础课表 `schedule` 始终只读；`class-list.js` 的 `loadDayClasses` 按日期装载时合并覆盖。
- 覆盖读取是异步的，列表先渲染基础课表再补刷一次，属预期行为。
- 调休（`holiday_data`）与临时调课叠加时，先按调休换日、再按日期应用格位覆盖；调休换日后的格位覆盖以绝对日期为准。
- 已调过课的格位再次参与调课时，以当前显示内容为准（`build` 会先合并已有覆盖）。
- 候选范围固定为今天与明天，符合「课堂上临时宣布」的场景；不提供跨周选择。

## 实测结论

- 构建：`npm run build:dev` 通过，产出 `com.application.watch.classschedule.debug.1.9.147.rpk`（8095ms）。
- ev-six 源码扫描：禁用符号 0 命中、小于 24px 字号 0 命中；全页字号 28 / 24，行高 38 / 34，页面 padding 12px、卡片 8px，头部三要素齐备。**ev-six：通过**。
- 数据层：`applySwap` 一次写盘生成两条共享 group 的覆盖记录；`clearDates` 同时清今天与明天，避免跨天交换只清一半。
- 已知限制：覆盖读取是异步的，首页先显示基础课表再补刷一次；周视图 / 全课表 / 表盘按星期渲染，不体现临时调课，属预期边界。
- 构建期既有告警（非本页引入）：`index/modules` 里 `require("../../data/utils.js")` 解析不到，以及若干历史页面的属性告警。
- 截图验收（ev-shapes，未完成）：已打通 release 全量包（297 条目 / pages 129 / 含 course-swap）、EvFleet 票据 `T-000041`、两屏实例启动与部署、`page --start-page pages/course-swap` 构建成功。但多会话并发导致 adb server 5037 双 daemon 竞争启动失败、`adb devices` 恒空、5 台实例全判僵，帧缓冲持续「显示未激活」。两张纯黑假图已按纪律删除，票据与实例已归还，**未产出验收图**。
- 重跑前置：单会话独占模拟器且 `adb devices` 能列出设备；应用驻留优先用 `vela up --rpk`，避免 `page` 的 pipe 会话结束即退导致黑屏。
