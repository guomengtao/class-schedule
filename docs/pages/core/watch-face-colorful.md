## 功能说明

表盘栏目第 2 条。以「色块构成」为视觉母题的时钟表盘：文字每位一色（原设计保留），外加三层几何色块——屏顶四段色标、每位数字下方同色 chip、秒数 5 段离散方格。提供 4 套配色（糖果 / 霓虹 / 马卡龙 / 冷色），选择写入 `storage`（key `wf_colorful_palette`，与旧版同名，老用户设置继续生效）。

与旧版的差别：旧版只有 `HH:MM` + 两个按钮（内容带 3 段，文字占屏 18.6%），本版重做为 7 段信息层级 + 三处色块结构 + 12 秒跳格的秒表达。

**与渐变表盘的分工**（同栏目相邻两块，必须能一眼区分）：

| | 渐变 `watch-face-gradient` | 彩色 `watch-face-colorful` |
|---|---|---|
| 母题 | 色彩**流动** | 色块**构成** |
| 背景 | 48 条色带连续插值、上亮下暗 | 纯深底，不铺垫任何渐变 |
| 秒 | **连续**进度条（宽度 = 秒/60） | **离散** 5 段方格（12 秒跳一格） |
| 面板 | 文字列表 | **色卡**（色块 + 名称） |

## 实现要点

### 1. 顶部通栏色标被胶囊屏裁掉（实测，不要再做通栏）

首版把色标做成**通栏贴顶**（48×4 = 192，`position: absolute; top: 0`）。截图实测：`y=3` 这一行，x=20 / 70 / 170 采样全是 `(0,0,0)`，只有 x=120（屏心）有颜色——**胶囊圆角把整条吃掉，只剩中间约 30px**。

改成**排版流内居中**（40×4 = 160），彻底避开圆角，且参与布局不再依赖绝对定位层。

结论：胶囊屏的顶部/底部约 96px（≈屏宽一半，即圆角半径）不可用作"贴边"设计，任何通栏元素都不能贴顶或贴底。

### 2. 色标不刷新：不是渲染问题，是回调没回来（诊断过程值得记）

现象：首版色标一直是首帧暗色 `#2a2438`，而数字颜色、秒格亮色都正常。

- 第一次判断：以为是「数组整体替换不触发重渲染」，改成 `cap0..cap3` 四个显式字段 → **仍然不变**
- 第二次判断：既然显式字段也不变，说明不是渲染层，而是 **`applyPalette` 压根没在首帧执行**
  （数字正常是因为 data 里的初始值本身就是「糖果」配色，看着像执行了；秒格亮格是 `tick()` 用默认 `segOn` 画的，也看不出差别）

根因：`storage.get` 的 `success/fail` 回调在本环境首帧不稳，`applyPalette` 悬空。修复：

```js
loadPalette() {
  const self = this
  this.applyPalette(0)   // 先同步落默认，首帧就有确定画面
  try { storage.get({ ... }) } catch (e) { this.applyPalette(0) }
}
```

并在 `onShow()` 里再读一次（回页能跟上别处改动）。

顺带确认：`for` + `$item` 绑 `background-color` 的**数组整体替换是可用的**——换配色后色标四段确实跟着变了（霓虹实测采样 `(189,8,115)` / `(8,165,189)` / `(8,186,106)` / `(189,80,8)`）。

### 3. 秒为什么用 5 段方格而不是进度条

与渐变表盘刻意错开母题。语义：每 12 秒亮一格，`lit = min(5, floor(sec/12) + 1)`，整分钟回到 1 格。

同样用「先对齐整秒再起 interval」：

```js
this.alignTimer = setTimeout(function(){ self.tick(); self.timer = setInterval(...) }, 1000 - (Date.now() % 1000))
```

不对齐会让跳格时刻在 12 秒边界前后乱飘。

### 4. 双屏分支

```js
device.getInfo → screenWidth >= 300 → wide = true
模板：if="{{ !wide }}" 192 版式 / if="{{ wide }}" 宽屏版式
```

| 项 | 192×490 | 336×480 |
|---|---|---|
| 主时间 | 60px（原值未动） | 104px |
| 冒号 | 54px / margin 0 2px | 96px / margin 0 6px |
| chip | 14×4 | 20×6 |
| 色标 | 4 段 × 40（总 168 含间隔） | 4 段 × 65（总 272 含间隔） |
| 秒格 | 5 × 24×6 | 5 × 44×8 |
| 面板 | 240 宽 | 284 宽 |
| 可读文字 | 24px | 28px |

104px 沿用 landscape / gradient 的最坏字宽反算：`4×0.6×104 + 0.35×96 + 6×4 ≈ 308 ≤ 316`，116px 会到 343 溢出。实测两侧留白 28 / 26px。

### 5. ev-six 合规

- 可读文字 24（192）/ 28（宽屏），24 为绝对下限；旧版 22px 已全部抬到 24
- 主时间 60 / 104px 属「表盘图形本体」，豁免 24/28/30/44 四档，样式注释写明理由
- 分隔用 1px 竖线，不用 `|` `/` 符号（第 5 条）

## 已知问题

1. **存储持久化未能在模拟器闭环验证**：`page` 命令每次都会重推 rpk 并重新解压应用目录，等于清空应用存储，所以"选好霓虹 → 重进页面"必然回到默认。真机不受此影响。已用「先落默认 + 回调覆盖 + `onShow` 重读」把首帧与回页行为做成确定路径。
2. **冒号在 96px 档退化成两个小方块**：该字体冒号在超大字号下字形偏小，与数字的视觉重量不匹配（渐变表盘同款现象）。若要修，只能把冒号拆成两个 4×4 方块自行绘制，本次未做。
3. **秒格整分钟会从 5 格跳回 1 格**：语义正确（59 秒满格 → 00 秒重新开始），但若后续想要"更顺"的表现，需要在过分钟时做一次性衰减动画，本次未做。
