## 功能说明

表盘栏目第 3 条。以「渐变色带」为视觉母题的时钟表盘：整页背景由 24/48 条色带纵向渐变铺成，主时间 5 个字符取自同一条色带的 5 个位置，底部一根秒进度条按秒推进。提供 4 套色带（晚霞 / 海洋 / 森林 / 极光）可切换，选择写入 `storage`（key `wf_gradient_theme`）持久化。

与旧版的差别：旧版只给 5 个字符各绑一个色值、背景纯色、无日期无秒，内容占屏仅 18%；本版重做为三层排版 + 背景渐变 + 秒级动效。

## 界面结构

```
背景层   48 条横向色带（纵向堆叠，上亮下暗）
EV       品牌行            24px（宽屏 28px）
时间     H H : M M         60px（宽屏 104px）五档渐变色
日期     10-25 周日         24px（宽屏 28px）
进度条   4px（宽屏 6px）    宽度 = 秒/60 × 满格宽
渐变 │ 返回                 24px（宽屏 28px），1px 竖线分隔
```

## 交互流程

| 操作 | 结果 |
|---|---|
| 点击「渐变」 | 弹出色带面板（4 套 + 取消），`suppressTap` 挡住整页返回 |
| 点面板外区域 | 关闭面板，300ms 后恢复整页点击 |
| 点色带名 | 应用色带 + 写 storage + 关面板 |
| 点「返回」/ 页面空白 | `router.replace` 回 `pages/watch-face-list` |

## 实现要点

### 1. 渐变怎么画（探针实测结论，重要）

`linear-gradient` 在本项目 **不可用**。实测方法：同页放两个 90×100 的 div，左侧 `background-color: #ff3b30`、右侧 `background-image: linear-gradient(to bottom, #ff3b30, #0a84ff)`，构建截图 → 左侧正常显示红色方块，右侧**完全无渲染**（露出页面底色）。

替代方案：**色带分层法**。

- 色带数量 `BAR_N = 48`，每条高 11px（48×11 = 528 ≥ 两屏屏高 490/480，末条溢出被裁）
- 颜色沿 7 锚点色带线性插值，叠加"上亮下暗"梯度：顶部主色 36% → 底部 14%（与深底 `#12111c` 混合）
- 48 条时每步色差 < 8 RGB，肉眼已是连续渐变；24 条时（每步 ~15 RGB）顶部亮区仍能看出横向分界

为什么必须"上亮下暗"：纯色相变化（亮度恒定）在深底上只看得出"换了个色调"，加亮度梯度后才有光从上方打下来的方向感。

### 2. 两个实测踩到的坑

| 坑 | 现象 | 处理 |
|---|---|---|
| **Vela 的 div 默认是 row** | 12 条色带被横向挤成顶部一条（宽 16px、高 42px，像一条彩色标题条） | `.bg` 必须显式 `flex-direction: column` |
| **百分比高度不可靠** | `height: 8.4%` 在绝对定位层里算不准 | 改固定 `height: 11px` |

### 3. `for` + `$item` 可绑 style（已实测）

```html
<div for="{{ bars }}" class="bg-bar" style="background-color: {{ $item }}"></div>
```

数组整体替换（`this.bars = out`）会整段重建，比逐条赋值 `b0..b47` 更省代码，也避免漏项。
（对比：`watch-face-flip` 里曾遇到"动态属性名不被 Vela 观测"，所以那里用显式分支赋值；这里是 `for` 直接绑 `$item`，不是动态属性名，可正常工作。）

### 4. 双屏分支

```js
device.getInfo → screenWidth >= 300 → wide = true
模板：<text if="{{ !wide }}"> 192 版式 / <text if="{{ wide }}"> 宽屏版式
```

| 项 | 192×490 | 336×480 |
|---|---|---|
| 主时间 | 60px（原值未动） | 104px |
| 冒号 | 54px / margin 0 2px | 96px / margin 0 6px |
| 品牌行 | 24px | 28px |
| 日期 | 24px | 28px |
| 进度条 | 140px × 4px | 288px × 6px |
| 按钮 | 24px，同排 | 28px，同排 |
| 面板 | 240 宽（被父级约束为 ~176 实际渲染） | 284 宽 |

**104px 的来历**（沿用 landscape 最坏字宽反算）：

- 116px：`4×0.6×116 + 0.35×116 + 6×4 ≈ 343 > 316` ❌ 溢出
- 104px：`4×0.6×104 + 0.35×96 + 6×4 ≈ 308 ≤ 316` ✅ 实测两侧留白 40 / 46px

### 5. 秒进度条

- `barW = round(秒 / 60 × maxBar)`，`maxBar` = 140（192）/ 288（宽屏，在 `fitScreen` 回调里改）
- 先 `setTimeout(1000 - now%1000)` 对齐整秒，再起 `setInterval(1000)` —— 不对齐会看出"忽快忽慢"
- 宽度用 `style="width: {{ barW }}px"` 绑定，与翻页表盘 `top: {{ p0 }}px` 同一手法，已在实机验证

### 6. ev-six 合规

- 可读文字统一 24px（192）/ 28px（宽屏），24 为绝对下限。旧版的 22px 全部抬到 24
- 主时间 60 / 104px 属「表盘图形本体」，不套 24/28/30/44 四档（套 44 就不是表盘了），样式注释已写明豁免理由
- 分隔用 1px 竖线 + 间距，不用 `|` `/` 等符号（第 5 条）

## 已知问题

1. **顶部亮区仍有轻微横向分界**（截图放大可见，1.8 寸屏实看不明显）：48 条 → 每步 ΔRGB <8，PNG 量化后仍留极淡条纹。若后续要做更平滑，只能加条数（96 条，5.5px/条），代价是节点数翻倍。
2. **背景色带层会吞点击**：`.bg` 是满屏绝对定位层，已在它身上也挂 `onclick="onTap"`，否则点空白不返回。注意 `.bg` 与内容层是兄弟关系，内容层按钮的点击不会冒泡到 `.bg`，无副作用。
3. **数字未做等宽处理**：`1` 比 `2` 窄，分钟变化时整行宽度会轻微抖动（大屏更明显）。landscape 表盘注释明确"位宽不写死"，此处沿用，未设固定 width。
4. **小屏面板宽度被父级压缩**：设 240px，实际渲染约 176px（`width:100%` 的 mask 约束）。视觉上仍居中留边，未溢出，故未强改。
