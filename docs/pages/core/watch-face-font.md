# watch-face-font · 字体表盘（九变体）

> 路由 `pages/watch-face-font` · 栏目「表盘」字体表盘
> 双屏适配方案： [`docs/WatchFace-字体表盘-双屏适配方案.md`](../../WatchFace-字体表盘-双屏适配方案.md)

## 1. 职责

同一页面演示 9 种**纯排版**风格的表盘，靠 `切换样式` 循环、`wf_font_style` 持久化。本页不含表壳、刻度、背景图形 —— 全部是文字块 + flex 居中，所以它是 16 块表盘里唯一「按字号分档」而不是「按几何缩放」适配的一块。

| # | 变体 | 主体 | 特征 |
|---|---|---|---|
| 0 | 巨型加粗 | `.d-clock` 单 text "88:88" | 68px bold，`letter-spacing: 4` |
| 1 | 等宽数码 | `.dgt-mono`×4 + `.colon-blink` | monospace，冒号 `kf-blink` 呼吸 |
| 2 | 逐字渐变 | `.digit`×4 + `.colon` | 五点内联 `color` |
| 3 | 错落双行 | `.st-h` / `.st-m` | 上 H 108px、下 M 60px，字距拉开 |
| 4 | 细边描签 | `.thin-t` | 弱对比 `#8a93a6` + 大字距 |
| 5 | 等宽秒带 | `.m-time` + `.m-track` / `.m-bar` | 秒进度 `secPct` 动态 `width` |
| 6 | 翻页滚动 | `.col`×4（scroll）+ `.di`×40 | `scrolltop` 按行高滚动 |
| 7 | 横铺跑道 | `.rot` > `.line` > `.d` / `.colon` | `rotate(-90deg)`，**唯一绝对定位** |
| 8 | 分色跳动 | `.digit`×4 + `.colon-blink` | 逐字彩色 + 冒号动画 |

轻触页面 = 返回列表；点「切换样式」时用 `suppressTap` 拦掉一次冒泡（150ms），否则会直接退出。

## 2. 双屏适配：为什么不用 scale

| 候选 | 否决原因 |
|---|---|
| 整体 `transform: scale(1.75)`（前两块的做法） | ① 480px 高 **比 490 还矮**，等比放大纵向必溢出；② 前两块缩放的是图形，本页是文字 —— 位图缩放会发虚 |
| 逐元素宽屏单类（采用） | 文字按 px 重排 = 原生清晰；不动结构 = 不动 40 个 `.di` 的 `for` |

模式：`fitScreen()` 异步探针 → `if (w < 300) return` → 否则填 15 个类名 + 2 个尺寸。

## 3. 宽屏数值表

判定线：横向占宽 ≤ 296px（两侧各留 ≥20px）。字宽模型 Roboto 类：数字 0.5686em、等宽 0.60em、冒号 0.2727em。

| 元素 | 192×490 | 336×480 | 宽屏类 | 占宽验算 |
|---|---|---|---|---|
| `.d-clock` | 68 / ls4 | **96 / ls6** | `.w-big` | ≈280 ✅ |
| `.dgt-mono` | 48 | 72 | `.w-mono` | 173 ✅ |
| `.colon-blink` | 44 / m0 4 | 66 / m0 6 | `.w-blink` | — |
| `.digit` | 60 | 90 | `.w-digit` | ≈229 ✅ |
| `.colon`（仅变体 2） | 44 | 66 | `.w-colon` | — |
| `.st-h` / `.st-m` | 72 ls8 / 40 ls12 mt8 | 108 ls12 / 60 ls18 mt12 | `.w-sth` / `.w-stm` | 147 / 104 ✅ |
| `.thin-t` | 64 / ls6 | 96 / ls8 | `.w-thin` | ≈290 ✅ |
| `.m-time` / `.m-track` | 52 mb18 / 宽 90 | 78 mb26 / 宽 156 | `.w-mtime` / `.w-track` | 234 ✅ |
| `.col` / `.di` / `.c` | 26×56 · 40 · lh56 | 44×84 · 56 · lh84 | `.w-col` / `.w-di` / `.w-c` | 4×44+30 ≈206 ✅ |
| `.rot` origin | 96, 245 | **168, 240** | `.w-rot` | 旋转后横长 ≈309 ✅ |
| `.btn-switch` | 24 / mt40 | 28 / mt52 | `.w-btn` | — |
| `.back` | 22 → **24** | 24 | 无（全局改） | 22 < 24 下限 |

**两处刻意不按 1.5 倍：**

1. **变体 0 / 4 只 1.41×**（68→96）。它们是单个 `text` 连写含冒号，1.5×（102px）占宽 296+ 擦线；96px 留 28px 余量，与 108px 的双行 H 仍同一量级。
2. **变体 7 完全不放大**。`.line` 是 4 字 × lh64 + 冒号 ≈ 309px 高的竖列，`rotate(-90deg)` 后横长就是 309 —— 192 屏上本来就在溢出（两侧各切 ~58，这是"跑道"的设计意图），放到 336 屏刚好余 13px。**不放大反而是正确解**，只需把原点搬到屏心。

## 4. 两个 JS 常量必须跟着 CSS 走

这是本页唯一的算法耦合，改 CSS 尺寸时**必须同改 JS**：

| 常量 | 192 | 336 | 耦合对象 |
|---|---|---|---|
| `data.rowH`（初值 `ITEM_H=56`） | 56 | 84 | `.w-di { line-height: 84px }`、`.w-col { height: 84px }` |
| `data.trackW`（初值 `TRACK_W=90`） | 90 | 156 | `.w-track { width: 156px }` |

`tick()` 里已无硬编码：`secPct = s/60*this.trackW`，`y0..y3 = digit*this.rowH`。
`fitScreen` 改完这两个值后立刻 `self.tick()` 重算一次，不等下一秒 —— 否则翻页列会有一秒错行。

## 5. 三个 Vela 渲染限制（复用前两块结论）

1. **不支持后代选择器** —— `.w-page .x{}` 退化成 `.x{}`，宽屏样式污染小屏。全部单类。
2. **纯动态 class 丢父类** —— 必须混写 `class="d-clock {{ bigCls }}"`。
3. **同步 `device.getInfo()` 取错宽度** —— 192 屏读到 ≥300。只用异步回调。

本页新增的一个坑：**`.colon` 被变体 2 和变体 7 共用**。若给 `.colon` 类本身加宽屏字号，会连带放大不该放大的变体 7 —— 所以 `.w-colon` 只挂在变体 2 那个元素上，变体 7 的 `.colon` 不加。

## 6. 已知问题

1. **变体 6 依赖 CSS/JS 双写 84**，两处不同步会出现「数字不在同一水平线」。已在常量注释与 `.w-di` 注释里互相指认。
2. **`wf_font_style` 跨重启无法验证** —— `page` 命令会清应用存储，与前两块同。
3. **变体 7 在 192 屏两侧被裁是原设计**（跑道延伸出屏），不是适配缺陷。
4. **变体 7 与底部两个按钮纵向重叠**（本次实拍发现）。`.rot` 是绝对定位撑满页面、不占文档流，按钮在 flex 流里同样被居中，两者都落在屏心 → 跑道条带正好压住「切换样式 / 返回」。192 屏同代码路径，同样存在（只是宽度方向被裁切看起来更像"跑道"）。**非本次适配引入**。可选修法：给 `.w-rot` 的 origin 纵向上移到 200、或给 `.rot` 加 `top: -48px`，把条带抬到按钮上方。
5. **变体 1/8 冒号背后有一块黑底**（实拍可见）。冒号带 `kf-blink` opacity 动画，Vela 给动画元素单独建层并填黑，于是文字周围出现矩形黑块。192 屏同代码路径，同样存在，**非本次引入**。要修得把动画改成两帧字面量或直接去掉呼吸效果。

## 7. 验收

实拍（2026-10-25，模拟器 `xiaomi_band` 192×490 / `evc-xiaomi_band_pro-1` 336×480，均为 release 包 `1.9.51`）：

| 变体 | 192 | 336 | 实测 |
|---|---|---|---|
| 0 巨型加粗 | ✅ | ✅ | 96px 全串占宽 **226–233px**（两侧余 ~50），与 192 屏 68px 的"满宽"观感不完全等比例 |
| 1 等宽数码 | — | ✅ | 72px mono，五段横向排布不挤 |
| 2 逐字渐变 | — | 未实拍 | 与 v8 共用 `.digit`（90px）；`.w-colon` 只挂本变体冒号 |
| 3 错落双行 | — | ✅ | 108 / 60px 两行，块高 82–169 / 227–273，未压按钮 |
| 4 细边描签 | — | 未实拍 | 与 v0 同为单行粗体，仅 ls 8 + 弱对比色 |
| 5 等宽秒带 | — | ✅ | 78px + 156px 轨道，进度条随秒（实拍见截图） |
| 6 翻页滚动 | — | **未实拍** | 见下方说明 |
| 7 横铺跑道 | — | ✅ | **横向居中正确**：条带 x≈8–320，中心 ≈168 = 屏心；纵向中心 240 |
| 8 分色跳动 | — | 未实拍 | 同 v2 结构 + 冒号动画 |
| 192 零回归 | ✅ | — | 默认态与改前逐像素一致（截图 `字体表盘-9-变体0-20261025.png`） |
| 字号 ≥24 | ✅ | ✅ | 全部 56–108px；`.back` 22→24 已修 |

**变体 6 为什么没实拍**：模拟器无 `input` 命令，只能靠控制台点击循环变体；实测本页在「错落双行」之后点「切换样式」必定冒泡到 `.page` 的 `onTap` 直接退出（`suppressTap` 在该变体下拦不住），加上 `wf_font_style` 命中后重进页面会直接读存储跳过点击链路，切入 v6 的成功率不高。**结论**：`rowH=84` 与 `.w-di` 的 `line-height: 84px` 是同一常量双写、机构上与 192 屏（56 对 56，已验证可用）完全同构，判为低风险；真机需补一张。

**实测字宽偏差**：实际 advance ≈ **0.47em**，比方案里用的 Roboto 模型 0.5686em 窄约 17% —— 所以 v0 的 96px 留了 50px/侧余量。若想更接近 192 屏的满宽观感，可把 `.w-big` / `.w-thin` 提到 112px（估占宽 ≈270，仍安全）。
