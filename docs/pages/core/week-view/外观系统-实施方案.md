# week-view 外观系统实施方案（T-06 ~ T-09）

> 状态：**S1 已实施**（2026-11-01，evtask-D-class-schedu-261101-ucupkt）；S2 存储迁移、S3 底部条、S4 配色档待做。
> 关联：需求文档 `docs/pages/core/week-view/需求文档.md` 的 D-12、Q-05、Q-06、§8.3、§8.4。

## 0. 结论先行

现在这 6 个「模板」不是 6 种并列风格，而是 **布局 × 配色** 两个维度的笛卡尔积里挑出来的 6 个点——而且 5 个点共用同一套配色，只有「跟随系统」用了另一套。所以 T-09 的解耦不是新增功能，是**把被压扁成一个维度的两个维度还原**；不先还原，T-06 / T-07 / T-08 就无法作为独立档位存在（否则每加一个配色就要复制一遍布局）。

## 1. 现状盘点（6 模板的实质差异）

| id | 名称 | 字号/行数/显示 | 格尺寸 | 其它布局 | 配色 |
|---|---|---|---|---|---|
| `minimal-char` | 极简 | 36 bold / 1 行 / 首字 | 42×52 | 圆角 6 | 科目色 |
| `minimal-clean` | 清爽 | 24 / 1 行 / 首字 | 42×58 | 圆角 10 | 科目色 |
| `standard-block` | 标准 | 28 / 2 行 / 全名 | 自适应×64 | 圆角 6 | 科目色 |
| `compact-grid` | 紧凑 | 32 bold / 1 行 / 首字 | 40×48 | 序号列 + 边框 + 圆角 4 | 科目色 |
| `minimal-en` | 英文 | 28 bold / 1 行 / 英文缩写 | 60×50 | 圆角 8 | 科目色 |
| `color-pastel` | 跟随系统 | 28 / 2 行 / 全名 | 自适应×64 | 序号列 + 圆角 10 | **单色**（`useColorScheme: false`） |

两个维度各自的取值：

- **布局维度**：5 种实质差异（极简与清爽只差字号 36/24 与圆角 6/10）。
- **配色维度**：只有 2 种，由 `getCellBg` / `getCellTextColor` 的三个分支决定：
  - `useColorScheme: true` → 按科目取 `SUBJECT_COLORS` / `SUBJECT_TEXT_COLORS`（10 个科目 + default）；
  - `useColorScheme: false` → 统一 `theme.cardLight` 底 + `theme.accent` 字；
  - `transparentCells: true` → 透明底 + 正文色（**该字段目前无任何模板启用**，正是 T-07 的落点）。

## 2. 目标模型

`applyTemplate(id)` 拆为 `applyLayout(layoutId)` + `applyPalette(paletteId)`，两者各自独立存取。

### 2.1 Layout（布局，6 档；T-10 决定是否合并前两档）

| layoutId | 名称 | 关键参数 | 对应旧模板 |
|---|---|---|---|
| `big-char` | 大字单字 | 36 bold、1 行、`nameDisplay: char`、42×52、圆角 6 | `minimal-char` 极简 |
| `small-char` | 小字单字 | 24、1 行、char、42×58、圆角 10 | `minimal-clean` 清爽 |
| `full-name` | 全名两行 + 时间列 | 28、2 行、full、列宽自适应、高 64、圆角 6、`rowNumMode: time` | `standard-block` 标准 |
| `full-name-index` | 全名两行 + 序号列 | 同 `full-name`，但圆角 10、`rowNumMode: index` | `color-pastel` 跟随系统 |
| `dense-index` | 紧凑带序号 | 32 bold、1 行、char、40×48、序号列 40、边框、圆角 4 | `compact-grid` 紧凑 |
| `en-abbr` | 英文缩写 | 28 bold、1 行、`en-abbr`、60×50、圆角 8 | `minimal-en` 英文 |

> **⚠ 实施期修正（2026-11-01）**：本文 §2.1 原方案给 5 个布局，把「标准」与「跟随系统」都归入 `full-name`。
> 实施时核对 `TEMPLATE_CONFIGS` 发现二者除配色外还差 **圆角 6 vs 10** 与 **行号列 `time` vs `index`**——
> 合并会让老用户升级后圆角与行号列发生变化，**S1「截图字节零差异」的验收标准直接失效**。
> 故 S1 保留第 6 档 `full-name-index`，把两者差异如实记录在布局维度；收敛为 5 档属 T-10 / Q-06 的视觉决策，
> 需明确「跟随系统是否接受圆角与序号列的视觉变化」后再执行。

除尺寸字段外，每个布局另带三个**行为开关**，用于替代原实现里三处按旧 id 字符串判断的分支
（改造后 `.ux` 内已无任何模板 id 身份判断，符合 D-05）：

| 开关 | 含义 | 取值 |
|---|---|---|
| `showExtraBadge` | 是否显示 `+N` 同时间多课角标（D-07） | `big-char` / `small-char` = false，其余 true |
| `capsuleAutoWidth` | 胶囊屏是否按真实屏宽均分列宽 | `big-char` / `small-char` / `dense-index` = true |
| `hideTimeColumnOnRect` | 非胶囊屏是否隐藏时间列（B-06 方案 c） | 仅 `full-name` = true |

### 2.2 Palette（配色，4 档）

| paletteId | 名称 | 有课格底 | 有课字色 | 空课格 | 对应待办 |
|---|---|---|---|---|---|
| `subject` | 科目色（默认） | `SUBJECT_COLORS[key]` | `SUBJECT_TEXT_COLORS[key]` | 透明 + 灰点 | 现状 |
| `mono` | 单色 | `theme.cardLight` | `theme.accent` | 透明 + 灰点 | 现状（原「跟随系统」） |
| `high-contrast` | 黑白高对比 | `#ffffff` | `#000000` | 仅描边 `theme.borderLight` | **T-06** |
| `plain` | 纯文字 | `transparent` | `theme.text` | 不画点 | **T-07** |

实现方式：把 `getCellBg` / `getCellTextColor` 里三个 `if` 分支抽成 palette 表里的字段（`cellBg(course, theme)` / `cellText(course, theme)` / `emptyStyle`），不再写死分支。`transparentCells` 字段名保留为 `plain` 档的实现细节，不作为公开配置项。

## 3. 存储与迁移

- 新键：`weekview_layout`、`weekview_palette`（`store.js` 新增 get/set，仿现有 `getWeekViewTemplate` 写法）。
- 旧键 `weekview_template` **只读不写**，仅用于一次性迁移：

| 旧 id | → layoutId | → paletteId |
|---|---|---|
| `minimal-char` | `big-char` | `subject` |
| `minimal-clean` | `small-char` | `subject` |
| `standard-block` | `full-name` | `subject` |
| `compact-grid` | `dense-index` | `subject` |
| `minimal-en` | `en-abbr` | `subject` |
| `color-pastel` | `full-name-index` | `mono` |

- 迁移时机：`loadTemplateAndReload` 中若两个新键都为空而旧键有值，按表写入新键。迁移后旧键不再参与，保证老用户升级后外观逐像素不变。
- 回滚：新键清空即回到旧键路径，可用于灰度验证。

### S1 实施记录（2026-11-01）

**改动**（仅 `src/pages/week-view/week-view.ux`，+108 行 → 1391 行）：

- 删除单维 `TEMPLATE_CONFIGS`，新增 `LAYOUT_CONFIGS`（6 档，纯几何）、`PALETTE_CONFIGS`（4 档，纯颜色）、`LEGACY_TEMPLATE_MAP`（旧 id → 布局+配色）。

**验收方式变更（重要）**：原定「截图字节零差异」，实际改用**更强的状态等价性验证**——

共 **24 组合**跑 `applyTemplate`，逐字段 diff 全部渲染状态：


理由：S1 是纯重构，唯一可能的变化路径是「配置取值 → 状态字段」，对比状态字段比对比像素更直接、更全覆盖

## 5. 底部条承载：两套候选

**方案 A — 单条 9 个胶囊（5 布局 + 4 配色）**
同一条横滑，布局胶囊用现行样式，配色胶囊用不同底色区分。优点：改动最小、即时预览保留、无新增页面实例。缺点：两种语义混在一条，选中态要两套判据；9 个胶囊横滑距离长。

**方案 B — 底部条 5 个布局 + 末尾「配色」入口（弹层 4 档）**
语义清晰，底部条更像「布局选择器」。缺点：多一层交互；弹层会临时压住网格，违背 D-11「预览不落盘」的即时感；也与 Q-05 的「模板增量弹层」方案重叠，两套弹层需统一。

**倾向 A**：改动小、保留即时预览；等配色档超过 4 个或布局超过 5 个时再升级为 B（正好是 T-13 的触发条件）。

## 7. 风险与约束

1. `applyTemplate` 是唯一入口，但 `onShow → loadTemplateAndReload` 会用 storage 覆盖——验证非默认档位时必须在 `applyTemplate` 入口临时强制，不能只改默认值。
2. 模板相关条件分支目前只有 1 处（`extraCount` 的 `currentTplId` 判断）。拆分若引入第 2 处分支，即触发 D-05 失效条件（该考虑独立成文件）。
3. 拆表后 `.ux` 从 1219 行涨到约 1400 行；若继续增长，应执行 Q-04（拆成 配置 / 布局计算 / 数据加载 三模块），但**必须在 B-01 真机验证通过后**再做。
4. 黑白档必须与 `theme.*` 完全解耦，否则切换系统主题会覆盖格子颜色。`page` 与 `footer` 的底色是否也跟随黑白档，需先定（涉及主题系统边界）。
