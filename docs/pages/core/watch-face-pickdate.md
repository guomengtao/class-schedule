# watch-face-pickdate · 鼓轮时间表盘

> 角标精确命中，不走组级回退。上级目录见 [watch-face.md](./watch-face.md)。
> 双屏适配全过程与尺寸推导见 `docs/WatchFace-鼓轮表盘-双屏适配方案.md`。

## 定位

三列自绘鼓轮（时 / 分 / 秒），可直接手指上下滑调时，停止操作 3 秒后回到现在。下方显示日期、年内天数与操作提示。

**不是系统 picker**：三列都是自绘的裁切窗 + 9 格数字带，靠 `strip` 的 `top` 位移产生滚动，分 5 帧推进（每帧 40ms）。

## 结构

| 元素 | 作用 |
|---|---|
| `.drum` | 横向 flex 容器，装三列 + 两个冒号 |
| `.band` | 选中行底衬（鼓内第 2 格） |
| `.col` → `.win` → `.strip` → `.di` ×9 | 列 → 裁切窗（只露 3 格）→ 数字带 → 单格 |
| `.edge-t` / `.edge-b` | 选中行上下沿线（1px） |
| `.back` | 顶部返回热区（0–120，与鼓区分离，滑动不会误触返回） |

## 几何耦合（改这个文件最容易出错的地方）

**`CELL_H` 同时决定三件事**，任一处不同步就会出现「数字被裁」或「滚半格」：

1. JS 的 `CELL_H`（滚动步长 `delta * CELL_H`）
2. CSS 的 `.di { height; line-height }`
3. CSS 的 `.win { height }` = 3 × `CELL_H`

192 是 50 / 50 / 150；336 是 62 / 62 / 186。

**`BASE_TOP` 的第一项必须是 `CELL_H` 本身**：

```js
let BASE_TOP = CELL_H - CELL_H * PAD   // 正确：CELL_H × (1 − PAD)
// 曾经的写法：50 - CELL_H * PAD      // CELL_H 变了会算错，差 12px
```

`BASE_TOP` 决定「静止时中心格 = 当前值」。算错的表现很隐蔽：数字不换格，只是整体偏十几像素，要量 band 中心与数字 ink 中心才发现。

**三条带的 `t0/t1/t2` 是 data 字段**，改常量不会自动跟，`fitScreen` 里必须手动复位三个值。

## 双屏参数

| 元素 | 192×490 | 336×480 |
|---|---|---|
| `CELL_H` / `BASE_TOP` | 50 / −150 | **62 / −186** |
| 列宽 `.col/.win/.di/.strip` | 52 | 72 |
| `.drum` | 6,150 · 180×150 | 44,120 · **248×186** |
| `.band` | 0,50 · 180×50 | 0,62 · 248×62 |
| `.di` 字号 | 24 | 30 |
| `.di-c`（中心格） | 28 | 38 |
| `.c` 冒号 | 12×150 · 26px | 16×186 · 34px |
| `.edge-t` / `.edge-b` | 4,200 / 4,249 | 42,**182** / 42,**243** |
| 品牌 / 副标 | 52·20px / 76·11px | 40·26px / 74·18px |
| 日期 / 天数 | 300·24px / 338·24px | 322·24px / 360·24px |
| 返回提示 | 452·**14px** | 440·24px |

横向：`3 × 72 + 2 × 16 = 248`，`left = (336 − 248) / 2 = 44`，中心 168。

## 三个坑

1. **`.hint` 在 192 屏只能用 14px**。文案「上下滑调时 · 点顶部返回」12 个字，24px 需约 288px > 192，会被裁成「上下滑调时 · 点」。192 宽下 15px 是极限，取 14px 留余量。336 屏用 24px（288 < 336）。这是「可读文字 ≥24px」的唯一例外。
2. **`.strip` 宽度要跟着 `.di` 走**。column flex 会按容器宽度处理子元素，`strip` 停在 52 而子格是 72 时行为不可靠——宽屏类里必须一起给 72。
3. **中心格用单值类 `.w-di-c`，四条属性写全**（width/height/font-size/line-height）。曾考虑 `diCCls = "w-di w-di-c"`，但动态值带空格能否被正确解析为两个类未经验证，遂改为不依赖叠加。

## 生命周期

- `fitScreen()` 从 `onInit` 调，排在 `syncClock()` / `align()` 之后 —— `align()` 的定时器回调会在 1s 后重跑 `jumpTo`，届时已用新 `BASE_TOP`
- `onShow` 调 `realign()` 把三条带复位到整格，系统挂起后回来不会错位
- 页内 `require("@system.device")`，不用顶部 `import`
