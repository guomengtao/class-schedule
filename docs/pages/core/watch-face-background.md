## 功能说明

表盘栏目第 5 条。以「**场景氛围**」为视觉母题的时钟表盘：整页由「天空色带 + 7px 地平线 + 平涂地面」三层构成一个可站进去的夜景/日景，每套场景带一个天体（月/日）圆盘。提供 **8 套场景**可切换，选择写入 `storage`（key `wf_background_index`）持久化。

与旧版的差别：旧版只是把 `.page` 的 `background-color` 换成一个纯色值 —— 6 套背景本质是 6 个近似深色，无场景、无日期、无层次，内容占屏 **19.2%**；本版重做为天地分层 + 天体 + 三行信息，占屏 **38.4%**（192）/ **43.3%**（336）。

## 界面结构

```
天空层    17 段 × 21px 色带      sky[0] → sky[1] 插值（357px）
天体      圆盘 64px（192/宽屏同）discT/discL 决定位置，纯黑场景不画
地平线    7px 细线               地面色掺 accent（"地面受光的边缘"）
地面层    116px 平涂              地面色掺 12% accent
──────────────────────────────
场景名    午夜蓝                 24px（宽屏 28px），该场景 accent 色
时间      H H : M M              60px（宽屏 104px）
日期      10-25 周日              24px（宽屏 28px，与场景名合并一行）
操作      场景 │ 返回             24px（宽屏 28px），1px 竖线分隔
```

## 交互流程

| 操作 | 结果 |
|---|---|
| 点击「场景」 | 弹出场景面板（8 格色票 + 取消），`suppressTap` 挡住整页返回 |
| 点面板外区域 | 关闭面板，300ms 后恢复整页点击 |
| 点某个色票 | 应用场景 + 写 storage + 关面板 |
| 点「返回」/ 页面空白 | `router.replace` 回 `pages/watch-face-list` |

## 实现要点

### 1. 三层结构：天空色带 / 地平线 / 地面

```js
第 0..16 段   天空   17 × 21 = 357px   mixHex(sky[0], sky[1], i/16)
第 17 层      地平线 7px               mixHex(fTop, accent, 0.40)
第 18 层      地面   116px 平涂         mixHex(floor[0], accent, 0.12)
```

`fTop = mixHex(floor[0], accent, 0.14)`。

**地平线必须从「地面色」推算，不能从「天空色」推算。** 首版是 `mixHex(sky[1], accent, 0.45)`，实机看是「天上一条亮带」，且正好压在「场景│返回」按钮下方 12px 处，读起来像给按钮加了下划线（UI 分隔条）。改成从地面色推算后，它是「地面受光的边缘」，配合下方平涂地面才成立。

### 2. ⚠️ Vela 的 flex 会压缩超出容器的子项（本次最关键的一个坑）

`.bg` 是 `flex-direction: column` 的满屏绝对定位层。子项总高（17×21 + 7 + 160 = 524）超过屏高时，**不会溢出被裁，而是按比例 flex-shrink**：

| 屏高 | 子项总高 | 压缩比 | 每段实际高度 | 地平线实际 y |
|---|---|---|---|---|
| 490 | 504 | 0.972 | 20.4px | 347（设计值 357） |
| 480 | 524 | 0.916 | 19.2px | 326（设计值 357） |

后果：**地平线位置随屏高漂移**，宽屏上正好切在「场景│返回」按钮中间（截图实锤）。而且因为漂移是"比例式"的，改 padding / 改字号都会连带移动地平线，很难定位。

**修法：让色带总高精确等于宽屏屏高 480**（357 + 7 + 116），两个屏都不触发压缩；192 屏（490）少覆盖的 10px 用 `.page` 背景补 —— `.page` 的 `background-color` 直接绑定 `floorColor`，与地面同色，无缝。

> 这条对后续任何"全屏横向色带"页面都适用：**色带叠层的总高不要指望溢出裁剪，要算准**。

### 3. 地面为什么是平涂而不是渐变

试过 6 段渐变（`floor[0] → floor[1]` 插值），实机下半屏出现几道明显横条：屏是 **RGB565**（R/B 5bit、G 6bit），R 与 B 每级台阶 ≈8，渐变每段的色差恰好跨一个量化级 → 每段一个可见台阶。远处地面本来就是一块暗色，平涂反而更像地。

顺带解释了渐变表盘那个遗留问题（"顶部亮区仍有极淡横向分界"）：同一量化机制，**缩窄相邻锚点色差比加条数更有效**。

### 4. 天体定位：只用「上方安全区」，不按天空比例算

```js
const d   = 64                  // 两屏同尺寸
const top = wide ? 6 : 12       // 安全区上沿
const span= wide ? 4 : 24       // 纵向可动范围
discY = round(top + discT * span)
discX = round((screenW - d) * discL)
```

早期版本按 `discY = (SKY_H - d) * discT` 算，`discT` 0.62 的场景（暖阳）圆盘会直接压到「场景名」上：圆盘的下沿刚好落在文字带上。**改成固定窄安全区后，纵向变化只剩微调，主要区分交给 `discL`（横向）与颜色** —— 视觉上够用，且任何场景都不会压字。

### 5. 双屏差异：宽屏把场景名与日期合并一行

| 项 | 192×490 | 336×480 |
|---|---|---|
| 主时间 | 60px（原值未动） | 104px |
| 冒号 | 54px / margin 0 2px | 96px / margin 0 6px |
| 场景名 | 24px，单独一行 | 28px，与日期同行 |
| 日期 | 24px，单独一行 | 28px，与场景名同行 |
| 操作行 | 24px | 28px |
| 面板 | 176 宽 / 格 82×40 | 284 宽 / 格 130×52 |
| 天体 | 64px | 64px |
| stack 底部留白 | 56px | 30px |

为什么宽屏要合并：宽屏 stack 内容（场景名 + 时间 116 + 日期 + 操作）单列排下来会到 290px，480 屏居中后内容顶到 y≈95，**上方只剩 95px 给圆盘（96px）→ 必然压字**。合并后省 44px，内容顶下移到 y≈100，圆盘（64px，6..70）有了安全区。192 屏 24px 字号下「午夜蓝 + 10-25 周日」合计约 199px > 192 屏宽，合并会溢出，所以必须分行。

### 7. 面板：双列色票而不是纯色方块

每格 = 天空块（`sky[0]` 填充，承载场景名）+ 地面条（`floor[0]` 填充）。与主画面同构，用户看到的就是将要得到的效果。两列用 `.p-row` + `.opt2 { margin-left: 8px }` 实现（Vela 无 `gap`）。

### 8. ev-six 合规

- 可读文字统一 24px（192）/ 28px（宽屏），24 为绝对下限；旧版 22px 的按钮全部抬到 24
- 主时间 60 / 104px 属「表盘图形本体」，不套 24/28/30/44 四档，样式注释已写明豁免理由
- 分隔用 1px 竖线 + 间距，不用 `|` `/` 等符号

## 已知问题

1. **天空渐变有 ~6–8 级可见台阶**：屏是 RGB565，R/B 每级 ≈8，场景天空两色差 ≤30 → 只能落到 4~6 个量化级上，缩略图/放大图可见横向分界。同一机制见渐变表盘已知问题 1。彻底消除需做 1px 棋盘抖动（节点数不可接受），或改用更大色差（违背"深色不刺眼"），本轮接受。
2. **地面是平涂，没有远近层次**：6 段渐变在 565 下变条纹（见实现要点 §3），故平涂。若后续要层次，得用"3 块硬边界色块"而不是渐变。
3. **天体位置纵向变化很窄**（192 只有 24px 可动）：为了保证任何场景都不压字，牺牲了纵向构图自由。横向（`discL`）与颜色承担主要区分。
4. **模拟器无法验证持久化闭环**：`page` 命令每次重推 rpk + 重解压应用目录 = 清空应用存储，`wf_background_index` 写入后无法在模拟器里跨重启验证。存储代码路径与渐变/彩色表盘完全一致（同一套 `storage.get/set` + 同步兜底），风险低但未实机闭环。
5. **数字未做等宽**：`1` 比 `2` 窄，分钟变化时整行宽度轻微抖动，沿用 landscape 口径未设固定 `width`。
