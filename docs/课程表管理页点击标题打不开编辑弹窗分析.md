> 分析日期：2026-09-27
> 相关文件：[schedule-manager.ux](file:///Users/Banner/Documents/guomengtao/tom/class/class/src/pages/schedule-manager/schedule-manager.ux)
> 现象：**手环 9 真机**点课程名（标题）打不开底部操作弹窗；而今天**第一次**改这个页面时（当时的包）弹窗是可以打开的。

## 一、结论速览（TL;DR）

**今天最后一次改动的错，是给 `.indicator`（行首圆圈）补了 `onclick="openSheet($idx)"`，导致一行里出现两个 `onclick`。**

| 版本 | 手环 9（胶囊屏）每行生效的 `onclick` | 点课程名结果 |
|---|---|---|
| 第一次改动后（`fbac618`，含"删除毛病"修复） | **1 处**（只在 `.name` 上；`.more-hit` 在胶囊屏是 `display: none`，不生效） | ✅ 弹窗打开 |
| 现在（工作区未提交） | **2 处**（`.indicator` + `.name`） | ❌ 打不开 |

修复方向只有一句话：**每行只保留一个 `onclick`，而且放在整行容器 `.item` 上**，行内子元素（圆圈、文字、装饰 div）一律不绑 `onclick`。

## 四、为什么断定是"多了一个 onclick"（闭环推理）

### 4.1 手环 9 上，唯一的功能性差异就是它

`git diff`（HEAD → 工作区）的全部改动只在这几处：

1. 模板：`.indicator` 增加 `onclick`；删除 `.more-hit` 节点及其 CSS
2. CSS：`.item` 左右 padding、`.indicator` 尺寸（基础 16px → 32px）
3. `src/data/version.js`、`src/manifest.json`：只有 `versionName`/`versionCode`（1.6.133 → 1.6.139）

逐条排除：

| 改动 | 会不会影响手环 9 的点击？ |
|---|---|
| 版本号变更 | ❌ 与逻辑无关 |
| 删除 `.more-hit` | ❌ **在胶囊屏它本来就是 `display: none`**（不占位、不参与命中），删了等于没删 |
| `.item` padding / `.indicator` 尺寸 | ❌ 只改变宽度预算与视觉，不改变谁来接管点击 |
| **`.indicator` 增加 `onclick`** | ✅ **唯一变化**：每行从 1 个 onclick 变成 2 个 |

> 顺带说明：`.more-hit` 的删除对方屏是"少一处 onclick"、对胶囊屏是"零影响"；而 `.indicator` 的新增是三种屏型都增加的。**两件事叠加后，手环 9 上就是净增一处 onclick。**

### 4.2 "同一层级链上多个 onclick 会吞掉点击"是本项目已有的先例

`docs/勾选框点击无效问题分析.md`（同一页面、同类结构）已经踩过一次并定位过：

> **点击事件被嵌套的父子 `onclick` 冲突截断，无法正确触发。** 这是快应用框架的事件处理限制——**同一元素层级链上不应有多个 `onclick` 处理器**。
> 修复：**移除子元素上的 `onclick`，依赖父级的 `onclick` 统一处理。**

当时的修法（只留父级一处）已验证有效。今天方案 C 的动作方向**与之完全相反**——在已有 `onclick` 的行里又加了一个 `onclick`。

### 4.3 上一版"点圆圈也能开面板"，恰恰证明方向错在"加 onclick"

`docs/schedule-manager-click-issues.md` 的「问题 1」：圆圈当时**没有** `onclick`，可点圆圈也能打开弹窗，于是把原因归为"事件冒泡/热区重叠/框架默认行为"，并给出"方案 C：给圆圈补 `onclick`"。

这个观察的真正含义是反的：**在 Vela 手环上，这一行的命中判定本来就是"以行为单位"的**（或者圆圈 `background-color: transparent` 时不可成为命中目标），点圆圈被算作行内那个唯一处理器的点击。也就是说：

- 一行只有 1 个 `onclick` → 行内任意位置（含圆圈）都能触发它 → 看起来"圆圈也能点" ✅
- 一行有 2 个 `onclick` → 事件归属解析失败 → **被丢弃，两个都不执行** → 点哪里都打不开 ❌

所以"给圆圈加 onclick"解决的是一个**并不存在**的问题，却制造了一个真实的问题。

### 4.4 还有一处 11:42 文档判断失误

`docs/schedule-manager-click-issues.md` 说"胶囊屏媒体查询没有隐藏三点小点"，与 `fbac618`（`.more-hit { display: none }` 就在胶囊屏媒体查询里）不符——**该文档是在已修版本的基础上写的旧结论**，把它直接当成现场事实来指导改动，是这次回退的流程性原因。

## 五、修复方案

### 5.1 推荐：`onclick` 提到整行容器（唯一一处）

模板改为：

```html
<div for="{{ list }}" class="item" onclick="openSheet($idx)" style="background-color: {{ theme.card }}">
  <div class="indicator"
       style="background-color: {{ $idx === currentIndex ? theme.accent : 'transparent' }}; border-color: {{ $idx === currentIndex ? theme.accent : theme.textMuted }}"></div>
  <text class="name" style="color: {{ $idx === currentIndex ? theme.accent : theme.text }}; font-weight: {{ $idx === currentIndex ? 'bold' : 'normal' }}">{{ $item.name }}</text>
</div>
```

**收益**：

1. 一行只有 1 个 `onclick` → 回到"能打开"的状态
2. 点击热区 = 整行（`.item` 高 64px、宽 160px 内容区），远好于 32px 的圆圈或只有文字宽度的 `<text>`
3. 点圆圈、点文字、点行尾空白**行为完全一致**，也就顺便"实现"了 11:42 文档想要的"圆圈可点"
4. 与 `index.ux` 的 `class-grid-item onclick="goToClassDetail($item)"` 惯例一致（同样是把 onclick 放在行容器上）
5. 三种屏型（方屏/圆屏/胶囊屏）行为统一

### 5.2 备选（最小改动）：撤掉 `.indicator` 的 `onclick`

只把 `onclick="openSheet($idx)"` 从 `.indicator` 上删掉，其余不动 —— 也能恢复到"每行一处 onclick"。

**代价**：热区仍然只有课程名文字本身，点圆圈/行尾空白无反应，不算真正修好体验。

### 5.3 建议同时做的收尾

| 项 | 动作 |
|---|---|
| `.item` 的触控上限 | 若担心整行过高误触，可不改；64px 行高在胶囊屏属于合理范围 |
| `docs/schedule-manager-click-issues.md` | 在「方案 C」处标注**已否决**（原因见本文件），避免下次再被它的结论带偏 |
| 排错日志 | `logPageWidth()` 属取证代码，验证通过后应删除 |

## 七、防回退规则（建议写入红线清单）

> **Vela 手环：同一行 / 同一层级链上只允许一个 `onclick`。列表行的写法固定为「onclick 放整行容器，行内子元素零 onclick」。**

- 绝不为"扩大热区"给行内元素补 `onclick`——要扩大热区就把 onclick 提到行容器
- 改动这类行结构后，必须逐屏型（方屏 / 圆屏 / 胶囊屏）核对**每行 onclick 数量**，因为媒体查询里的 `display: none` 会让"代码里有 onclick" ≠ "运行时有 onclick"
- 分析文档写现场事实前，先 `git diff` 核对当前真实代码，避免基于过期文档做判断
