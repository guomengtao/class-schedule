"把热区扩到整行"这个**修法**从头到尾都是对的；错的是我给它配的**理由**。当时的推理是"手环 9 上唯一的功能性差异 = 多了一个 onclick → 所以是多 onclick 吞掉了点击"。这个推理在**逻辑上没错**（差异确实只有一个），但它的**前提**（"能打开的版本 = 只有一个 onclick"）是拿不到真机包版本时的一种假设，而且**没有做 A/B 就写成了结论** —— 这正是本项目 `MEMORY.md` 里记过的教训："高置信度推断却改不好时，先做 A/B 而不是继续分析"。

## 三、修复后的代码

```html
<!-- onclick 只放整行；行内子元素一律不绑 onclick（热区 = 整行 160×64） -->
<div for="{{ list }}" class="item" onclick="openSheet($idx)" style="background-color: {{ theme.card }}">
  <div class="indicator" style="..."></div>
  <text class="name" style="...">{{ $item.name }}</text>
</div>
```

```js
openSheet(idx) {
  // 越界守卫：列表未就绪或删除后索引失效时，早期实现会抛异常导致"点了没反应"
  if (idx < 0 || idx >= this.list.length) return
  this.sheetIndex = idx
  ...
}
```

**越界守卫是本次单测新发现的问题**：`openSheet` 原来直接 `this.list[idx].name`，一旦 `idx` 越界（或在 `loadData()` 异步回来之前被调用）就抛异常、**静默失败**（表现为"点了完全没反应"）。同文件 `toggleHolidayReminder()` 本来就有 `if (idx < 0 || idx >= this.list.length) return` 的写法，本次按同样风格补齐。

## 六、防回退规则

1. **列表行：`onclick` 只放整行容器，行内子元素不绑 onclick** —— 热区稳、且不引入"一链多处理器"的可疑结构
2. 打开浮层的处理器**必须有越界守卫**，否则表现为"点了没反应"，最难排查
3. **不要拿"多 onclick 必被吞"当结论外推**（本项目 10 处一行多 onclick 长期正常）
4. 改这类行结构后，逐屏型核对"**运行时有几个 onclick**"——媒体查询里的 `display: none` 会让代码意图与运行时不一致
5. 给真机问题下结论前，**先确认装机包的 `r` 参数**，能 A/B 就 A/B（本项目可用的 A/B 通道：IDE 模拟器截图 `/Users/Banner/Downloads/vela_screenshot/`，AI 可直接读图）
