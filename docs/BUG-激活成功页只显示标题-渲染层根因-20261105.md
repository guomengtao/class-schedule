## 一、现象

真机上激活成功后，页面**只剩顶部标题「激活成功」四个字**，下方大片空白。
项目里明明做过「恭喜 / 高级版到手 / 权益 / 开始体验」这个成功页（`done-box`），却始终对接不上。

关键点：标题 `{{ verifySuccess ? '激活成功' : '激活码' }}` 已经切成「激活成功」，
**证明数据层 `verifySuccess === true` 是成立的**，不是状态没切、也不是激活链路失败。
坏的是「把已为 true 的状态画出来」这一步。

## 二、根因（两层，叠加）

### 第 1 层：隐藏节点 un-hide 不重绘（主因）

`activation-code.ux` / `activation-code-v2.ux` 的成功态显隐全部写成 `style` 里的动态 `display`：

```html
<div class="done-box" style="display: {{ verifySuccess ? 'flex' : 'none' }}">
```

`done-box` 首帧是 `display:none` 的隐藏节点，切成功态靠把它 un-hide 成 `flex`。
Vela 真机对隐藏节点的 un-hide **不重绘**（`settings.ux:113-116` 已有实证注释：
「显隐一律用 if（与重构前一致，真机验证过可用）。2026-10-23 那次重构把它改成
display:none→flex，手环上点「主题配色」就不弹了」）。
于是隐藏方向生效（输入区/键盘消失），un-hide 方向失效（done-box 不出现），
净效果就是：**标题变了，中间空了**。

### 第 2 层：同一 style 内多个 `{{ }}` 绑定静默截断渲染树（放大器）

`pit-20261025-23` 记录过同款现象——「Vela 页面只渲染出 header 标题，其余节点全不出现、无报错」，
根因是同一个 `style` 里写了两个 `{{ }}` 绑定，编译通过但运行期静默截断整棵树。
本页恰好有多处：

| 行（v1） | 写法 |
|---|---|
| 9 | `style="font-size: {{ }}; color: {{ }}"`（header-title） |
| 18 | `style="display: {{ }}; color: {{ }}"`（source-hint） |
| 85 | `style="background-color: {{ }}; display: {{ }}"`（status-strip） |
| 136 | `style="background-color: {{ }}; display: {{ }}"`（verify-btn） |

修法按 pit 给的路线：「一个 style 只放一个绑定；先还原成 if，再逐条加回 display」。

## 三、为什么之前的截图「看起来是对的」

`scripts/shot-done-page.sh` 注入的是 `verifySuccess: true` **初值**，
`done-box` 从首帧起就是 `display:flex`，**绕过了整个 none→flex 的动态切换路径**。
`BUG-激活成功页进不去-根因分析-20261105.md` §三 已指出这层验证盲区，
但当时归因为「触发逻辑到不了」；本轮补上第二层：**即便状态到了，渲染层也画不出来**。
两轮修复合起来才是完整解。

## 四、修复（2026-11-05，evtask-B-evclass-sche-261105-uqwzyg）

两页输入态 / 成功态显隐一律改 `if` 条件渲染（节点新建，不再依赖 un-hide 重绘），
并顺带把明显的双绑定拆成单绑定：

| 文件 | 处数 | 改动 |
|---|---|---|
| `activation-code.ux` | 6 | source-hint / cells-grid / status-strip / keypad / verify-btn → `if="{{ !verifySuccess }}"`；done-box → `if="{{ verifySuccess }}"` |
| `activation-code-v2.ux` | 5 | cells-grid / status-strip / keypad / verify-bar → `if="{{ !verifySuccess }}"`；done-box → `if="{{ verifySuccess }}"` |

静态 `display` 值不再写在行内（Vela 的 `div` 默认 flex，CSS 里的 `flex-direction` 继续生效）；
`source-hint` 保留静态 `display: block`，style 内只剩 `color` 一个绑定。
**不动** `auth-store.js`、不动激活校验、不动数据层、不动成功页文案与字号。

既有问题（与本次改动无关，未处理）：
- `npm run lint` 报 `eslint-formatter-codeframe` 未安装（formatter 已不在 ESLint core）。
- `npm test` 44 通过 / 1 失败：「源课表无数据时提示且拦下」，属 `schedule-manager` 复制课表用例，与 activation 两页无文件重叠。

尝试过的验证路径（记录以免重复踩）：往 `onShow` 注入 `setTimeout(() => succeed(), 6000)` 想验
「输入态→成功态」动态切换，两张截图字节完全一致（`/tmp/ev-act-input.png` 与 `/tmp/ev-act-success.png`
均 10832 字节）——`page` 命令是「拉起（pipe）」复用已有页面实例，`onShow` 不会重跑。
裸 `adb shell vapp` 又被 vela 管理守卫拦下（须走 `vela up xiaomi_band --rpk` / `vela push`）。
**结论：模拟器侧无法可靠构造动态切换场景，这一步只能靠真机。**

## 六、遗留项（本轮未动，避免扩大改动面）

1. `doneSub` / `statusDetail` / `statusText` 三个数据项算好了但**模板从未绑定**，
   成功页副标题是硬编码「高级版到手」，有效期/剩余天数不显示。
2. `scripts/shot-done-page.sh` 的 `--sub` 参数是空转的：Python 注入段读了 `sub = sys.argv[3]`
   却从未使用，也没传 `params.sub`，`npm run shot:done -- 剩余30天` 不生效。
   要修需同时把 `doneSub` 绑回模板，涉及 ev-six 字数与胶囊屏行数复核，单独立项。
3. v1 `header-title`（第 9 行）仍是 `font-size` + `color` 双绑定。本轮保守未动
   （它已能正常渲染标题）；若真机复测仍有节点缺失，按 pit 的二分法下一个就拆它。

## 七、排查提示（写给以后的人）

- 「只有标题变了、主体空了」= 数据已到位、渲染没跟上，**先查显隐写法，不要再去查激活状态**。
- Vela 里凡是「首帧隐藏、后来显示」的区块，一律用 `if` / `block if` 条件渲染；
  `display: {{ }}` 只适合「首帧就显示、后来隐藏」的方向。
- 一个 `style` 里只放一个 `{{ }}` 绑定；配色与显隐拆到内外两层容器。
- 截图脚本注入「初值」自证不了任何动态切换问题，别再被「截图看着是对的」骗第三次。
