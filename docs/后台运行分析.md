## 二、实现架构

### 2.1 平台能力声明

在 [manifest.json](file:///Users/Banner/Documents/guomengtao/tom/class/class/src/manifest.json#L34-L36) 中声明了 `system.resident` 能力：

```json
{
  "name": "system.resident"
}
```

这是快应用手环平台的后台常驻 API，允许应用在退到后台后继续保持运行。

### 2.2 核心代码入口

所有后台运行逻辑集中在 [src/app.ux](file:///Users/Banner/Documents/guomengtao/tom/class/class/src/app.ux)（应用入口文件）。

#### 模块加载（第 15-19 行）

```javascript
var resident = null
try {
  resident = require("@system.resident")
} catch (e) {
  dlog("[BACKGROUND] resident not available: " + e)
}
```

使用 try-catch 安全加载，在不支持 `@system.resident` 的设备上不会崩溃。

#### 启动后台常驻（第 22-37 行）

```javascript
function startResident() {
  if (!resident) {
    return
  }
  try {
    resident.start({
      message: "课程表后台运行中",
      success: function() {
        dlog("[BACKGROUND] resident started")
      },
      fail: function(data, code) {
        dlog("[BACKGROUND] resident start fail: " + code)
      }
    })
  } catch (e) {
    dlog("[BACKGROUND] resident error: " + e)
  }
}
```

启动常驻服务时显示消息「课程表后台运行中」。

#### 停止后台常驻（第 41-55 行）

```javascript
function stopResident() {
  if (!resident) {
    return
  }
  try {
    resident.stop({ ... })
  } catch (e) { ... }
}
```

虽然有 stop 方法，但**当前代码中从不调用**。

#### 自动启动（第 640-642 行）

```javascript
export default {
  onCreate() {
    // ...
    startResident()  // ← 无条件启动！
    initSyncReceiver()
  },
```

在应用 `onCreate` 生命周期中**无条件调用** `startResident()`，无论用户是否有意开启。

#### 预留的按需启动方法（第 646-651 行）

```javascript
initBackgroundRunning() {
  store.getBackgroundRunningConfig(function(config) {
    if (config && config.running) {
      startResident()
    }
  })
},
```

这是一个预留方法，从 storage 读取用户配置后决定是否启动。但**此方法在当前代码中从未被调用**，属于预留接口。

#### 销毁时保持不变（第 653-655 行）

```javascript
onDestroy() {
  // 不再主动 stopResident：保持常驻以持续接收同步消息（如需停止由系统或用户决定）
}
```

注释明确说明：**刻意不在销毁时停止常驻**，目的是保持 interconnect 同步通道随时可用，持续接收来自手机插件（AstroBox）的消息。

## 三、数据层

### 3.1 Storage 存储（[store.js](file:///Users/Banner/Documents/guomengtao/tom/class/class/src/data/store.js#L639-L694)）

提供了配置和日志的读写方法：

| 方法 | 功能 | Storage Key |
|------|------|-------------|
| `setBackgroundRunningConfig(config, cb)` | 保存后台运行配置 | `background_running_config` |
| `getBackgroundRunningConfig(cb)` | 读取后台运行配置 | `background_running_config` |
| `getBackgroundRunningLogs(cb)` | 读取后台运行日志 | `background_running_logs` |
| `setBackgroundRunningLogs(logs, cb)` | 保存后台运行日志 | `background_running_logs` |


## 五、为什么需要后台运行

项目使用后台常驻的主要目的是**保持 `@system.interconnect` 通信通道活跃**。

代码中（app.ux）同时加载了 `@system.interconnect`，用于与手机端 AstroBox 插件进行数据同步：

- 导入课表（`action: "import"`）
- 导出课表（`action: "export"`）
- 编辑配置（`action: "update_settings"`）
- 心跳探测（`action: "ping"`）
- 数据备份

如果后台常驻被停止，手机插件向手环发送消息时将无法被接收。

## 七、潜在问题与建议

### 7.1 问题

1. **用户无法控制**：后台运行强制开启，没有 UI 开关。用户无法选择关闭以省电。
2. **`initBackgroundRunning()` 是死代码**：方法定义完备但从未被调用，如果未来要加开关建议直接复用。
3. **日志系统空闲**：`background_running_logs` 表已定义但代码中不写日志，无法排查后台运行异常。
4. **配置字段未使用**：`interval`、`lastRun` 列已设计但在代码中无实际逻辑。

### 7.2 建议

1. 在设置页或工具页增加「后台运行」开关，调用已有的 `store.setBackgroundRunningConfig()` / `store.getBackgroundRunningConfig()`。
2. 将 `onCreate()` 中的 `startResident()` 改为调用 `initBackgroundRunning()`，让配置生效。
3. 如需调试，可在 `startResident()` 的 success/fail 回调中加入日志写入 `setBackgroundRunningLogs()`。
4. 考虑到这是手表应用，后台持续运行会增加电量消耗，建议至少在设置页给用户一个关闭选项。
