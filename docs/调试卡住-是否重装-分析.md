# 调试卡住——要不要重装？分析（2026-10-08）

> 现象：IDE 里点「调试」后，日志走到最后一行就停住——
> ```
> [toolkit]: Excuting: adb -s emulator-5554 shell vapp --jsdebugger=10.0.2.15:101 app/com.application.watch.classschedule &
> ```
> 之后没有下文，模拟器上 App 不出现 / 黑屏。

## 结论先说

**❌ 不需要重装。**

- 构建 ✅、推包 ✅、解压 ✅ 全部成功，产物是好的；
- 卡住的只有**最后"启动 App"**这一步，而且这是**已知问题**（详见
  `docs/aiot-ide调试卡住-根因分析.md`），和装没装好无关，重装模拟器/重装 IDE 都解决不了；
- 这次日志里的每条告警（`stopResident`、`_syncConnect`、`syncSendToPhone` 未使用，及各类
  `Descendant Selector`、`text.lines`、`scrolltop` 不支持）都只是**无害告警**，不阻断构建。

## 二、为什么卡住（两层叠加，都不是"没装好"）

1. **`--jsdebugger` 让 App 等调试器**
   这条启动命令带调试开关。App 起动后会等调试器连到 hostfwd 映射端口
   （`10.0.2.15:101` → 宿主 `127.0.0.1:10055`）。若没有调试器连上，App 会一直停在等待/黑屏，
   表现就是"卡住没下文"。

2. **debug 模式下启动期 interconnect 触发 QuickJS 断言（历史已确认）**
   `src/app.ux` 的启动期会走 `interconnect create → connect → jse_request`（去连手机端同步器，
   构建告警里的 `_syncConnect` / `syncSendToPhone` / `stopResident` 都是这套）。
   历史根因文档已实测确认：**普通 `vapp`（不带 `--jsdebugger`）能正常跑；只有 `--jsdebugger` 下
   这条路径触发 `quickjs/quickjs.c:3375` 断言崩溃**。这不在模拟器/端口/重装能力范围内。

## 三、怎么办（按优先级）

1. **宿主侧重启兜底（推荐，100% 可控）**
   用普通方式（**不带 `--jsdebugger`**）在宿主侧后台启动，脱离 adb 会话存活：
   ```bash
   /opt/homebrew/bin/adb -s emulator-5554 shell vapp app/com.application.watch.classschedule
   ```
   然后确认进程 + 截屏：
   ```bash
   /opt/homebrew/bin/adb -s emulator-5554 shell ps        # 应有 vapp app/com... 进程
   node scripts/emulator-eye.js shot 8554 /tmp/after.png  # gRPC 8554 = emulator-5554
   open /tmp/after.png                                    # 看文件大小：纯黑≈1.3KB / 有内容≈大很多
   ```

2. **尽量用 IDE 的「运行」而非「调试」**：运行模式不带 `r=true` → 启动命令里没有 `--jsdebugger`，
   就能避开这两层叠加。

3. **根治（应用侧，超出本次范围）**：把 `src/app.ux` 启动期的 interconnect 调用**延迟/降级**——
   不放到 `onInit`，改到 `onShow` 加延时，或对端不可达时跳过，或调试环境跳过。这样能绕开
   debug 模式下的触发路径。历史文档 §四 有完整方案。

> 端口检查口诀：`lsof -nP -iTCP:10055 -sTCP:LISTEN` 应只有 IDE 的模拟器在听；若被别的占（如
> EvEmuBuddy），先按 `docs/aiot-ide调试卡住-根因分析.md` 的端口分区契约清掉。

## 四、一句话备份

重装解决不了这个问题。构建/推包都成功，App"卡住/黑屏"是 **debug 启动（`--jsdebugger`）+ 启动期
interconnect 触发 QuickJS 断言** 的历史已知问题。先跑第三节第 1 条宿主侧重启兜底，一切正常就继续。
