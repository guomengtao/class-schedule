## §1 形态判定（第一分叉：几何量在 CSS 还是 JS）

| 表盘 | 几何量位置 | 路线 |
|---|---|---|
| evpointer / metal / gold | CSS 字面量 | 父级 `scale()` |
| animated | JS 常量算绑定坐标 | 改 JS 常量 + 重算 |
| **pickdate（本块）** | **两边都有，且必须同步** | 改 JS 常量 + CSS 类，**不允许 scale** |

本页是「三列自绘鼓轮」：`CELL_H = 50` 在 JS 里决定滚动步长与 `BASE_TOP`，同时 `.di { height: 50; line-height: 50 }`、`.win { height: 150 }` 在 CSS 里决定裁切窗口。**两者任何一侧改错都会表现为「数字被裁」或「滚半格」**。

不能 scale 的理由同 animated：9 格数字带靠绑定 `top` 位移，scale 会把位移一起放大。

## §2 两处硬编码耦合（本块真正的风险）

### ① `BASE_TOP` 的公式里写死了 50

```js
const CELL_H = 50
const BASE_TOP = 50 - CELL_H * PAD   // = -150，看着对，其实第一项是字面量
```

`CELL_H = 62` 时上式得 `50 − 248 = −198`，而正确值是 `62 − 248 = −186`，**差 12px = 半格多一点**，表现为「静止时中心格不是当前值」。

修法：`BASE_TOP = CELL_H - CELL_H * PAD`，并随 `CELL_H` 在 `fitScreen` 里重算。

### ② 三条带的 `top` 是 data 字段，改常量后不会自动跟

`t0/t1/t2` 初值 `BASE_TOP`，此后由 `setTop()` 维护。`fitScreen` 重算 `BASE_TOP` 后必须**手动把三条带一起复位**，否则要等下一次 `jumpTo` 才纠正。

### ③ 27 个 `.di` 的 `height` 必须等于 `CELL_H`

与 gold 的「字号变了 height 没变」、animated 的「窗高 ≠ 行高」同一个病。本次 `CELL_H = 62`，则 `.di { height: 62; line-height: 62 }`、`.win { height: 186 }`（3 格）三者咬死。

## §5 风险

| 风险 | 对策 |
|---|---|
| `BASE_TOP` 差 12px → 中心格不是当前值 | 公式改 `CELL_H - CELL_H * PAD`，并在 fitScreen 复位三条带 |
| `.di` 高 ≠ `CELL_H` → 数字被裁 | 三者咬死 62 / 62 / 186 |
| 手势步长 3 格 × 62 = 186，超出 9 格带容量？ | `PAD = 4`，中心格上下各 4 格 = 支持 3 格滚动，与 192 同构，不受 `CELL_H` 影响 |

| 192 日期/天数/提示提字号后互相压 | 已按 300/334/338/452 重排并留 30px 行高 |

## §6 验收标准
