# 倒计时 栏目 · 重构方案（更多首页 · countdown）

> 定位：**课程的仪表盘**——课名是整屏最大字，时钟可小可无。
> 判据来自 `docs/表盘盘点与升级方案.md` §九：课名最大 → 此页归「更多首页」；若改成时钟最大，应移出本栏目。

## 0 · 共同约束（七份方案共用，写死勿破）
- 画布 **192×490**，页边距 12，卡片圆角 12。
- 色板：主 `#7ec8e3` / 正文 `#f2fbff` / 次 `#8fa6b5` / 卡底 `#16213e` / 分隔 `#0f3460`。
- **禁区**：带文字的 `transform`（必白屏）、`<scroll>+scrolltop`（引擎不认）、
  `@keyframes` 承载读数（会冻结）。动画只许 `opacity`。
- 数据只走 `require("../../data/store.js")`，分钟级刷新，禁止秒级轮询（除秒相关页）。
- 每个栏目**必须**有一个 120px 高的顶部返回热区，页面根节点不挂 onclick（防 drag 被当点击）。

## 1 · 现状实测（2026-10-20 核对源码后回写）
- 文件 `src/pages/schedule-panel-countdown/schedule-panel-countdown.ux`，重构前 **216 行**，最大字号 **104px**（`@media (width>=400px)`），192 屏走 56px。
- 结构判定（源码事实，**与初稿推测不符**）：104px 不是「距上课 X 分钟」，而是
  `MM:SS` 形式的**倒计时时钟**（`.countdown-time` + `setInterval(1000)` 秒级刷新）。
  也就是说它当时是「一块跳秒的电子表 + 课名小字」，属表盘语汇，不是课程仪表盘。
- 附带问题：秒级 `setInterval` 与 §0「分钟级刷新」冲突；`MM:SS` 5 字符在 192 屏要降到 56px 才不折行，
  大数字被秒数吃掉，课名只能 32px。

## 2 · 问题
- `MM:SS` 把版面让给了「秒」，而用户真正要看的是「还有多久上课」——秒在这页没有决策价值。
- 秒级刷新每秒写 4 次数据绑定，手环上纯耗电。
- 大数字位置被秒数锁死，课名只能挤在卡片里，看不出「这是到哪节课」。


## 3 · 新结构（2026-10-20 已落地）
| 区 | 内容 | 字号/尺寸（192 屏） |
|---|---|---|
| A 课名 | 单行省略，卡片顶部 | 26px / max-width 148 |
| B 大数字 | **最多 3 字符**：分钟数，≥100 压 `99+` | 96px |
| C 单位 | `分钟后上课` / `分钟后下课` / `小时后上课`（≤4 字，20px 下再多必折行） | 20px |
| D 日期 | 仅跨天时出现：`明天` / `星期三` | 18px |
| E 时间 | `08:00 - 08:45` | 20px |
| F 地点 | 有则显示 | 18px |

A→C 垂直排列在 168×约 300 的卡片里，D 藏在 E 上方（当天有课时不占位）。
**溢出规则**：≥100 分钟时 B 显示 `99+`（3 字符，159px < 168px 可用宽）。

实测修正：初稿把 `明天` 写成 `小时后 · 明天首节` 后缀，20px 下 9 字必折行 → 拆成 D 独立一行；
`明天 08:00 - 08:45` 前缀写法同样折行 → 也废弃。

## 4 · 数据与四态
`store` 取全周课表，按 `now` 判四态（分钟级重算一次，不轮询）：
1. **上课中**：B = `endMin - nowMin`，C = `分钟后下课`；
2. **今天下一节**：B = `startMin - nowMin`，C = `分钟后上课`，≥100 压 `99+`；
3. **今日已结束**：往后 1~7 天找最近有课的一天，B = 小时数，C = `小时后上课`，D = `明天` / `星期X`；
4. **全周无课**：空态 `暂无课程`。

## 8 · 冷启纪律（本轮踩坑，七栏通用）
1. **首帧必须自带内容**：`onInit` 里先用 `builtinSchedule.schedule` **同步**算一遍并置 `isLoading=false`，
   再把异步 storage 结果覆盖上去。实测本机冷启偶发「storage 回调不来 + 定时器全不跑」，
   任何靠 `setTimeout` 兜底的写法（600ms watchdog）在这种卡死下**同样不会触发**，只有同步首帧能救。
2. **别并发打 storage**：`store.getTheme` 未回就 `database.init` 会加大丢回调概率；串行（主题回调里再 init）。
3. **取证别信第一帧**：`vela-loop.py` 一旦出现非黑帧就立即抓拍，冷启时可能抓到首帧之前的短暂空窗，
   得出「还在加载中」的假结论。判定要用 `vela-pix.py shot` 在 8s 后再补一拍，或比对两次抓帧 md5。
