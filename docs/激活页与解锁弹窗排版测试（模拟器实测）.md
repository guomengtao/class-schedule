> 日期：2026-09-27

> 用户报告：**"弹窗有点靠左，多处歪歪扭扭，文字也乱"**，要测「文字和是否居中」
> 方法：模拟器 gRPC 截图取证（[模拟器眼睛与手指打通复盘.md](模拟器眼睛与手指打通复盘.md)）+ 自写像素测量工具 `/tmp/sched/png-measure.js`（零依赖 PNG 解码 → 亮像素列/行分布 → 边距与居中定量）

## 一、结论速览

| 用户疑问 | 实测结论 | 证据 |
|---|---|---|
| 弹窗/卡片是否**靠左**？ | ❌ **不成立**：卡片**完美居中**（左右边距各 **16px**，差 0）；头部标题也基本居中（±1px） | `color`/`bands` 测量 |
| 文字是否**居中**？ | ⚠️ **部分是**：卡片居中、标题居中；但**卡内文字块整体比卡片中心偏左约 4px**（文本中心 101.5 vs 卡片中心 105.5） | `bands` 测量 |
| **多处歪歪扭扭、文字乱**？ | ✅ **成立，而且找到了量化真凶**：`.step-header` 把 32px 标题挤到只剩 **110px** 可用宽 → 每行只能放 **3 个字**，「购买高级版兑换码」被拆成 3 行并省略号截断 | 截图 + 宽度计算 |

**一句话**：不是"整体没居中"，而是**"内容宽度不够导致的强行换行 + 行宽参差"**把版面搞得歪乱；在 192px 的手环 9 上会**更严重（每行只剩 2 个字）**。

## 四、逐条判定（对着用户的三个疑问）

### 4.1 "弹窗有点靠左" —— 卡片本身不靠左，但**卡内文字块偏左 4px**

- 卡片：**严格居中**（16/16）。
- 卡内文字：三段测量得到**同一个中心 101.5**，比卡片中心 105.5 偏左 4px —— 是一个**系统性偏移**（不是某一处写错），怀疑与 `align-items: center` 在 Vela 上对文本块的取整/字体左右留白有关，**建议在 192×490 上复核**（本次只测了 212×520）。
- **观感上"靠左"更可能来自另一点**：状态卡里几行文字**宽度参差**（下面 4.2），视觉重心被拉偏。

### 4.2 "多处歪歪扭扭" —— 根因是**可用宽度不足导致强行折行**

截图里 `有效期 2026-10-17` 被拆成两行（「有效期」/「2026-10-17」），而模板里它本是**一行**：

```html
<text class="status-expiry" ...>有效期 {{ expireTimeText }}</text>
```

- `.status-expiry` = 28px；「有效期 2026-10-17」≈ 3×28 + 空格 + 10 字符 ≈ **226px**
- 卡片内宽 = 屏宽 212 − 页面 padding 32 − 卡片 padding 28 = **152px**
- 226 > 152 → **必然折行** → 两行长短差极大（3 字 vs 10 字）→ 这就是"歪歪扭扭"

### 4.3 "文字也乱" —— `.step-header` 把标题挤成 **每行 3 个字**

```html
<div class="step-card">
  <div class="step-header">          <!-- flex-direction: row -->
    <div class="step-badge">1</div>  <!-- 32×32 + margin-right 10 -->
    <text class="step-title">购买高级版兑换码</text>   <!-- font-size: 32px -->
  </div>
```

宽度账（212px 屏）：

```
卡片内宽   = 212 − 32(页面 padding) − 28(卡片 padding) = 152px
减徽标     = 152 − (32 + 10)                            = 110px  ← 标题只能用这么多
「购买高」  = 3 字 × 32px                                = 96px   ✅ 放得下
「购买高级」= 4 字 × 32px                                = 128px  ❌ 放不下
→ 8 个字要 3 行，并被 text-overflow 截断
```

截图里正是「购买高 / 级版单…」——**这就是用户说的"文字乱"**。

**在 192×490 手环 9 上推算（更糟）**：

```
卡片内宽 = 192 − 32 − 28 = 132px；减徽标 42 → 标题可用 90px
每行最多 2 个字（64px）→ 8 个字的标题要 4 行
```

### 4.4 附带发现（同一根因家族）

- `.section-title`（「激活软件」）只有 `padding-left: 4px`，是**左对齐**设计，与卡片居中风格不一致 → 也是"看着歪"的来源之一。
- `.status-card` 里 `剩余 21 天` 走的是条件渲染（`if="{{ statusDetail }}"`），与「有效期」「版本」三行的对齐方式各不相同。

## 五、关于「解锁高级版」弹窗（真正的"弹窗"）——本次**未能截图**

- 触发条件：`store.isPremiumUnlocked()` 为 **false** 时才会显示（`schedule-manager.ux` 的 `checkAndShowOverlay()` / `addSchedule()`；`settings.ux:149` 也有同名弹窗）
- 本机模拟器**已处于高级版状态**（截图显示「有效期 2026-10-17 / 剩余 21 天」）→ **弹窗无法自动触发**
- 因此对弹窗只能做**静态分析**（待非高级版环境下补截图）：

```css
.overlay-modal { align-items: center; justify-content: center; }   /* 遮罩居中 */
.modal-card    { width: 80%; align-self: center; padding: 20px 18px; }
.modal-title, .modal-desc { text-align: center; }                 /* 标题/说明居中 */
.benefit-list  { width: 100%; padding-left: 12px; }               /* ⚠️ 整体左内边距 12px */
.benefit-item  { text-align: left; }                              /* ⚠️ 逐条左对齐 */
```

⚠️ **弹窗内是"混合对齐"**：标题与说明**居中**，而「✓ 多课表管理 / ✓ 数据备份与恢复 …」4 条**左对齐**且带 12px 左内边距 → **同一卡片里三种对齐方式混用**，这极可能就是用户"靠左 + 歪歪扭扭"的第一现场。**建议优先修这里**，并在非高级版环境补一张实测截图。

## 六、修复建议（最小改动，按优先级）

| # | 改动 | 位置 | 效果 |
|---|---|---|---|
| 1 | `.step-title` 加 `flex: 1; min-width: 0; lines: 2; text-overflow: ellipsis;`；`.step-header` 加 `align-items: flex-start` | `activation.ux` | 标题占满剩余宽度、最多 2 行截断，不再"3 字一行" |
| 2 | 胶囊屏内降字号：`.step-title 32→26px`、`.status-main 40→32px`、`.status-expiry 28→24px` | `activation.ux` 的 `@media (shape: capsule/pill-shaped)`（目前**完全没覆盖这几项**） | 192px 上「购买高级版兑换码」≈ 得 2 行内 |
| 3 | 有效期拆成两行**有意**排版：`有效期` 与日期分成两个 text 并分别居中；或缩小字号 | `activation.ux` | 消除"参差不齐"的两行 |
| 4 | `.benefit-list` 去掉 `padding-left: 12px`；`.benefit-item` 改 `text-align: center`（或整块左对齐但标题也左对齐，**统一一种**） | `settings.ux` / `schedule-manager.ux` | 弹窗内对齐方式统一 |
| 5 | `.status-card` 文字 4px 左偏：加 `align-self: center` 或改用 `text-align: center` 复核 | `activation.ux` | 消除系统性偏移（需 192 复核后再定） |
