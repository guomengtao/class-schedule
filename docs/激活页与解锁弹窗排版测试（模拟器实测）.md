### 0.2 根因（比"排版"更根本）：**同一个弹窗被复制了 6~7 份，胶囊屏适配各不相同**


## 四、逐条判定（对着用户的三个疑问）

### 4.1 "弹窗有点靠左" —— 卡片本身不靠左，但**卡内文字块偏左 4px**

- 卡片：**严格居中**（16/16）。
- 卡内文字：三段测量得到**同一个中心 101.5**，比卡片中心 105.5 偏左 4px —— 是一个**系统性偏移**（不是某一处写错），怀疑与 `align-items: center` 在 Vela 上对文本块的取整/字体左右留白有关，**建议在 192×490 上复核**（本次只测了 212×520）。
- **观感上"靠左"更可能来自另一点**：状态卡里几行文字**宽度参差**（下面 4.2），视觉重心被拉偏。

### 4.2 "多处歪歪扭扭" —— 根因是**可用宽度不足导致强行折行**

截图里 `有效期 2026-10-17` 被拆成两行（「有效期」/「2026-10-17」），而模板里它本是**一行**：

```html
<text class="status-expiry" ...>有效期 {{ expireTimeText }}</text>
```

- `.status-expiry` = 28px；「有效期 2026-10-17」≈ 3×28 + 空格 + 10 字符 ≈ **226px**
- 卡片内宽 = 屏宽 212 − 页面 padding 32 − 卡片 padding 28 = **152px**
- 226 > 152 → **必然折行** → 两行长短差极大（3 字 vs 10 字）→ 这就是"歪歪扭扭"

### 4.3 "文字也乱" —— `.step-header` 把标题挤成 **每行 3 个字**

```html
<div class="step-card">
  <div class="step-header">          <!-- flex-direction: row -->
    <div class="step-badge">1</div>  <!-- 32×32 + margin-right 10 -->
    <text class="step-title">购买高级版兑换码</text>   <!-- font-size: 32px -->
  </div>
```

宽度账（212px 屏）：

```
卡片内宽   = 212 − 32(页面 padding) − 28(卡片 padding) = 152px
减徽标     = 152 − (32 + 10)                            = 110px  ← 标题只能用这么多
「购买高」  = 3 字 × 32px                                = 96px   ✅ 放得下
「购买高级」= 4 字 × 32px                                = 128px  ❌ 放不下
→ 8 个字要 3 行，并被 text-overflow 截断
```

截图里正是「购买高 / 级版单…」——**这就是用户说的"文字乱"**。

**在 192×490 手环 9 上推算（更糟）**：

```
卡片内宽 = 192 − 32 − 28 = 132px；减徽标 42 → 标题可用 90px
每行最多 2 个字（64px）→ 8 个字的标题要 4 行
```

### 4.4 附带发现（同一根因家族）

- `.section-title`（「激活软件」）只有 `padding-left: 4px`，是**左对齐**设计，与卡片居中风格不一致 → 也是"看着歪"的来源之一。
- `.status-card` 里 `剩余 21 天` 走的是条件渲染（`if="{{ statusDetail }}"`），与「有效期」「版本」三行的对齐方式各不相同。

## 五、关于「解锁高级版」弹窗（真正的"弹窗"）

> ⚠️ 本节原先写的是"本次未能截图"——**已被 §零 修正**：在 **`xiaomi_band`（192×490、未激活）** 上可正常触发，用户已提供 3 张实测截图，弹窗在该尺寸下**严重破碎**。下文的静态分析仍然有效，可作为代码侧补充。

- 触发条件：`store.isPremiumUnlocked()` 为 **false** 时才会显示（`schedule-manager.ux` 的 `checkAndShowOverlay()` / `addSchedule()`；`settings.ux:149` 也有同名弹窗）
- 我当时在 `xiaomi_band_10` 上测试，该实例**已是高级版**（「有效期 2026-10-17 / 剩余 21 天」）→ 所以看不到弹窗；**换成未激活的 `xiaomi_band` 即可复现**
- 代码侧静态分析：


## 十、第二处根因：胶囊屏弹窗"左小右大"（用户复测报告，已修复并实测）

### 10.1 现象与测量（`xiaomi_band` 192×490，`scripts/png-measure.js runrow`）

用户复测：文字改好了，但**卡片靠左、右边空一大块**，右侧还透出底页按钮。逐行色带实测：

| 截图 | 卡片区间 | 左边距 | 右边距 | 卡片宽 |
|---|---|---|---|---|
| `xiaomi_band-17-05-18`（设置页弹窗） | x=8..151 | **8** | **40** | 144 = **90% × 160** |
| `xiaomi_band-17-05-36`（首页设置弹窗） | x=8..167 | 8 | 24 | 160 |
| `xiaomi_band-17-05-45`（数据备份弹窗） | x=8..167 | 8 | 24 | 160 |

### 10.2 根因（两条，都与"居中"本身无关）

1. **卡片宽度用百分比 + 遮罩用 padding，是两套互不相干的计算**：
   `左边界 = 遮罩 padding-left`，而 `卡片宽度 = 某个基准 × 百分比`（实测基准 ≠ 屏宽）→ 只要两者不"配套"，左右必然不等。
   `90% × 160 = 144`、左 8 → 右 = 192 − 8 − 144 = **40** ✅ 与实测完全吻合。
2. **同一文件里存在两个 capsule `@media` 块，两处都写了同属性** → 实测**谁生效并不稳定**（`settings` 用了旧的 90%，`backup-restore` 用了新写的 100%）。所以"在后面追加一个块去覆盖"这条路**不可靠**（这也解释了 §9.1 那次"文字改了、宽度没改"）。

### 10.3 修复：让所有定义取同一个值（不再依赖级联顺序）

用脚本 `normalize_modal_geom.py` 把 7 个文件、**每个 capsule 块内**的弹窗几何统一为：

```css
.overlay-modal / .dialog-overlay { padding: 40px 16px; }   /* 左右对称 */
.modal-card    / .dialog-card    { width: 100%; }          /* 不用百分比、不用 max-width */
```

- 关键点：**卡片 `width: 100%` 填满"对称 padding 之后的内容区"** → 左边距 = padding、右边距 = padding，**与屏幕宽度无关，天然等距**（不是"算出来的居中"）
- 同时删掉 `max-width: 176px`：它在 212/336 屏上会把卡片卡窄，反而破坏这份对称

### 10.4 实测验证（修复后）

```

       左 8 | 右 8                       ✅ 完全对称
y=380: 内层按钮行 x=26..165（左右各 18） ✅ 内层也对称
```

## 十一、主题配色改为"底部抽屉弹"（用户要求，已实现并实测）

### 11.1 需求与原因

### 11.2 实现

| 位置 | 改动 |
|---|---|
| `settings.ux` 模板 | 删除页内 `if="{{ showTheme }}"` 展开区；页面末尾新增 `.theme-drawer > .theme-drawer-panel`（把手条 + 标题 + 两行主题 + 「完成」） |
| `settings.ux` 样式 | 抽屉用 `position: absolute; left: 0; bottom: 0; width: 100%` + 上圆角 `16px 16px 0 0`；胶囊块字号/圆点同步降档 |
| `settings.ux` 脚本 | `toggleTheme` 改为打开抽屉；新增 `closeThemeDrawer`；`selectTheme` 先 `showTheme = false` 再走"已解锁/未解锁"分支（否则未解锁时弹窗会被压在抽屉下面） |

### 11.3 关键坑：抽屉贴不到屏幕底（引擎差异）

第一版抽屉虽然贴底，但被页面自身的 padding 内缩（不到屏幕边缘）。原因：

> **Vela 里绝对定位子元素是按父级"内容盒"定位的，不是标准 CSS 的 padding 盒** —— 父级有 padding 时，`left: 0 / bottom: 0` 会从 padding 之内开始算。

解法：把页面 padding 从根容器**下移到内层容器**，抽屉留在外层不再受 padding 影响。

```
.settings-page { position: relative; }          /* 只留定位上下文 */
.settings-body { padding: 30px 16px; }          /* 页面内容的内层，承载 padding */
.theme-drawer-panel { left: 0; bottom: 0; width: 100% }  /* 贴屏幕四边 */
```

模板相应把页面内容包进 `.settings-body`，而抽屉/弹窗作为 `.settings-page` 的直接子元素。

### 11.5 模拟器部署知识（这次踩的坑，很有价值）

- 运行时**只认 `/data/quickapp/app/<包名>/` 这个"解包目录"**，`adb push` 一个 rpk 过去**不会**自动解包 → 必须本地解包后把文件推进目录（否则跑的还是旧代码，表现为"改了没生效"）
- 批量 `adb push` 目录经常在第一个文件后报 `failed to read copy response: EOF`；**改单页时只推 `pages/<页面>/<页面>.jsc` 最稳**（几十 KB，秒过）
- 刚推送完的第一次 `vapp` 启动可能黑屏，**再启动一次即可**（本次实测第二次成功）
- 目标目录可临时改名（`mv … _old_…`）来判断"运行时到底加载了哪个版本"，比猜可靠

## 十二、首页设置弹窗修复（同一个"根容器 padding"病根 + 两处文本预算缺陷）

### 12.1 决定性对比：同一份弹窗 CSS，两个页面对称性不同

| 页面 | 卡片实测区间 | 左边距 | 右边距 |
|---|---|---|---|
| 设置页（上轮已把 padding 移到内层） | x=16..175 | **16** | **16** ✅ |
| 首页设置（根容器仍带 padding） | x=8..167 | **8** | **24** ❌ |

**根因**：页面根容器 `.page` 在胶囊屏的 padding 是 `30px 8px 30px 8px`（左右各 8）。由于 **Vela 的绝对定位子元素按父级"内容框"计算**（不是标准 CSS 的 padding 盒），弹窗整体被右移 8px ⇒ 左 8 / 右 24。

**修法**（与 §11.3 抽屉同一个病根、同一个解法）：把 padding 从根容器下移到内层，弹窗作为根容器直接子元素。

```
.page      { flex: 1; width: 100%; height: 100%; }        /* 去掉 padding */
.page-body { padding: 30px 8px; }                          /* 内容内层承载 padding（4 个屏型块同步改） */
```

**实测（修复后）**：卡片 `x=16..175`（宽 160）⇒ **左 16 / 右 16 完全对称**。
