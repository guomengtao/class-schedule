# 日期选择器表盘 → 时分秒「时间鼓」重构方案

> 目标页：`src/pages/watch-face-pickdate/watch-face-pickdate.ux`（现 382 行）
> 目录条目：「日期选择器表盘」（`src/pages/watch-face-list/watch-face-list.ux:90`，路由 `:202`）
> 基线机型：小米手环 9 · 192×490 跑道屏（`xiaomi_band` / emulator-5554）
> 日期：2026-10-20
> 前序文档：`docs/日期选择器表盘-方案.md`（日期鼓的原始设计）、`docs/日期选择器改造为自动走时表盘-方案.md`（10-10 的官方 picker 路线，未落地）
> 复用基座：`src/pages/watch-face-flip`（commit `f3202b0` 已证明「裁切窗口 + 竖向数字带 + 推 top」在本引擎跑得通）

## 一、一句话目标

把这块表盘的主体从**「手动选的日期鼓」**换成**「自己走时的 时:分:秒 三鼓」**，
视觉继续用日期选择器那套基础样式（鼓窗切口、上下淡字、中央最亮），
但交互必须**像人的手指真的在拨它**：按下跟手、松手带惯性、最后吸附进格。

---

## 二、现状诊断（382 行，4 个硬伤）

| # | 问题 | 证据 | 后果 |
|---|---|---|---|
| 1 | **没有真滑动** | `applyDate(dir)` 里 `curCls` 切 `c1/c2`（top 132/144），120ms 后回 `c0` | 手指滑一下，数字只抖 6px 再弹回，本质是「闪一下」不是「滚过去」 |
| 2 | **不是时间表盘** | `tick()` 只在 `d !== lastDay` 时 `applyDate(0)` | 一天只重绘一次；它没有秒、没有分，连"几点"都不显示 |
| 3 | **鼓是假的** | 上下「邻居」`prevDay/nextDay` 是写死的独立 text，永远 16px | 中央 88px 与邻居 16px 之间没有连续位移关系，滚不起来 |
| 4 | **交互语义是"翻日期"** | 上滑 → 后一天、下滑 → 前一天、长按 → 回今天 | 与「时间表盘」的产品语义冲突，需要重定义 |

**结论：不是给 `cur` 加动画就能救。** 要换鼓的实现机制，只保留它的视觉语言。

## 三、"基础样式"到底继承什么、不继承什么

用户明确要求「使用日期选择器的基础样式」。逐条拆解，避免做成一块新表盘：

| 元素 | 现 pickdate | 新时间鼓 | 决策 |
|---|---|---|---|
| 页面底色 | `#0f1115` | `#0f1115` | **原样继承** |
| 鼓窗左右切口竖线 | `.cut-l/.cut-r`（1×106，`#333a42`） | 同款，高度随鼓窗 | **继承**，只改尺寸 |
| 鼓窗上下沿 | `.edge-t` 亮 / `.edge-b` 暗 | 同款 | **继承**（这是"切口"质感的来源） |
| 中央值最亮 + 邻居压暗 | `#e9eef2` vs `#454c54` | 同位色阶 | **继承** |
| 顶部 `MON` + 年份两行小字 | `sp()` 手撑字距 | 换成 `EV` + `时间鼓` 副标 | 位置继承、**内容换** |
| 底部 星期 + 细分割线 + 一年第几天 | `.wd` / `.hr` / `.doy` | **原样继承** | 日期信息保留在鼓外 |
| 中央值字号 88px | 单个「日」 | **缩到 52px** | 3 列 × 2 位数塞不进 88px |
| 交互：上下滑翻日期 | `browseOffset ±1` | 上下滑**拨时间** | **重定义**（见 §5） |

## 四、三条路线比选

### 路线 A：官方 `picker type="time"`（否决）

10-10 的 `日期选择器改造为自动走时表盘-方案.md` 推荐过它。否决理由已有实证：

1. 选中行位置、行高、可视区全不可控 → 做不出「鼓窗切口」这套基础样式；
2. 192px 宽塞 3 列 picker，每列只剩 ~60px；
3. `日期选择器表盘-方案.md` 已记录：picker 上叠动画会**每秒整页重绘**（闪烁来源）；
4. 更要紧的一条：**picker 的手感是系统给的，不是我们要的**。它的阻尼、吸附曲线改不了，"像人手工滑动"这个核心诉求它给不了。

### 路线 B：三层鼓 + 分帧推 `top`（可做，但只是"动画"）

复用 flip 的机制：`overflow:hidden` 窗 + `top: {{p}}px` 条带，JS 分 N 帧推过去。

- 优点：地基已验证（`f3202b0`），风险最低；走时场景够用。
- 缺点：**手指在屏上移动时画面不动**，松手才播动画。它"像视频"，不像"手在拨"。

### 路线 C：路线 B + 手势驱动（推荐）

在 B 的地基上加一次「位移直传」：

```
touchstart → 冻结走时，记 y0 与当前 offset
touchmove  → offset = base + (y0 - y)   ← 手指走 1px 画面走 1px
touchend   → 取末速度 v，惯性衰减 + 吸附整格
```

- 优点：唯一能满足「像人手工上下滑动」的路线；手感参数全在自己手里。
- 风险：**`ontouchmove` 在本引擎上没有任何先例**（下面 §5.1 细说）。

## 五、路线 C 的关键不确定性与降级链

### 5.1 头号风险：`ontouchmove` 是否有事件

实测统计（全仓库 77 页）：

```
grep -rn "ontouchmove" src/pages/   → 0 处
grep -rln "ontouchstart" src/pages/ → 8 处（全部只做 start/end 位移判定）
```

`docs/vela-unsupported-reference.md` 里也**没有** touchmove 的条目（既没写支持也没写不支持）。

所以 **P0 必须先做一次 5 分钟探测**，不许直接开写：

```html
<div class="page" ontouchstart="ts" ontouchmove="tm" ontouchend="te">
<text class="dbg">{{ dbg }}</text>

ts(e){ this.tmN = 0; this.dbg = "start" }
tm(e){ this.tmN++; this.dbg = "move " + this.tmN + " y=" + (e.touches?e.touches[0].clientY:e.clientY) }
te(e){ this.dbg = "end n=" + this.tmN }
```

判定标准：

| 探测结果 | 走向 | 说明 |
|---|---|---|
| `n ≥ 20` 且 y 连续变化 | **走路线 C-A（真跟手）** | 按 60Hz 估算，1 秒拖动应 ≥ 20 次 |
| `n` 很小（1~5）或 y 跳变 | 路线 C-B（**准跟手**） | 用稀疏采样插值，仍能跟手，略滞后 |
| `n = 0` | 路线 C-C（**降级**） | 退成路线 B + 惯性尾巴 |

**这条探测就是本方案的第一步交付物**，探测结论会回写进本文档。

### 5.2 降级链（每一级的观感差异要提前说清）

| 级别 | 跟手 | 惯性 | 观感 | 实现成本 |
|---|---|---|---|---|
| C-A | 1:1 真跟手 | 末速度衰减 + 吸附 | 和真表一样 | 中 |
| C-B | 采样插值跟手 | 同上 | 略有延迟 | 中 |
| C-C | ❌ 松手才动 | 按总位移/耗时推算"甩了几格" + 缓动落位 | 像有阻尼的动画，不像手拨 | 低（= B + 2 行） |
| 现状 | ❌ | ❌ | 闪一下 | — |

即使退到 C-C，也比现状好一个档：现状是 120ms 两帧抖动，C-C 至少有 200~300ms 的缓出 + 多余格数。

## 六、鼓的 DOM 结构：为什么不能用 60 格全量条带

分/秒是 0~59，若照抄 flip 的「11 格数字带」思路做成全量条带：

```
3 列 × 61 格（0~59 + 副本 0）= 183 个 text 节点
strip 高度 = 61 × 76 = 4636px
```

问题：节点数翻 16 倍、strip 高度近 5 屏，Vela 的内存与首次布局都不划算，且 4636px 的盒子在 490 屏上的裁切行为没验证过。

**采用「5 格滑动窗口」（虚拟带）**：

```
.win（宽 52 / 高 76 / overflow: hidden / position: relative）
  └ .strip（position: absolute / top: {{p_i}}px / flex column）
      ├ .d  idx -2   ← 缓冲（滚出视野上方）
      ├ .d  idx -1
      ├ .d  idx  0   ← 当前值
      ├ .d  idx +1
      └ .d  idx +2   ← 缓冲
```

- 节点数：3 列 × 5 格 = 15 个 text（另加冒号 2 个），比全量方案少 168 个；
- 每格 76 高，strip 共 380px，只有 `.win` 的 5 倍；
- **滚动过程纯位移、不改内容**（不闪）；只在落位后一次性重写这 5 格的文本，并把 `top` 归 0；
- 5 格窗口允许**一次滑 2 格不用重排**，够覆盖大部分甩动；超过 2 格时逐段串行（每段 ~90ms），观感上仍是连续滚动。

三种滚动场景共用同一个 `roll(col, targetIdx, ms, ease)`：

| 场景 | 触发 | 落位后 |
|---|---|---|
| 自动走时 | 每秒 tick，只对变化的列 | 写回 5 格文本，环形取模 |
| 手动跟手 | touchmove 实时写 `top`，**不进 roll** | touchend 后算 target |
| 惯性/吸附 | touchend | easeOut 到整格，再写回 |

## 七、手感参数（先给初值，实拍后调）

| 参数 | 初值 | 依据 / 调整方向 |
|---|---|---|
| `ITEM_H` | 76 | 中央字 52px + 上下各 12px 余量 |
| 跟手比例 | 1 : 1 | 手指走 1px 数字走 1px；若引擎有位移缩放再校 |
| 惯性衰减 | 每 16ms × 0.92 | 0.96 更"滑"、0.88 更"黏" |
| 惯性停止阈值 | \|v\| < 0.03 px/ms | 低于此不再外推，直接吸附 |
| 甩动最大格数 | 3 | 再大就会"一甩飞一整圈"，不像手表 |
| 吸附时长 | 120ms / 4 帧 easeOut | 太长显得拖、太短显得硬 |
| 自动走时帧数 | 5 帧 × 45ms | 沿用 flip 已验证值（225ms） |
| 手动互斥 | 手指按下即冻结走时 | 避免"手在拨、秒在抢" |
| 回现在的延迟 | 3 秒 | 复用现 pickdate 的 3 秒逻辑，语义从"回今天"改成"回现在" |

`easeOut` 用整数近似，避免浮点误差导致落不进整格：

```
// k = 1..N
top = start + (end - start) * (k * (2 * N - k)) / (N * N)   // 抛物线缓出
```

## 九、状态机与数据流

```
        ┌──────────────────────────────┐
        │            RUN               │  setInterval 1000ms
        │  tick：只roll变化的列          │
        └──────────┬───────────────────┘
      touchstart   │           3s 无操作（browse 态）
        ┌──────────▼───────────────────┐
        │           DRAG               │  touchmove 直写 top
        │  冻结 tick、冻结吸附           │  （C-C 降级时本态不存在）
        └──────────┬───────────────────┘
               touchend
        ┌──────────▼───────────────────┐
        │          GLIDE               │  惯性外推（可跳过）
        └──────────┬───────────────────┘
              |v| < 阈值
        ┌──────────▼───────────────────┐
        │         SETTLE               │  easeOut 落整格 + 写回 5 格
        └──────────┬───────────────────┘
            与真实时间不一致
        ┌──────────▼───────────────────┐
        │          PAUSE               │  3 秒倒计时 → 回到 RUN（对齐真实时间）
        └──────────────────────────────┘
```

**脏检查沿用 flip 的做法**：`shown[3]` 记录每列真正的 index，`tick` 只对变化列发 roll。
正常每秒只有秒列变化 → 1 次写入；跨分 2 列、跨时 3 列。

**令牌顶替**：每列一个 `tok[col]`，新动画递增，旧帧发现自己令牌过期就自杀，
避免「自动走时」和「手动吸附」两头抢写同一列。

## 十、必须遵守的三条历史铁律（改本页前必读）

1. **禁群组选择器** `.a, .b { }` —— 整张样式表被丢弃 → 黑屏（`docs/emulator-black-screen.md`）；
2. **禁 `transform` 数据绑定** —— 本页完全不用 transform，位移一律走 `top`；
3. **`.page` 只给 `width/height:100%` + `flex-direction: column`**，不加 `justify-content` / `align-items`；
   所有 absolute 子元素必须有 `position: relative` 的父级，否则会叠到页面左上角（flip v3 踩过）。

另：本页的 `overflow: hidden` 用在**有 relative 父级的绝对定位窗**上，这个组合已在 flip v4 实拍验证可用。

## 十三、风险表

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| `ontouchmove` 无事件 | **中高** | 拿不到真跟手 | 已设计 C-C 降级，产物仍是"有阻尼的滑动" |
| touchmove 频率过低（<10Hz） | 中 | 跟手顿挫 | 采样插值 + 只写 `top` 一个字段，减少 setData |
| 每秒 60 次数据写入触发 `domUpdate` 报错 | 低 | 掉帧/黑屏 | 限流：每 16ms 最多写 1 次；同一列合并写入 |
| 5 格窗口在连续甩动时露白 | 中 | 看到空档 | 限制单次 ≤3 格、逐段串行、落位必先写回再归 0 |
| 52px 字号放两位数字溢出（flip 踩过 46 塞 26） | 中 | 数字被裁 | 先按 52 出图核宽，超标降到 46；`text` 居中不折行 |
| 跨分/跨时连滚两列，观感抢戏 | 低 | 花 | 秒列滚 225ms、分列错开 120ms 起跑 |
| 与 `watch-face-flip` 手感不一致 | 低 | 系列割裂 | 两者共用 `ITEM_H/STEPS/STEP_MS` 常量语义，参数表写进本文档 |

## 十四、明确不做

- 不做官方 `picker`（理由见 §4 路线 A）；
- 不做农历、不做课程信息（`watch-face-class` 已承担）；
- 不做「选时间」的持久化语义——本页滑动的只是**显示**，不写系统时间（现 pickdate 的 `browseOffset` 也是同一原则）；
- 不拆成 6 个单数字鼓（6×30+2×12 = 204 > 192，且与日期选择器的"整块两位数"观感不符）。
