## 〇、需求更正（重要，防止再走弯路）

本方案**推翻了同日上一版**（自绘鼓 + 手势跟手 + 惯性 + 吸附）。原因：

- 用户原话：「不是真的跟着手操作，不需要，我意思本来是想简单用 picker 作为一种时间表盘而已」。
- 所以「像人手工上下滑动」= **用 picker 的原生滚动**，它的阻尼与吸附就是系统的手感，不用自己写。
- 自绘鼓那一套（`touchmove` 跟手、速度衰减、吸附缓动）**全部作废，不再实现**。
- 自绘鼓唯一还需要的东西是**外观**：保留页面既有的品牌行、日期行、提示行；主体换成 picker。

一句话：**主体交给官方 `picker`，我只负责排版、走时和交互出口。**

## 一、为什么 picker 这条路这次是对的

| 维度 | picker 原生 | 自绘鼓（上一版） |
|---|---|---|
| 上下滑手感 | 系统原生阻尼 + 吸附，**就是人手滑的样子** | 要自己采样、算惯性、写缓动，还可能因无 `touchmove` 而做不成 |
| 代码量 | 3 个标签 + 十几个字段 | 300+ 行状态机 |
| 黑屏风险 | 极低（不就动 transform / 不就动 scroll 嵌套） | 中（`overflow` 嵌套 + 每秒多字段写入） |
| 样式自由度 | **只能调 5 个属性**（见 §2） | 全自由 |
| 结论 | **采用** | 作废 |

上一版之所以绕开 picker，是因为要"机械日期鼓"的质感；而用户这次要的是**简单、能用**，不要求自绘质感。需求变了，路线就该变。

## 二、picker 的三条硬约束（先认清，再设计）

### 2.1 只能调 5 个属性

从 `date-picker-demo` / `countdown-date` 的实际用法看，picker 可定制项就这些：

```css
.pick {
  font-size: 25px;                 /* 未选中行字号 */
  color: #ffffff;                  /* 未选中行颜色 */
  selected-font-size: 30px;        /* 选中行字号 */
  selected-color: #7ec8e3;         /* 选中行颜色 */
  selected-background-color: #0f3460;  /* 选中行底色 */
}
```

行高、可视行数、选中行位置（永远居中）、上下淡出渐变**都不可控**。
这正好就是「日期选择器的基础样式」——本次直接沿用这套参数，不另创一套。

### 2.2 `type="time"` 没有秒

官方 time picker 只给 时 : 分。要「秒」只有一条路：

```html
<!-- 时 -->
<picker type="text" range="{{ hours }}"   selected="{{ hIdx }}" onchange="onH"></picker>
<!-- 分 -->
<picker type="text" range="{{ mins }}"    selected="{{ mIdx }}" onchange="onM"></picker>
<!-- 秒 -->
<picker type="text" range="{{ secs }}"    selected="{{ sIdx }}" onchange="onS"></picker>
```

三列全用 `type="text"` + 字符串 range，好处是**三列外观完全一致**（不会出现"时分是一套、秒是另一套"）。

### 2.3 表盘页从没用过 picker

```
grep -rln "<picker" src/pages/  →  只有 countdown-date、date-picker-demo（都是普通页）
grep -rln "<picker" src/pages/watch-face*  →  0
```

`manifest.json` 里表盘页只是普通注册（`"pages/watch-face-pickdate": { "component": ... }`），
没有特殊标记，理论上 picker 能跑。但**没先例 = 必须实测**，这是本方案 P0 的第一项。

另有一条历史记录要正面处理：`日期选择器表盘-方案.md:19` 写过
「`selected` 一变就整块重排」+「picker 上叠 `animation` 会每秒重绘」。
当时是**每秒同时写 `mIdx` + `animClass` 两个字段**，且 picker 上还叠了动画。
本次不同（每秒只写 `sIdx` 一个字段、不叠动画），但**仍需实测是否闪**。

## 三、三种形态候选

### 形态 A · 横排三列（推荐先试）

```
┌────────────────────┐
│        EV          │
│      时 分 秒       │
│                    │
│  ┌──┐    ┌──┐    ┌──┐
│  │19│ :  │47│ :  │08│   ← 3 个 picker，各 52 宽
│  └──┘    └──┘    └──┘
│                    │
│   10-20  周二       │
│   293 / 365 天      │
└────────────────────┘
```

- 宽度账：`52 × 3 + 12 × 2 = 180`，左起 6，两侧各留 6。
- 未知量：**picker 能不能接受 CSS `width: 52px`**。若 picker 内部写死整宽或最小宽，会溢出错行。
- 优点：最像表盘，一屏看全。

### 形态 B · 纵排三行（A 失败时的保底）

```
┌────────────────────┐
│        EV          │
│   19               │  ← 时 picker，整宽 192
│   47               │  ← 分 picker
│   08               │  ← 秒 picker
│   10-20  周二       │
└────────────────────┘
```

- 每行一个整宽 picker，**不依赖宽度约束**，最稳。
- 缺点：像"三个选择器叠起来"，不像表盘；每行可视行数少，上下邻居露得少。

### 形态 C · `type="time"` + 秒列（否决）

时:分用原生 time picker，秒用 text picker 补一列。否决原因：两种 picker 的
行高/字号基准很可能不一致，并排会出现"秒列和时分列对不齐"，正好踩中"不可控"这条。

**倾向：A 先试，30 分钟出结论；不行立刻切 B，不再纠缠。**

## 四、P0 实测结论（2026-10-20 12:20~12:30，已跑完）

| # | 问题 | 结论 | 证据 |
|---|---|---|---|
| P0-1 | picker 能否在表盘页渲染 | ✅ 能，首次构建即出图 | `/tmp/vela-loop/pick-v1.png`：三列 `12:19:42` |
| P0-2 | 能否用 CSS 约束宽度 | ✅ 生效，`width:52 / height:150` 都吃 | 三列并排无溢出、无折行 |
| P0-3 | `selected` 每秒变会自己滚吗 | ⚠️ **值会变，但瞬间定位、没有滚动动画** | 14 帧 / 1.08s 连拍只出现 **2 种**画面 |

### 由实测新增的四条认知（方案原稿没预料到）

1. **"像鼓"靠的是高度，不是字号**：`height:76` 只露 1 行（观感像单行文字）；
   改成 `height:150` 露 3 行（行高 50），上下邻居才出现。这是本页观感的分水岭。
2. **未选中行默认白色太亮**：`color:#ffffff` 时三行抢戏，压到 `#5a6470` 才有远近层次。
3. **`selected-background-color` 看不出来**：设了 `#0f3460`，实拍选中行没有明显色块，
   疑似被组件忽略。选中感只能靠 `selected-color` + `selected-font-size`，
   另加两条 1px 上下沿（`#2f3846` / `#232a34`，落在选中行上下边）补"鼓窗"的形。
4. **滑动会冒泡成页面点击 —— 最危险的一条**：
   页面根节点挂 `onclick` 时，一次 drag 会被判成点击 → `router.replace` 回目录。
   给鼓区加 `onclick="stopBubble"` **拦不住**（实测照样跳页）。
   **最终解法：页面根节点不挂 onclick，返回改到顶部 120px 热区**，
   鼓区（150~300）与热区完全不重叠。代价是不能再"点任意处返回"，
   hint 改为「上下滑调时 · 点顶部返回」。

### 最终形态

三列 picker 鼓（52 宽 / 150 高 / 三行可见）+ 自动走时（秒跳变）+ 3 秒回现在 + 顶部热区返回。

秒位是**跳变**而非滚动：这是 picker 的固有行为（`selected` 赋值不做补间动画），
用户已确认不需要自绘滚动，故不再追求。

## 五、走时设计（已实现）

### 5.1 脏检查：每秒只写变化的列

```js
tick() {
  const d = new Date()
  const H = d.getHours(), M = d.getMinutes(), S = d.getSeconds()
  // 只在值真的变了才写，避免每秒 3 次 setData
  if (H !== this.shownH) { this.shownH = H; this.hIdx = H }
  if (M !== this.shownM) { this.shownM = M; this.mIdx = M }
  if (S !== this.shownS) { this.shownS = S; this.sIdx = S }
  // 日期行：跨日才写
  ...
}
```

- 常态每秒只写 **1 个字段**（秒列）；
- 跨分写 2 个、跨时写 3 个，都是必要的；
- 绝不写 `animClass`、绝不在 picker 上叠 `animation`（历史闪烁根因）。

### 5.2 抑制 change 回环

`selected` 被程序改动后，picker 可能回报一个 `change`：

```js
onS(e) {
  if (this.suppress) { this.suppress = false; return }   // 自己写的，忽略
  this.browseS = e.newSelected                            // 用户手滑了
  this.manualTs = Date.now()
}
```

**实现时改成了更稳的"值比较"**，不用布尔标记：

```js
onManual(i, e) {
  const v = e.newSelected
  if (v === this.shown[i]) return   // 程序刚写进去的值回环 / 值没变 → 忽略
  this.shown[i] = v                  // 用户真的滑了 → 接受
}
```

布尔标记的隐患是：若程序写入后**不回环**，标记会残留成 `true`，把用户下一次真手滑吞掉。
值比较没有状态，天然免疫。

### 5.3 手动滑之后：3 秒回现在

沿用现 pickdate 的成熟做法（它现在是"3 秒回今天"，这里改成"3 秒回现在"）：

```
手指滑过 → 进入 browse 态，停止 tick 写入
3 秒无操作 → 三个 selected 一次性对齐真实时间 → 回 RUN
```

倒计时提示写在底部 `.hint`（`3 秒后回到现在`），复用现有文案位。

### 5.4 定时器纪律

- `setInterval(1000)` 起在 `onInit`，清在 `onHide` / `onDestroy`（**两个都要清**，flip 表盘踩过漏清）；
- 整秒对齐用 `setTimeout(1000 - now % 1000)` 再起 interval，避免跳秒；
- 表盘页可能被系统挂起，`onShow` 里补一次 `tick()` 兜底。

## 十、明确不做

- ❌ 自绘鼓 / 手势跟手 / 惯性 / 吸附（本版已删除，理由见 §0）；
- ❌ `transform` 数据绑定、`scroll + scrolltop`（本引擎已验证不可用）；
- ❌ 在 picker 上叠 `@keyframes` 动画（历史每秒重绘的根因）；
- ❌ 持久化写系统时间——滑动只改显示；
- ❌ 农历、课程信息（后者由 `watch-face-class` 承担）。
