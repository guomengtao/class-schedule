## 问题 1：设置改「模版选择」后首页不生效

### 现象
在设置里改了模板，回到首页没变化。你怀疑首页模板代码和周列表（总课表）模板搞混了。

### 排查

设置项（`settings.ux` L81-87）：

```html
<div class="row" onclick="openTemplatePicker">
  <text class="row-label">模版选择</text>
  <text class="row-hint">{{ currentTemplateName }}</text>
</div>
```

- `openTemplatePicker()` → `router.push({ uri: "/pages/template-picker" })`
- `loadTemplateName()`（L531-541）读的是 **`store.getWeekViewTemplate`**

而首页 `index.ux` 全量检索 `template`：

```
只有 <template> 标签本身 + reloadTemplate（与总课表模板无关）
```

**首页不使用这个模板数据。**

### 根因

**不是代码 bug，是作用域被误解 + 文案误导。**

- 「模版选择」这个设置项绑定的是 **总课表（week-view）模板**，它只影响 `week-view` 页面；
- 首页的布局/栏目由 **首页设置（homepage-settings）** 控制，是另一套数据；
- 但设置项文案只写了笼统的「模版选择」，用户自然会以为它管首页。

你的直觉方向是对的：**确实是"首页模板"和"周列表模板"被混为一谈了**——只不过混淆发生在**文案和用户认知**层面，代码并没有串。

### 修复建议

1. **改文案**（最低成本、立即生效）：设置项改为「**总课表模版**」，hint 补「仅影响总课表页面」。
2. 若确实需要"首页模板"（首页布局方案），需另建一套数据与页面，不能复用 week-view 模板。
3. 长期：把设置项按作用域分组（首页相关 / 总课表相关 / 全局），避免同类误解。

### 验证
改设置 → 进入**总课表**页面看是否变化（应变化）；首页不变是预期行为。

## 问题 2：方屏头部箭头过大、加号黑框、无「添加课程」文字

### 现象
方形屏幕：① 头部左右切换按钮圆圈大小合适但要**三角形改小**；② 底部加号按钮（蓝色主题）显示为**黑框**；③ 方屏希望**保留「添加课程」文字**。

### 排查

**① 箭头过大**

`index.ux` 方屏块（`@media (shape: rect)` L1215-1218）：

```css
.nav-btn-img {
  width: 48px;
  height: 48px;      /* ← 箭头图片被设成 48px，与圆圈同大 */
}
```

模板 L8-10 / L23-25：左右切换是 `<div class="nav-btn-circle"><image class="nav-btn-img">`——
**圆圈是容器、箭头是图片**。方屏把箭头图片设成 48×48，等于三角形撑满整个圆圈，所以显得笨重。

对照：胶囊屏块把箭头设为 22×22（容器内居中，视觉合适）。

**② 加号黑框**

我上一轮把加号按钮改成透明底 + 描边（解决胶囊屏实心块问题）：

```html
<div class="add-btn-wrapper"
     style="background-color: transparent; border-width: 2px; border-color: {{ theme.accent }}">
```

这个改动**对所有屏型生效**。方屏块（L1344-1349）只定义了：

```css
.add-btn-wrapper {
  flex: 1; height: 42px; border-radius: 21px; margin-right: 3px;
}
```

**没有背景/边框定义**，于是方屏也变成透明底 → 深色页面底色透出来 → 看起来是「黑框/黑洞」。

**③ 方屏文字**

模板：`if="{{ !isCapsule }}"` → 方屏**会显示**文字，方屏块也定义了 `.add-btn-label { font-size: 20px }`（L1354）。
但方屏下 `add-btn-wrapper` 是 `flex: 1` 且与 `style-btn` 并排，图标 + 文字可能挤压。

### 根因

| 项 | 根因 |
|:---|:---|
| 箭头过大 | 方屏 `.nav-btn-img` 被设成 48×48（应与圆圈区分，取 24~28） |
| 加号黑框 | 透明底改动**未区分屏型**，方屏深色底上呈现黑框 |
| 文字 | 逻辑上已显示，但方屏布局下可能被挤压/截断 |

### 修复建议

1. **箭头**：方屏 `.nav-btn-img` 48 → **28**（圆圈保持 48 不变，箭头居中）—— 即"圆圈不变、三角形改小"。
2. **加号按钮按屏型区分**：
   ```html
   style="background-color: {{ isCapsule ? 'transparent' : theme.accent }};
          border-width: 2px; border-color: {{ theme.accent }}"
   ```
   方屏恢复**蓝色实心**（即你要的"蓝色模板"），胶囊屏保留透明描边。
3. **方屏文字**：确认 `add-btn-wrapper` 在方屏给文字留够宽度（必要时调 `flex` 比例或减小 icon）。

### 验证
方屏真机：箭头视觉大小、加号是否为蓝色实心、文字是否完整显示。

## 问题 3：删除后首页不更新 + 二次删除报错不友好

### 现象
编辑页删除课程后首页不刷新；回到编辑页课程还在；再点删除提示报错且不友好。

### 排查

**删除链路**（`detail.ux` L640-716）：

```
deleteCourse() → database.deleteCourse(classId, day)
  ├─ 成功 → showUndo()（停留本页 5 秒撤销窗口）
  │         └─ 5 秒后 finishDelete() → router.back()
  └─ 失败 → toast「删除失败: xxx」
```

**首页刷新链路**（`index.ux`）：

```
onShow() (L299)
  └─ loadScheduleData(idx, true)          ← forceRefresh = true
       └─ database.getAllCoursesWithIndex(idx, cb, true)
            └─ if (forceRefresh) invalidateCache(index)   ← database.js L739
                 └─ getAllCoursesStorageWithIndex() 重读 storage
```

`invalidateCache`（database.js L159-167）会 `delete _cache[index]` 并置 dirty，**链路本身是正确的**。

**错误文案**（database.js L375-376）：

```js
logErr("deleteCourseStorage course not found: " + id + " day " + day)
callback(formatError("deleteCourseStorage", "课程不存在"))
```

→ 用户界面直接弹出「**删除失败: 课程不存在**」，用户不知道该怎么办。

### 根因分析

**3a. 首页未刷新 —— 代码链路正确，需进一步定位（待验证）**

已排除：forceRefresh / invalidateCache 逻辑本身没问题。

剩余可能（按可能性排序，需日志验证）：

| 可能 | 说明 | 验证方法 |
|:--:|:---|:---|
| ① `_skipNextShow` 时序 | `index.ux` L270 置 true、L311 消费；若返回首页时该标志仍是 true，会跳过整条刷新（只 `$forceUpdate`） | 在 onShow 打日志看是否命中 `return` |
| ② 删除的 `day` 与首页当前 `day` 不一致 | 编辑页改过星期但**未保存**时，`self.day` 是新值；删除的是新 day 记录，原 day 记录仍在 → 首页（原 day）看起来"没变" | 删除前后打印 `self.day` 与首页 `currentDay` |
| ③ 页面栈导致 onShow 未触发 | 若首页被销毁后重建，onInit 会加载（应正常）；若 `!self.initialized` 提前 return | 打日志确认 onShow 是否进入 |

**3b. 二次删除报错不友好 —— 确认**

`deleteCourseStorage` 找不到记录时返回「课程不存在」错误，直接 toast。
从用户视角："我明明看到这门课，点删除却说不存在"——典型的不友好错误。

### 修复建议

1. **首页刷新（先验证再改）**：
   - 建议删除成功后**主动失效缓存并通知首页**：在 `database.deleteCourse` 成功后已 `invalidateCache`（确认 L679 附近），可再加一个 storage 脏标记（如 `courses_dirty`），首页 `onShow` 检测到即强制刷新，**不依赖 `_skipNextShow` 判断**。
   - 或：`onShow` 中把 `_skipNextShow` 的跳过范围**限制为"仅跳过读盘"但保留 `loadDayClasses()`**，避免界面用旧数据。
2. **编辑页删除前校验 day**：删除时用 `originalDay`（记录的原始星期）而非当前 `day`，避免"改了星期没保存导致删错天"。
3. **错误文案友好化**：
   - 「课程不存在」→ 视为**已删除**：`toast「该课程已删除」` + `router.back()`，而不是报错。
   - 真正的失败（写盘错误）才提示「删除失败，请重试」。

### 验证
删除 → 立刻看首页是否少一门课；再进编辑页点删除，看提示是否友好。

## 问题 4：输入法点「更多」后文字被挤压、宽度丢失

### 现象
打开输入法，点开「更多」（展开面板）后，文字被挤压，宽度设置丢失。

### 排查

`chinese-input.ux` 使用输入法组件（L21-29）：

```html
<input-method
  keyboardtype="QWERTY"
  maxlength="{{ maxlen }}"
  screentype="{{ screenType }}"
  oncomplete="onCharacter" ondelete="onDeleteChar">
```

`screenType` 默认 `"pill-shaped"`（L47），`onInit` 里**异步**探测后赋值（L61-69）：

```js
device.getInfo({ success: function(data) {
  var shape = data.screenShape || "circle"
  if (shape === "capsule") shape = "pill-shaped"
  self.screenType = shape
}})
```

`InputMethod.ux` 内部（`src/components/InputMethod/`）：

| 行 | 代码 | 问题 |
|:--:|:---|:---|
| L263 | `if="{{screentype==='pill-shaped'}}"` → `width:100%; height:305px` | 高度写死 |
| L166 | `if="{{screentype==='rect'}}"` → `width:100%; height:255px` | 高度写死 |
| L265/266 | `margin-left: {{(screenWidth - 192)/2}}px` | **硬编码 192** |
| L303/323 | `left: {{(screenWidth - 192)/2}}px; width: 192px` | **硬编码 192** |
| L407 | `screenWidth: 336` | rect 默认宽 |
| L811-818 | `adjustScreenWidth()` 用 `device.getInfo` 取真实宽度 | 异步 |

### 根因

1. **硬编码胶囊屏宽度 192px**（L265/266/303/323）：不论实际屏宽多少，内容区都按 192px 计算并居中。方屏（336px）下两侧各留白 72px，内容挤在中间 192px —— 这就是"**宽度设置丢失**"。
2. **键盘区高度写死**（rect 255px / pill 305px）：展开「更多」面板（候选/符号）时，容器高度固定，空间从上方输入显示区挤占 —— 这就是"**文字被挤压**"。
3. **screenType 异步**：首帧用默认 `pill-shaped`，真实屏型回来后才切换（组件有 `$watch("screentype","adjustScreenWidth")`），可能先错后跳，观感像"宽度丢失"。

### 修复建议

1. **去硬编码 192**：改为按屏宽动态计算内容宽度
   ```js
   // 例如：内容宽度 = min(screenWidth, 屏型上限)，偏移 = (screenWidth - contentWidth)/2
   ```
   把 L265/266/303/323 的 `192` 换成 `contentWidth` 变量。
2. **输入显示区固定/最小高度**：给 `input-display`（`chinese-input.ux` L12）设 `min-height`，面板展开时不压缩它；键盘区高度改为自适应或给面板单独区域。
3. **screenType 首帧**：在拿到真实屏型前显示 loading 或用屏型无关的基础布局，避免错乱闪动。

### 验证
方屏 + 胶囊屏分别打开输入法 → 点「更多」，检查文字是否挤压、内容宽度是否占满。
