## 一、验收过程

按 ev-page-job 方案执行：`vela-loop.py --page activation --entry --scroll 0 --tap ...`
（emulator-13000，小米手环9 标准版 192×490）。首轮即暴露两个缺陷。

## 二、发现的缺陷与修复

### 缺陷1（阻断）：子页正文完全不渲染

- 现象：从主页点「输入激活码」进入子页，只有头部（返回箭头+标题），
  18 格码位 / 键盘 / 验证按钮 / 结果框全部不渲染。
- 根因：抽取新页时漏掉 `.page-scroll` 样式类。该类定义在 activation.ux
  自身样式块（`flex:1; flex-direction:column`），是本项目每页滚动容器
  的固定模式（对照 device-info 的 `.di-scroll`）。新页 `<scroll class="page-scroll">`
  无样式 → 无高度约束 → 正文不渲染。
- 修复：新页样式块补 `.page-scroll { flex:1; flex-direction:column; }`。

### 缺陷2（验收不达标）：布局超出一屏

- 现象：修复渲染后，键盘底行贴屏幕底缘，「验证」按钮在折叠下方。
  抽取自原页的尺寸（格 50px / 键 50px / padding 44px）总高 ≈492px，
  超出可用 434px，违背本步骤「主任务一屏内完成」的目标。
- 修复（紧凑化，全部保持审计合规：显式高度 ≥44px、字号 ≥18px）：
  - `.cell` 高 50→44、`.keypad-btn` 高 50→44、`.verify-btn` 高 48→44
  - `.page` padding 44/12→38/8；`.cells-grid`/`.keypad` 间距 12→10
  - 结果框仍为流式布局位于折叠下方；即时结果反馈由既有 toast 承担
    （doVerify 每个分支均 showToast）。

## 四、附注（流程教训）

1. **点击时机**：冷启约 14s「画面稳定」≠ 页面稳态——状态卡异步加载
   （加载中→高级版）会位移布局，此时点按钮必脱靶或黑屏。验收点击须在
   稳态确认后进行（本次 vela-loop 固定 3.3s 补拍太早，改受控手动点击）。
2. **二级页当 entry**：pages/activation 作 entry 冷启仍会崩（手动与
   vela-loop 均复现），验收直达靠 am stop + 全新 vapp 会话 + 重试。
