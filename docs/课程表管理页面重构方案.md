# 课程表管理页面重构方案

## 一、现状问题分析

### 1.1 onclick 嵌套冲突（核心问题）

当前模板中，`item-header` 父级 `<div>` 和内部的 checkbox 都存在 `onclick`：

```html
<!-- 问题代码 -->
<div class="item-header" onclick="selectSchedule($idx)">     ← 父级 onclick
  <div class="checkbox" onclick="selectSchedule($idx)">       ← 子级 onclick（冲突）
    <text>✓</text>
  </div>
  <text class="schedule-name">...</text>
</div>
```

快应用框架对嵌套 `onclick` 处理不稳定，子元素（尤其是 `<text>`）会拦截点击事件，导致事件无法正确冒泡到父级或被子级截断。

### 1.2 架构问题

| 问题 | 说明 |
|------|------|
| 父级 div onclick 范围过大 | 整个 `item-header` 绑定了 `selectSchedule`，但内部还有多个子元素（checkbox、名称、徽章），点击目标不明确 |
| 事件冒泡不可靠 | 快应用的 `<text>` 组件点击行为与 `<div>` 不同，子元素点击不保证冒泡 |
| 模板与样式耦合 | 大量 inline style 绑定，模板臃肿，难以维护 |
| 重命名栏/编辑状态耦合 | `editingIndex` 状态散落在多个函数中，逻辑分散 |

### 1.3 功能列表

当前 schedule-manager 包含以下功能：
- 选择/切换课程表（`selectSchedule`）
- 重命名（`startRename` / `finishEdit` / `cancelEdit`）
- 复制（`copySchedule`）
- 删除（`deleteSchedule`，二次确认）
- 新增（`addSchedule`）
- 导出二维码（`openQrPopup`）
- 总览（`openWeekView`）
- 统计（`openScheduleStats` / `openStatistics`）

---

## 二、重构目标

1. **彻底解决 onclick 嵌套问题** — 每个可点击元素独立绑定 onclick，不依赖事件冒泡
2. **简化模板结构** — 减少 inline style，使用 CSS 类
3. **保持功能完整** — 所有现有功能均保留
4. **独立于原页面** — 新建文件，原页面不动，通过实验室入口访问

---

## 三、重构方案

### 3.1 新页面文件

| 文件 | 路径 |
|------|------|
| 页面组件 | `src/pages/schedule-manager-v2/schedule-manager-v2.ux` |

### 3.2 模板结构（扁平化，无嵌套 onclick）

```
┌─────────────────────────────────────────┐
│  ◀ 返回         课程表管理         统计  │  ← 顶部栏
├─────────────────────────────────────────┤
│  [输入框: 新名称]        [保存] [取消]   │  ← 重命名栏（show 控制）
├─────────────────────────────────────────┤
│  ┌───────────────────────────────────┐  │
│  │ ☑ 课程表1                   使用中 │  │  ← 卡片头部（纯展示，无 onclick）
│  ├───────────────────────────────────┤  │
│  │ [选择] [重命名] [复制] [导出]     │  │  ← 每行独立 onclick
│  │ [总览] [统计] [删除]             │  │
│  └───────────────────────────────────┘  │
│  ┌───────────────────────────────────┐  │
│  │ ☐ 课程表2                         │  │
│  ├───────────────────────────────────┤  │
│  │ [选择] [重命名] [复制] [导出]     │  │
│  │ [总览] [统计] [删除]             │  │
│  └───────────────────────────────────┘  │
├─────────────────────────────────────────┤
│  [+ 新增课程表]                         │  ← 底部按钮
└─────────────────────────────────────────┘
```

### 3.3 关键设计决策

#### 决策1：选择按钮替代全区域点击

**原方案**：整个 `item-header` 可点击 → 与子元素 onclick 冲突  
**新方案**：头部纯展示，新增独立的「选择」按钮，点击后切换课程表并返回主页

```html
<!-- 每个课程表卡片 -->
<div class="schedule-item">
  <!-- 头部：纯展示 -->
  <div class="item-header">
    <div class="checkbox-icon">✓</div>          <!-- 选中状态图标，无 onclick -->
    <text class="schedule-name">课程表1</text>
    <text class="badge">使用中</text>           <!-- 仅当前项显示 -->
  </div>
  
  <!-- 操作按钮：每个独立 onclick -->
  <div class="actions-grid">
    <div class="action-row">
      <div class="action-btn" onclick="selectSchedule($idx)">选择</div>    <!-- 独立 onclick -->
      <div class="action-btn" onclick="startRename($idx)">重命名</div>
      <div class="action-btn" onclick="copySchedule($idx)">复制</div>
      <div class="action-btn" onclick="openQrPopup($idx)">导出</div>
    </div>
    <div class="action-row">
      <div class="action-btn" onclick="openWeekView($idx)">总览</div>
      <div class="action-btn" onclick="openScheduleStats($idx)">统计</div>
      <div class="action-btn delete-btn" onclick="deleteSchedule($idx)">删除</div>
    </div>
  </div>
</div>
```

#### 决策2：checkbox-icon 纯展示

勾选图标仅作为视觉指示器，不绑定 onclick。选中状态由 `$idx === currentIndex` 控制 CSS 样式。

#### 决策3：保留原页面

原 `schedule-manager.ux` 不动，新页面为 `schedule-manager-v2.ux`，通过实验室入口测试。

## 四、实施步骤

### Step 1：创建新页面文件

```
src/pages/schedule-manager-v2/
  └── schedule-manager-v2.ux
```

### Step 2：注册路由

在 `src/manifest.json` 的 `router.pages` 中添加：

```json
"pages/schedule-manager-v2": {
  "component": "schedule-manager-v2"
}
```

### Step 3：在实验室添加入口

在 `src/pages/test-area/test-area.ux` 中添加菜单项：

```html
<div class="menu-item" onclick="openScheduleManagerV2" style="background-color: {{ theme.card }}">
  <text class="menu-label" style="color: {{ theme.text }}">课程表管理 V2</text>
  <div class="menu-right">
    <text class="menu-desc" style="color: {{ theme.textMuted }}">重构版课程表管理</text>
    <text class="menu-arrow" style="color: {{ theme.textMuted }}">›</text>
  </div>
</div>
```

### Step 4：实现功能

按照原页面功能逐一实现，保持与 `store.js` 和 `database.js` 的接口一致。

## 六、状态管理

| 状态 | 类型 | 说明 |
|------|------|------|
| `scheduleList` | Array | 课程表名称列表，从 `store.getScheduleNames` 加载 |
| `currentIndex` | Number | 当前使用的课程表索引，从 `store.getCurrentScheduleIndex` 加载 |
| `editingIndex` | Number | 正在重命名的课程表索引，-1 表示未编辑 |
| `editName` | String | 重命名输入框的值 |
| `deleteConfirmIndex` | Number | 删除确认状态，-1 表示未确认 |
| `theme` | Object | 主题色配置，从 `store.getTheme` 加载 |

---

## 七、数据流

```
loadData()
  ├── store.getScheduleNames() → scheduleList
  └── store.getCurrentScheduleIndex() → currentIndex

selectSchedule(index)
  └── database.setScheduleIndex(index)
       └── currentIndex = index
       └── router.back()

addSchedule()
  └── store.setScheduleNames(names)
       └── loadData()

deleteSchedule(index)
  └── store.setScheduleNames(names)
       └── database.setScheduleIndex(newIndex)
            └── loadData()
```

## 八、测试要点

1. 点击「选择」按钮能否切换课程表并返回主页
2. 勾选图标是否正确显示当前选中状态
3. 重命名、复制、删除、新增功能是否正常
4. 删除确认二次点击逻辑是否正常
5. 删除当前使用的课程表后，是否正确切换到索引 0
6. 主题色是否正确应用
7. 三种屏幕形状（circle/capsule/rect）的响应式布局是否正常
