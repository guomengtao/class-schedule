# 包体构成分析（2026-09-25）

> 起因：反馈"包怎么还是那么大"。本文解压实包逐项核对，定位体积构成，并逐项排查是否有多余内容。

## 一、先分清两个包：debug 2.4MB / release 809KB

同一版本号（1.6.123）下 `dist/` 可能同时存在两种包，体积差 **3 倍**：

| 类型 | 文件名 | 压缩包 | 解压后 | JS 形态 |
|---|---|:---:|:---:|---|
| **debug** | `…classschedule.debug.1.6.123.rpk` | **2,533,212（2.4MB）** | **15MB** | 明文 `.js`（如 `chinese-input.js` = 1.77MB） |
| **release** | `…classschedule.release.1.6.123.rpk` | **828,681（809KB）** | 2.1MB | `.jsc` 字节码（同名页面仅 233KB） |

**结论：如果看到的是 2.4MB，那是 debug 包。** 给用户测试/发布的应当是 **release 包**（`aiot release --enable-jsc` 产出）。debug 不启用 JSC、保留明文源码，体积必然大三倍，这是正常的。

> 注：`dist/` 是 `npm run clean` 清理的目录，`aiot release` 产出会**覆盖** debug 包，两者不会同时长期存在。

## 二、release 包（809KB / 解压 2.1MB）构成

| 部分 | 未压缩字节 | 占比 |
|---|:---:|:---:|
| `pages/`（28 个页面） | **1,710,498** | **81%** |
| `app.jsc` | 55,680 | 3% |
| `components/`（键盘 PNG ×61） | 95,413 | 4.5% |
| `common/` 图标 | ~104,000 | 5% |
| `logo.png` | 10,385 | 0.5% |
| manifest / config / i18n / data | ~30,000 | 1.5% |

**`pages/` 是唯一的大头（81%）**，其余全部加起来不到 20%。

### 2.1 两个"巨无霸"页面 = 整包体积的 1/4（未压缩）

| 页面 | 字节 | 占整包（未压缩） |
|---|:---:|:---:|
| `pages/input-crash-diag/input-crash-diag.jsc` | **250,598** | **13%** |
| `pages/chinese-input/chinese-input.jsc` | **233,289** | **12%** |
| **两者合计** | **483,887** | **25%** |
| 其余 27 页合计 | 1,226,611 | 63% |

> 压缩后这两页约占发行包的 **58%**。

### 2.2 原因：词典被"整份复制"进每个引用页

两个页面都 `<import>` 了 `components/InputMethod/InputMethod.ux`，而键盘组件会把这些词典文件**内联**进页面：

| 词典源文件 | 字节 |
|---|:---:|
| `dic.js`（6763 单字表） | 26,314 |
| `dic_words.js`（词库） | 69,043 |
| `dic_words_initials.js`（简拼倒排） | 41,020 |
| `dic_jp.js`（日文表） | 25,116 |
| `pinyin_syllables.js` | 3,513 |
| `dicUtil.js` | 20,125 |
| **合计** | **~185,000** |

**Vela 打包按页面独立 bundle，没有共享 chunk 机制** —— 引用一次就复制一份。目前有 2 个页面引用 → **词典被打了两份（约 370KB 未压缩）**。

证据：`components/` 在包内只有 **61 个 PNG、95KB**，**不含任何组件 JS** —— 组件代码已全部内联到引用页的 `.jsc` 里。

## 三、逐项排查：有没有"多余的东西"

| 检查项 | 结果 |
|---|---|
| sourcemap（`.map`） | ❌ 无 |
| 文档 / `.txt` / `LICENSE` / `.md` | ❌ 无 |
| 已归档的三个文件（`InputMethodOfficial` / `InputMethodStaged` / `input-crash-diag2`）是否进包 | ❌ **未进包**（`components/` 内无任何痕迹，仅 61 个 PNG） |
| 键盘皮肤是否为死资源 | ❌ **四套全部在用**：`arc` 引用 11 次、`full` 30 次、`horizontal` 13 次、`t9` 7 次 |
| PNG 总量 | 115,587 字节（**占 6%，非瓶颈**） |
| 空目录 / 冗余配置 / 重复文件 | ❌ 无 |
| `data/schedule.json` | 6,231 字节（内置示例数据，正常） |

### 结论

**release 包是干净的，没有可以轻易删掉的"垃圾"。** 体积构成就是"28 个页面的业务代码 + 两份额外复制的词典"，前者无法压缩，后者是打包机制决定的。

## 四、若要继续瘦身（均需权衡）

| 方案 | 预估收益（压缩后） | 代价 |
|---|:---:|---|
| 归档 `input-crash-diag`（它比正式输入页还大） | 约 **-105KB**（-13%） | 失去输入法崩溃排查主力工具。**崩溃问题尚未定位，当前不建议做** |
| 归档 `vibration-lab`（`v2` 已存在） | 约 -25KB | 失去旧版振动测试页 |
| 归档其他实验室工具页（`qrcode-generator` 36KB / `device-id-diagnosis` 32KB / `black-screen-check` 30KB） | 合计约 -80KB | 失去对应排查能力 |
| 词典裁剪（6763 单字 → 常用 3000；或移除 `dic_jp.js` 25KB） | 每引用页 -60KB × 2 | 影响中文输入完整度 / 日文输入 |
| 诊断页不引用完整键盘 | 约 -185KB | 需改造诊断页实现 |
| **移除所有对键盘组件的多余引用** | —— | 只保留 `chinese-input` 一处引用，是消除"词典复制"的唯一根本途径 |

**结构性成本说明**：词典 ×2（约 370KB 未压缩）无法通过清理消除，只能通过**减少引用页数量**或**裁剪词典**来降低。

## 五、复查方法（可复现）

```bash
# 1) 构建 release 包
npx aiot release --enable-jsc

# 2) 解压并看构成
rm -rf /tmp/rpk && mkdir -p /tmp/rpk && cd /tmp/rpk
unzip -q /path/to/dist/xxx.release.x.y.z.rpk
find . -type f -exec ls -l {} \; | awk '{print $5, $9}' | sort -rn | head -30
du -sh */
```

**核对要点**：
- `.js` 明文 = debug 包；`.jsc` = release 包
- `components/` 只有 PNG → 说明组件代码已内联（正常）
- 若 `components/` 里出现 `*Official*` / `*Staged*` → 说明归档失效、注册被误加回
