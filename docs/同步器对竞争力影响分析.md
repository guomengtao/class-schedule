# 同步器上线对 Ev课程表竞争力的影响分析

> 分析对象：EV 同步器插件（`EV Schedule Sync`，`.abp`，v1.0.20 内测中）上线后，对 Ev课程表产品竞争力的实际提升。
>
> **一句话结论**：**战略价值很高（补上了我们唯一缺失的短板），但当前实际提升 ≈ 0 —— 因为快应用侧还没有"接收数据"的能力，通路尚未闭环。** 一旦闭环，竞争格局会从"落后半步"变为"持平或领先"。

---

## 零、结论速览

| 判断 | 内容 |
|---|---|
| 补的短板 | 竞品都有、我们**唯一缺**的「**手机侧批量导入课表**」 |
| 当前状态 | ⚠️ **通路未闭环**：`src/` 全量扫描**未发现任何 `interconnect` / 接收接口代码** |
| 实际提升 | **当前 ≈ 0**（数据进不到手环）；**闭环后显著** |
| 闭环后提升 | 从「落后半步」→「**持平或领先**」（主观估算：竞争力 +15~25 分 / 100） |
| 真正的杀器 | 不是同步器本身，而是「**腕上直接编辑 + 手机侧批量导入**」的**双通道**（竞品只有后者） |

---

## 一、先明确：同步器补的是哪块短板

### 1.1 竞品的能力分布

| 能力 | Jursin/Schedule-Vela | Var课程表 | **Ev课程表（现状）** |
|---|---|---|---|
| 腕上直接编辑（无需手机） | ❌ | ❌ | ✅ **独有** |
| **手机侧批量导入** | ✅（AstroBox 插件 / 同步器 App） | ✅（Var课程表同步器插件） | ❌ **缺** |
| 导入第三方课表格式 | ✅ 拾光 / WakeUp / 星链 / CSES | ✅ 支持多种导入 | ❌ 无 |
| 开源 | ✅ GPL-3.0 | ❌ | — |
| 商业化 | 爱发电接受支持 | 爱发电付费 | ✅ 标准版 / 高级版 + 激活码 |

**结论**：我们的短板**只有一条**——「手机侧批量导入」。同步器正是冲着这条来的。

### 1.2 为什么这条短板很致命

目标用户（学生）**大多已经有现成的课表**（学校教务、拾光课程表、WakeUp 课程表等）。让他们放弃已有数据、在 192px 的手环上一门一门手输 30 门课——**这是巨大的迁移成本，足以劝退大部分用户**。

> 所以：**"腕上编辑"是特色，但"手机导入"是刚需。** 缺了刚需，特色也卖不出去。

---

## 二、事实核查：通路到底打通了没有

这是本分析最关键的一节。按链路逐环核查：

| 环节 | 状态 | 依据 |
|---|---|---|
| ① 插件侧（`.abp` v1.0.20） | ✅ **已发布** | GitHub release（2026-09-22） |
| ② 插件 UI / 校验（设备菜单、守卫检查、JSON 校验） | ✅ **已实现** | v1.0.20 release notes |
| ③ 插件 → 手环（`interconnect.send_qaic_message`） | ❓ 待确认 | release notes 未明确"已成功写入" |
| ④ **快应用接收接口** | ❌ **未发现** | `src/` 全量扫描 `interconnect` / `send_qaic` / `qaic` / `onconnect` / `onopen` → **0 命中** |
| ⑤ 写入 `@system.storage`（`allCourses_N`） | ❌ 依赖 ④ | — |
| ⑥ 手环界面刷新显示 | — | — |

### 结论：**通路未闭环，链条断在 ④**

`src/` 是为了本项目唯一的源码目录，且路由页面中也没有任何 sync / import 相关页面。也就是说：

> **插件目前"发得出去"，但手环"收不到"。**

这意味着内测用户很可能遇到"插件显示导入成功，但手环课表没变"的现象。

**⚠️ 这是内测期间最优先要解决的一件事，否则同步器等于空转。**

---

## 三、三种情景下的竞争力提升评估

| 情景 | 前提 | 竞争力提升 | 说明 |
|---|---|---|---|
| **悲观** | 快应用侧始终不实现接收接口 | **≈ 0** | 插件是空壳，用户装了也没用，反而可能因"承诺未兑现"损伤口碑 |
| **中性** | 实现接收，但只支持 **自有 JSON 格式** | **中等（+8~12）** | 补齐短板，但对标竞品仍缺"格式生态"（用户要重新整理数据） |
| **乐观** | 实现接收 **+ 支持导入主流课表格式** | **显著（+15~25）** | 用户迁移成本降到最低，配合"腕上编辑"形成**双通道**优势 |

> 评分口径：对"产品竞争力综合分"（0~100）的主观估算，仅用于比较量级，非精确值。

---

## 四、竞争力维度评分（对标竞品）

| 维度 | 权重 | Ev（现状） | Ev（乐观闭环） | Jursin | Var |
|---|---|---|---|---|---|
| 腕上直接编辑 | 20% | 5 | 5 | 0 | 0 |
| **手机侧批量导入** | **25%** | **0** | **5** | 5 | 5 |
| 第三方格式兼容 | 15% | 0 | 4 | 5 | 4 |
| 功能完整度（模板/节假日/统计等） | 15% | 5 | 5 | 3 | 3 |
| 分发渠道覆盖 | 10% | 4 | 5 | 4 | 3 |
| 商业化与授权 | 10% | 5 | 5 | 2 | 4 |
| 扩展生态（插件/自动化） | 5% | 1 | 4 | 4 | 4 |
| **加权合计** | 100% | **≈ 2.4 / 5** | **≈ 4.6 / 5** | **≈ 3.6 / 5** | **≈ 3.3 / 5** |

**读法**：
- 现状 ≈ **2.4**（低于两个竞品）——短板太致命，被单一维度拖垮。
- 闭环后 ≈ **4.6**（明显领先）——因为我们是唯一"双通道 + 功能最全 + 有授权体系"的产品。
- 竞品 ≈ 3.3~3.6（强在导入生态，弱在功能与商业化）。

> **关键洞察**：**这 20%+ 的权重集中在"手机侧批量导入"这一项上**——它是一票否决式的短板。补齐它，整体竞争力直接跃升一档半。

---

## 五、提升到底有多少：三个必要条件

同步器要真正转化为竞争力，必须同时满足三件事：

| # | 条件 | 现状 | 缺了会怎样 |
|---|---|---|---|
| 1 | **快应用侧实现接收接口** | ❌ 未发现 | 一切都是空谈（当前卡在这里） |
| 2 | **支持导入主流课表格式**（拾光 / WakeUp / 星链 / CSES / ICS） | ❌ 无 | 用户仍要手工整理数据，吸引力大打折扣 |
| 3 | **同步器与授权体系联动** | ❓ 未见说明 | 若"导入"与"高级版权益"绑定，可提升付费转化；若不联动，则损失一个变现抓手 |

---

## 六、真正的竞争力不是"同步器"，而是"双通道"

这是本次分析最重要的战略认知：

```
        ┌───────────────────────────────┐
竞品：  │  只有手机侧导入（一旦没网/没电脑就抓瞎）│
        └───────────────────────────────┘

        ┌───────────────────────────────────────────┐
Ev：    │  腕上直接编辑（临时改课、加课，立刻生效）      │
        │  + 手机侧批量导入（首次迁移、批量维护）        │
        │  = 唯一「双通道」课程表                      │
        └───────────────────────────────────────────┘
```

**"腕上直接编辑"是竞品完全没有的能力**——用户临时调课、加一节自习，不需要掏手机；这是手环场景的天然优势。

所以正确的宣传定位应该是：

> **"能导入，也能腕上改"** —— 而不是单纯说"我们也有同步器了"。

如果只宣传"同步器"，就是在竞品的主战场（导入）上打平手，浪费了自己的独有优势。

---

## 七、建议行动（按优先级）

| 优先级 | 动作 | 理由 |
|---|---|---|
| **P0** | **快应用侧实现 interconnect 接收接口**（注册接收 → 解析 JSON → 写 `allCourses_N` → 刷新 UI） | 通路闭环的**唯一阻塞点**，不做则同步器无意义 |
| **P0** | 内测验收标准加一条：**"导入后手环课表确实变化"** | 避免出现"插件成功、手环没变"的假成功 |
| **P1** | 支持导入 **拾光 / WakeUp / 星链 / CSES / ICS** 格式 | 降低迁移成本，直接对标竞品 |
| **P1** | 宣传语改为「**双通道**：手机批量导入 + 腕上直接编辑」 | 打差异化，而非同质化 |
| **P2** | 同步器与高级版权益联动（如导入功能属高级版） | 增加付费转化抓手 |
| **P2** | 上架 AstroBox 插件市场 | 渠道曝光（与米坛互补） |

## 八、风险与不确定性

1. **最大风险**：快应用侧接收接口若长期缺位，同步器会从"竞争力"变成"负面资产"（用户预期落空）。
2. **技术风险**：一周课表 JSON 通过 interconnect 传输的**载荷上限**未知，需实测。
3. **平台风险**：AstroBox 插件在 **iOS 为解释模式**，性能与稳定性需真机验证。
4. **数据风险**：导入会**覆盖用户课表**，必须提供二次确认与备份/撤销（与本项目既有"删除二次确认 + 5 秒撤销"的约定一致）。
5. **生态风险**：拾光 / WakeUp 等格式可能随版本变化，解析层需容错设计。

---

## 九、最终判断

| 问题 | 回答 |
|---|---|
| 同步器的战略价值 | **高**（补唯一短板、开启双通道叙事） |
| 当前实际竞争力提升 | **≈ 0**（通路未闭环） |
| 闭环后预期提升 | **显著**（由落后半步 → 明显领先） |
| 关键前提 | **快应用侧接收接口**（P0，未完成） |
| 最该做的一件事 | 先把"手环能收到数据"做完，再谈宣传 |

> **一句话**：**同步器是"竞争力的钥匙"，但锁还没打开——快应用侧的接收接口就是那把锁芯。**
