## 0. 一句话结论

**能做，但"一致"必须重新定义。** 苹果表盘 = 字形 + 版式 + 动效三层，其中**字形与配色可以做到视觉等价**，**版式受屏幕物理比例限制只能"等价重构"而非像素 1:1**。59 款里真正可做的是 **12 款（S 档）**，其余 47 款因依赖 3D / 动画 / 专属资产 / 商标，按"似是而非就放弃"的红线应当直接剔除。

**首款对象（2026-10-26 修订）**：**macOS 桌面时钟小组件（小号模拟版）优先**——它是卡片而非全屏，天然允许留白，是唯一能绕开比例硬伤的路线，且纯几何无字形依赖。**X-Large 退为兜底方案**（若 widget 路线因 Liquid Glass 材质或观感被否）。详见 §4。

## 2. "一致"的工程化拆解（这是本方案最关键的一节）

你要求"必须一致，否则放弃"。这句话必须落到可测量的三层，否则永远吵不清：

| 层 | 一致的定义 | 可达性 | 判定方法 |
|---|---|---|---|
| **L1 字形层** | 数字/字符的骨架、笔画粗细对比、字形比例与苹果一致 | ✅ **可达**（自绘矢量到视觉等价） | 与原字形叠加，边界偏差 ≤1px（336 宽基准）、笔画宽度差 ≤8% |
| **L2 版式层** | 层级关系、间距比例、对齐重心、留白节奏一致 | ⚠️ **等价重构**（非 1:1） | 关键元素中心点与屏宽/屏高的**比例**误差 ≤3% |
| **L3 动效层** | 秒针/冒号闪烁/Liquid Glass 折射等动态 | ❌ X-Large 无动效；其余多为苹果私有渲染 | 若原表盘有私有动效 → 直接归入 C 档放弃 |

**物理边界（必须先接受，否则方案不成立）**：

| 设备 | 分辨率 | 比例 | 与 Apple Watch 45mm（396×484，0.818）的关系 |
|---|---|---|---|
| Apple Watch S7–S9 45mm | 396×484 | 0.818 | 基准 |
| Apple Watch Ultra | 422×514 | 0.821 | 基准 |
| 手环 10Pro | 336×480 | 0.700 | 更"瘦高"，需向下压缩纵向留白 |
| 手环 9 | 192×490 | 0.392 | 胶囊屏，**比例差一倍以上**，只能是"苹果风"不是"高仿" |

结论：**"复刻"只在 10Pro（336×480）上成立**；192×490 胶囊屏做同款只能算"改编版"，必须在文档和 UI 文案里区分，不能混称"复刻"。这条按总纲 §3.24「换版式不换比例」执行。

### 2.1 为什么 192 胶囊屏不行——不是"屏幕小"

这一点必须说准，否则容易得出错误结论（"以后换个更大的圆屏就行"）。三条原因按致命程度排序：

| 序 | 原因 | 性质 | 能否绕过 |
|---|---|---|---|
| 1 | **比例 1:2.55**（192×490），苹果是 1:1（widget）或 0.82（Watch） | **结构性，不可调和** | ❌ 无解。方形版式进 1:2.55 的框只有两个结果：纵向拉伸变形，或上下留 60% 空白 |
| 2 | **胶囊圆角吃掉四角**：R=96 = 屏宽一半，四角是完全半圆 | **结构性** | ❌ 无解。苹果表盘的刻度环、四角复杂功能位正好落在这两个区域，会被直接切掉 |
| 3 | **横向空间仅 192px**（苹果 396px，压缩 51%） | **可设计规避** | ✅ 有解。精简元素、砍掉次要信息即可 |

**准确表述**：尺寸小只是第 3 位原因，且可绕过；第 1、2 条是结构性的，无法绕过——**这是"这块屏不适合复刻方形设计"的根本原因，与屏幕分辨率高低无关，换一块更大的胶囊屏同样不成立。**

反过来看 10Pro：336×480 = 1:1.43，方形卡片能占 70% 高度，观感成立 → 复刻载体选它。

## 3. 59 款可仿性分级

分级维度（四个否决项，命中任一即降档）：

1. **字形依赖**：是否依赖 SF 系字体的复杂字形/多字重（可自绘小字符集的 → 不否决）
2. **图形复杂度**：纯几何 → 可做；3D 渲染/光照/折射 → 否决
3. **数据依赖**：是否需要天文、活动环、心率、气压等真实数据（有公开公式的 → 可做）
4. **资产/法律**：是否含苹果专属形象（Snoopy / Mickey / Memoji）、第三方商标（Nike / Hermès）→ **一律否决**

### A 档（7 款）— 字体装饰重，可做但工作量 3–5 倍

`California`（罗马/阿拉伯混排 + 多字重）、`Typograph`、`Metropolitan`（数字动态变药丸形）、`Meridian`（四小盘 + 经典字）、`Palette`（渐变随指针变化）、`Contour`（等高线浮雕）、`Utility`

→ **不建议先做**：字形变体多，任一变体不达 L1 就会"似是而非"。

### B 档（6 款）— 依赖数据，可做但要么假数据要么放弃

`Solar Analog / Solar Dial / Solar Graph`（需太阳位置算法，公式公开可算）、`Lunar`（月相算法，本项目已有 `lunar.js` 可复用）、`World Time`、`Activity Analog / Digital`（需活动环数据，手环无此数据源 → 建议放弃）

### C 档（34 款）— **按红线直接放弃**

- **3D/光照/折射**：Astronomy、Flow、Flux、Reflections、Liquid Metal、Kaleidoscope
- **动画/图像序列**：Motion、Timelapse、Playtime、Artist、Breathe、Nike Bounce、Pride 系列 10 款（Celebration/Radiance/Threads/Woven/Harmony/Luminance…）、Unity 系列 6 款（Bloom/Lights/Mosaic/Rhythm…）
- **苹果专属形象**：Snoopy、Mickey Mouse and Minnie Mouse、Memoji
- **第三方商标**：Nike 全系 6 款、Hermès 全系、Siri Modular
- **Ultra 独占**：Modular Ultra、Wayfinder、Waypoint
- **复杂功能过载**：Infograph（8 个复杂功能位，手环无法填满 → 必然"空得不像"）

> **C 档的判断依据**：这些表盘的"像"来自苹果的私有渲染引擎、专属美术资产或商标，我们没有合法途径取得，任何近似都必然是"似是而非"——正是你要放弃的那一类。

## 4. 复刻对象选型

### 4.1 候选 0：macOS 桌面时钟小组件（2026-10-26 追加，评估结论：可行，且优先级高于 Apple Watch 表盘）

**事实澄清**（口径来自 macOS 系统行为，本机 macOS 27）：

| widget | 小号 | 中/大号 |
|---|---|---|
| 时钟 | **模拟表盘** | **数字时间 + 日期** |
| 世界时钟 | 单城市 | 多城市列表 |

- macOS 26 起所有 widget 统一为 **Liquid Glass 材质**（实时折射壁纸）。
- 苹果官方同时提供 **单色（Monochrome）** 与 **全彩（Full color）** 两种小组件样式（系统设置 → 桌面与程序坞 → 小组件样式）。

**为什么它比 Apple Watch 表盘更适合复刻**：

1. **它是卡片，不是全屏** → 天然允许四周留白，**不要求铺满**。这一条直接绕开了 §2 里最致命的比例冲突：Apple Watch 表盘必须撑满 396×484，塞进 192×490 只能变形；而卡片只需放下自己，比例不同也能成立。
2. **元素量最小档**：模拟版 = 12 个刻度 + 3 根指针 + 可选数字；数字版 = 城市名 + HH:MM。
3. **无连续动画**：秒针每秒跳一格（离散），不存在无法复现的插值动效。
4. **有官方静态外观可对标**：单色模式是苹果自己提供的样式，以它为基准不涉及"猜苹果怎么渲染"，合法性干净。
5. **认知成本最低**：你身边就有，验收时不用开模拟器就能对照。

**风险（必须写进验收口径）**：

1. **Liquid Glass 不可复现**：那是实时采样壁纸做折射，手环上无对应能力 → 基准必须锁定为**单色模式**，全彩玻璃版不做，否则必然"似是而非"。
2. **卡片在窄长屏上的观感**：圆角方形卡片放 192×490，卡片只占 39% 高度，上下各空约 149px，会像"漂浮卡片"而非"表盘"。放 336×480 则占 70%，观感成立。
3. **细节必须真机取模**：刻度是点还是线、有无 12/3/6/9 数字、秒针颜色（橙/红）、圆角半径比例——凭印象写必然跑偏。

**结论**：**10Pro 上优先级最高**，192 屏只能出"卡片居中改编版"，需在文档与 UI 标注，不得称复刻。

### 4.2 候选对比（含 macOS widget）

| 候选 | 形态 | 元素数 | 是否要求铺满 | 动效 | 一致性可判定性 | 失败成本 |
|---|---|---|---|---|---|---|
| **macOS 时钟 widget · 小号模拟版** | 圆角方卡 + 圆形表盘 | 12 刻度 + 3 指针 | **否**（卡片自带留白） | 秒针离散跳格 | 高：有官方单色模式可对标 | 低 |
| **macOS 时钟 widget · 大号数字版** | 卡片 + 城市名 + 大数字 | 城市名 + HH:MM + 日期 | **否** | 无 | 高 | 最低 |
| **X-Large** | 全屏数字 | **11 个字形**（0–9 + 冒号） | **是**（必须撑满） | 无 | **极高**：整屏只有字形+纯色底 | **最低** |
| Simple | 全屏指针 | 指针 2 + 刻度 60 + 槽位 4 | 是 | 秒针 | 中：小屏描边易糊 | 中 |
| Exactograph | 全屏三组刻度 | 3 组刻度 + 3 指针 | 是 | 无 | 中高 | 中 |
| Numerals Mono | 全屏数字 | 11 个字形 | 是 | 无 | 高 | 低 |

**关键区分**：`是否要求铺满` 这一列决定了成败。macOS widget 是卡片，比例不匹配也能成立；Apple Watch 表盘必须铺满，比例不匹配就只能变形。**同样是 192×490 的胶囊屏，widget 能活、Watch 表盘不能活。**

### 4.3 推荐路线（两级）

**第一推荐：macOS 时钟 widget 小号模拟版（10Pro 336×480）**
- 唯一的"卡片化"路径，规避了比例硬伤；
- 元素量适中（12 刻度 + 3 针），纯几何，无字形依赖——**这条路线连造字都不需要**，比 X-Large 少一整块工作量；
- 基准锁定单色模式，验收口径干净。

**第二推荐 / 兜底：X-Large（若 widget 路线因材质或观感被否）**
1. **字符集最小**（11 个字形）→ 自绘矢量的工作量可控，是"字形一致"能落地的现实路径。
2. **无噪声源** → 一致性可量化到像素级，不存在"说不清差在哪"。
3. **已有渲染通路先例** → `watch-face-font.ux` 变体 0「巨型加粗」已验证大字在双屏的居中/字距/字号，只需换字形来源。
4. **失败成本最低** → 连它都做不到一致，说明字形管线不通，可立即止损。
5. **超越空间明确** → 可加「课程倒计时」小位，属信息密度超越，不是跑偏。

### 4.5 双屏分工（回答「9 手环怎么办」）

**结论：不排除、也不必凑合——两台复刻的是 widget 家族里不同的两款。**

| 机位 | 复刻对象 | 理由 |
|---|---|---|
| **10Pro 336×480** | 模拟表盘（四数字白卡） | 卡片 336×336 占据 70% 高，接近源尺寸（326px），**几乎是 1:1，线宽不失真** |
| **9 192×490** | 数字版（城市名 + 大数字） | 模拟表盘的分钟刻度缩到 192 后线宽不足 1px 必糊；而数字版只有 5 个字符 + 粗体，缩到 192 仍清晰可读。**这是选对了款式，不是降级** |

9 屏版式（1:2.55 的屏，卡片只占 39% 高，上下留白）不是缺陷——**widget 的原生语境本来就是「桌面上的一个方块，周围是壁纸」**，手环上「壁纸」即深色底：

```
┌──────────┐ 192×490 胶囊
│  10月26日 │ ← 留白区（日期，小字）
│ ┌──────┐ │
│ │ 12:32│ │ ← 数字版卡片 192×192，圆角 46
│ │ CUP  │ │
│ └──────┘ │
│  下节 数学 │ ← 留白区（课程信息，手环原生价值）
│  14:00    │
└──────────┘
```

**唯一必须写进验收的让步**：9 屏若走模拟表盘，必须砍掉 48 条分钟刻度（否则必然糊成一团），砍了就不再与苹果一致 → 那时它叫「简化刻度改编版」，不能叫复刻。**走数字版则没有这个让步。**

## 5. 一致性怎么达成：技术路线三选一

### P0 前置验证（30 分钟，必须第一个做）

Vela 手环引擎能否加载**项目内 ttf/otf**（`@font-face`）？

- 快应用联盟文档明确支持 `@font-face`（ttf/otf，项目内绝对路径），但**那是手机大屏快应用规范**；
- 本项目 **全部 17 个表盘页零 `@font-face` 先例**，Vela 精简引擎是否支持**未经实测**；
- 验证方法：新建探针页，`@font-face` 引入一个测试 ttf，渲染 "0123456789:"，`page` 直达截图看是否生效（不污染 manifest，按 §3.24）。

### 三条路线

| 路线 | 做法 | 优点 | 风险 |
|---|---|---|---|
| **A（优先）** | `@font-face` 加载**自绘的 11 字形 ttf** | 渲染清晰、可任意缩放、代码量最小 | 依赖 P0 通过；需自己造字（FontForge 脚本化） |
| **B（保底）** | 11 张 PNG 位图切片，按目标字号缩放 | 一定可行，字形可直接描摹自官方渲染 | 缩放会糊；10Pro 需要 2 套尺寸 |
| **C（不推荐）** | canvas / svg path 直绘 | 完全可控 | Vela 对 canvas 支持有限，且路径数据体积大 |

**造字合法性问题（必须写清）**：

- **不得**提取、分发、内嵌 SF 字体文件本体 —— SF 系字体许可仅授权苹果平台 UI 使用，嵌入快应用属侵权。
- 允许的做法是：**以官方渲染为参照，自行重绘视觉等价的字形**（这是设计还原，不是字体盗用）。11 个字符的重绘工作量可控（每个字形约 20–40 个控制点）。
- Nike / Hermès / Snoopy / Mickey / Memoji **一律不碰**，这些是商标与版权，不是字体问题。

## 7. 放弃判据（红线，命中即停）

1. **P0 双向皆败**：`@font-face` 不支持 **且** 位图方案在大屏缩放后笔画明显糊 → 整个"高仿"方向放弃，改做"苹果风"（明示为改编版）。
2. **字形不收敛**：11 个字形重绘三版后仍有 >5% 边界偏差 → 换 Numerals Mono 或直接放弃该款。
3. **需要专属资产**：任何方案要求引入 SF 字体文件、Nike/Hermès 商标、Snoopy/Mickey 形象 → **立即停手**，不存在折中。
4. **必须改版式才放得下**：允许按 §3.24「换版式不换比例」处理，但产物必须在文档与 UI 里标注为"适配版"，**不得对外称"复刻"**。
5. **胶囊屏硬凑方形版式**：192 屏若出现四角被切、留白失衡 → 该款不做小屏，只出 10Pro 单屏版（这一点与现有 17 款表盘的"双屏交付"惯例不同，需你拍板）。
