| 路径 | 选什么 | 官方支持 | 是否自造 |

## 1. 官方能力边界（已核实）

| 事实 | 来源 | 影响 |
|---|---|---|
| Vela picker 只支持 **selector（普通）/ time（时间）**两种 | 小米 Vela JS 官方文档 `components/form/picker.html` | **无原生 date 年月日控件** |
| Vela `input` **仅允许 `type="button"`** | 项目 `docs/vela-unsupported-reference.md` §3.3 | 无法靠 input date/calandar 调起原生日期盘 |
| Vela 无 `picker-view`（微信小程序才有） | Vela 组件表 | 手绘滚轮（scroll+实时滚动）是唯一自绘途径，**按铁律弃用** |
| 项目已有自绘滚轮 `time-picker-demo.ux` | 现存代码 | 作为**反例存档**，本文不复制它 |

### 1.1 官方 picker 属性（Vela）

通用属性（两种模式共用）：

| 属性 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `type` | string | 是 | `selector`（普通）/ `time`（时间） |
| `start` | string | 否 | 起始值（selector 为数组首项索引；time 为起始时刻） |
| `end` | string | 否 | 结束值 |
| `value` | string | 否 | 当前选中值 |
| 事件 | `change` | — | 选中变化回调，`e.detail` 含结果 |

> ⛔ 以官方文档**当前页为准**；本文属性表为探索初稿，落地前需按官方文档最终版核对。

## 2. 三路径详情

### 路径 A · 官方 `type="time"`（纯时分）

**适合**：只要「时分」，不要年月日。官方原生，黑屏风险最低。

```html
<!-- A 型：官方时间选择器 -->
<picker type="time" start="00:00" end="23:59" value="{{ timeVal }}" onchange="onTimeChange">
  <text>选择时间</text>
</picker>
```

```js
data: { timeVal: '12:30' },
onTimeChange(e) {
  this.timeVal = e.detail.value   // 形如 "12:30"
}
```

**优点**：官方滚动（上下滑是系统内置），零手绘，无黑屏风险。
**限制**：无年月日。时分为范围限制只能 `start`/`end` 精确到分。

---

### 路径 B · 官方 `type="selector"` 三列级联（年月日）

**适合**：一定要「年月日」。用官方普通选择器逐列选，分「年 / 月 / 日」三列。

> 关键：selector 一次只弹一列。要做「三列滚动」有两种子方案，**都在官方 selector 能力内**：

#### B1 · 三列并排（若官方支持多列 selector）
若 Vela selector 支持内嵌多列（`multiSelector`），则：

```html
<picker type="selector" :data="[years, months, days]" value="[2026,9,10]" onchange="onDateChange">
  <text>选择日期</text>
</picker>
```

```js
data: {
  years: [2020,2021,...,2030],
  months: [1,2,...,12],
  days: [1,2,...,31]
},
onDateChange(e) {
  const [y, m, d] = e.detail.value   // 级联后年月日
}
```

**优点**：官方滚动；年月日一次三列。
**风险**：取决于 Vela selector **是否支持多列**——需按官方文档确认；若不支持，落 B2。

#### B2 · 三次单列 selector（逐步选 → 拼接）
若官方只支持单列，则年、月、日三个入口逐步选：

```html
<picker type="selector" :data="years" value="{{ yIdx }}" onchange="onYear">
  <text>{{ years[yIdx] }} 年</text>
</picker>
<picker type="selector" :data="months" value="{{ mIdx }}" onchange="onMonth">
  <text>{{ months[mIdx] }} 月</text>
</picker>
<picker type="selector" :data="days" value="{{ dIdx }}" onchange="onDay">
  <text>{{ days[dIdx] }} 日</text>
</picker>
```

```js
data: { yIdx:56, mIdx:9, dIdx:9 },   // 初始 2026-10-10
onYear(e){ this.yIdx=e.detail.value; this.rebuildDays(); },
onMonth(e){ this.mIdx=e.detail.value; this.rebuildDays(); },
onDay(e){ this.dIdx=e.detail.value; }
get dateText(){ return `${this.years[this.yIdx]}-${this.months[this.mIdx]}-${this.days[this.dIdx]}`; }
```

**优点**：只用官方单列 selector，零手绘，最稳。
**缺点**：三列分三次点击，不是「一屏三列同时滚」，交互略繁琐——但满足「不自己造」。

---

### 路径 C · 组合（A 时分 + B 年月日 双入口）

**适合**：Demo 想同时演示时分和年月日。一个页面放两个官方选择器入口。

```html
<div class="page">
  <text class="label">时间（官方 time）</text>
  <picker type="time" ... onchange="onTimeChange">…</picker>

  <text class="label">日期（官方 selector 级联）</text>
  <picker type="selector" ... onchange="onDateChange">…</picker>
</div>
```

**优点**：一条 Demo 覆盖官方两种能力，验收点明确。
**建议**：Demo 默认做 C；A、B 作为 C 的两半即是。若年月日交互在真机上繁琐，再退回只保留 A。

## 4. 风险分级（按「宁可不做也不黑屏」）

| 风险 | 级别 | 处置 |
|---|---|---|
| selector 不支持多列 → B1 需回落 B2 | 🟡 中 | 先查官方文档确认列数能力；不确定就**默认 B2 单列** |
| 官方 `time` 的存值格式（`HH:mm` vs 数值） | 🟡 中 | 严格按官方 onchange 返回值处理 |
| 页面重绘黑屏（沿用 `if` 蒙层 + `$forceUpdate`） | 🟢 低 | 克隆现有已上线详情页蒙层；不碰 transform 数据绑定 |
