# 勾选框点击无效问题分析

## 问题描述

在课程表管理页面（`schedule-manager.ux`）中，新增的勾选框按钮显示正常，但点击后没有任何反应，无法切换课程表。

## 根因分析

### 问题代码

```html
<!-- 修复前：checkbox 和 item-header 都有 onclick -->
<div class="item-header" onclick="selectSchedule($idx)">
  <div class="checkbox" onclick="selectSchedule($idx)" ...>
    <text class="checkbox-mark">...</text>
  </div>
  <text class="schedule-name">...</text>
  <text class="badge">使用中</text>
</div>
```

### 原因：嵌套元素的 onclick 事件冲突

在快应用（QuickApp）框架中，当**父子元素都绑定了 `onclick` 事件**时，存在以下问题：

1. **事件目标不明确**：点击 checkbox 内部的 `<text>` 元素时，点击事件首先到达 `<text>`，但 `<text>` 没有绑定事件处理器。然后事件需要冒泡到 `<div class="checkbox">`，但在这个冒泡过程中，快应用运行时可能无法正确确定事件目标。

2. **父子 onclick 冲突**：即使事件到达了 checkbox 的 `<div>`，触发了 `selectSchedule($idx)`，事件还会继续冒泡到父级 `item-header`，再次触发 `selectSchedule($idx)`。在某些快应用实现中，这会导致：
   - 事件被丢弃（两个 onclick 都不执行）
   - 或者只执行一次但状态混乱

3. **对比其他正常工作的按钮**：页面中的操作按钮（重命名、复制等）没有嵌套在另一个带 `onclick` 的父元素中，所以它们能正常工作：

```html
<!-- 正常工作的模式：只有一层 onclick -->
<div class="action-btn" onclick="startRename($idx)">
  <text>重命名</text>
</div>

<!-- 有问题的模式：两层 onclick 嵌套 -->
<div class="item-header" onclick="selectSchedule($idx)">        ← 父级 onclick
  <div class="checkbox" onclick="selectSchedule($idx)">          ← 子级 onclick（冲突！）
    <text>✓</text>
  </div>
</div>
```

### 总结

**点击事件被嵌套的父子 `onclick` 冲突截断，无法正确触发。** 这是快应用框架的事件处理限制——同一元素层级链上不应有多个 `onclick` 处理器。

## 修复方案

移除 checkbox 子元素上的 `onclick`，依赖父级 `item-header` 的 `onclick` 通过事件冒泡来处理点击：

```html
<!-- 修复后：只有父级 item-header 有 onclick -->
<div class="item-header" onclick="selectSchedule($idx)">
  <div class="checkbox" style="...">          <!-- 无 onclick，点击冒泡到父级 -->
    <text class="checkbox-mark">...</text>
  </div>
  <text class="schedule-name">...</text>
  <text class="badge">使用中</text>
</div>
```

**原理**：点击 checkbox 或其内部的 `<text>` 时，事件会自然冒泡到父级 `item-header`，由父级的 `onclick="selectSchedule($idx)"` 统一处理。这样无论用户点击的是 checkbox、课程表名称还是"使用中"徽章，都能正确触发切换。

## 附加改动：增加调试日志

在 `selectSchedule` 函数中增加了 `console.log` 日志，覆盖所有分支路径，方便排查问题：

```javascript
selectSchedule(index) {
    console.log("[SCHEDULE-MANAGER] selectSchedule called, index=" + index + ...)
    if (this.editingIndex >= 0) {
      console.log("[SCHEDULE-MANAGER] selectSchedule blocked by editingIndex")
      return
    }
    if (index === this.currentIndex) {
      console.log("[SCHEDULE-MANAGER] selectSchedule same index, going back")
      router.back()
      return
    }
    console.log("[SCHEDULE-MANAGER] selectSchedule switching to index=" + index)
    database.setScheduleIndex(index, function() {
      console.log("[SCHEDULE-MANAGER] setScheduleIndex done, new index=" + index)
      self.currentIndex = index
      router.back()
    })
  },
```

日志输出示例（切换成功时）：
```
[SCHEDULE-MANAGER] selectSchedule called, index=1 currentIndex=0 editingIndex=-1
[SCHEDULE-MANAGER] selectSchedule switching to index=1
[SCHEDULE-MANAGER] setScheduleIndex done, new index=1
```
