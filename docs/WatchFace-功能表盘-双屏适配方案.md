## §1 现状解剖

纯 flex 纵向居中，**零 absolute、零 JS 定位**，比前四块都干净：

| 元素 | 作用 | 192 基线 | 定位方式 |
|---|---|---|---|
| `.page` | 容器 | 100%×100% · bg `#101820` · column 居中 | `onclick="onTap"` 回列表 |
| `.clock` | 时间 | 48 bold · ls 2 | flex 居中 |
| `.date` | 日期（`10月25日 周六`） | 22 · mt 4 | flex 居中 |
| `.item` ×3 | 空间/剩余/电量 各一组 | w 158 · mt 16 | flex column |
| `.head` | 组标题行 | w 158 · row space-between | flex row |
| `.k` / `.v` | 标签 / 数值 | 22 / 22 | row 两端 |
| `.bar` | `<progress>` | w 158 · stroke-width 12 | 官方组件 |
| `.batt` 系列 | 电池图标（壳+芯+正极帽） | 壳 34×16 · 芯 h8 · 帽 3×8 · 芯宽 **JS 算** | row |
| `.back` | 返回 | 22 · mt 24 | flex 尾部 |

**三处硬耦合**（决定动法）：

1. **电量芯宽在 JS 里**：`battW = Math.round(res.level * 30)` —— `30` 是壳内净宽（34 − 2×2 边框）。壳放大后必须同步改，否则宽屏上 100% 电量只画半格。
2. **电量在 `onInit` 就算过 `battW`**，而宽度探针要到 `onReady` 才有值 → 必须在探针里用保存的 `battLevel` **重算一次**。这一条最容易漏，视觉症状是"电量条短一截"。
3. `.item` / `.head` / `.bar` 三处 **158 各写一遍**，漏一个就出现"标题比进度条宽"的错位。

## §2 路线选择

| 路线 | 做法 | 判定 |
|---|---|---|
| A 整体 `transform: scale(1.75)` | 套 `.page` | ❌ 否决。480 < 490 高更矮；文字位图缩放发虚（本页全文字 + `<progress>` 组件，缩放后进度条会糊边） |
| B 逐元素宽屏单类（12 个 `.w-*`） | `fitScreen()` 异步探针填 class | ✅ **采用**，延续前四块范式 |
| C 只加 `width` 不定字号 | 最小改动 | ❌ 字太小不达 ev-six 可读下限，等于没适配 |

## §3 宽屏数值表（含占宽/占高验算）

横向基准：`336 − 2×30 = 276`（左右各留 30，与列表页一致）。

| 元素 | 192 | 336 目标 | 占宽验算 | 判定 |
|---|---|---|---|---|
| `.clock` | 48 / ls2 | **84 / ls3** | 4 数字×0.47×84 + 冒号 0.30×84 + ls ≈ **222** / 276 | ✅ 余 54 |
| `.date` | 22 / mt4 | **28 / mt6** | `10月25日 周六` 10 字 ≈ 132 | ✅ |
| `.item` / `.head` / `.bar` | 158 | **276** | 满栏 | ✅ |
| `.k` / `.v` | 22 | **28** | `空间使用`+`1.2GB / 3.8GB` ≈ 52 + 165 = **217** / 276 | ✅ 余 59 |
| `.bar` stroke | 12 | **18** | 与 28 字号相称 | ✅ |
| `.batt-shell` | 34×16 · 边框 2 | **56×26 · 边框 2** | 净宽 52 | ✅ |
| `.batt-level` | h 8 | **h 13** | — | ✅ |
| `.batt-nub` | 3×8 | **5×13** | — | ✅ |
| **`battInner`（JS）** | 30 | **52** | = 56 − 2×2 | ✅ |
| `.back` | 22 / mt24 | **28 / mt20** | — | ✅ |

**纵向预算**（480 是硬约束，`.page` 居中溢出会两端同时裁）：

| 项 | 高度 |
|---|---|
| clock 84（行盒 ≈1.4×） | 118 |
| date 28 + mt6 | 45 |
| item ×3（head 39 + bar mt8 + 18 + mt16） | 243 |
| back 28 + mt20 | 59 |
| **合计（三项全显示）** | **465 / 480** ✅ 余 15 |
| 合计（仅两项，电量不支持时） | 384 ✅ 居中余 96 |

> 三项全显示仅余 15px，**所以 `clock` 定 84 而不是 96**。取 96 会让 worst case 溢到 505 直接裁字。这是本页唯一"不敢往上顶"的地方。

## §4 改动清单

**模板（12 处绑定）**：`class="clock {{ clockCls }}"` 式混写，覆盖 clock、date、item×3、head×3、k×3、v×3（含 `.head-right` 内那个）、bar×3、batt、batt-shell、batt-level、batt-nub、back。

**CSS（12 个单类，全部平铺，禁后代选择器）**：`.w-clock` `.w-date` `.w-item` `.w-head` `.w-k` `.w-v` `.w-bar` `.w-batt` `.w-shell` `.w-level` `.w-nub` `.w-back`

**JS（3 处）**：
1. `import device from "@system.device"`（当前是函数内 `require`，探针需要在 `onReady` 用）
2. data 增 `battInner: 30`、`battLevel: 0`、以及 12 个 `*Cls` 空串
3. `fitScreen()` 异步探针：`device.getInfo({success: d => { if (d.screenWidth < 300) return; ... }})`，末尾**必带** `if (this.battLevel) this.battW = Math.round(this.battLevel * 52)`
4. `loadBattery`：`battW = Math.round(res.level * this.battInner)`（并把 `res.level` 存进 `battLevel`）

## §5 零回归口径

`fitScreen` 首行 `if (w < 300) return`，12 个 `*Cls` 全空、`battInner` 保持 30 → 模板解析结果与改前**逐字节相同**。

**唯一有意变更：无。** 192 屏一个像素都不动。

> 说明：`.date` / `.k` / `.v` / `.back` 现为 22px，理论上低于 ev-six 的 24 可读下限。但 `.head` 在 192 屏上已经被 `空间使用` + `1.2GB / 3.8GB` 占到约 171px > 158，**再抬字号只会把现有轻微挤压放大成重叠**。故 192 屏保持 22 不动，宽屏按 28 合规；这条记入页面文档「已知问题（非本次引入）」，留给后续单独修（需先缩数值文案格式）。前四块把 sub-24 直接抬到 24 的做法在本页不适用。

## §6 已预判的坑

1. **`battW` 二次重算漏掉** → 宽屏电量芯只有 30px（看着像半格电）。见 §1 第 2 条。
2. **`.v` 类在两个位置**（普通组 + `.head-right` 内），宽屏类要两处都挂；只挂一处会出现同一行两种字号。
3. **`<progress>` 的宽高由 class 决定**，`percent` 只管填充比例。若 `width` 漏设，宽屏上进度条仍是 158 —— 三条 bar 里最容易漏第三条（电量组）。
4. **`.page` 有 `onclick="onTap"`**：一切点击都会回列表页，验收时**不要点屏幕**，只截图（这是本页验收便宜的前提，也是别手痒去点的原因）。
5. **三项全显示时纵向只剩 15px 余量**：若实测发现裁字，第一刀砍 `item` 的 mt（16→10），第二刀砍 clock 到 78，不要动 bar 的 stroke（会变细线难看）。
