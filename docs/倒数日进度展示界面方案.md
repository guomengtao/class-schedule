# 倒数日进度展示界面 · 方案

> 目标机型：9 手环胶囊屏（192×490，`shape: pill-shaped`）
> 依据：现有统一数据层 `src/data/countdown.js`（v2 数据，字段 `{id,title,date,enabled}`，`recompute()` 已产出 `daysLeft`/`dateDisplay`）
> 范围：本方案只规划**展示与排序**的升级，不动添加/编辑/删除的既有交互逻辑；首页模块仍未纳入。

---

## 一、背景与目标

当前管理页列表（`src/pages/countdown-manage/countdown-manage.ux`）已能显示每条的天数（"剩 N 天"/"已过 N 天"），但有三个体验问题：

1. **排序不分状态**：`sortByAbsDays` 按 `|daysLeft|` 升序，会把手表已结束的项目**插在未结束项目中间**，用户一眼看不出"哪些还在倒数、哪些已经完了"。
2. **进度不直观**：只有一个数字（剩 N 天），没有"它还差多少、还剩几分之几"的视觉反馈，"倒数感"弱。
3. **信息拥挤**：192 宽胶囊屏上，一行里塞了 环形数字 + 标题 + 开关 + 日期 + 天数 + 编辑 + 删除，七零八落、不美观。

本方案目标：让每条倒数日**状态清晰、进度可视、界面美观**，并落实"**进行中在前、已结束在后**"的分组排序。

---

## 二、状态模型（数据派生，入参仅为 `daysLeft`）

不改存储结构，仅基于 `daysLeft` 派生四种状态：

| 状态 | 判定 | 语义 | 展示要点 |
|---|:---:|---|---|
| **即将到期（today）** | `daysLeft === 0` | 就在今天 | 排进行中最前，高亮强调 |
| **进行中（active）** | `daysLeft > 0` | 还在倒数 | 剩 `N` 天，进度环亮色饱满 |
| **已结束（done）** | `daysLeft < 0` | 目标已过 | 已过 `N` 天，置灰、进度归零感 |
| **已停用（disabled）** | `enabled === false` | 开关关闭 | 行整体降透明度，不参与"亮色"表达 |

> `statusOf(item)` = `daysLeft < 0 ? "done" : daysLeft === 0 ? "today" : "active"`，实现放于数据层。

---

## 三、排序规则（核心：进行中在前 / 已结束在后）

新增 `sortForDisplay(list, mode)` 替代/增强现有 `sortByAbsDays`，分两段，组内排序受"最近/名称"切换控制：

```
组1「进行中」= daysLeft >= 0   （含 today）
     · mode=最近：today 排最前，其余按 daysLeft 升序（越近越前）
     · mode=名称：组内按 title 拼音升序（today 仍是该组最前）
组2「已结束」= daysLeft < 0
     · mode=最近：按 daysLeft 降序（越刚结束越前，即 |-1| < |-10|）
     · mode=名称：组内按 title 拼音升序
组内稳定：同值保持原添加顺序（排序函数需稳定，避免列表跳动）
停用项：保留在各自组内位置，仅视觉降灰
```

排序示例（最近的默认视图）：

```
🔥 高考倒计时       剩 3 天      ← 进行中，最近
🎂 生日             剩 21 天
🚗 驾照考试         剩 88 天
─── 分隔线（弱化）───
✅ 上次体检         已过 12 天   ← 已结束
📄 上次续签         已过 40 天
```

> 分隔线保持极轻（2px、低对比），是"分组视觉"的点睛之处，但不可喧宾夺主。

## 四、界面布局方案（双层结构，解决 192 宽局促）

单页塞不下"进度+信息+操作"，故拆成**列表态**与**详情态**两个视图，用"点按卡片 → 聚焦查看/操作"贯通：

### 4.1 列表态（默认，主展示）

每张卡片 = **标题行 + 进度条行 + 元信息行**，三段式，纵向清爽：

```
┌──────────────────────────┐
│ 🎂 生日                 │ ← 标题（1 行截断）+ 状态小标
│ ▓▓▓▓▓▓▓▓░░░░░░░ 剩 21 天 │ ← 进度条 + 天数（进度视觉）
│ 2027-11-03   已启用       │ ← 日期 + 停用标记（弱化行）
└──────────────────────────┘
```

- **进度条**：整卡宽度的细圆角条（高 ~6px），填充比例 = 该条进度（见 §六），进行中为渐变亮色、今天满格热色、已结束全空淡灰。这是"倒数感"的主体。
- **天数**：右对齐加粗，进行中/今天用主题强调色，已结束用弱化色并前缀"已过"。
- **状态小标**：仅"今天"给一个高亮角标（"今"）吸引注意；日常态不额外放徽标，避免噪点多。
- 点击卡片 → 进入详情态（4.2）。

### 4.2 详情态（点按聚焦，承载操作）

全屏一屏一条，突出"倒数效果"并收拢操作按钮（编辑/删除/开关/关闭）：

```
┌──────────────────────────┐
│       ╭──────╮            │
│      │  剩    │            │ ← 大号弧环（直径 ~150px）
│      │  21    │            │    环内 = 天数数字（大字）
│      │  天    │            │    环饱和度 = 进度
│       ╰──────╯            │
│       🎂 生日              │ ← 标题（居中）
│       2027-11-03           │ ← 日期
│  ┌────┐ ┌────┐ ┌────┐     │
│  │编辑 │ │删除 │ │ ON │     │ ← 操作排（开关/编辑/删除收拢于此）
│  └────┘ └────┘ └────┘     │
└──────────────────────────┘
```

- 弧环用 Vela 原生 `<progress type="arc">` 或自绘段环，环弧填充 = 进度比例，颜色随状态。
- 详情态内"编辑 / 删除 / 开关"复用现有 `startEdit/deleteItem/toggleItem`。

> 列表态保持轻量（可常驻多个卡片），详情态负责"大而美 + 可操作"，各司其职，规避 192 宽挤压。

## 五、视觉规范

| 维度 | 进行中 | 今天 | 已结束/停用 |
|---|---|---|---|
| 进度条/环色 | 主题 `accent`，可渐隐 | 强调热色（如 `#ff7a45` 类） | 灰 `textMuted` / 卡灰 |
| 天数文字 | `accent` 加粗 | `accent` 加粗 + 角标 | `deleteText`（弱化） |
| 卡片底色 | `theme.card` | `theme.card` + 1.5px 高亮描边 | `theme.card` 降 40% 透明 |
| 停用行 | —— | —— | 整行 `opacity` 降低 + 文字灰 |

- **留白节奏**：卡片纵向间距 6px、卡片内 3 段行距 4px 出头，横向统一 `padding: 12px 16px` 级；圆角统一 `10–12px`。让"密度低、呼吸感强"。
- **字体层级**：标题 28px/行高 36px、天数 30px 加粗（数值越大越可上浮到 36）、元信息 20px 弱化。**数值永远是视觉主角**。
- **颜色**：跟随现有 `theme`（明/暗两套自动跟随），无需新主题；明暗下都保证灰阶对照 ≥ 4.5:1。
- 表达式可视修正阶段在模拟器 `/devexpress` 逐步核字号。

## 六、进度 `progress` 的定义与计算

只有"目标日"没有"起点"，进度需一个可解释的口径。推荐在数据层补一个**轻量生命周期**字段：

- **推荐做法**：每条新增 `createdAt`（添加时写 `Date.now()`）。则
  `progress = clamp( (today − createdAt) / (target − createdAt), 0, 1 )`
  它语义真实（"从创建走到目标，走完多少了"），且已结束项自然 ≈1、全新项 ≈0。
- **兼容旧数据**：迁移/归一化时对无 `createdAt` 的条目，按 `target − 名义跨度` 回填起始点；名义跨度建议默认 `90 天`（短程事件观感最好），可选依 `date−today` 估算，具体口径一键可改。
  ```
  backfill: createdAt = (target - 90d)  // 旧数据统一视为"90 天前开始倒数"
  ```
- 归一化在 `normalizeItem()` 里补：`o.createdAt = it.createdAt ? Number(it.createdAt) : backfill()`
- 排序/展示只依赖 `daysLeft` 与 `statusOf`，`progress` 仅用于环/条填充，二者解耦，避免一处改动联动另一处。

> 备选口径（无 `createdAt`、零数据改动）：`progress = 1 − daysLeft / horizon`，其中 `horizon` 为选定的参考周期（如 90 天）。观感略滞后但实现最简——若不想碰存储，可先上线此口径，后迁移 `createdAt`。

## 七、交互与容错

- **开关**：停用项整行降透明、环变灰，仍可按开关复原；位置保持在组内不跳。
- **删除确认**：沿用现有"删除→确认"两段式，避免误触。
- **超长标题**：标题 `lines: 1` 截断 + true-dot 省略，详情态标题最长 1 行。
- **跨午夜**：`recompute()` 在 `onShow` 时重算，`daysLeft` 归 0/负 时卡片平滑切换分组与配色，不闪烁（分组用稳定排序）。
- **空态**：无倒数日时保留现有提示 + 引导添加。
- **可达性**：进度条不单独承载信息，文字天数始终在旁，保证色盲/弱视可读。

## 八、数据层改动清单（`src/data/countdown.js`）

| 能力 | 说明 |
|---|---|
| `statusOf(item)` | 派生 active/today/done |
| `sortForDisplay(list, mode)` | 分组排序（进行中在前/已结束在后，组内最近或名称） |
| `normalizeItem()` | 补 `createdAt`，兼容回填 |
| `progressOf(item)` | 计算 0..1 进度（二选一口径，见 §6） |
> 全部为**只读/附加计算**，不改变落盘结构主键；`save()` 仍写 `{version:2, items}`，`createdAt` 随 items 序列化即可。

## 九、界面改动清单（`countdown-manage.ux`）

1. **模板**：卡片重构为 三行式（标题行 / 进度条行 / 元信息行）；组间插入轻分隔线；状态小标；点击卡片进详情。
2. **详情态**：新增一屏（或页内 `if` 切换的面板），大弧环 + 标题/日期 + 操作排。
3. **样式**：按 §五 规范重排，`@media (shape: pill-shaped)` 下校准字号与间距；详情态独立样式。
4. **数据接入**：`onShow/load` 改用 `sortForDisplay`，绑定 `progress`/`statusOf`。

> 列表态仍为主要展示点；详情态为增强项，可分两步上线（先列表态进度化，再补详情态）。

## 十、分阶段实施与验收

| 阶段 | 内容 | 验收 |
|:---:|---|---|
| P0 | 数据层：`statusOf`/`sortForDisplay`/`createdAt`/`progress` + 兼容回填 | 单测：进行中在前、已结束在后；today 最前；旧数据进度可算 |
| P1 | 列表态卡片重构 + 进度条 + 分组分隔线 + 停用降灰 | 模拟器/真机：192 宽不挤压、字号清晰、进度可读 |
| P2 | 详情态（大弧环 + 操作排） | 点卡片进出顺畅、编辑/删除/开关可用 |
| P3 | 视觉打磨：明暗主题对照、图标、渐变色、今天角标 | 明/暗两套色调协调，无溢出/断行 |

**回归用例**：`C/M/D` 增删改开关 → 分组与进度即时刷新；跨午夜 `daysLeft→0` 状态正确切换；旧 v1 数据迁移后进度正常回填；停用项灰显不遮挡。

## 十一、风险与备注

- **弧环可用性**：`<progress type="arc">` 在 capsule（pill 分支）上的渲染曾有兼容疑问（见输入法/表盘黑屏档案，其罪魁是 `adjustScreenWidth` 的渲染竞态而非 arc 本身）。实施时先在模拟器验证弧环，若不稳定则以"分段横条 + 环形数字"替代，不引入渲染风险。
- **进度口径**（`createdAt` vs 固定 horizon）需要你定一个默认；文档默认推荐 `createdAt` 口径，观感与语义更贴合"倒数"。（当前文案即为推荐值，可改。）
- 本方案不改首页展示模块；落地时仅动 `countdown.js` 与 `countdown-manage.ux`，如需详情态另设一页则加一份 `manifest` 路由.
