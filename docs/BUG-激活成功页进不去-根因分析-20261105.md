# 激活成功页「进不去」根因分析（2026-11-05 14:40 +0800）

## 一句话结论

真机从「设置 → 激活」进的是 **`activation-code-v2`**，而这个页面**只有"在手环上当场输码成功"一条路**能切到成功态：
它既没有轮询、也没有"刚激活就展示"的判定。凡是在网页/手机 APK 完成激活、再回手环查看的人，永远停在输入引导页。

## 现象

- 反复卸载重装、UUID 换新、激活码重新签发，激活本身是成功的（首页显示「高级版」）。
- 但「恭喜 / 高级版到手 / 权益 / 开始体验」这个成功页，无论怎么测都不出现。

## 代码证据

| 位置 | 事实 |
|---|---|
| `src/pages/settings/settings.ux:333` | `router.push({ uri: "/pages/activation/activation-code-v2" })` —— **真机入口是 v2**，不是 v1 |
| `activation-code.ux:280-302` | v1 有 `startActivationWatch()`：1.5 秒轮询本地激活态，一旦从「未激活」变「已激活」就 `succeed()` |
| `activation-code-v2.ux:250-258` | v2 的 `onShow` **只调了 `loadStatus()`，没有轮询** |
| `activation-code-v2.ux:231` | `verifySuccess: false` 初值 |
| `activation-code-v2.ux:487-490` | `succeed()` 只有两行：置 `verifySuccess = true` |
| `activation-code-v2.ux:543-636` | `succeed()` 的**唯一调用点**在 `doVerify` 的 `markActivated` 回调里 |
| `activation-code-v2.ux` 全文 | 无 `_actSeen`，没有"进页面时已激活"的判定分支 |

结论：v2 的成功态只在本页 `doVerify` 成功时出现，其余路径一律到不了。

## 为什么「卸载 + 换 UUID」没用

卸载只清本地数据，**不改变页面结构**；换 UUID 只是让激活码能重新签发。
一旦激活动作发生在网页或手机端，手环这边的 v2 页面没有任何事件、也没有轮询去感知，
`verifySuccess` 就永远是 `false`。这条路跟 UUID 无关，换多少个号都进不去。

## 我的截图为什么"看起来是对的"

截图脚本注入的是 `verifySuccess: true` **初值**，绕过了状态切换，所以能出图。
它证明的只是"版式能渲染"，不证明"真机路径能到达"——这是上一轮的验证盲区。
更糟的是脚本只覆盖 v1，而用户实际走 v2，连截图对象都不是同一个页面。

补充实测：用同样注入法截 v2（`/tmp/v2-success.png`，192×490），成功态渲染完全正常，
布局、字号、卡片、按钮都在——**所以问题 100% 在触发逻辑，不在 UI**。

## 修复方案（本次落地）

1. **v2 补 `startActivationWatch()`**，与 v1 同口径：1.5 秒轮询，页面开着时手机端激活也能立刻切成功态。
2. **两页统一加「刚激活」判定**：`status.isActivated && (now - status.activatedAt) < 5 分钟` 且本次会话未展示过，
   直接铺成功态。这样网页/APK 激活后第一次进页面也能看到，且只出现一次，老用户不会被反复打扰。
3. **截图脚本支持指定页面**（v1/v2），不再只截 v1 自证；同时保留 `--keep` 供手工复验。

## 验收标准

- 卸载重装 → 网页激活 → 手环进入激活页 → 应看到「恭喜 / 高级版到手 / 权益 / 开始体验」。
- 5 分钟后再次进入 → 回到输入引导，不重复打扰。
- 手环当场输码成功 → 立即切成功态（原有路径不回归）。

## 后续决策（2026-11-05 15:20 +0800）：删除 v2，只保留 v1

本文档前几节把 `activation-code-v2` 当作"真机入口"来分析，那是当时的实际状态。
该页面本身只是 **2026-11-04 挂上去的临时对比入口**（`settings.ux` 里那行「激活码键盘 v2 对比」，
代码注释写着"验证通过后再替换并删除本行"），从未成为正式用户路径。

真实用户路径一直是：

```
设置 → 高级版本（openActivation）
     → pages/activation（网关页）
     → path-b-redeem（兑换码）
     → activation-code（v1，原页面）
```

Tom 2026-11-05 决定：**暂时不再推进 v2 方案，删除该页面，只保留原 v1。**

本次删除范围（可回滚，见 git 历史）：

| 位置 | 动作 |
|---|---|
| `src/pages/activation/activation-code-v2/` | 整目录删除（单文件 32KB） |
| `src/manifest.json` | 移除 `pages/activation/activation-code-v2` 路由 |
| `src/pages/settings/settings.ux` | 删除「激活码键盘 v2 对比」入口行与 `openActivationCodeV2()` |

删除前已核对 **v1 具备全部修复**，能力不因删 v2 而丢失：

- `startActivationWatch()` 1.5 秒轮询 ✅
- `_actSeen` 会话内只展示一次 ✅
- `lastActivatedAt`（每次激活都刷新）判定优先 ✅

因此本文档第 2 节「修复方案」中的第 1 条（v2 补轮询）已随文件删除而失效，
其余结论（触发逻辑而非 UI、需要轮询 + 刚激活判定、`activatedAt` 不能用于续期判定）对 v1 仍然成立。
后续若重启 v2 方案，从 git 历史恢复该文件即可。
