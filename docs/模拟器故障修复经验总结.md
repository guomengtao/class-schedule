# 模拟器故障修复经验总结

> 2026-09-29 一天内完整走了一遍「起不来 → 排障 → 修复 → 验证」闭环，本文沉淀全部实战经验，供下次直接对照使用。
> 配套：`docs/模拟器启动稳定性方案.md`（方案与铁律）、`scripts/emu-start.sh`（一键启动器）。

---

## 一、故障时间线（真实案例）

| 时间 | 动作 | 结果 |
|---|---|---|
| 上午 | 用户 IDE 点运行 | 没反应（"起不来"） |
| 排障① | 发现 3 个 qemu 实例并存，其中 `emulator-5554`（xiaomi_band）guest adb 僵死，还有一个卡死的 `adb shell unzip` 部署进程 | 杀卡死进程 + 杀僵死实例 |
| 重启① | 沿用原参数重启（含 `-qt-hide-window`） | 裸跑 qemu 先报 dyld 缺库 → 改用 SDK 启动器成功，但**无窗口**，用户仍以为"起不来" |
| 重启② | 去掉 `-qt-hide-window` 重启 | 窗口出来了，应用能跑（欢迎页/首页截图为证） |
| 下午 | 用户 IDE 再拉起实例 | 又"起不来" |
| 排障② | 实例在跑（etime 仅 4 分钟）但 `adb devices` 认不出 | `adb kill-server && adb start-server` 恢复识别——**adb server 状态过期** |
| 验证 | vapp 拉起应用 | 欢迎页 ✓ → 首页 ✓ |
| 新故障 | 进首页约 1 分钟后画面全黑、点击唤不醒 | guest `ps` 系统进程全活着 → **quickapp 运行时进程死了**，`vapp` 重新拉起即恢复 |
| 复测 | 进首页后 100 秒连拍 | 帧稳定无崩溃，交互正常 ✓ |

## 二、根因速查表（症状 → 原因 → 处置）

| # | 症状 | 真实原因 | 处置（验证过） |
|---|---|---|---|
| 1 | IDE 点运行没反应 | ① guest adb 僵死 + 卡死的 `adb shell unzip` 部署进程挂住 IDE 管线；② adb server 状态过期；③ guest 还在 boot 就部署 | ① 杀部署进程→重启实例；② `adb kill-server && adb start-server`；③ 等 boot（`ps -o etime` ≥2 分钟）再部署 |
| 2 | 屏幕全黑 | ① 1373B=未渲染（没起应用）；② ~1.6KB=运行时死了的黑屏 | ① `vapp app/<pkg> &`；② 同左，**不用重启模拟器** |
| 3 | 有实例但看不到窗口 | 启动参数带了 `-qt-hide-window`（无头模式） | 去掉该参数重启 |
| 4 | 裸跑 qemu 报 dyld 缺 `libandroid-emu-tracing.dylib` | 直接执行 qemu-system-armel，缺库路径 | 必须走启动器 `~/.vela/sdk/emulator/darwin-aarch64/emulator` |
| 5 | 一个实例救不回来 | guest adb 僵死（`emu avd name` 通 + `shell echo` 不通） | 只能 `stop` + `start` |
| 6 | 命令输出乱码/矛盾 | 会话工具通道异常（本日实际发生） | 换文件工具核验；以抓图字节数/内容为最终事实 |

## 三、验证方法论（比猜可靠）

### 3.1 探活两步法（分层定位）
```bash
ADB=<项目>/node_modules/@aiot-toolkit/emulator/node_modules/@miwt/adb/bin/mac/adb
$ADB -s emulator-5554 emu avd name        # 第1层：宿主侧 qemu 控制台
$ADB -s emulator-5554 shell echo alive    # 第2层：guest 内 adbd
```
| 第1层 | 第2层 | 结论 |
|---|---|---|
| 通 | 通 | 健康，可直接部署 |
| 通 | 不通 | guest adb 僵死 → 重启实例 |
| 不通 | 不通 | 实例死了 / serial 不对 → 先 `adb devices` + 重启 adb server |

### 3.2 抓图判据（PNG 字节数，本项目实证值）
| 字节数 | 含义 |
|---|---|
| 1373B | 纯黑，LCD 无内容（应用未起） |
| ~1.6KB | 近黑，运行时死亡黑屏（系统进程还在） |
| 12828B | 欢迎页 |
| ~20.7KB | 编辑课程页（稳定帧） |
| ~28.9KB | 首页 |

判稳方法：`emulator-eye.js bulkshot <port> <prefix> <n> <间隔ms>` 连拍，字节数持续不变且 >5KB = 画面稳定。

### 3.3 以"看得见"收尾
所有修复必须以抓图（`emulator-eye.js shot`）确认渲染内容收尾，字节数+肉眼看图，不接受"命令成功了"推断画面正常。

## 四、写启动脚本学到的（v1 → v2 教训）

| 教训 | 说明 |
|---|---|
| **别用 `set -u`** | v1 因某个变量未绑定直接硬失败（`unbound variable`），防御脚本自己先崩；v2 去掉，改用 `${var:-}` 默认值 |
| **别解析 lsof 端口** | v1 用 lsof+awk 从监听端口反推 serial，脆弱；v2 改为遍历 `adb devices` 的 `emulator-*` 用 `emu avd name` 匹配，直观且容错 |
| **管道后判空要单独做** | `cmd \| awk ... \|\| echo 无` 管道成功返回 0，`\|\|` 永远不触发；要 `grep -q . \|\| echo 无` |
| **复用优先于重启** | 脚本 start 先查同 AVD 是否在跑，健康就复用、僵死才重启，杜绝多实例 |

## 五、标准处置流程（下次照抄）

```
现象：IDE 运行失败/模拟器异常
 1. bash scripts/emu-start.sh status          # 实例、serial、guest 存活、卡死进程
 2. 有卡死部署进程？ → bash scripts/emu-start.sh clean
 3. adb 认不出 serial？ → 脚本已自动 kill-server/start-server 重试
 4. 实例 guest=否？ → bash scripts/emu-start.sh stop <avd> && start <avd>
 5. 实例健康但画面黑？
    a. 抓图判字节：1373B → vapp 拉起应用
    b. ~1.6KB → vapp 重新拉起（运行时死了），勿重启模拟器
 6. 全黑且 vapp 拉不起 → stop + start 重启实例（最后手段）
 7. 修复后必须抓图确认 + bulkshot 判稳，再交还用户
```

## 六、仍开放的问题

- 运行时偶发死亡黑屏只出现一次、未定位根因（未复现）；再次遇到时先抓 `vapp` 前后对比与 guest 日志，不要急于归因于代码改动。
- 多实例（pro/band/10 并存）的需求未支持，脚本刻意单实例；需要并行联调时再扩展。
- IDE 内部拉起逻辑不可控，只能靠「先 status 再运行」规避。
