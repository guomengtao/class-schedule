# 倒数日功能 —— 9 手环胶囊屏稳定升级方案

> **版本**：v1（方案阶段）
> **目标**：让「添加 / 编辑 / 删除 / 显示」在 9 手环胶囊屏上稳定可用，一次改到位、可验证、可回滚。
> **背景**：倒数日当前「还是用不了」——已有的 `capsule-countdown-redesign-plan.md`、`countdown-days-analysis.md` 只做了美化/评估，未解决**功能链路本身**在胶囊屏失效的根因。

---

## 〇、结论摘要（先看这里）

倒数日「用不了」的**根因不是样式，而是交互链路在胶囊屏上走不通**：

1. **日期输入用 `prompt.showDialog` 弹窗**，胶囊屏（Vela / 9 手环）的 showDialog **没有文本输入框**，回调用 `res.value` 恒为 `undefined` → 添加、编辑永远到不了落盘那一步（**致命**）。
2. **两段式流程靠多个分散 storage 键传参**，`router.push` 还嵌在 `storage.set` 的 success 回调里 → 链路脆弱、半途中断会残留脏键、下次进页面被误触发。
3. **「显示」不成立**：当前只有管理列表能看，没有任何「胶囊屏/首页」入口展示倒计时对外表达。
4. 日期用 `new Date("YYYY-MM-DDT00:00:00")` 字符串解析、排序用 `Math.abs(天)`，存在时区/未来过去混排等隐患。

**升级思路（一次到位）**：用**官方 `picker` 做日期（年/月/日级联）** + 复用已有 `chinese-input` 做名称 + **单一流程上下文（storage 一个对象）** + **共享数据层 `src/data/countdown.js`** + **首页胶囊屏展示模块**。管理页保留增/删/改/开/排序/清空，全部走胶囊屏合规的紧凑布局。

## 三、整体架构

### 3.1 数据层（单一读写入口）

新建 `src/data/countdown.js`，收敛所有存储/计算/排序/序列化逻辑，管理页与首页展示模块**共用同一份数据源**，杜绝各自为政。

```
src/data/countdown.js
  - STORAGE_KEY = "countdownDays.v2"        // 版本化，见 §3.3 迁移
  - load(cb)                  // 读 + 迁移旧键 + parse + 容错
  - save(list, cb)            // 只存纯字段(id/title/date/enabled) + 原子写
  - compute(list)             // 手动解析 YYYY-MM-DD，防时区/hardcoded parse
  - recompute(list)           // 排序后统一 {daysLeft,dateDisplay}
  - sorting
      .byRecent(abs(daysLeft))
      .byName(title)
      .apply(list, mostRecentFirst)
  - migrate()                 // 旧 "countdownDays" → 新键补 id/version
```

数据模型（每项）：

```json
{
  "id": "cd-<ts>-<rand>",
  "title": "高考",
  "date": "2027-06-07",
  "enabled": true
}
```

顶层（可选）：
```json
{ "version": 2, "items": [ ... ] }
```

> 建议：**直接存 `{version, items}`**，将来要加字段（分类/提醒/类型）只升版本号做 migrate，不用再改 key。

### 3.2 UI 三层

```
┌─ 数据层  src/data/countdown.js（唯一读写）
├─ 管理页  countdown-manage.ux（增/删/改/开/排序/清空）
├─ 名称页  chinese-input.ux（复用，名称输入）
├─ 日期页  countdown-date.ux（新增，官方 picker 年/月/日级联，返回"确定/取消"）
└─ 首页模块 modules/countdown.js（胶囊屏展示 enabled 项）＋ index.ux 注册
```

### 3.3 迁移策略（不丢用户数据）

1. 首次运行 `countdown.js.load()` 时检测：新键 `countdownDays.v2` 不存在、旧键 `countdownDays` 有数据 → 自动迁移（补 id、套 `{version:2, items}`）→ 写新键 → 删除旧键。
2. 迁移失败/Json 损坏 → 返回 `[]`，绝不 throw，首页/管理页正常空态。
3. 兜底：迁移前把旧值备份到 `countdownDays.v2.backup`，可回滚。

## 四、关键升级点明细

### 4.1 日期选择：新增官方 picker 页 `countdown-date.ux`（替代 R1/R2）

**不要再写键盘/弹窗输日期。** 照 `date-picker-demo.ux` 的做法，独立出一个专页：

- 三列官方 `picker type="text"`：年 `2020..今+5` / 月 `1..12` / 日（按年月动态重算，含闰年，复用 `buildDayStrs`）。
- 进入时**预填**当前倒数日的日期（编辑场景），默认今天（添加场景）。
- 底部 `[确定] [取消]`。
- 确定 → 写 **唯一流程上下文**（见 4.2）→ `router.back()`。
- 取消/返回 → 写 `{aborted:true}` → `router.back()`，上游据此**清空上下文**、不再弹。

小字说明：
> `picker onchange → e.newSelected`（下标），改年后重算 days 并钳制 dIdx，全部参考 demo 已验证的写法，避免"60 行自绘滚轮"这类此前常见翻车点。

### 4.2 单流程上下文：一个对象替代多个散键（解决 R3/R4）

统一用一个 storage key：`countdown_flow`，管理页只认这一个键。

```json
// startAdd 进入流程前写入（一次性、成功后才 push）
{ "mode": "add" }
// 名称页返回后：{ mode:"add", title:"高考" }
// 日期页返回后：{ mode:"add", title:"高考", date:"2027-06-07" }
// 完成落盘后：整键 delete（一次性消费 + 清理）
```

关键改造：
- **`router.push` 移出 `storage.set` 回调**：先同步 `storage.set(flow)`（不依赖其成功回调做跳转），立刻 `router.push(...)`；set 的 fail 也要 `delete` 并 toasting 提示，不静默。
- 流程状态机集中在一个 `beginFlow(mode, idx)` / `consumeFlowReturned()`，承担：
  1. 到 chinese-input（拿名称）→ 回；
  2. 到 countdown-date（拿日期）→ 回；
  3. 若两项齐 → `save()` 落地 → `delete(countdown_flow)`；
  4. 任一步返回带 `aborted` → 立即 `delete(countdown_flow)`，**不去弹下一段**。
- `onShow` 不再裸读多个 `countdown_xxx` 键，只消费 `countdown_flow`，读到即删，天然防残留误触发。
- 传入 `countdown_edit_index` 用**每流程一个 id**：`flow.itemId`（编辑目标项 id，注意列表已排序，别用易漂移的数组下标）。

### 4.3 名称输入：复用 `chinese-input`（现状已具备，补齐健壮性）

- 保持 `chinese_input_*` 传参 + `chinese_input_return_key`，但 return_key 改为流程上下文相关的键（如把结果回写到 `countdown_flow`）。
- maxlen 维持 6（胶囊屏一行可完整显示，避免 `text-overflow: ellipsis`）。
- 用户直接返回（未点确定）→ 视为中止，回 `aborted:true`，上游清理。

### 4.4 管理页 UI 改造（胶囊屏合规 + 交互闭环）

- **增/删/开/排序/清空**全部走 **4.2 状态机 + 4.1 日期页**，不依赖 showDialog。
- 日期列：显示 `<已选日期: 2027-06-07>`，点击该行/「编辑」→ 进 `countdown-date.ux` 预填改日期。
- 删除：保持「再点一次确认」交互（现有 deleteConfirmIndex + 3s 超时），落到 `countdown.js.save()`。
- 删除最后一行后自动回到空态引导（现有 empty-text）。
- 胶囊字号/行高按 `capsule-countdown-redesign-plan.md` §三 的规范表执行（正文 24/32、辅助 22/30、按钮 22、数字动态 22-28），**统一在一次改完**，避免再出现历史那种"加了样式没最终校验被评审打回"。

### 4.5 首页/胶囊屏展示模块 `modules/countdown.js`（解决 R5）

照 `modules/custom-content.js` / `modules/holiday.js` 的成熟模板，在 `index.ux` 注册：

```
moduleNames 追加 { key: "countdown" }
loadModule("countdown", require("./modules/countdown.js"))
index 模板：<div if="{{ showCountdown && countdownShowList.length }}"> …
```

- init()：读 `countdown.js.load()`，过滤 `enabled===true`，`compute()` 后取最近 3 条，压成紧凑展示数组。
- **放在首页已有内容之后、滚动课程表之前**（对齐 `countdown-days-analysis.md` §3.5 的视觉位置）。
- 单行紧凑卡片：`标题  剩 N 天`；数量上限 3 条，超出「+N」折叠。
- **条件渲染语义（已核实）**：`if`（v-if 语义）= 条件为假时**整棵子树不创建**，故该块的 **layout / paint 开销 = 0**；这与 `show`（v-show 语义，如 `custom-content-edit.ux`/`schedule-manager.ux` 用的 `show=` = 节点仍在树、仅隐藏）不同，OFF 场景下 `if` 优于 `show`。
  > ⚠️ **措辞修正（2026-10-17 一核实）**：**不是"整体零开销"**。`modules/countdown.js` 的 `init()`（`storage.get` → `JSON.parse` → `compute()` → `filter()`）是**数据准备，在模板 `if` 求值之前就跑，哪怕全部 OFF 也 100% 执行**；只是量级为微秒级（实测：200 项 × 1000 轮 compute+filter ≈ 64ms，即单轮 < 0.1ms，可忽略）。`if` 真正归零的只限于插入对应的**渲染/布局/绘制**。故推荐措辞：**「OFF 时渲染/布局/绘制开销为零；JS 数据读取与条件求值仍有微秒级开销（可忽略）」**。
- destroy() 清引用、无定时器（日期是静态值，**不需要也不该**用 setInterval 每秒刷，避免又一轮定时器泄漏）。
- 首页数据与管理页同源，管理页改动后回首页自动反映（onShow 里 `refresh()`，照 customContent 模式）。

### 4.6 稳健性修复清单

| 项 | 改法 |
|---|---|
| 日期解析 | 手动 `split('-')` 为 y/m/d 再做天数差，不用 `new Date(string)` |
| 天数差 | `Math.round((target - today)/86400000)` 并用本地 0 点；今天=0 天 |
| 排序 | 已过/未到分开：未到升序在前、已过降序在后，不混排 |
| 存储原子性 | 每次 save 只写纯字段；写失败 → toast「保存失败」并回读旧值 |
| 定时器 | 确认/删除/清空的超时在 onDestroy 全部 clear，且每次进入先 clear 旧的 |
| teardown | 修正 `this.countdowns=null`（应为 `countdownList`/模块引用） |
| 残留键体检 | onShow 消费 `countdown_flow` 后立即 delete；流程 aborted 也 delete |
