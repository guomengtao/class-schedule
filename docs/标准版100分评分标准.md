> **配套文档**：[标准版完善度综合评分.md](./标准版完善度综合评分.md)（评分依据与逐轮记录）、[Ev课程表_手环字号规范_v1.md](./Ev课程表_手环字号规范_v1.md)（字号硬规范）

> **制定日期**：2026-09-19

## 二、各维度 100 分达标细则

### 维度 1｜功能完整性（15%）— 当前 100 ✅

**达标条件**

- [x] 添加 / 编辑 / 删除三条主流程在标准版**完整可用**，且不被高级版拦截（不得因未付费而用不了课程表）
- [x] **时间冲突检测**：同天时间段重叠时给出提示，需二次确认才保存（`database.checkDayConflict`）
- [x] **空态引导**：列表为空时有明确入口引导（首页「今天没有课」、课程管理「点击 + 添加」）
- [x] 编辑页支持修改星期（无需删掉重加）

**判定方法**：手动走查三条主流程；检查权限拦截点是否阻断主流程。

**回退红线**
- 不得在主流程加付费拦截
- 不得移除冲突检测或空态引导
- 新增列表页必须补空态

---

### 维度 2｜胶囊屏文字可读性（20%，权重最高）— 当前 100 ✅

胶囊屏内容区约 **160px**（192px − padding 16×2）。

**达标条件**

- [x] `week-view` 五模板可视列数 ∈ **[2.5, 3.5]**：`可视列数 = 160 ÷ cellWidth`
- [x] 每个模板**显式定义 `cellWidth`**（走兜底 `Math.max(100, nameFontSize×5)` 会得 100px → 仅 1.6 列，不达标）
- [x] 课名字号 **28px**、行高 34px（`nameDisplay: "full"`，不得用 `charAt(0)` 只显示 1 字）
- [x] 首页课程名可用宽度 ≥143px（32px 字号 → 约 4.5 字）
- [x] `add-course` 课程条课名可辨 ≥4 字（条目宽 120px，24px 字号 → 约 4.5 字）
- [x] 星期标题不溢出（缩为单字）

**判定方法**：列数算式 `160 ÷ cellWidth`；课名字数 = 可用宽度 ÷ 字号。

**回退红线**（这条最容易踩）
- **胶囊屏不得开启行号列**（`rowNumWidth > 0` 会吃掉 40~50px，列数 2.67 → **1.57**）
- 新增模板必须显式 `cellWidth`，胶囊屏下 ≤60px
- 胶囊屏分支必须在 JS 里探测屏型后**重新应用配置**（屏型是异步返回的）

---

### 维度 3｜字号控制合规性（12%）— 当前 100 ✅

**达标条件**

- [x] 静态字号 **≥20px**（含 `src/components` 与所有已注册页面）
- [x] 行高 **= 1.2 × 字号**（不得出现 1.14~1.19 倍这类偏小值）
- [x] 动态字号有下限保护：`Math.max(..., 20)`
- [x] 内联字号不击穿 CSS 降级：按屏型算好再注入

**判定方法**：全量扫描模板与 CSS 中的 `font-size` / `line-height`，校验下限与 1.2 倍关系。

**回退红线**
- 不得新增任何 <20px 的字号
- 改字号**必须同步改行高**（两者绑定，改一个即掉分）

---

### 维度 4｜布局与触控（15%）— 当前 100 ✅

**达标条件**

- [x] 危险操作（编辑 / 删除）隔离：换行或留足间距，点"编辑"不可能点到"删除"
- [x] 内容不溢出屏幕
- [x] **触控目标 ≥48px**（胶囊屏 9 处 44px 已全部提到 48px）

**曾被认为不可达，后破解**：原判断是"胶囊屏 header 为 ◀ + 标题 + 功能键三件套，`160 − 48×3 = 16px` 标题被挤没，故 44px 是物理上限"。复核发现该前提已过时，三种破解方式：

| 方式 | 应用处 | 算式 |
|:---|:---|:---|
| **减少同排元素** | `index`：总/今/明 已下移到 `.nav-toolbar` | header 只剩 2 个按钮 → `160 − 48×2 = 64px`，标题单字 26px 绰绰有余 |
| **header 换行** | `detail`：按钮行 + 标题 `order:1 / width:100%` 换第二行 | 按钮与标题不再争抢同一行宽度 |
| **改纵向** | `detail` 轮播区：卡片 `order:0` 全宽，箭头 `order:1` 落第二行 | 箭头 48px 达标，卡片反由 80px 变全宽 160px |

**判定方法**：逐元素核对高度；胶囊屏按 192px 宽度做算式推导。**遇到"放不下"先检查元素是否真的在同一排**，不要直接接受 44px。

**回退红线**
- 不得缩小已有按钮高度
- 新增按钮默认 ≥48px（胶囊屏受限处不得低于 44px）

---

### 维度 5｜操作流畅性（10%）— 当前 100 ✅

**达标条件**

- [x] 常态路径**零日志开销**：`console.log` 统一纳入 `DEBUG` 开关 + `dlog()` 包装
- [x] 首屏**无重复异步 IPC**：`device.getInfo` 全链路仅 1 次（屏型由首屏统一探测后回填，其它模块复用）
- [x] 预热 + 缓存 + `defer` + `onShow` 去重
- [x] 定时器全部在 `onDestroy` 清理，无泄漏

**判定方法**：检索常态路径的 `console.log`；核对 `device.getInfo` 调用点；核对定时器清理。

**回退红线**
- 不得在常态路径新增 `console.log`
- 新页面**不得重复调用** `device.getInfo`（复用已回填的屏型值）
- 新增定时器必须在 `onDestroy` 清理

---

### 维度 6｜数据稳定性（10%）— 当前 100 ✅

**达标条件**

- [x] 跨星期更新为**单次原子写盘**（`updateCourseAcrossDays`），杜绝"删成功插失败即丢课"
- [x] `JSON.parse` **全量 try/catch** 且有语义化兜底（41 处解析点全部在 `try` 内）
- [x] 写盘后正确失效缓存

**判定方法**：检索所有 `JSON.parse` 是否在 `try` 内；核对写盘路径是否单次。

**回退红线**
- 不得把跨星期更新改回「`deleteCourse` → `insertCourse`」两段写盘
- 新增 `JSON.parse` 必须包 `try/catch`（`JSON.parse(JSON.stringify(...))` 深拷贝除外，其输入是内存对象不抛错）

---

### 维度 7｜数据安全性（防误删，8%）— 当前 100 ✅

**达标条件**

- [x] 删除**二次确认**：有明确文案（"再点确认"）+ 超时反馈（8 秒复位并提示"已取消"）
- [x] 删除后**可撤销**：删除前暂存完整快照 → 写盘后显示 5 秒撤销浮条 → 点撤销按时间重排插回并写回
- [x] 确认态隐藏易误触的相邻按钮
- [x] 撤销定时器在 `onDestroy` 清理（离开页面不误回滚）

**判定方法**：走查三个删除入口（课程管理单条、编辑页删除、清空全部）。

**回退红线**
- 不得移除二次确认或撤销通道
- 撤销恢复**必须写回存储**（只改内存不算）
- 不得让撤销定时器残留到页面销毁后

---

### 维度 8｜UI 一致性与防混乱（10%）— 当前 100 ✅

**达标条件**

- [x] **防混乱**：设置项若设计上只作用于单页，必须在 UI **明确声明作用范围**
  - 例：字号设置只作用于首页课程卡片 → 标题为「**首页课程字号**」+ 说明「仅影响首页课程卡片，其他页面为固定字号」
- [x] 胶囊屏内容区 padding 统一为 16px
- [x] 解锁弹窗按钮统一 48px，文案降低付费压迫感
- [x] 跨页面触控目标尺寸一致（胶囊屏按钮统一 48px，含 `detail` 页 back / trash / stepper）

**关键判定原则**：同一设置在各页面表现不一致时，要区分是**缺陷**还是**有意设计**——
有意设计且已向用户声明范围的，**不构成"混乱"**（如首页课程字号）；未声明却只作用于单页，才扣分。

**回退红线**
- 单页生效的设置**必须声明范围**，否则用户会理解为"设置没生效"
- 不得引入新的跨页不一致文案或控件尺寸

## 四、常见回退陷阱

| 看似合理的改动 | 实际后果 |
|:---|:---|
| **做"全局字号联动"**（让所有页跟随字号设置） | 按钮文字溢出、胶囊屏文本截断，同时威胁维度 3（字号合规）、2（胶囊屏可读性）、4（布局）三个已满分维度 |
| 给 `week-view` 胶囊屏加回行号列 | 列数 2.67 → **1.57**，跌破 2.5 下限 |
| 把 `add-course` 时间盒改回固定宽度 | 80×2 + 30 = 190px > 176px，溢出 |
| 跨星期更新改回「先删后插」两段写盘 | 插入失败即**永久丢课** |
| 撤销定时器未在 `onDestroy` 清理 | 离开页面后误触发回滚 |
| 新页面自己调 `device.getInfo` | 首屏重复异步 IPC，拖慢首屏 |
| 新增设置项却只在一处生效、且不说明 | 用户认为"设置没生效"，维度 8 掉分 |

## 五、自检流程

改动涉及哪类，就走哪条：

| 改动类型 | 自检动作 |
|:---|:---|
| 改字号 / 行高 | 全量扫描 `font-size` <20px 与行高是否 =1.2×字号 |
| 改 `week-view` | 算 `160 ÷ cellWidth ∈ [2.5, 3.5]`；确认胶囊屏行号列为 0 |
| 改胶囊屏样式 | 按 192px 宽度做算式推导，确认不溢出 |
| 改删除流程 | 确认二次确认文案 + 超时反馈 + 撤销写回 + 定时器清理 |
| 改存储读写 | 确认单次原子写盘 + `JSON.parse` 在 `try` 内 |
| 新增页面 | 补空态引导；复用已回填屏型；定时器清理 |
| 新增设置项 | 确认作用范围并在 UI 声明 |

**无法静态判定的项**（列入真机清单，不阻塞评分）：

- 胶囊屏竖向空间：自定义内容 + 状态条 + 快捷添加全开时，课程列表能否显示 2 张卡
- 非基础符号（`◀ ▶ ⇄ ▲ ▼ ·`）在手环字体下是否渲染为方框
