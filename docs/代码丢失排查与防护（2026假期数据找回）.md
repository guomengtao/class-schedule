### 2. 但内容仍留在 git 对象库里（关键）

```
$ git fsck --lost-found | awk '/dangling blob/{print $3}'
→ 遍历所有悬空对象，逐个 grep "2026-01-01"
→ HIT 837fbefa4ef5e886beb7fd2ec681a30e90a66304

**悬空 blob（dangling blob）** = 曾经执行过 `git add`、把内容写进了 `.git/objects`，但后来没有 commit（或被撤销add），于是对象"悬空"了。这正是找回的关键线索。

```

已恢复 3215 字节，见 `src/data/holidays-2026.js`。**这是原始字节，不是重抄的版本。**

## 三、根因分析

### 根因 A（直接原因）：`git reset HEAD && git clean -fd`

在 shell 历史 `~/.zsh_history` 里找到唯一一条：

```bash
cd /Users/Banner/Documents/guomengtao/tom/class/class && git reset HEAD && git clean -fd && git status --short
```

这条命令的完整破坏过程是：

1. `git reset HEAD` —— 把**暂存区里所有还没提交的改动**全部取消暂存；
2. 那些内容（包括 `holidays-2026.js`）瞬间从"已追踪待提交"降级为"未跟踪文件"；
3. `git clean -fd` —— **删除所有未跟踪的文件和目录**（`-f` 强制、`-d` 含目录），且**没有回收站、无法撤销**。

于是 `src/data/holidays-2026.js` 在工作区被物理删除。之所以今天还能找回来，纯粹是因为第 1 步之前它曾进过对象库，正好被 `git fsck` 扫到了。**这是运气，不是保障。**

> 补充：如果当时用的是 `git clean -fdx`（多了 `-x`），还会连 `.gitignore` 里忽略的东西一起删（`node_modules`、`dist/`、签名目录 `sign/` 等），后果更严重。

### 根因 B（另一个更大的损失）：`docs/` 被整体删除并提交

```
$ git show --stat 6e1fa0b
commit 6e1fa0b  Release v1.6.49: fix font size display and settings page layout
 docs/13-delete-methods-analysis.md   | 581 -------------
 docs/CRYPTO_SPEC_V5.md               | 369 ----------
 docs/CHANGELOG.md                    |  40 -
 ...（265 个 md 全部删除）
 src/data/store.js                    |  （正常修改）
```

关键事实：

| 检查项 | 结果 |
|--------|------|
| `git ls-tree HEAD~1 -- docs` 文件数 | **265** |
| `git ls-tree HEAD    -- docs` 文件数 | **0** |
| 该提交新增文件数 | **0**（纯删除 + 少量 src 修改） |
| `rm -rf docs` 的 shell 记录 | 无 |

也就是说：一个名为 "Release v1.6.49" 的提交，把 265 个文档从**磁盘和版本库同时抹掉**，自己却没有新增任何东西。典型的"AI 助手在做发布整理 / 目录清理时执行了过度删除"，随后又被自动 commit 固化，导致 `git status` 干干净净、看不出异常。**这类删除比 `git clean` 更危险，因为它被写进了历史。**

已恢复：

```bash
git checkout HEAD~1 -- docs     # 从被删前的父提交取回全部 265 个文件（229 个 md + 子目录）
```

## 四、回答你的核心疑问：关 IDE 没保存会丢吗？

**基本不会。** 原因：

- AI 助手（CodeBuddy / Trae 等）的写文件工具（`write_to_file` / `replace_in_file`）是**直接落盘**的，不依赖你按 ⌘S；
- 现代 IDE 默认有 autosave；即使没有，AI 写入的内容已经在磁盘上了；
- 因此"AI 改完 → 我没点保存 → 关 IDE"这条路径**不是本次丢失的原因**。

真正会丢代码的场景，按危险度排序：

| 排序 | 场景 | 本次是否命中 | 可否找回 |
|------|------|--------------|----------|
| 1 | `git clean -fd` / `git reset --hard` 清掉未提交的成果 | ✅ 命中（ holidays-2026.js） | 极难，只能靠 dangling blob 碰运气 |
| 2 | AI 助手误判为"临时文件/冗余文档"执行删除并自动 commit | ✅ 命中（docs/ 265 个） | 可以，只要父提交还在 |
| 3 | 多个 AI 工具（本仓库同时有 `.codebuddy/` 与 `.trae/`，远端还有 `origin/trae/agent-*` 分支）并行改动同一仓库 | ⚠️ 高风险 | 不确定 |
| 4 | 构建脚本的 `rm -rf dist / .temp_class / release` 误伤（历史里有 40+ 条 rm -rf） | ⚠️ 潜在风险 | 难 |
| 5 | 未保存的编辑器缓冲区直接关闭 IDE | ❌ 未命中 | 一般不可找回 |

## 五、防护清单（建议照做）

### 立即可做（1 分钟）

```bash
# 1) 把当前所有成果固化，未跟踪文件从此有了保护
git add -A
git commit -m "chore: 保护当前工作成果（含 2026 假期数据）"

# 2) 每天收工前打一个本地标记，随时可回滚
git tag backup-$(date +%m%d%H%M)
```

### 长期规则

1. **禁止在 AI 对话中执行 `git clean -fd/-fdx`、`git reset --hard`、`rm -rf <未明确路径>`**——已在项目规则中添加，AI 只能使用 `git status` / `git add` / `git commit`。
2. **改完一个小功能就提交一次**，尤其 AI 刚生成的文件必须立刻 `git add`；只有进了对象库才算安全（本案例就是靠一次偶然的 `git add` 救回来的）。
3. **不要让 AI 自行"整理/清理/精简"目录**。需要清理时，先 `git commit` 再让它删，保证随时 `git checkout HEAD~1 -- <路径>` 可恢复。
4. **一个仓库同一时间只开一个 AI 工具**；`.trae/` 与 `.codebuddy/` 并存时，两边的自动操作会互相覆盖。
5. **重要数据双写保护**：像节假日这类"没有就很难再凑齐"的数据，既放源码 `src/data/holidays-2026.js`，也在 md 里留一份（本文档第六、七章即是备份）。

### 以后再丢时的标准抢救流程

```bash
# 第 1 步：查工作区最近操作（谁在什么位置动过 HEAD）
git reflog

# 第 2 步：找历史版本里的文件
git log --all --oneline -- "<文件名>"
git log --all --find-object=<blob-hash> --oneline

# 第 3 步：找从未提交、但曾 add 过的悬空内容
git fsck --lost-found
# 然后逐个 git cat-file -p <blob>

# 第 4 步：从父提交取回误删的目录
git checkout HEAD~1 -- <路径>
```

## 七、数据核对结论

### 1. 放假日期（33 天），与官方通知完全一致

| 节日 | 放假时段 | 天数 | 核对 |
|------|----------|------|------|
| 元旦 | 1月1日 - 1月3日 | 3 | ✅ |
| 春节 | 2月15日 - 2月23日 | 9 | ✅ |
| 清明节 | 4月4日 - 4月6日 | 3 | ✅ |
| 劳动节 | 5月1日 - 5月5日 | 5 | ✅ |
| 端午节 | 6月19日 - 6月21日 | 3 | ✅ |
| 中秋节 | 9月25日 - 9月27日 | 3 | ✅ |
| 国庆节 | 10月1日 - 10月7日 | 7 | ✅ |

### 2. 调休上班日期（6 天），与官方通知完全一致

1月4日（周日）、2月14日（周六）、2月28日（周六）、5月9日（周六）、9月20日（周日）、10月10日（周六）。

> 注：2026 年没有"国庆+中秋连休"冲突（中秋在 9/25-9/27，国庆在 10/1-10/7，中间隔了 9/28-9/30 三天），所以 10 月没有额外的调休日。

### 3. `targetWeekDay` 字段的性质（重要）

- 国务院官方文件**只规定**「哪天放假、哪天补班」，**从不规定**「补星期几的课」。
- `targetWeekDay`（1=周一 … 7=周日）是中小学/高校通用的补课对应惯例：挪用了假期里哪一天的工作日，就补对应星期的课。
- 个别学校若有独立调休规则，由用户在「节假日与调休」页面用自定义日期覆盖内置映射即可，不影响本文件的正确性。
