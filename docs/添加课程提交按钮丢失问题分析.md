# 添加课程页面 · 提交按钮丢失问题详细分析

## 一、问题概述

在「添加课程」页面（`src/pages/add-course/add-course.ux`）中，页面底部的**「取消」+「确认添加」**两个按钮，在部分屏幕形态下用户看不到、或者需要手动滚动才能看到。

---

## 二、页面结构

当前页面 DOM 结构（已修复后的版本）：

```
.page-root (flex column, height: 100%)
├── .header               ← 返回按钮 + 标题（flex-shrink: 0）
├── .main-scroll          ← 滚动内容区（flex: 1, min-height: 0）
│   ├── .section          ← 区块1：选择课程 + 管理按钮
│   ├── .section          ← 区块2：上课时间（开始/结束步进器）
│   ├── .section          ← 区块3：上课位置（输入框）
│   └── .weekday-section  ← 区块4：星期选择
└── .bottom-bar           ← 底部按钮栏（flex-shrink: 0，在滚动区外）
    ├── input.cancel-btn  ← "取消"
    └── input.save-btn    ← "确认添加"
```

**关键：** 当前 `.bottom-bar` 已经在 `<scroll>` 元素之外，位于 `.page-root` 的直接子级，理论上应始终可见。

---

## 三、导致按钮不可见的 6 个原因（按影响程度排序）

### 3.1 原因一：胶囊屏垂直空间极度有限（根本原因）

快应用胶囊屏的典型分辨率约为 **402×476** 或类似尺寸。可用高度分析：

| 占用项 | 高度（胶囊版） |
|---|---|
| 系统状态栏 | ~40px |
| 快应用标题栏 | ~44px |
| `.page-root` 上内边距 | 30px |
| `.header` 头部 | 48px |
| `.bottom-bar` 按钮区（纵向排列） | 48 + 8(间距) + 48 + 30(下内边距) = **134px** |
| **已占用合计** | ~296px |

> **剩余给 `.main-scroll` 的高度 = 476 - 296 = 约 180px**

而 `.main-scroll` 内的内容实际需要的高度：

| 内容区块 | 胶囊版估算高度 |
|---|---|
| 区块1：选择课程（标题 + 横向滚动课程条） | ~106px |
| 区块2：上课时间（标题 + 4组步进器） | ~420px |
| 区块3：上课位置（标题 + 输入框） | ~88px |
| 区块4：星期选择（分隔线 + 星期滚动条） | ~82px |
| **滚动区内容总高** | **约 696px** |

> 结论：**内容高度是可用滚动空间的约 3.9 倍**，用户必须滚动才能看完所有内容。虽然底部按钮在滚动区外、始终可见，但用户可能会误以为按钮在滚动内容的最下方而找不到。

### 3.2 原因二：胶囊屏下 `.bottom-bar` 纵向堆叠进一步增加高度

```css
@media (shape: capsule), (shape: pill-shaped) {
  .bottom-bar {
    flex-direction: column;      /* 从水平排列变为垂直排列 */
    align-items: stretch;
    padding: 10px 0 30px 0;
  }
  .cancel-btn {
    width: 100%;
    height: 48px;
    margin-bottom: 8px;          /* 按钮之间增加间距 */
  }
  .save-btn {
    width: 100%;
    height: 48px;
  }
}
```

胶囊屏下 `flex-direction: column` 导致按钮区域高度从 **48px** 暴涨至 **48 + 8 + 48 + 40 = 144px**，进一步挤占可用空间。

### 3.3 原因三：`flex: 1` 按钮宽度在极窄屏幕下可能导致按钮截断

```css
.cancel-btn {
  flex: 1;        /* 占 1/3 */
}
.save-btn {
  flex: 2;        /* 占 2/3 */
}
```

胶囊屏可视宽度仅 **160px**（扣除左右 padding 各 16px 后）。`flex:1` 和 `flex:2` 分配在水平排列时，"确认添加"按钮宽度约为 `160 * 2/3 - 12(margin) = 约95px`。配合 `font-size: 26px`，4 个中文字符（"确认添加"）需要约 104px，存在截断风险。

### 3.4 原因四：`min-height: 0` 可能被快应用运行时忽略

```css
.main-scroll {
  flex: 1;
  min-height: 0;      /* 关键：防止 flex 子项撑开父容器 */
  flex-direction: column;
  padding-bottom: 12px;
}
```

`min-height: 0` 的作用是覆盖 flex 子项的默认 `min-height: auto`，确保 `.main-scroll` 可以被压缩到为 0，从而让 `.bottom-bar` 不会被挤出可视区域。但**部分快应用运行时可能不完全遵循 CSS Flexbox 规范**，导致 `.main-scroll` 依然以内容高度为准，将 `.bottom-bar` 挤出屏幕底部。

### 3.5 原因五：`.page-root` 上内边距过大

```css
.page-root {
  padding: 30px 16px 0 16px;    /* 上方 30px 内边距 */
}
```

胶囊屏下 30px 的顶部内边距在仅约 476px 的屏幕高度中占比约 6.3%，这是一个较大的比例。对比方屏版通常只需 `padding: 16px 8px 16px 8px`。

### 3.6 原因六：视觉对比度不足（间接因素）

```html
<input class="save-btn" type="button" value="确认添加" onclick="saveCourse"
       style="background-color: {{ theme.accent }}; color: {{ theme.bg }}" />
```

`theme.accent` = `#7ec8e3`（浅蓝），`theme.bg` = `#1a1a2e`（深蓝黑）。虽然对比度足够，但在深色背景下，浅蓝按钮与周围的深色卡片（`#16213e`）颜色接近，在低亮度屏幕或户外强光下可能被用户忽略。

## 五、根因总结

```
页面太高 (696px 内容)
  +
屏幕太矮 (仅 180px 滚动空间)
  +
按钮区域在柔性布局中最底部
  =
用户直觉上以为按钮跟随内容、需要滚到底才能看到
但实际上按钮固定在屏幕底部，始终可见
  →
用户的"看不见"更多是「不知道按钮在哪里」而非真正的不可见
```

## 六、推荐修复方案

### 方案 A：视觉强化（最低成本）

在 `.bottom-bar` 上方添加一条渐变或分割线，明确提示"这是页面底部，按钮在这里"。

```css
.bottom-bar {
  border-top-width: 1px;
  border-top-color: rgba(255, 255, 255, 0.12);
  padding: 12px 0 30px 0;
}
```

同时在按钮区域添加背景色，使其从内容区中更明显地分离出来：

```css
.bottom-bar {
  background-color: inherit;   /* 继承 page-root 背景，避免被内容覆盖 */
}
```

### 方案 B：压缩内容区高度（中等成本）

在胶囊屏下减少各区域的间距和字号，压缩总内容高度：

```css
@media (shape: capsule) {
  .section {
    margin-bottom: 6px;        /* 从 10px 减至 6px */
  }
  .stepper-time {
    padding: 4px;              /* 从 6px 减至 4px */
    margin-bottom: 4px;        /* 从 6px 减至 4px */
  }
  .stepper-row {
    margin-bottom: 4px;        /* 从 6px 减至 4px */
  }
}
```

### 方案 C：分段式表单（高成本，根本方案）

将单页表单拆分为多个步骤（参考 `add-course-v2.ux` 的分步设计），每步内容少、按钮始终可见。这是**最彻底的解决方式**，但需要重构页面。

---

## 七、结论

按钮并非真的"丢失"——它始终固定在 `.page-root` 底部。用户感到"看不见"的原因是：

1. **胶囊屏天然空间限制**（内容 696px vs 可用 180px）
2. **按钮与内容区之间缺少视觉分隔**
3. **用户心理预期**：填完表单后习惯性向下滚动找按钮，但按钮已在底部

最简单的改进是在按钮区域添加视觉分隔（方案 A），让用户一眼就能区分"上面是表单内容、下面是操作按钮"。
