## 零、一句话结论

7 个表盘**都能在快应用层（`.ux` 页面）实现**，但风险分三档：
**② 彩色 / ⑤ 背景 → 低风险先上；③ 渐变 / ⑥ 功能(保险版) / ① 横屏 → 中风险；④ 动画 / ⑦ 翻页 → 高风险，必须先做最小 demo 真机验证**。
其中 **④ 动画**（黑屏高危，用户明确要求慎重）与 **⑦ 翻页**（3D 翻转是否支持待核实）需要额外前置验证；**⑥ 功能表盘的"电量"在手环 9 上官方不支持**。

## 一、平台能力底座（侦察结论 · 已核实）

### 1.1 认知纠偏：这里的"表盘"= 快应用页面，不是米坛 `.bin`
本项目所有表盘都是 `src/pages/watch-face-*/xxx.ux`，由 Vela 快应用运行时渲染，**与米坛表盘工具的 `.bin` 是两条链路**。因此：
- 自由度 = 写 `.ux` 代码（不是米坛的"配置式拖拽"）；
- 只受 **Vela 快应用 CSS/JS 限制**，不受表盘引擎限制。
- 新增表盘必须 **`src/manifest.json` 的 `router.pages` 显式注册**（非自动发现）+ `watch-face-list.ux` 加入口。

### 1.2 屏幕
| 屏型 | 设备 | 分辨率 | shape |
|---|---|---|---|
| 跑道屏（胶囊） | 手环 9 / 10 | 192×490（9）/ 212×520（10） | `rect`（本项目实测） |
| 方屏 | 手环 9 Pro | 336×480 | `rect` |
| 圆屏 | 手表 | 466×466 | `circle` |

> 本方案默认以 **跑道屏 192×490 为主目标**；方/圆屏靠 `@media (shape:)` 或运行时宽高比适配（沿用项目既有做法）。

### 1.3 CSS 禁用清单（摘自 `vela-unsupported-reference.md`，违者白/黑屏）
`box-sizing` · `height:auto` · `position:fixed` · `z-index` · `border-*`(单边/单角) · `transition` · 伪类(`:nth-child/:hover/::before`…) · `left/top` 百分比(仅 px) · 内联 `opacity`/`rgba()`(须写进 `<style>` 类) · JS 字符串 `transform`(须 `JSON.stringify` 对象)。
> 弹窗/遮罩用 `<stack>` + `position:absolute` + 书写顺序控层级（项目已有成熟套路，经典表盘换色面板即此）。

### 1.4 动画官方支持（核实自 iot.mi.com/vela/quickapp）
官方《动画样式》文档明确支持：
- ✅ `transform` / `transform-origin`
- ✅ `animation-name` / `animation-delay` / `animation-duration` / `animation-iteration-count`（**支持 `infinite`**）/ `animation-timing-function`（linear/ease/…/`steps()`/cubic-bezier）
- ✅ `@keyframes`（项目 `anim-test.ux` 用 `@keyframes kf-spin{from{rotate(0)}to{rotate(360)}}` + `infinite` 已验证可跑）
- ⚠️ `transition-*`：**官方文档列了，但项目实测不支持** → **一律禁用，改用 `@keyframes`**。
- ⚠️ 项目实测：**`transform: rotate({{xx}}deg)` 用数据绑定 = 整页黑屏**（唯一实锤元凶）；静态字面量 rotate 完全安全。

### 1.5 黑屏铁律（新表盘必遵）
1. `.page` 用 `flex:1/position:relative; width:100%; height:100%; flex-direction:column`，**绝不叠加 flex centering + absolute 子元素**（实测元凶之一）。
2. **`transform: rotate` 禁止 `{{}}` 数据绑定**；实时转动一律用 `@keyframes` 动画，不用 js 改角度。
3. 渲染元素**宁少勿多**（`for` 生成量起步 ≤20，逐档加、逐档真机验证）。
4. `onInit` 里的 `for` 用 `try-catch` 包；`setInterval` 间隔 **≥200ms**；`onShow/onHide/onDestroy` 完整启停定时器。
5. 背景色由最外层 div 提供（`config.json` 的 `window.backgroundColor` 无效）。

## 二、七个表盘逐个设计

> 统一保留经典表盘的骨架：**返回按钮 + 点击空白返回 + 换色面板（storage 持久化）**，各表盘按需增删。

### ① 横屏表盘（Landscape） 🟠 中风险
- **需求**：内容整体"右转/横过来"，时间尽量最大；**隐藏所有按钮**；**长按弹出改色**。
- **实现**：
  - 容器 `div` 加**静态字面量** `transform: rotate(90deg)` + `transform-origin` 居中；内部放动态时间文本（**文本内容动态 OK，rotate 是字面量，不违反铁律**）。
  - 屏 192×490，旋转后"可用横向长度≈屏高(490)、纵向厚度≈屏宽(192)"，字号上限由 192 方向决定 → **必须真机实测确认"最大且不溢出"**。
  - 隐藏按钮：不渲染返回/换色按钮，仅留整页 `onlongpress` 触发换色面板（`onlongpress` 为规范支持的事件）。
- **降级**：若整页旋转黑屏 → 只旋转"数字块"；再不行 → 横排大字（不旋转，仅加大字号）。
- **待核实**：整容器静态 rotate 在真机的稳定性（见 §五-1）。

### ② 彩色表盘（Colorful digits） 🟢 低风险
- **需求**：HH:MM 每个数字颜色都不同。
- **实现**：把时间拆成单字符（`H H : M M`，5 个 `<text>` 或 `for`），各自绑定 `color`（色板数组循环）。**纯 color 数据绑定，不碰 transform，零黑屏风险**。
- **备注**：与 ⑤ 背景表盘同源（都是"色板 + 绑定"套路）。

### ③ 渐变表盘（Gradient） 🟡 中风险
- **需求**：颜色是渐变色。
- **实现（两选一）**：
  - **A（首选，最保险）**：逐字符**伪渐变**——按 5 个字符在一条色带上取渐变 5 档色（复用 ② 的结构），视觉接近渐变且 100% 安全。
  - **B（更炫，待实测）**：背景用 Vela `linear-gradient`（官方《渐变样式》称支持）。**项目内无先例实测**，且**渐变文字**（`background-clip:text`）大概率不支持。
- **降级**：B 不通即退 A。
- **待核实**：`linear-gradient` 在真机的支持程度（见 §五-2）。

### ④ 动画表盘（Animated） 🔴 高风险（黑屏高危，用户明确要求慎重）
- **需求**：表里加入酷炫动画，但**特别容易黑屏**。
- **红线**：**只用已核实属性**——`@keyframes` + `animation-*`（含 `infinite`）；`transform` 的 `rotate/translate/scale`（**只能在 keyframes 内 / 字面量**）；`opacity`（写进 CSS 类）。**禁用** transition、JS 动态 transform、伪类。
- **强制前置**：**先做"最小 demo 页面"**（1~2 个动画元素：如旋转光环 + 呼吸透明度），真机确认不黑，**再逐步加**动画元素（每档真机验证，元素红线起步 ≤20）。
- **交付方式**：先交 demo（独立页面或本表盘的极简版），验证通过后再交完整版。
- **风险**：整页多元素 + 无限动画会压垮渲染管道（历史黑屏主因）。

### ⑤ 背景表盘（Backgrounds） 🟢 低风险
- **需求**：背景色/背景风格多种多样，可选。
- **实现**：预置若干背景方案（纯色 / 双色块 / 伪渐变），点击或长按切换，`@system.storage` 持久化（**直接复用经典表盘换色面板的 overlay 套路**）。
- **风险**：低（纯样式绑定）。

### ⑥ 功能表盘（Functional） 🟡 中风险 · 需按机型降级
- **需求**：显示电量、手环空间、手电筒等；**先加几个保险的功能**。
- **官方核实结论（关键）**：
  | 功能 | API | 手环9/9Pro | 手环10 | 结论 |
  |---|---|---|---|---|
  | 电量 | `@system.battery` | ❌ **不支持** | ✅ 支持 | 手环9上**做不了**，须探测降级 |
  | 空间 | `@system.storage`(仅键值)/`@system.file`(文件) | 无容量 API | 无容量 API | **大概率做不了**（待核实） |
  | 手电筒 | — | Vela 组件/API 列表**无手电筒** | — | **大概率不支持**（待核实） |
  | 时间/日期 | 本地 `Date` | ✅ | ✅ | **保险** |
  | 设备信息 | `@system.device` | ✅ | ✅ | **保险** |
  | 课程数量/下一节课 | `@system.storage` 本地数据 | ✅ | ✅ | **保险** |
- **保险版范围（本方案落地）**：**时间 + 日期 + 设备型号/分辨率 + 课程数量统计 + 下一节课**（全为本地/已支持）。
- **电量卡片**：做成**可选卡片**——`battery.getStatus` 成功才显示，失败（手环9）**静默隐藏**，不报错不黑屏。
- **明确暂不做**：空间、手电筒（列入 §五 待核实，确认无 API 则正式砍掉）。
- **风险**：保险功能低；电量卡片需正确处理"不支持"分支（try-catch + 隐藏）。

### ⑦ 翻页表盘（Flip clock） 🟠 中风险 · 3D 待核实
- **需求**：翻动走时间的效果。
- **官方核实**：Vela transform 文档为 **2D 转换**；**3D 翻转（`rotateX/rotateY`）在官方文档与项目均未见确认** → **3D 真翻页大概率不支持**。
- **实现（两选一）**：
  - **A（首选降级，2D 可兜底）**：用 `@keyframes` + `steps()` 做**数字阶梯滚动**模拟翻页；或"上下滑出/滑入"过渡（用 animation，非 transition）。
  - **B（待核实）**：若真机实测 3D `rotateX` 支持，则做真翻转卡片。
- **降级**：B 不通即退 A。
- **待核实**：3D transform 支持性（见 §五-3）。

## 五、待核实清单（前置条件，未确认前对应表盘不开发）

1. **【横屏① 前置】** 整容器静态 `transform: rotate(90deg)` 在真机是否稳定、字号上限多少。
2. **【渐变③ 前置】** Vela `linear-gradient` 真机支持程度 → 否则走"逐字符伪渐变"。
3. **【翻页⑦ 前置】** Vela 是否支持 3D `transform`（`rotateX/rotateY`）→ 否则走 2D 模拟。
4. **【功能⑥】** 手环 9 电量不支持已确认；需拍板：电量卡片是否只在支持的机型（手环10+）显示，还是干脆不做。
5. **【功能⑥】** 存储空间 / 手电筒 API 是否存在 → 大概率无，确认即砍。

> 这些验证有的需要**真机/模拟器**（本会话此前的表盘改动一直由用户"人肉测试"）。

## 六、预算与验证

- **预算**：1 个表盘 ≈ 1 段开发（≤4 积分 / ≤5 分钟）。7 个表盘 **建议分多轮**，每批 1~2 个；动画表盘单独拆段（先 demo）。
- **验证方式**：每张表盘**必须在模拟器/真机逐张点开**验证；沿用项目 SOP——① 先确认装的是新包 ② 先排部署/模拟器环节 ③ 分环节定位（欢迎页→目录→具体表盘）。
- **回滚**：每个表盘是独立文件，出问题删文件 + 撤 manifest 路由 + 撤目录入口即可；**未提交的改动随时可弃**。
