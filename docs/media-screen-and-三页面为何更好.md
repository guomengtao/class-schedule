# `@media screen and` 让三个页面反而更好？分析

> 背景：批量修正 `@media screen and` → `@media (shape: ...)` 后，首页/编辑课程/课程管理不再黑屏重启，但设备信息、欢迎页、设置页的界面反而变奇怪了。重新应用 `@media screen and` 后，这三个页面变好了。为什么？

---

## 一、`@media screen and` 是什么？

```css
/* W3C 标准写法 */
@media screen and (shape: pill-shaped) {
  .xxx { ... }
}

/* 快应用专用写法 */
@media (shape: pill-shaped) {
  .xxx { ... }
}
```

`@media screen and (shape: pill-shaped)` 是 **W3C CSS 标准**写法，意思：

| 部分 | 含义 |
|------|------|
| `@media` | 媒体查询开始 |
| `screen` | 设备类型 = 屏幕（不是 `print` 打印） |
| `and` | AND 逻辑运算符 |
| `(shape: pill-shaped)` | 屏幕形状 = 胶囊形 |

整句翻译：**当设备是"屏幕"且形状是"胶囊形"时**，应用里面的样式。

## 二、手环 9 上发生了什么？

快应用 CSS 引擎**只识别** `@media (shape: ...)` 这种专用语法，不认识 `screen and`。

```
@media screen and (shape: pill-shaped)
     ↓
  CSS引擎看到 "screen" → 不认识 → 整个媒体查询判定为 false
     ↓
  里面的样式全部不生效
     ↓
  回退到媒体查询外的基础样式（fallback）
```

**换句话说：`@media screen and` 在手环 9 上的作用是"让所有设备形状特定样式失效，统一使用基础默认样式"。**

## 三、三页面对比分析

### 3.1 设备信息页（device-info）

| 样式区域 | 基础 fallback 样式 | 胶囊屏专用样式 |
|----------|-------------------|:---:|
| 页面内边距 | `padding: 38px 8px 10px 8px` | `padding: 30px 16px 30px 16px` |
| 菜单项布局 | `flex-direction: row`（水平排列） | `flex-direction: column`（垂直堆叠） |
| 内容区宽度 | 192 - 16 = **176px** | 192 - 32 = **160px** |
| label 字号 | 24px | 22px |

**效果差异：**

- **胶囊屏专用样式**：垂直堆叠布局 + 16px 侧边距 = 内容区仅有 160px 宽，每项 label 和 value 分两行显示，"品牌"、"型号"等短标签独占一行浪费空间。
- **基础 fallback 样式**：水平排列布局 + 8px 侧边距 = 内容区 176px 宽，label 和 value 同行显示，空间利用率更高，信息密度适当。

**结论：去掉胶囊屏专用样式后，内容区更宽、不挤作一团，阅读体验反而更好。**

### 3.2 欢迎页（welcome）

| 样式区域 | 基础 fallback 样式 | 胶囊屏专用样式 |
|----------|-------------------|:---:|
| 页面内边距 | `padding: 20px`（四边 20px） | `padding: 60px 12px 30px 12px` |
| 进入按钮 | `width: 220px`（宽 220） | `width: 160px`（窄 160） |
| 设置按钮 | `width: 180px` | `width: 140px` |
| 退出按钮 | `width: 180px` | `width: 140px` |

**效果差异：**

- **胶囊屏专用样式**：按钮宽 140-160px，窄而趋向方形，留白多但按钮瘦小不协调。
- **基础 fallback 样式**：按钮宽 180-220px，宽高比合理（220×52 = 4.2:1），更有"按钮感"而非"方形块"。

**结论：基础样式下按钮更宽，比例更协调，不再像方形。**

### 3.3 设置页（settings）

| 样式区域 | 基础 fallback 样式 | 胶囊屏专用样式 |
|----------|-------------------|:---:|
| 页面内边距 | `padding: 44px 10px 12px 10px` | `padding: 30px 16px 30px 16px` |
| 行标签字号 | 30px | **32px**（更大） |
| 行内边距 | `padding: 12px 0` | `padding: 14px 0` |
| 行提示文字 | 显示 | `display: none`（隐藏） |
| 昵称行布局 | `flex-direction: row` | `flex-direction: column`（垂直） |

**效果差异：**

- **胶囊屏专用样式**：字号更大（32px）、内边距更多（14px）、侧边距更宽（16px）→ 内容区收窄到 160px，同时大字号在窄屏上容易截断。加之隐藏了行提示文字（hint），减少了有用信息。
- **基础 fallback 样式**：字号 30px、侧边距 10px → 内容区 172px，行提示文字可见，信息完整，不会产生截断感。

**结论：基础样式信息更完整、间距更合理，不会被大字号过度压缩。**

## 四、为什么胶囊屏专用样式反而更差？

核心问题：**胶囊屏专用样式被过度"优化"了**。

| 问题 | 表现 |
|------|------|
| 侧边距过大 | 16px 内边距在 192px 屏幕上吃掉 32px，只剩 160px |
| 字号反增 | 设置页 30px→32px，窄屏上反而把字号放大 |
| 布局改垂直 | 把水平布局改成垂直堆叠，本来一行能显示的要两行 |
| 隐藏信息 | 设置页把 hint 文字设 `display: none`，丢失功能提示 |

这些"优化"本意是适配窄屏，但实际效果是**把本来够用的空间进一步压缩，然后把内容粗暴地改成垂直堆叠**，反而让体验倒退了。

---

## 五、总结：不是所有页面都适合形状适配

```
蓝图：胶囊屏专用样式 > 基础样式 > 无样式（崩溃）
现实：基础样式 > 胶囊屏专用样式（这三个页面）
```

| 页面 | 去掉胶囊屏专用样式后 | 原因 |
|------|:---:|------|
| 首页 index | 🔴 崩溃重启 | 基础样式缺失，依赖 @media |
| 编辑课程 add-course | 🔴 崩溃重启 | 同上 |
| 课程管理 course-manager | 🔴 崩溃重启 | 同上 |
| 设备信息 device-info | 🟢 变好了 | 胶囊屏样式过度压缩 |
| 欢迎页 welcome | 🟢 变好了 | 胶囊屏按钮过窄 |
| 设置页 settings | 🟢 变好了 | 胶囊屏字号过大、信息隐藏 |

**启示**：对于有完整基础样式的页面，`@media screen and` 导致的"胶囊屏样式失效"反而是好事——基础样式的设计本身就在 192px 窄屏上运行良好，不需要额外的形状适配来过度压缩。
