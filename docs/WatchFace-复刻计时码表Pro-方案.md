## 一、参考图是什么

两张 `EV表盘-*.png` 是同一款：**Apple Watch「计时码表 Pro」(Chronograph Pro)** 风格。

可见要素：

| 要素 | 内容 |
|---|---|
| 表圈 | 黑色粗圈，约占半径 10%，与白盘硬边相接 |
| 盘面 | 米白（非纯白），哑光 |
| 小表盘 ×2（可见） | 左上、右上，深灰凹陷面，刻度 100/75/50/25，各带一根细指针 + 中心白点 |
| 主刻度 | **12 根灰色矩形条**，无数字；3/6/9/12 位明显加长 |
| 指针 | 时针（粗短黑）、分针（长黑）、秒针（极细长黑，尖端几乎抵到刻度） |
| 日期区 | 6 点上方 `OCTOBER` 小字 + 白底黑框 `30` |

⚠️ **重要：这个表盘不是快应用画的。** `ev-face/src/pages/index/index.ux` 只有 111 行，画的是 `hh:mm:ss` 数字；`faces.ux` 是 30 款表盘的纯文字清单。这两张截图是 Vela 模拟器（AVD `xiaomi_s4`、466×466）底下的**系统表盘透出来**的效果 —— 正好对应 `ev-face/docs/自带表盘清单.md` 第六节记的那个坑：CSS 写成 `420pxpx` 会让元素尺寸归零、整页透明，底下系统表盘就露出来了，看着像"表盘在快应用里跑"。

所以：**参考图只有视觉效果，没有可复用代码。** 一切要从零手写。

## 二、必须先拍板的矛盾：圆形表盘 vs 长条屏

这是整件事的核心风险，不谈清楚就动手会白做。

参考图是 **466×466 正圆**（Watch S4）。但本 App 的主力机型是 **192×490 长条屏**（手环 9 / 10）：

```
正圆放在 192×490 上：
  圆直径 = 192（受宽度限制）
  上下各空 (490 − 192) / 2 = 149px  → 屏幕利用率仅 39%
```

而 `docs/无框机械表盘-方案.md` 当初否决「正圆方案 C」的理由，原文就是：

> ✌ **否决**。违背「按屏幕比例」需求，且浪费长屏

也就是说：**直接复刻圆盘，等于把当初被否掉的设计再捡回来。**

### 三条出路

| 方案 | 做法 | 代价 | 适用 |
|---|---|---|---|
| **① 双形态**（推荐） | `a/b` 比 ≤ 1.15 的屏（Watch S4 466²、Pro 336×480、REDMI Watch 6 432×514）走**正圆 1:1 复刻**；长条屏（192×490、212×520）走**圆盘 + 上下承接区** | 两套版面，工作量 ×1.6 | 全机型 |
| ② 只在方屏提供 | 表盘列表里对长条屏机型隐藏此项 | 主力用户（手环 9/10）看不到 | 小工作量试水 |
| ③ 椭圆拉伸 | 圆盘按屏比拉成椭圆 | 指针长度失配、刻度变形，**不像 Apple Watch 了** | ❌ 不建议 |

**方案 ① 的「上下承接区」具体长什么样**（192×490 举例）：

```
┌─────────────┐  y=0
│  10月3日 周五  │  顶栏 40px：日期 + 星期
├─────────────┤  y=40
│             │
│   ╭─────╮   │
│   │ 圆盘 │   │  圆盘 192×192 居中，y=110~302
│   ╰─────╯   │
│             │
├─────────────┤  y=370
│ 今日 3/8 节   │  底栏 90px：课时进度条
│ ▓▓▓░░░░░     │
└─────────────┘  y=490
```

用上下两块**课表信息**把 149px 的空白填掉 —— 这反而是本 App 相对 Apple Watch 的差异化优势（Apple Watch 的圆盘上下本来就没法放东西）。

## 三、候选复刻目标对比

从 `ev-face/docs/自带表盘清单.md` 的 19 个原生表盘 + 参考图里筛：

| 候选 | 来源 | 参考图 | 难度 | 与本 App 的契合度 | 结论 |
|---|---|---|---|---|---|
| **A. 计时码表 Pro** | 参考截图（Apple Watch 风格） | ✅ 有，清晰 | ★★★ | 高：三个小表盘正好可映射「课时进度 / 剩余课 / 电量」 | ⭐ **推荐** |
| B. 银面机械 #12 | `120917345469` 5.00MB | ❌ 无（`resource.bin` 黑盒，无 PNG） | ★★★★ | 中：延续当前"机械"定位，但圆盘同样撞长条屏 | 备选 |
| C. Minerals-GMT #19 | `120917345845` 6.64MB | ❌ 无 | ★★★★★ | 低：矿物纹理靠渐变，Vela 画不出 | ❌ 放弃 |
| D. 入门款 #1 | `120917345117` 387KB | ❌ 无 | ★☆☆ | 低：数字款，与「机械/仿真」方向相反 | ❌ 放弃 |

**为什么推荐 A**

1. **唯一有清晰参考图的**。B/C/D 都是私有 `resource.bin`，文档第 36 行写明"没有任何 PNG/BMP/JPEG 头，图片不是标准格式，无法直接取出当素材"，只能肉眼看。而 A 有 466×466 截图，每个像素都能对着写。
2. **三个小表盘可承载真实数据**。Apple Watch 上它们是装饰性的计时秒/分表，我们可以改造成：左上 = 今日课时进度（`3/8`）、右上 = 距下节课剩余（环形）、下方 = 电量。视觉 1:1，功能是 App 自己的。
3. **视觉冲击强于当前的无框款**。现在的无框机械是"留白多、极简"，但 192 屏上上下大片空白本来就是妥协；换成白盘黑圈的强对比，在小屏上反而更抓眼。
4. **技术难度在可控区间**。核心难点（三个凹陷小表盘的多层错位圆、中央细秒针）都是 `watch-face-gold` 已经验证过的技法。

**B 不可行的具体原因**：银面机械款是 5MB 多图层，且没有任何参考素材。要复刻只能靠"去模拟器里看看然后凭记忆画"，做出来必然不像 —— 这种复刻没有验收标准，等于自由发挥。

## 四、Vela 硬约束 → 能画什么、不能画什么

这些是本项目已经用血换来的结论（见 `开发须知-硬约束.md`、各表盘文件头注释），方案必须绕着走：

| 约束 | 后果 | 本方案的应对 |
|---|---|---|
| **禁用动态 transform** | `transform: rotate({{deg}}deg)` 会整页黑屏 | 走针一律用 **120 档字面量类** `.r0`~`.r119`，只切 class 名 |
| **旋转轴 = 元素顶部中点** | `transform-origin` 不按 CSS 语义生效 | 针一律「顶部中点压在盘心 + 向下延伸」，`rotate(180+θ)` |
| **无渐变** | 金属高光、凹陷阴影都做不了 | 用**错位双圆**造月牙（亮圆在下、暗圆向右下偏 1–3px） |
| **多兄弟节点 `if`** | 会整页白屏 | 条件渲染一律用 `display` 绑定 |
| **无 canvas / 无 SVG** | 不能画任意图形 | 全部拆成 `div`（圆角靠 `border-radius: 50%`）+ `text` |
| **`px` 不能重复** | `420pxpx` → 尺寸归零 + 整页透明 | 所有尺寸字符串由 JS 拼接后统一校验 |

### 逐要素可行性

| 参考图要素 | 快应用能否还原 | 做法 |
|---|---|---|
| 黑色粗表圈 | ✅ 轻松 | 外层 `div` 圆 + `border-width` |
| 米白哑光盘面 | ✅ | 纯色 `background-color` |
| 灰色矩形刻度 ×12 | ✅ | 12 个 `div`，复用 120 档 `.rN` 定向 |
| 三个凹陷小表盘 | ✅ 但费工 | 每盘 4–5 层错位圆（外暗环 / 内亮环 / 盘面 / 内阴影月牙） |
| 小表盘刻度 100/75/50/25 | ✅ | 8 个 `text` + 8 根细 `div` |
| 中央细长秒针 | ✅ | 1px 宽 `div`，配重尾反向延伸 |
| 日期窗白底黑框 | ✅ | 2 层 `div` + `text` |
| **Apple Watch 的秒针扫动动画** | ❌ | Vela 无 60fps 动画；退化为**每秒跳一格**（现有 `setInterval` 1s） |
| **表盘随抬腕渐亮** | ❌ | 快应用不是真表盘，无此通道 |

> 最后两条不是方案缺陷，是「快应用 ≠ 表盘」的本质差异。`自带表盘清单.md` 第 7 节已列过对照表：快应用不能常驻主屏、无 AOD。这个页面本质是**"用快应用模仿表盘"的观赏页**，用户需要主动点开看。

## 五、实施步骤

### 阶段 1：几何内核（不改视觉）

在 `watch-face-random.ux` 现有骨架上改，**保留**可直接复用的部分：

| 现有资产 | 复用 |
|---|---|
| `stepClass(deg)` 120 档映射 | ✅ 原样保留 |
| `data` 里的五机型尺寸档（`mtCls`/`hmCls`/`dwCls`…） | ✅ 保留并扩展 |
| 走针的 `hx/hy/hh` 坐标 + `hourCls` 更新 | ✅ 保留 |
| 椭圆时位分配（`a=min(0.44W,0.42H)`） | ❌ 替换为**正圆/圆盘**逻辑 |

产出：一个空的圆盘骨架 + 走针能转，跑通 5 个机型。

### 阶段 2：视觉层

按参考图逐层叠：

1. 表圈（黑）+ 盘面（米白）
2. 12 根矩形刻度（3/6/9/12 加长）
3. 两个小表盘（左上/右上）—— 先画静态，不接数据
4. 主针三层（时针/分针/秒针 + 中央轴帽）
5. 日期区（月份小字 + 日号框）

产出：**静态截图与参考图逐像素对照**，这是本阶段唯一的验收手段。

### 阶段 3：数据接入 + 双形态

1. 小表盘接真实数据（左上课时进度 / 右上剩余课 / 下方电量）
2. 长条屏的上下承接区（顶栏日期星期、底栏进度条）
3. `a/b` 比 ≤ 1.15 时走正圆、否则走圆盘 + 承接区

### 阶段 4：真机

`docs/` 里所有表盘方案的最终验收都在真机，模拟器只能验几何。必须至少过：手环 10（192×490）+ Watch S4（466×466）+ 10 Pro（336×480）。

## 六、验收标准

| # | 项 | 判据 |
|---|---|---|
| 1 | 无白屏 | 五机型首帧、切换、返回均不白屏 |
| 2 | 无黑屏 | 走针 1 分钟内不出现整页黑屏（动态 transform 的典型症状） |
| 3 | 圆盘居中 | 192×490 上圆心偏差 ≤ 1px，上下留白对称 |
| 4 | 刻度不出界 | 所有元素距屏边 ≥ 4px |
| 5 | 与参考图相似度 | 192 屏缩印后，表圈/刻度/小表盘/日期区位置关系一致 |
| 6 | 秒针无残影 | 每秒切 class 时旧针不残留 |
| 7 | 包体增量 | 新增 CSS 不超过 25KB（当前 watch-face-random 22.1KB 压缩后） |
