### 4.4 数据备份与恢复（隐形刚需锚点）

**设计动机**：中小学生对"多课表"需求不大，但对"手环重置/换设备数据全丢"极度恐惧。把"数据备份"作为高级解锁的隐形刚需卖点，覆盖所有用户。

**触发时机**：用户在设置页点击「数据备份」或「数据恢复」入口时；也可在课程表管理页的导出功能处触发。

**实现方案**（初期无需服务器）：
- **备份**：将当前课程表数据导出为 JSON 文件，保存到手环本地存储
- **恢复**：从本地存储读取 JSON 文件，导入课程表数据
- 后续可升级为云端备份（需服务器支持）

**改造方案**：
- 免费用户点击「数据备份」或「数据恢复」→ 弹出升级弹窗
- 已解锁用户 → 正常使用备份/恢复功能

**弹窗文案**：同 4.1 统一弹窗，`feature: 'backup'`

## 五、支付方案设计

### 5.1 支付方式

小米快应用支持以下支付方式：

| 方式 | 可行性 | 说明 |
|------|--------|------|
| 小米支付SDK | 推荐 | 快应用原生支持，需接入小米支付 |
| 米币支付 | 备选 | 学生用户有米币充值习惯 |
| 微信/支付宝 | 需评估 | 快应用内跳转H5支付 |

推荐：优先使用小米支付SDK，1-2元小额支付体验最流畅。

### 5.2 支付失败兜底：自动转激活码入口（关键）

**背景**：学生群体绑银行卡/实名认证的成功率极低。如果小米支付失败，用户直接流失。

**兜底逻辑**：
```
用户点击「立即解锁」
  → 调用小米支付SDK
  → 支付成功 → 设置解锁状态 → 执行操作
  → 支付失败/取消 → 弹出兜底弹窗
```

**兜底弹窗文案**：
```
┌──────────────────────────────────┐
│         支付遇到问题？             │
│                                  │
│  可选择以下方式完成解锁：          │
│                                  │
│  [ 获取激活码 ]                   │
│  跳转微信小程序/公众号，1元购买激活码│
│                                  │
│  [ 稍后再说 ]                     │
└──────────────────────────────────┘
```

**激活码流程**：
1. 用户点击「获取激活码」→ 跳转微信小程序/H5页面
2. 支付1元 → 获得6位激活码
3. 回到快应用「激活码」页面输入 → 解锁高级功能
4. 激活码一次有效，绑定设备

**激活码生成规则**：服务端生成，简单校验即可（1-2元产品，破解成本 > 购买成本）

### 5.3 激活码方案（作为主要支付方式的兜底）

考虑到快应用支付接入可能有门槛，备选方案：

```
用户通过微信小程序/公众号支付后获得激活码，
在快应用「激活码」页面输入激活码解锁高级功能。
```

**优点**：不依赖快应用支付SDK，开发简单，同时沉淀用户到微信私域
**缺点**：用户需要跳转外部支付，流程稍长

### 5.4 激活状态存储

```
存储键：premium_unlocked
存储值：true | false（或存储激活时间戳）
```

- 激活后写入本地存储
- 每次启动检查激活状态
- 激活码方案：存储激活码 + 本地校验
- 重复激活：同一设备已激活，再次输入激活码提示"已解锁"

## 七、技术实现要点

### 7.1 状态管理（store.js 新增）

```javascript
// 检查是否已解锁高级功能
isPremiumUnlocked: function(callback) {
  storage.get({
    key: 'premium_unlocked',
    success: function(data) {
      callback(data === 'true')
    },
    fail: function() {
      callback(false)
    }
  })
},

// 设置解锁状态
setPremiumUnlocked: function(callback) {
  storage.set({
    key: 'premium_unlocked',
    value: 'true',
    success: function() { if (callback) callback(true) },
    fail: function() { if (callback) callback(false) }
  })
}
```

### 7.2 拦截点改造

| 文件 | 拦截位置 | 拦截条件 |
|------|----------|----------|
| `schedule-manager.ux` | `addSchedule()` 方法 | 免费用户，`list.length >= 1` 时弹窗 |
| `homepage-settings.ux` | 所有开关 `onclick` / 输入框 `onclick` | 免费用户，弹窗拦截 |
| `settings.ux` | 主题切换点击 | 免费用户点击非默认主题，弹窗拦截 |

### 7.3 拦截示例代码

```javascript
// schedule-manager.ux - addSchedule 方法改造
addSchedule() {
  var self = this
  store.isPremiumUnlocked(function(unlocked) {
    if (unlocked) {
      self.doAddSchedule()
    } else {
      // 第一套课表免费，只有已有1套及以上时拦截
      if (self.list.length >= 1) {
        self.showUnlockDialog({
          feature: 'schedule',
          benefits: ['多课表管理', '数据备份与恢复', '首页自定义', '10套主题'],
          primaryImage: 'homepage_custom_preview.png',
          cancelText: '继续使用标准版'
        })
      } else {
        self.doAddSchedule()
      }
    }
  })
},

doAddSchedule() {
  var name = "课程表" + (this.list.length + 1)
  database.addSchedule(name, function() {
    this.loadData()
  })
}
```

## 十一、风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 学生绑银行卡/实名认证率低 | 小米支付成功率低 | 支付失败自动转激活码兜底，微信小程序购买 |
| 小米支付SDK接入困难 | 无法收费 | 先用激活码方案过渡，同时沉淀微信私域用户 |
| 用户破解/绕过激活 | 收入损失 | 简单校验即可，1-2元产品破解成本 > 购买成本 |
| 免费竞品功能追赶 | 竞争力下降 | 持续强化手环编辑体验，这是核心壁垒 |
| 用户对"付费"反感 | 卸载/差评 | 基础功能完全免费，仅增值功能收费，日常无骚扰 |
| 用户担心数据丢失 | 不信任产品 | 数据备份捆绑高级解锁，同时作为付费转化锚点 |
