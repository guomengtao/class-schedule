# 一键重置默认数据功能失效分析

## 概述

`reset-data` 页面提供了三个操作：恢复默认课程、一键重置全部、重置为空。经代码审查，发现多个导致功能失效或行为异常的缺陷。

---

## 缺陷清单

### 1. 【严重】`resetToDemoData` / `_doResetToDemoData` 永远返回成功

**文件**: [database.js](file:///Users/Banner/Documents/guomengtao/tom/class/class/src/data/database.js#L1029-L1041)

**问题描述**: `finalizeReset()` 函数在所有路径中都调用 `callback(true)`，无论中间步骤是否成功。

```javascript
function finalizeReset() {
  storage.set({
    key: "scheduleNames",
    value: JSON.stringify(names),
    success: function() {
      currentScheduleIndex = 0
      storage.set({
        key: "currentScheduleIndex",
        value: "0",
        success: function() {
          log("resetToDemoData: complete")
          if (callback) callback(true)    // ← 永远 true
        },
        fail: function() {
          if (callback) callback(true)    // ← 失败也返回 true
        }
      })
    },
    fail: function() {
      if (callback) callback(true)        // ← 失败也返回 true
    }
  })
}
```

**影响**:
- `handleResetAll` 中的 `success` 参数永远为 `true`，用户看到"全部数据已重置"但实际数据可能未写入
- 无法区分真正的成功和失败

**调用链**:
```
handleResetAll → resetToDemoData → _doResetToDemoData → saveAll → finalizeReset → callback(true)
```

### 2. 【严重】Storage 路径下 `saveToStorageWithIndex` 调用缺少回调，存在竞态条件

**文件**: [database.js](file:///Users/Banner/Documents/guomengtao/tom/class/class/src/data/database.js#L970-L973)

**问题描述**: 在非 SQLite 模式下，`saveToStorageWithIndex` 被调用时没有传入回调函数，导致 `finalizeReset()` 在数据写入完成前就执行。

```javascript
} else {
  saveToStorageWithIndex(0, schedule1)   // ← 异步，无回调
  saveToStorageWithIndex(1, schedule2)   // ← 异步，无回调
  finalizeReset()                        // ← 立即执行，不等上面两个完成
}
```

`saveToStorageWithIndex` 函数的定义 ([database.js:L366-L377](file:///Users/Banner/Documents/guomengtao/tom/class/class/src/data/database.js#L366-L377)):

```javascript
function saveToStorageWithIndex(index, schedule, callback) {
  storage.set({
    key: STORAGE_KEY + "_" + index,
    value: JSON.stringify(schedule),
    success: function() {
      if (callback) callback(true)      // ← callback 为 undefined，跳过
    },
    fail: function(e) {
      logErr("saveToStorageWithIndex failed: " + JSON.stringify(e))
      if (callback) callback(false)     // ← callback 为 undefined，跳过
    }
  })
}
```

**影响**:
- `scheduleNames` 和 `currentScheduleIndex` 可能在课程数据写入前就被设置
- 如果用户在数据写入完成前退出页面或切换课表，可能导致数据不一致
- 写入失败时完全没有感知

**时序图**:
```
时间线 →

saveToStorageWithIndex(0, s1) ──────────────────[写入中]──→ 完成
saveToStorageWithIndex(1, s2) ──────────────────[写入中]──→ 完成
finalizeReset()              ─→ 立即设置 scheduleNames 和 currentScheduleIndex
                                   ↑ 此时课程数据可能还未写入！
```

### 3. 【严重】`resetToEmpty` 中 Storage 删除操作存在竞态条件

**文件**: [database.js](file:///Users/Banner/Documents/guomengtao/tom/class/class/src/data/database.js#L1091-L1093)

**问题描述**: `storage.delete()` 是异步操作，但在 for 循环中发起后立即调用 `finalizeEmpty(callback)`，没有等待删除完成。

```javascript
} else {
  for (var i = 0; i < 10; i++) {
    storage.delete({ key: STORAGE_KEY + "_" + i })  // ← 异步，fire-and-forget
  }
  finalizeEmpty(callback)  // ← 立即执行！
}
```

**影响**:
- `finalizeEmpty` 会写入新的 `scheduleNames` 和 `course_preset_list`
- 但旧的删除操作可能还在进行中，甚至可能在新数据写入后才执行删除
- 极端情况下，删除操作可能把刚写入的新数据删掉，导致数据完全丢失

**时序图**:
```
时间线 →

storage.delete(key_0) ────────────────────[删除中]──→ 完成
storage.delete(key_1) ────────────────────[删除中]──→ 完成
...
finalizeEmpty()       ─→ 写入 scheduleNames ─→ 写入 course_preset_list
                              ↑ 删除操作可能在这之后才完成！
```

### 5. 【中等】SQLite 路径下 `DELETE FROM courses` 失败被静默忽略

**文件**: [database.js](file:///Users/Banner/Documents/guomengtao/tom/class/class/src/data/database.js#L949-L963)

**问题描述**: 当 `DELETE FROM courses` 失败时，代码仍然继续执行插入操作，不向调用者报告错误。

```javascript
sqlite.executeSql({
  name: DB_NAME,
  sql: "DELETE FROM courses",
  success: function() {
    insertScheduleToSqlite(0, schedule1, function() {
      insertScheduleToSqlite(1, schedule2, function() {
        finalizeReset()
      })
    })
  },
  fail: function() {
    // ← 失败也继续插入！
    insertScheduleToSqlite(0, schedule1, function() {
      insertScheduleToSqlite(1, schedule2, function() {
        finalizeReset()
      })
    })
  }
})
```

**影响**: 如果 DELETE 失败（如数据库锁定、权限问题），旧数据不会被清除，新数据用 `INSERT OR REPLACE` 写入，但如果有旧课程 ID 与新课程 ID 不重叠，则旧数据会残留。

### 6. 【中等】`insertBatchSqlite` 单条插入失败被静默跳过

**文件**: [database.js](file:///Users/Banner/Documents/guomengtao/tom/class/class/src/data/database.js#L1008-L1022)

**问题描述**: 批量插入时，如果某条记录插入失败，只打印错误日志，然后继续下一条，最终回调成功。

```javascript
function insertBatchSqlite(courses, index, cb) {
  if (index >= courses.length) {
    cb()           // ← 全部完成，不管成功几条
    return
  }
  var c = courses[index]
  sqlite.executeSql({
    // ...
    success: function() {
      insertBatchSqlite(courses, index + 1, cb)
    },
    fail: function(e) {
      logErr("reset insert failed: " + JSON.stringify(e))
      insertBatchSqlite(courses, index + 1, cb)  // ← 失败也继续
    }
  })
}
```

**影响**: 40 条课程（5天 × 8节）中某几条插入失败时，用户看到成功提示但课程表不完整。

## 根本原因分析

所有严重缺陷的根因可以归纳为两类：

### 类 A：错误处理缺失

`resetToDemoData`、`resetToEmpty` 等函数采用"尽力而为"策略，无论中间步骤成功与否，最终都返回成功。这意味着：

- 当 `storage.set()` 失败时，代码仍返回 `callback(true)`
- 当 `sqlite.executeSql()` 失败时，代码继续执行后续操作
- 当 `INSERT` 失败时，代码跳过该条记录继续

**根因**: 代码设计时没有考虑错误传播机制，所有错误路径都被"吞掉"了。

### 类 B：异步操作未正确编排

在 Storage 后端模式下，多个异步操作（`storage.set`、`storage.delete`）没有通过回调链正确编排：

- `saveToStorageWithIndex` 调用时不传回调，导致后续操作提前执行
- `storage.delete` 在 for 循环中 fire-and-forget 后立即执行 `finalizeEmpty`

**根因**: 代码在编写时假设 `storage.set`/`storage.delete` 是同步操作，或忽略了其异步特性。

## 修复建议

### 修复缺陷 1 和 4：正确传播错误

```javascript
function finalizeReset() {
  storage.set({
    key: "scheduleNames",
    value: JSON.stringify(names),
    success: function() {
      currentScheduleIndex = 0
      storage.set({
        key: "currentScheduleIndex",
        value: "0",
        success: function() {
          log("resetToDemoData: complete")
          if (callback) callback(true)
        },
        fail: function(e) {
          logErr("resetToDemoData: failed to set currentScheduleIndex: " + JSON.stringify(e))
          if (callback) callback(false)    // ← 改为 false
        }
      })
    },
    fail: function(e) {
      logErr("resetToDemoData: failed to set scheduleNames: " + JSON.stringify(e))
      if (callback) callback(false)        // ← 改为 false
    }
  })
}
```

### 修复缺陷 2：为 Storage 路径添加回调链

```javascript
} else {
```

### 修复缺陷 3：等待删除完成后再执行 finalizeEmpty

```javascript
} else {
  var pendingDeletes = 10
  var hasError = false
  function onDeleteDone() {
    pendingDeletes--
```

### 修复缺陷 5 和 6：传播 SQLite 错误

```javascript
// 在 saveAll 中

  name: DB_NAME,

// 在 insertBatchSqlite 中

  // ...
  fail: function(e) {
    logErr("reset insert failed: " + JSON.stringify(e))

    insertBatchSqlite(courses, index + 1, cb)
```
