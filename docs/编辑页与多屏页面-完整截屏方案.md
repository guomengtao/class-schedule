# 编辑页与多屏页面：完整截屏方案（给"眼睛"用的检查底稿）

> 背景：此前逐页采集**只截了第一屏**，且 `detail`（编辑页）因为没有真实课程数据，只拍到"这门课已经被删除"的空态。
> 本方案解决三件事：**① 多屏页截全 ② 编辑页走真实传值、把每个步骤/弹窗都截到 ③ 每屏都有"眼睛"核对清单**。
> 设备：`xiaomi_band` 192×490（手环 9 胶囊屏），adb `emulator-5554` / gRPC `8554`。

---

## 一、页面分三类，打法不同

| 类型 | 例子 | 打法 | 单页成本 |
|---|---|---|---|
| **静态单屏页** | welcome / activation / donate / 工具页 | 自动巡航（已落地，3s/页） | ~3s |
| **静态多屏页** | settings / tools / device-info / 周视图 | **滚动步进连拍**（滚一屏拍一张） | ~8s/屏 |
| **流程页（有状态）** | **detail(编辑)** / add-course / 中文输入 / 重置确认 | **脚本化点击序列**，每步一截 | 视步骤数 |

> 关键认知：**流程页没法纯自动巡航**——它是一台状态机，必须"点一下 → 等渲染 → 截一张"逐步走。
> 但流程页里的按钮坐标是固定的，**标定一次即可复用**，所以第二次起就很快。

## 二、多屏页怎么截全（滚动步进）

### 2.1 工具现状
- 滚动：**`cswipe`（模拟器控制台 `event mouse` 拖动）可用** ✅；gRPC 的 `swipe` 是空实现，**无效**。
- 实测一次 cswipe（y 430→120，14 步）≈ 滚动 **255px**。

### 2.2 步进策略
- 每屏滚动 **~240px**（略小于整屏 490px，**留 50% 重叠**，避免漏内容）。
- **到底判定**：连续两张截图字节数一致 → 已到底，停止。
- 命名规范：`<页id>-<状态>-s0.png / -s1.png / -s2.png …`
  （`pages.json` 的 `shots` 本来就是**数组**，多屏直接多加几条记录，`pages.html` 无需改造即可并排展示。）

### 2.3 新增工具
```
node scripts/emulator-eye.js scrollshot <port> <prefix> <maxScreens> <gapMs> <x> <y1> <y2> <steps>
```
逻辑：拍 s0 → 滚 → 拍 s1 → … 直到字节数与前一张相同（到底）或达到 maxScreens。

### 2.4 ⚠️ 红线
**页头（返回键）会随内容一起滚出屏幕** → 要点返回必须先滚回顶部，否则会点中内容行误入别的页面（本轮踩过）。

## 三、编辑页（detail）：真实传值 + 步骤全截

### 3.1 真实传值是什么（源码结论，别伪造）

入口 = **首页点某节课的卡片**（`index/modules/class-list.js:169` `goToClassDetail`）：
```js
storage.set("detail_classId", String(course.id))   // 课程 id（字符串）
storage.set("detail_day",     instance.currentDay) // 星期几，"星期一" 这种格式
router.push({ uri: "/pages/detail" })
```
`detail` 取数有**两处**，缺一不可：
1. `course_preset_list`（storage）→ "选择课程"轮播的课程名列表（空则用内置 defaultCourses）
2. `database.getAllCourses()`（`allCourses_0`…）→ 按 `detail_day` 找到当天，再按 `id === detail_classId` 定位真课，填入表单

> ❌ **上一轮失败的完整根因**：只造了 `allCourses_0` + `detail_classId`，
> **没写 `detail_day`、没写 `course_preset_list`** → 定位失败 → 显示"这门课已经被删除"。
>
> ✅ **结论：编辑页走真实入口（首页点真实课程行），不要伪造 storage。**
> 理由：两个键必须**配对**、还要与数据库联动，伪造极易错；而真实入口一次点击就全部就位。
> （模拟器里本就有真实课程：星期一有"语文"。）

### 3.2 前置：确保"今天有课"
- 采集日 = 星期几，`detail_day` 就会是星期几 → **当天必须有课**才能走到真实编辑态。
- 若当天无课：先走一遍 add-course 造一门今天的课（这本身也是要采集的流程页，一举两得）。

### 3.3 detail 的交互点（源码枚举，共 19 个 onclick）
| 类别 | 处理函数 | 说明 |
|---|---|---|
| 步骤切换 | `nextStep` / `prevStep` / `swipeNext` / `swipePrev` | 编辑流程分步 |
| 课程选择 | （presetCourses 轮播） | "选择课程"横滑 |
| 时间 | `increase/decrease Start/End Hour/Min` ×4 | 上下步进 |

| # | 动作 | 截图名 | 眼睛重点 |
|---|---|---|---|

## 四、"眼睛"核对清单（每屏必查，缺一不可）

1. **左右对称**：`scripts/png-measure.js runrow <图> <y>` 量化左右边距（历史坑：百分比宽度 + padding 两套算法会"左小右大"）。
2. **字号/截断**：标题是否被挤成多行 + 省略号；`lines: N` 是否够（历史坑：17 字文案写了 `lines: 2`）。
3. **底部安全区**：胶囊屏下圆弧是否压住最后一行/按钮。
4. **热区整行**：可点行是否整行可点（历史坑：192px 上只有文字框可点）。
5. **弹窗几何**：遮罩 `padding` 与卡片 `width` 必须同源（历史坑：同文件两个 capsule `@media` 块写同一属性，级联不稳定）。
6. **多屏完整性**：滚动到底后，最后一段内容没有被裁掉。
7. **传值正确性**：编辑页回填的课程名/时间/地点 = 首页点的那个课程。

## 六、为什么这样最快

- **静态页**继续自动巡航（已验证 2–3 分钟/27 页）；
- **多屏页**用 `scrollshot` 一次连拍（每页 ~8s × 10 页 ≈ 1.5 分钟）；
- **流程页**用标定好的 `flow` 步骤表重放（每页 ~30–60s × 2 页 ≈ 2 分钟）；
- **总计 ≈ 6 分钟采全 + 采全**（而不是"采快但只看到第一屏"）。

> 速度与完整性不冲突：**巡航解决"到得了"，滚动连拍解决"看得全"，流程脚本解决"走得完"。**

## 七、实测记录（2026-09-28，192×490 实机验证）

### 7.1 ✅ 打通的真实路径
**课程管理 → 行内「编辑」→「重命名课程」**（带出真实课程"语文" + 中文键盘）
```
welcome →(96,252)→ 首页 →(96,337)→ 快速添加展开 →(96,295)→「管理」→ 课程管理 →(60,258)→ 重命名课程
```
- 该入口**不需要伪造任何 storage**，课程名由 App 自己带出 ✅
- 顺带复现历史显示问题：**中文键盘右侧键位（D/S/X 列）被屏幕右缘裁切**（截图即证）——这就是"眼睛"要抓的第一手问题

### 7.2 ❌ 未打通的路径（记录待查）
- **首页直接点课程卡片**：192×490 上课程卡片被「即将上课 Hero 区 + 快速添加」挤压，**只露出一条**，合成点击 `(96,205/216/232/245/262)` 均未触发 `goToClassDetail`（Hero 区本身不可点）。
  → 待查：卡片可点区域 / 列表滚动位置；**备选方案 = 周视图入口**（`week-view.ux:825` 同样写 `detail_classId` 后进 detail，且格子更大更好点）。

### 7.3 关键数据结论（修正上一轮的错误认知）
| 键 | 用途 | 上轮错在哪 |
|---|---|---|
| `course_preset_list` | detail「选择课程」轮播的课程名列表 | **上轮没写这个键** |
| `allCourses_0` | 课程数据（按 day+id 定位） | 上轮写了，但缺下面两个 |
| `detail_classId` + `detail_day` | 必须成对（id + "星期一"） | 上轮没写 `detail_day` |

**结论维持：编辑页不要伪造 storage，走真实入口（课程管理→编辑 或 周视图）。**

### 7.4 实测坑（补充到红线）
1. **第二次 `vapp` 启动后只等 8s → App 未就绪，所有点击无效**（表现为"停在欢迎页"）。必须 ≥16s。
2. 双启动易触发进程累积黑屏 → 建议流程：`adb reboot` → 单次启动 → 等 20s 再操作。
3. 肉眼从缩略图估坐标不可靠 → **一律用 `png-measure.js rows/bands` 标定**（本次实测：欢迎页"进入首页"实心按钮中心 = **y252**，"设置"=y315，"退出"=y376）。
4. `cseq` 的文件名是 `<prefix>-<i>`（prefix 自带 `-` 时会变双横线），核对时注意。
