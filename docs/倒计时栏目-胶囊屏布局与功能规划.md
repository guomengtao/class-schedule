# 倒计时栏目 · 胶囊屏布局与功能规划

> 目标机型：手环9 胶囊屏 **192×490**（`capsule` / `pill-shaped` 两种 shape 都要认），向下兼容 rect 屏。
> 状态：规划稿。落地面：`countdown-manage`（列表改版）+ 新增 `countdown-add` / `countdown-edit` 两个独立页面。

---

## 一、现状问题（为什么改）

| # | 现状 | 问题 |
|---|------|------|
| 1 | 「＋ 添加」按钮在顶部 header 右侧 | 顶部热区小、拇指难按；且 header 挤（返回+标题+添加三件套） |
| 2 | 添加流程 = 跳输入页 → 返回 → `showDialog` 手输 `YYYY-MM-DD` | **弹窗手输日期**极易输错，逻辑绕两圈 |
| 3 | 编辑日期同样走 `showDialog` | 弹窗禁而不断，胶囊屏上弹窗几何已被证明易碎 |
| 4 | 列表行内同时有「编辑 / 删除 / ON-OFF」三个按钮 | 胶囊屏一行塞不下，字号被压缩，文字出现省略 |
| 5 | 空态文案"点击右上角添加" | 与"添加按钮下移"矛盾，需同步改 |
| 6 | 名称 `maxlen: 6`，超出省略 | 违反"文字显示全，禁止省略"红线 |

## 二、设计原则（硬红线）

1. **禁止省略**：所有文本完整显示。名称输入限制 8 字（8 字 × 18px ≈ 144px < 160px 行内宽，保证放得下）；**禁用 `text-overflow: ellipsis` 与 `lines` 截断**。
2. **禁弹窗**：全程不使用 `prompt.showDialog`。删除/清空用**行内二次确认**（按钮变「确认」，5s 超时自动还原，沿用现有机制）。
3. **按钮高 ≥ 48px**，主操作按钮高 52px；列表行高 ≥ 64px（含间距热区）。
4. **显式宽度**：所有容器显式 `width:100%`；根 padding 移到**内层容器**（Vela absolute 按父级内容盒计算）；禁百分比宽 + `max-width` 组合；同一媒体块内同选择器只出现一次。
5. **简洁大方**：列表页只做"看"，操作全部收进编辑页；一屏一级任务。

## 三、页面结构规划

### 3.1 列表页 `countdown-manage`（改版）

```
┌──────────────────────┐
│ ←  倒计时             │  header：返回(40px) + 标题(18px)，右侧留空
├──────────────────────┤
│ ┌──────────────────┐ │
│ │ 期末考试          │ │  行：名称 18px 完整显示
│ │ 2027-06-07 · 250 │ │  副行：日期 14px + 天数徽章 16px
│ │            [ON]  │ │  开关 44×32，整行可点 → 编辑页
│ └──────────────────┘ │
│ ┌──────────────────┐ │
│ │ …共 N 条          │ │
│ └──────────────────┘ │
├──────────────────────┤
│ [    ＋ 添加倒数日    ] │  底部固定栏，高 52px，width:100%
└──────────────────────┘  （由 header 的顶部按钮移到这里）
```

要点：
- **添加按钮下移**到页面底部固定栏（`absolute; bottom:0` 面板内，内容区留 `padding-bottom` 防遮挡）。
- 行内**只保留 ON/OFF 开关**；「编辑」「删除」全部收进编辑页 → 行内从 4 个控件减到 1 个。
- **整行点击进编辑页**（onclick 只绑整行容器，行内子元素不绑——热区=整行）。
- 天数显示：未来「剩 N 天」、今天「就是今天」、过去「已过 N 天」，徽章底色区分（accent / accent / muted）。
- 排序/清空工具栏收进 header 下方一行（仅 2 条以上时显示），按钮高 40px 文字 16px，不做图标。
- 空态文案改为「暂无倒数日，点下方按钮添加」+ 底部按钮依旧可用。

### 3.2 添加页 `countdown-add`（新独立页）

```
┌──────────────────────┐
│ ←  添加倒数日         │
├──────────────────────┤
│ 名称                  │
│ [点此输入名称____]     │  18px，点击跳 chinese-input（复用现有组件）
├──────────────────────┤
│ 日期                  │
│  2026  年  09  月  30 日│  内嵌三段步进选择器（无弹窗）
│   [−]   [−]   [−]     │
│   [＋]   [＋]   [＋]  │
├──────────────────────┤
│ [       保存        ] │  主按钮 52px，校验通过才可点
└──────────────────────┘
```

要点：
- **日期选择 = 页面内嵌步进器**：年 / 月 / 日 三列，各列「− / 数值 / ＋」垂直排布，数值 20px、按钮 44×40。列宽 52px × 3 + 间距 ≈ 180px < 192，可放。
- 年限范围：当年 − 1 ~ 当年 + 5；月 1–12；日 1–当月最大天（自动随年月联动，闰年含 2/29）。
- 实时回显完整日期 `YYYY-MM-DD`（16px），无需用户手拼格式。
- 保存校验：名称非空（空则按钮置灰 + 行内提示文字，不用 toast 也可，toast 仅作兜底）；日期合法由步进器天然保证。
- 保存成功 → `router.replace` 回列表页（新条目自动按最近日期排序置顶可见）。

### 3.3 编辑页 `countdown-edit`（新独立页）

布局同添加页，差异：
- 进入时预填名称与日期（通过 router 传 `index`，页面内从 storage 读，避免传长参）。
- 名称可改、日期可改、ON/OFF 状态一行内切换。
- 底部两个按钮：`[ 保存 ]`（accent 52px）+ `[ 删除 ]`（deleteBg 色 48px）。
- 删除走**页内二次确认**：按钮文字变「确认删除？」5 秒，再点执行并返回列表；不做弹窗。
- 保存/删除后 `router.replace` 回列表页。

### 3.4 输入复用

名称输入复用 `chinese-input` 全屏输入组件（上游组件零改动），通过 storage 传参，return key 分别为 `countdown_add_name` / `countdown_edit_name`。添加/编辑页 `onShow` 里消费回传值并立即回显到页面的名称框。

## 四、字号与尺寸规范（胶囊屏）

| 元素 | 规格 |
|------|------|
| 页面标题 | 18px / 行高 24px |
| 列表行名称 | 18px / 行高 24px，**最多 8 字，完整显示** |
| 列表行日期 | 14px / 行高 20px |
| 天数徽章 | 16px / 徽章高 28px |
| ON/OFF 开关 | 44×32px，文字 14px |
| 主按钮（添加/保存） | 高 52px，文字 20px，radius 26px |
| 次按钮（删除） | 高 48px，文字 18px |
| 步进器数值 | 20px / 按钮 44×40px |
| 空态文字 | 16px，居中 |
| 列表行高 | ≥ 64px，行间距 12px |
| 内容区左右 padding | 12px（移到内层容器） |

> rect 屏（336×480 等）复用同一套结构，仅通过 `@media (shape: rect)` 把内容区加宽到 2 列网格；不做第三套布局。

## 五、数据与逻辑

- 存储键沿用 `countdownDays`，条目结构不变：`{ title, date, enabled }`（扩展字段向后兼容：读取时缺省补齐）。
- `daysLeft` 每次进入列表页实时计算（含跨天场景，无需后台定时）。
- 排序：默认按 `|daysLeft|` 升序（最近的在最上），次要排序按名称——沿用现有 `sortItems`。
- 写盘统一走 `saveList()` 的序列化纯字段路径（JSON.parse 带 try/catch）。
- 校验规则集中一处 `validate(title, date)`，添加/编辑共用。

## 六、交互流（逻辑清晰版）

```
列表页 ──底部[＋添加]──▶ 添加页 ──保存──▶ replace 回列表
   │                                        ▲
   └──────点整行────────▶ 编辑页 ──保存/删除──┘
```

- 每一步只有一个主任务；所有"会不会丢数据"的疑虑由"显式保存按钮"消除。
- 返回键：添加/编辑页有未保存改动时，返回直接放弃改动（无脏数据写入，无需确认弹窗）。
