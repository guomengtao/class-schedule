# Icon 收集页面方案

## 目标

在实验室中新增一个 Icon 收集页面，用于测试和核实哪些 Unicode 图标/Emoji 在快应用（QuickApp）中能正常渲染显示。用户可逐个勾选确认，被确认的即为系统支持的图标。

## 核心需求

1. 分类展示大量图标（Emoji、符号、箭头等）
2. 每个图标实时渲染，直观显示是否支持
3. 允许勾选确认，记录哪些图标已验证可用
4. 页面必须稳定，图标多时不崩溃、不混乱

## 页面入口

```
实验室 (lab.ux) → Icon 收集
路由: /pages/icon-collect
```

## 防崩溃策略

### 1. 分页加载（每页最多 20 个图标）

- 不一次性渲染全部图标，按分类分页
- 每页 20 个图标（5 行 × 4 列），保证单页 DOM 节点数可控
- 切换分类时重置页码

### 2. 简单 DOM 结构

```html
<!-- 每个图标卡片结构极简 -->
<div class="icon-card" onclick="toggleIcon(idx)">
  <text class="icon-char">{{ icon }}</text>
  <text class="check-mark">{{ checked ? '☑' : '☐' }}</text>
</div>
```

- 不使用 `<image>`、`<canvas>` 等复杂组件
- 每个图标仅一个 `<text>` 渲染字符 + 一个 `<text>` 显示勾选状态
- 无嵌套滚动，仅一个外层 `<scroll>`

### 3. 同步渲染

- 不使用 `setTimeout` / `setInterval` 动态更新图标
- 数据全部在 `onInit()` 中准备好，模板一次性渲染当前页
- 翻页时直接替换 `currentPageIcons` 数组，触发模板更新

### 4. 内存控制

- 始终只保留当前页的 20 个图标在渲染树中
- 切换分类/翻页时，旧数据被覆盖，不累积

## 页面逻辑流程

```
onInit()
  ├── 加载主题
  ├── 读取已确认图标列表 (storage)
  └── 设置默认分类: 表情
       └── 渲染第1页，显示 20 个图标

用户操作:
  ├── 点击分类 Tab → 切换分类，重置页码
  ├── 点击图标 → toggleIcon()
  │     ├── 更新 confirmedIcons 数组
  │     └── 保存到 storage
  ├── 点击上一页/下一页 → 切换页码
  └── 点击保存 → 保存全部确认结果
```

## 注意事项

1. 快应用不支持 Web 字体，所有图标依赖系统内置 Emoji 字体，显示效果因设备/系统版本而异
2. 部分 Emoji 在手表上可能显示为方框（tofu），这些就是不被支持的图标
3. 确认结果持久化到 storage，卸载应用后会丢失，可后续考虑导出功能
4. 每页 20 个图标是保守估计，手表屏幕小，实际可调整为每页 12 个（3 列 × 4 行）
