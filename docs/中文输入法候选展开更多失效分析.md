# 中文输入法「候选展开更多」失效分析

> 分析对象：`src/components/InputMethod/InputMethod.ux`（1060 行，三套屏型实现）+ `src/pages/chinese-input/chinese-input.ux`
> 日期：2026-09-22
> 结论性质：基于代码静态分析得出的因果推断，第 5 章给出真机验证步骤可确认

---

## 一、一句话结论

**「展开更多」不是被某个改动删掉了，而是这个组件把同一套交互复制了三遍（circle / rect 方屏 / pill 胶囊），每一套的下展条件、容器类型、坐标都不一样。** 你的每次修复只作用在其中一个分支（或只改了 CSS 的一个数值），另外两处依旧是旧的病态实现，所以看起来"改了很多次都改不好"。

再加两个放大器：**外层 `<scroll>` 里再嵌一个 `<list>`**（Vela 上的经典冲突）、以及 **`<list>` 的内容缓存不刷新**（代码注释里你们自己也承认过）。三者叠加，表现就是"点了没反应"或"点了以后候选文字没了"。

---

## 二、现象要拆成三种来看

你说的"没有了"可能对应下面三种完全不同的根因，请先对照确认是哪一种：

| 现象 | 说明 | 对应根因 |
|------|------|----------|
| A. 箭头（展开更多）根本不出现 | 候选行右侧没有下拉箭头 | 显示条件是 `resultRow0.length > 0`，某些输入状态下不满足；或渲染的是另一套屏型分支 |
| B. 点了箭头没反应 | 面板不出来 | 命中区域过小 / 被外层 `<scroll>` 吃掉手势 / `if` + `<list>` 未挂载 |
| C. 点了以后候选文字"没了" | 原有候选行消失，但没看到展开列表 | **面板黑底把候选顶行盖住了**，且 `<list>` 内容为空/未刷新 |

## 四、根因分析（按可信度排序）

### R1｜★结构性根因：同一功能三套平行实现

胶囊屏的"展开"是这一段：

```311:311:src/components/InputMethod/InputMethod.ux
          <img show="{{resultRow0.length > 0}}" style="position: absolute;left: 130px;top: 57px;width: 50px;height: 40px;" src="/components/InputMethod/assets/arc/down2.png" @click="onBtnClick('down')" />
```

```322:333:src/components/InputMethod/InputMethod.ux
        <div style="position: absolute;top: 47px;width: 100%;height: 263px;background-color: black;" if="{{downFlag==='down'}}">
          <div style="position: absolute;left: {{(screenWidth - l66DownPanelWidth)/2}}px;width: {{l66DownPanelWidth}}px;height: 263px;"> 
            <list static class="list66" style="width: {{l66DownPanelWidth - 6}}px;">
              <list-item type="waitingRows66" class="item66" for="{{itemArray in resultList2}}">
                <div class="item column center" for="{{item in itemArray}}">
                  <text class="calbtn-down-text" @click="onRsSelect(item)">{{item}}</text>
                </div>
              </list-item>
            </list>
            <img static style="position: absolute;top:196px;left:56px;width: 80px;height: 60px;" src="/components/InputMethod/assets/arc/up2.png" @click="onBtnClick('down')" />
```

而圆屏（46–52）和方屏（249 起）是**另外两份几乎相同但细节不同的代码**。后果：

| 屏型 | 容器 | 每行候选数 | 关闭按钮 | 面板高度 |
|------|------|-----------|----------|----------|
| circle | `<list class="list3">` | 多个 | up2 图（那里是 down.png） | 由 `.list3` 决定 |
| rect | `<list class="list67">` | `cap` | 各自实现 | 各自实现 |
| pill-shaped | `<list class="list66">` | **1**（661 行） | up2（`top:196px`） | **186px** |

**任何一次"修好了"`，只是在某一个屏型/某一条路径上修好了。`**

### R2｜外层 `<scroll>` 嵌套内层 `<list>`

`chinese-input.ux:32` 把键盘放进 `<scroll scroll-y="true">`，而展开面板是 `<list>`（组件 324 行）。

在 Vela/hapjs 上，纵向可滚容器里再放一个可虚拟化滚动的 `<list>`，常见后果：

- 内层 list 拿不到正确的可视区高度 → **items 高度为 0 或不布局** → 面板"黑了但没字"（现象 C）
- 手势被外层 scroll 抢走 → 列表滚不动
- 外层 scroll 计算 content 高度时，绝对定位的子节点可能不参与高度计算 → **面板被裁剪**

这是"改 CSS 宽高永远改不好"的核心：问题不在尺寸，在嵌套结构。

### R3｜`<list>` 的内容缓存不刷新（代码已自证）

组件里有三段注释坦白了这一点：

```45:45:src/components/InputMethod/InputMethod.ux
          <!-- 这里使用show会导致每次输入都会加载全部候选列表，很卡 -->
```

```494:494:src/components/InputMethod/InputMethod.ux
          this.downFlag = "";   // 下展 list 在 Vela 中缓存不刷新，先收回用顶行展示新数据
```

也就是说：**当初为了性能把 `show` 改成了 `if`（每次展开都销毁/重建整棵子树），结果是在某些路径上 list 的内容不刷新。** 你们当时用"选字后强行收回面板"（`downFlag=""`）来绕开，但绕开不了"面板虽然重建了但数据为空/旧"的情况。这就是现象 C 的直接来源。

### R4｜面板黑底把候选顶行盖住 → 视觉上"没了"

按模板里的坐标算（胶囊屏，容器坐标）：

| 元素 | 位置 | 覆盖区间 |
|------|------|----------|
| 候选横滚行 `cvalWaiting` | `top:56px, height:42px` | y = 56–98 |
| 展开箭头 `down2.png` | `top:57px, height:40px` | y = 57–97 |
| **下展面板**（黑底） | `top:47px, height:263px`，且 `width:100%` | **y = 47–310，全宽** |

**面板从 y=47 起就是整块黑底 + `width:100%`，而候选行和箭头都在 y=56–98。**

所以面板一弹出，**候选文字和箭头统统被黑底遮住**（它们所在的 `div` 在 DOM 里比面板更早出现，层级更低）。用户看到的正是"点一下展开，候选文字没了"，而列表区要往下到 y≈57+186 之外才可能露出东西——如果 list 还没渲染出内容（R3），那里就是**一片纯黑**。

### R5｜箭头命中区域偏小且有重叠

- 箭头只有 **50×40px**，低于项目胶囊屏触控规范（≥48px 高度）；
- 箭头 `left:130`，候选 `<scroll>` 占据 `left:15, width:120` → **右边界 135 与箭头左边界 130 重叠 5px**，且同为可点击区域，边缘点击容易落到 scroll 上（scroll 会吃掉横向滑动/点击）；
- 结果：点击有时不触发 `onBtnClick('down')` → 现象 B"点了没反应"。

### R6｜`maxlength` 是字符串，失控时顶行与下展同时为空

`chinese-input.ux:56` 传 `"10"`；组件 659 行 `parseInt(this.maxlength)`。若某条调用路径传的是空串/非数字：

```javascript
const cap = parseInt(this.maxlength)   // NaN
for (let i = 0; i < list.length && row0.length < cap; i++)  // NaN 比较恒 false → row0 为空
```

→ `resultRow0.length === 0` → **箭头直接不显示**（现象 A）。这是潜在的隐性炸弹，不一定在本次表现为主因，但必须顺手堵上。

### R7｜屏型判定漂移

- 组件 props 默认 `screentype: "circle"`（第 373 行），页面默认 `"pill-shaped"`（第 62 行）
- `device.getInfo` 是**异步**的（80–88 行），若某些设备上 `screenShape` 返回值不在预期集合（既非 rect 也非 circle 也非 capsule），会落到**默认分支**
- 一旦落到别的分支，胶囊屏用户看到的就不是第 263 行那套布局，**你针对胶囊屏做的所有改动都不会生效**——表现同样是"按钮不见了"

## 五、为什么"改了很多次都改不好"

| 原因 | 说明 |
|------|------|
| 1. 修的是表现层，不是结构 | 病因是 R1（三套平行实现）+ R2（scroll 套 list）+ R3（list 缓存），这三条没动过，改宽高/改 top/改 if↔show 都只是在同一个坑里换姿势 |
| 2. 补丁叠补丁 | 1020 行注释「只是 `.list66` 之前漏了这条」——典型的后补 CSS 覆盖；`.list66 .item` 与 `.item { flex:1 }` 互相打架，每加一条新规则都可能被另一条屏型规则覆盖 |
| 3. 多主题并行修改同一文件 | git 历史里 `InputMethod.ux` 在多个无关主题的提交中被顺手改动：`d48b08f 胶囊屏全页面适配优化`、`29e6f1b UX-15/18 InputMethod 修复`、`793c6dc 移除箭头函数`、`f549d31 升级到最新版输入法`。多主题并发修改同一文件，容易出现"A 的改动被 B 覆盖、而双方都没察觉" |
| 4. 没有可回放的验证手段 | 手环上只能肉眼判断，改完不知道是"修好了"还是"只是这一屏型好了" |

## 六、真机验证步骤（按顺序做一遍即可定案）

1. **确认屏型**：进「设置 → 设备信息」（或 device-info 页），看 `screenShape` / `screenWidth`。
   - 若不是 `capsule` → 直接命中 **R7**
2. **给三个状态打日志**（组件内临时加，用 `adb logcat` 看）：

```javascript
// onBtnClick 的 'down' 分支里
console.log('[IME] down toggle, downFlag=', this.downFlag,
            'row0=', this.resultRow0.length, 'list2=', this.resultList2.length,
            'screentype=', this.screentype, 'width=', this.screenWidth)
```

   - 日志没打印 → **命中 R5**（点击没打到箭头）
   - `downFlag=down` 但 `list2=0` → **命中 R6 或 R3**（数据为空）
   - `screentype` 不是 `pill-shaped` → **命中 R7**
   - 打印了、`list2>0`，但屏幕还是黑 → **命中 R4 + R2**（被黑底遮住 / list 未布局）
3. **排除外层 scroll**：临时把 `chinese-input.ux:32–42` 的 `<scroll>` 去掉，直接放 `<input-method>`（给它固定 `height:305px`）。若面板立刻正常 → **确认 R2**
4. **排除 list 缓存**：临时把 322 行 `if` 改回 `show`。若内容出现 → **确认 R3**
5. **顶行遮挡检查**：把面板的 `top` 从 47px 临时改成 110px。若候选行重新可见 → **确认 R4**

## 七、推荐修复方案

### 方案 A（推荐，一次性根治）

把三份下展实现合并成一个公共子组件 `src/components/InputMethod/InputDownList.ux`：

- props：`items`（一维数组）、`panelWidth`、`itemHeight`、`onPick` 回调
- 内部用 `<div for>` + `<scroll scroll-y>`，**不再使用 `<list>`**（彻底绕开 R3 的虚拟化/缓存问题）
- 显隐用 `show`（面板节点常驻，避免 if 重建），数据更新时先置空再下一帧赋值，解决"缓存不刷新"
- 三种屏型只传宽度/高度参数，**业务逻辑只有一份**

配套调整：

- `chinese-input.ux` 去掉外层 `<scroll>`，改为固定高度容器（键盘自身可滚的部分由内部 scroll 负责）
- 面板从 `top: 47px` 下移到不与候选行重叠的位置（或给顶行留出 42px 的安全区），并给候选行/箭头设置 `z-index` 更高的层级
- 箭头命中区扩到 ≥48px，与候选 scroll 右边界留出至少 8px 间隙

### 方案 B（最小改动，先解胶囊屏）

1. `chinese-input.ux`：去掉外层 `<scroll>` 包裹
2. 322 行：`if` → `show`
3. 面板 `top: 47px` → `top: 100px`（避开候选行），高度相应调整为 `210px`
4. 箭头 `width:50px;height:40px` → `height:48px`，左边界从 130 → 138
5. `setResultListAll` 里给 `cap` 加兜底：`const cap = parseInt(this.maxlength) || 5`

### 回归验证清单

- [ ] 胶囊屏：输入拼音后有候选 → 箭头可见
- [ ] 点箭头 → 列出全部候选，且原候选行仍在（不被黑底遮住）
- [ ] 点收起箭头 → 回到候选行
- [ ] 在下展列表里选字 → 面板收回、文字上屏、`cval` 正确递减
- [ ] 圆屏（480×480）与方屏各走一遍同样流程（防止只修好一屏）
- [ ] `device.getInfo` 失败时布局不崩（手动 mock fail 分支）
