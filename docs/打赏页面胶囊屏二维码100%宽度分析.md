# 打赏页面胶囊屏二维码 100% 宽度分析

## 一、背景

打赏页面（`src/pages/donate/donate.ux`）需要三种屏幕形状适配：**圆形屏**、**方形屏** 和 **胶囊屏**。胶囊屏（192px × 490px）最窄，为最大化二维码的可扫描性，设计目标是在胶囊屏上让二维码**占满 100% 屏幕宽度**（即 192px），去掉所有横向内边距。

---

## 二、当前实现架构

实现 QR 尺寸 100% 宽度的机制由 **CSS** 和 **JS** 两部分协同完成：

```
┌─────────────────────────────────────────────────┐
│  CSS: @media (shape: capsule) 清除所有横向间距    │
│  页面 padding → 0, 卡片 padding → 0, 边框 → 0    │
├─────────────────────────────────────────────────┤
│  JS: computeQrSize(w, shape) 计算二维码像素尺寸   │
│  capsule → sum=0 → qrSize = screenWidth          │
├─────────────────────────────────────────────────┤
│  结果: qrSize = 192px，铺满整屏宽度               │
└─────────────────────────────────────────────────┘
```

---

## 三、CSS 层面：清除所有横向内边距

### 3.1 默认样式（所有屏型共享）

```css
.page-root {
  padding: 44px 8px 20px 8px;   /* 左右各 8px padding */
}

.qr-card {
  padding: 14px 12px;            /* 卡片左右各 12px padding */
}

.qr-wrapper {
  padding: 6px;                  /* 白底框各边 6px padding */
}
```

默认总横向间距 = `8 + 12 + 6 = 26px`（每侧），即 52px 被 padding 占用。

**192px 胶囊屏可用宽度** = 192 - 52 = **140px**，QR 码只能 140px，浪费了 52px 宽度。

### 3.2 胶囊屏 `@media` 规则：将所有 padding 清零

```css
@media (shape: capsule), (shape: pill-shaped) {
  .page-root {
    padding: 40px 0 16px 0;      /* 左右 padding → 0 */
  }
  .qr-card {
    padding: 10px 0;              /* 左右 padding → 0 */
    border-radius: 0;
  }
  .qr-wrapper {
    padding: 0;                   /* 白底框 padding → 0 */
    border-radius: 0;
    width: 100%;                  /* 容器宽度 100% */
    align-items: center;
  }
}
```

清零后总横向间距 = `0 + 0 + 0 = 0px`，**全部 192px 宽度可用于 QR 码**。

### 3.3 各屏型横向间距对比

| 屏型 | 页面 padding | 卡片 padding | 白底 padding | 总间距 | 可用宽度(192px时) |
|------|:----------:|:----------:|:----------:|:------:|:---------------:|
| **胶囊** | 0 | 0 | 0 | **0px** | **192px** |
| 默认 | 8 | 12 | 6 | 26px | 140px |
| 方形 | 12 | 16 | 8 | 36px | 120px |
| 圆形 | 28 | 10 | 5 | 43px | 106px |

## 四、JS 层面：动态计算 qrSize

### 4.1 核心计算逻辑

代码位置：[donate.ux:L89-L113](file:///Users/Banner/Documents/guomengtao/tom/class/class/src/pages/donate/donate.ux#L89-L113)

```javascript
QR_PADDINGS: {
  capsule: { sum: 0, max: 200 },     // sum=0 → 100% 全屏铺满
  rect:    { sum: 12 + 16 + 8, max: 280 },
  circle:  { sum: 28 + 10 + 5, max: 280 }
},

computeQrSize(w, shape) {
  var conf
  if (shape === "capsule" || shape === "pill-shaped") {
    conf = this.QR_PADDINGS.capsule
  } else if (shape === "rect") {
    conf = this.QR_PADDINGS.rect
  } else if (shape === "circle") {
    conf = this.QR_PADDINGS.circle
  } else {
    // fallback: 按通用分档计算
    if (w > 300) return Math.floor(w - 12*2 - 16*2 - 8*2 - 4)
    if (w > 200) return Math.floor(w - 10*2 - 14*2 - 7*2 - 4)
    return Math.floor(w - 8*2 - 12*2 - 6*2 - 4)
  }
  var size = Math.floor(w - conf.sum * 2)   // capsule: w - 0 = w
  if (size > conf.max) size = conf.max       // capsule 上限 200px
  if (size < 80) size = 80                   // 安全下限 80px
  return size
},
```

### 4.2 关键参数说明

| 参数 | 作用 | 胶囊屏值 |
|------|------|:-------:|
| `sum` | 单侧横向间距总和 | `0` |
| `max` | QR 尺寸上限（防止过大溢出） | `200px` |
| `w - sum * 2` | 实际 QR 可用宽度 | `w - 0 = w` |

### 4.3 计算流程

```
calcQrSize()
  → device.getInfo() 获取 screenWidth + screenShape
  → computeQrSize(w, shape)
    → shape === "capsule" → conf = { sum: 0, max: 200 }
    → size = Math.floor(192 - 0*2) = 192
    → 192 <= 200 → 不过上限
    → return 192
  → qrSize = 192
```

模板渲染：

```html
<qrcode value="{{ $item.url }}"
        style="width: {{ qrSize }}px; height: {{ qrSize }}px; ...">
</qrcode>
```

最终渲染：`width: 192px; height: 192px`，**恰好等于胶囊屏宽度**。

## 五、CSS 与 JS 的协同约束

**关键规则**：CSS 中的 padding 数值必须与 JS `QR_PADDINGS` 中的 `sum` 完全一致，否则计算的 qrSize 会与实际可用宽度不匹配。

```
QR_PADDINGS.capsule.sum = 0
        ↕ 必须一致 ↕
@media capsule 中:
  .page-root  padding 左 = 0  ✓
  .qr-card    padding 左 = 0  ✓
  .qr-wrapper padding 左 = 0  ✓
```

代码注释中也强调了这一点 ([donate.ux:L89](file:///Users/Banner/Documents/guomengtao/tom/class/class/src/pages/donate/donate.ux#L89))：

> 各屏型的内边距必须与样式表里的数值保持一致，否则算出的尺寸会溢出或留白

### 不一致的后果

| 场景 | 后果 |
|------|------|
| CSS padding > JS sum | qrSize 算大了，二维码溢出容器，可能被裁剪 |
| CSS padding < JS sum | qrSize 算小了，二维码两边出现空白（浪费屏幕空间） |

## 七、边界情况处理

### 7.1 `device.getInfo()` 失败

```javascript
fail: function () {
  self.qrSize = 120    // 安全回落值
}
```

如果无法获取屏幕信息，qrSize 回落到 120px（可以适配大多数屏幕）。

### 7.2 无法识别的屏型（fallback 逻辑）

```javascript
// 未识别屏型：按宽度保守回落
if (w > 300) return Math.floor(w - 12*2 - 16*2 - 8*2 - 4)  // ~232px
if (w > 200) return Math.floor(w - 10*2 - 14*2 - 7*2 - 4)  // ~142px
return Math.floor(w - 8*2 - 12*2 - 6*2 - 4)                 // ~84px
```

### 7.3 尺寸上下限裁剪

| 限制 | 值 | 触发场景 |
|------|----|----------|
| 上限 `max` | 200px（胶囊） / 280px（方/圆） | 宽屏设备，防止二维码过大 |
| 下限 `min` | 80px | 极小屏设备，确保二维码可扫描 |

## 八、与打赏 V2 Tab 版方案的对比

早期 Tab 版方案（`docs/capsule-donate-spec.md`）中，胶囊屏 QR 码**不是 100% 宽度**：

```javascript
shape === "capsule" → qrSize = 120px   // 固定 120px
```

当时 QrSize 固定 120px，左右有 padding（每个 8px），总占用 `120 + 16 = 136px`，胶囊屏 192px 有 56px 浪费。

**当前方案（V3 scroll 版）** 改为 100% 宽度铺满后：QR 码从 120px 提升到 192px，**可扫描面积增加 156%**（120²→192²），大幅提升扫码成功率。

## 九、总结

| 维度 | 实现方式 |
|------|----------|
| **CSS** | `@media (shape: capsule)` 将 `page-root`、`qr-card`、`qr-wrapper` 的横向 padding 全部置零 |
| **JS** | `QR_PADDINGS.capsule.sum = 0`，使 `computeQrSize` 返回 `qrSize = screenWidth` |
| **约束** | CSS padding 值必须与 JS sum 值一致，代码注释已明确标识此依赖 |
| **结果** | 胶囊屏 QR 码宽度 = 屏幕宽度（192px），实现 100% 全屏铺满 |
