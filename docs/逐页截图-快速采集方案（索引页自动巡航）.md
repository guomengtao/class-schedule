# 逐页截图：快速采集方案（索引页 + 自动巡航）

> 目标：把 app-auth「页面总览·逐页截图档案」的 27 个页面截图，从**耗时 ~2 小时**压到 **~2–3 分钟**。
> 设备：`xiaomi_band` 192×490（手环 9 胶囊屏），adb `emulator-5554` / gRPC `8554`。

---

## 一、现状：为什么现在这么慢

本轮（第十轮）实测耗时拆解：

| 环节 | 单次耗时 | 27 页合计 | 说明 |
|---|---|---|---|
| 构建 `aiot release --enable-jsc` | 7–12s | 只做 1 次 | 不慢 |
| 推送单页 `.jsc` | <1s | — | 不慢 |
| **App 冷启动**（`vapp app/<pkg>`） | **15–18s** | — | **每次都付** |
| **首启黑屏 → 再启一次** | 再付一次 | **×2** | 推包后首次必黑 |
| 截图 `emulator-eye shot` | 1–2s | ~40s | 还好 |
| 进程累积降解 → `adb reboot` | **70s/次** | 出现 2–3 次 | **大头** |
| 我逐张看图认页 | 每图一轮 | 15+ 轮 | 隐性大头 |
| `.js`/`.jsc` 误判排查 | — | **约 1 小时** | 一次性学费，已解决 |

**结论**：慢不在"截图"，而在 **①每页都要冷启动 ②黑屏翻倍 ③反复 `vapp` 累积进程导致 reboot ④截图顺序不确定，必须逐张认页**。

### 已确认的环境事实（别再踩）
1. **运行时优先 `.jsc`**：目录里 `.js` 与 `.jsc` 并存时**只用 `.jsc`** → 推 `.js` 被**静默忽略**。
2. **禁跑 `vapp help`**：挂住 stdin/服务，之后 App 全黑（截图 1373B），只能 `adb reboot`。
3. **推包后首次 `vapp` 必黑屏，第二次才出图**；黑屏那次**不推进**导航计数。
4. `adb reboot` 清场有效，但会**重置应用数据**。
5. 所有页面**都不吃路由参数**，状态全在 `storage`（例：`detail` 读 `detail_classId`）。⇒ "模拟参数" = **预置 storage**，不是 URI 参数。

## 二、你的方案（索引页 + 点击）：可行，且明显更快

思路：建一个临时索引页，列出全部页面入口；**只启动一次 App**，从索引页点进各页截图。

- 省掉了每页冷启动（15–18s→0）与黑屏翻倍（×2→无）。
- 单页成本 ≈ 点一下 + 渲染 2–4s + 截图 1.5s + 返回 + 滚到顶 ≈ **10–15s**。
- **27 页 ≈ 6–10 分钟**，比现在快一个数量级。✅

**但要当心的隐性成本**：索引页 27 项必然要滚动，而"点哪一行的坐标"需要探；且**页面头部会随内容滚出**，返回键必须先滚到顶才点得中（本轮踩过）。坐标发现与返航校验会吃掉一部分收益。

**判定**：方案成立，预计 **6–10 分钟**。若把索引页做成"每屏固定 7 项、共 4 屏"的固定坐标布局，可省掉滚动带来的不确定性，压到 **5 分钟左右**。

## 三、推荐方案：索引页 + **自动巡航**（零点击，~2–3 分钟）

在你方案基础上再去掉"点击"这一步：**索引页不用来点，而是自动按序跳页**，我只在旁边按固定节奏按快门。

### 核心改动（仅两处，全部临时）

1. **临时页面 `src/pages/__tour/index.ux`** 作为入口（临时把 `router.entry` 指向它，采完还原）。
   它做两件事：
   - **造数据**：把各页需要的 storage 预置好（见第四节表）；
   - **自动巡航**：`setInterval` 每 `T` 毫秒 `router.replace` 到下一个目标页，并把当前序号写回 storage（便于中断续采）。

2. **`scripts/emulator-eye.js` 新增 `bulkshot`**（可长期保留，属工具增强）：
   ```
   node scripts/emulator-eye.js bulkshot <grpcPort> <输出前缀> <张数> <间隔毫秒>
   ```
   一条命令连拍 N 张，省掉 N 次进程启动开销。

### 为什么定时器能跨页存活
`router.replace` 会销毁当前页面，但 **`app.ux` 的 JS 上下文贯穿整个 App 生命周期**。
⇒ 巡航定时器**放在 `app.ux` 的 `onCreate`（或一个被 app.ux 引用的模块单例）**，即可跨页存活。
> **已验证 ✅（2026-09-28 01:09）**：`aiot release --enable-jsc --start-page 'pages/device-info'` + 只推 `app.jsc` → 启动后**直接落在设备信息页**（截图 20238）。
> 早先"失效"纯因推的是 `.js` 被忽略。**app 级 `router.replace` 可用 ⇒ 定时器放 `app.ux`、跨页存活的自动巡航方案成立。**
>
> 顺带结论：`--start-page` + 推 `app.jsc` 本身就是一条**可用的逐页方案**（每页一次构建 ~10s + 启动 ~25s ≈ **27 页 16 分钟**），比本轮快 7 倍但慢于自动巡航；适合作为**巡航方案出问题时的兜底**。

### 时序建议
- `T = 3000ms`（渲染 ~1s + 稳定 ~1s + 余量）。页面重的（周视图/课表二维码）可给 4000ms。
- 每页成本 = 等 T + 连拍 ≈ 3.5s → **27 页 ≈ 95s ≈ 1.6 分钟**。
- 加上构建 12s + 推送 1s + 启动 30s（含一次黑屏重试）+ 收尾校验 → **总计 2–3 分钟**。

### 额外收益（比"快"更重要）
- **顺序确定 ⇒ 文件名确定**（`tour-00.png`…`tour-26.png`）⇒ **不用再逐张看图认页**，省掉本轮最大的隐性开销。
- 单会话、不重启 ⇒ **不会累积进程、不会黑屏**。
- 造数据统一步 ⇒ `detail`/`course-manager`/`countdown-manage` 不再是空态，截图有信息量。

## 四、各页状态依赖与"造数据"清单

> 全部页面都不吃路由参数，均从 storage/设备读取 ⇒ 索引页只需**预置 storage**。

| 页面 | 需要的状态 | 预置方式 |
|---|---|---|
| welcome / index / add-course / settings | 无 | — |
| schedule-manager / week-view / workday-info | 课程表数据 | 写入 `allCourses_0` 等样例课表 |
| **detail** | **`detail_classId`** | 先造一门课，取其 id 写入 storage |
| **course-manager** | 课程列表 | 写入样例课表（否则空列表） |
| **countdown-manage** | 倒数日列表 | 写入样例倒数日（否则"暂无倒数日"） |
| custom-content-edit | 自定义文案 | 写入样例文案 |
| schedule-qrcode / backup-restore / homepage-settings / reset-data / pinned-pages | 高级版状态 | 保持**未激活**（本就是最真实排障态，与既有结论一致） |
| activation / device-info / tools | 设备信息 | 无（设备侧自带） |

**实施要点**：巡航开始前一次性 `storage.set` 写入上述键；巡航过程中**不要**改数据，避免页间互相污染。

```bash

#    - 新增 src/pages/__tour/index.ux
#    - src/manifest.json: router.entry 临时改为 "pages/__tour"

# 2) 构建（必须 release+jsc，且绕开 safe-delete 垫片）
cd /Users/Banner/Documents/guomengtao/tom/class/class
env -u NODE_OPTIONS npx aiot release --enable-jsc

# 3) 只推改动页的 .jsc（不要推 rpk：会重置应用数据）
ADB=node_modules/@aiot-toolkit/emulator/node_modules/@miwt/adb/bin/mac/adb
PKG=com.application.watch.classschedule
$ADB -s emulator-5554 push build/pages/__tour/index.jsc \
     /data/quickapp/app/$PKG/pages/__tour/index.jsc

$ADB -s emulator-5554 shell "vapp app/$PKG &" ; sleep 16

# 5) 连拍 27 张（一张命令搞定）

```

## 七、还有更快的吗？

| 手段 | 收益 | 代价 / 判断 |
|---|---|---|
| 自动巡航（本方案） | 2h → **2–3 min** | 推荐，已具备全部前置条件 |
| 再压缩 `T` 到 2000ms | 再省 ~30s | 有截到"渲染中"半帧的风险，**不建议低于 3000ms** |
| 多设备并行（再造一个 192×490 VVD 分流） | 理论再砍半 | 需 `aiot createVVD` + 双份部署，**不划算** |
| 把索引页做成"长期保留的调试页" | 省 1 次构建 | 会把调试代码带进产品，**禁止** |
| 复用 IDE 扫码/运行装包 | 省手工 push | 依赖 IDE 交互，自动化反而更差 |

**结论**：自动巡航就是性价比最优解，**2–3 分钟**；再快就要牺牲稳定性或污染代码，不值得。
