# 方案分析：点课程名打开面板，面板内切换课表

## 需求演变

迭代了三次才找到真正想要的交互方式：

| 迭代 | 方案 | 问题 |
|------|------|------|
| 最初 | 点圆圈切换，点三点按钮打开面板 | 圆圈太小、三点按钮与课程名行为割裂 |
| 前一版 | 点课程名（或三点按钮）切换课程表 | 想打开面板编辑课表时无从下手 |
| **当前** | **点课程名 → 打开面板，面板内切换** | 统一、清晰、所有屏型一致 |

---

## 方案：「点开即处理」—— 点课程名打开面板，面板内含切换

### 核心思想

- **默认动作**：点击课程表行（课程名区域或三点按钮）→ 弹出底部操作面板
- **切换课程表**：移入面板内，作为一个显式按钮操作
- **适用范围**：所有屏型（方屏、圆屏、胶囊屏）行为完全一致
- **圆圈指示器**：只做视觉标记（高亮当前活动课表），不可点击

### 模板结构

```html
<div class="item" style="background-color: {{ theme.card }}">
  <!-- indicator 只做视觉，不可点击 -->
  <div class="indicator" ...></div>
  <!-- 点课程名 → 打开面板 -->
  <text class="name" onclick="openSheet($idx)" ...>{{ $item.name }}</text>
  <!-- 三点按钮也打开面板（可隐藏） -->
  <div class="more-hit" onclick="openSheet($idx)">
    <div class="more-dot" ...></div>
    ...
  </div>
</div>
```

### 面板布局改造

在面板内新增「切换课程表」按钮，放在最显眼位置：

```
┌──────────────────────────┐
│  数学                        │  ← 课程名
│  12 门课程                   │  ← 副标题
│                              │
│  ┌────────────────────────┐  │
│  │  切换到该课程表           │  │  ← 全宽主按钮，如已是当前课表则灰色禁用
│  └────────────────────────┘  │
│                              │
│  ┌──────┐  ┌──────┐         │
│  │ 重命名 │  │  复制  │         │
│  └──────┘  └──────┘         │
│  ┌──────┐  ┌──────┐         │
│  │  导出  │  │  总览  │         │
│  └──────┘  └──────┘         │
│  ┌──────┐  ┌──────┐         │
│  │  统计  │  │  删除  │         │
│  └──────┘  └──────┘         │
│                              │
│  ┌────────────────────────┐  │
│  │        取消                │  │
│  └────────────────────────┘  │
└──────────────────────────┘
```

```js
// 面板内新增的切换按钮
sheetSwitch() {
  var idx = this.sheetIndex
  if (idx === this.currentIndex) return  // 已经是当前课表，不操作
  this.toggle(idx)
  this.closeSheet()
}
```

### 胶囊屏的额外收益

三点按钮 (`more-hit`) 自然可以隐藏，因为点课程名已经能打开面板：

| 项目 | 改造前（胶囊） | 改造后（胶囊） |
|------|-------------|-------------|
| 三点按钮 | 隐藏（之前为腾空间） | 隐藏（天然无需） |
| 课程名空间 | 134px（5-6字） | 134px（5-6字） |
| 面板入口 | 无 | 点课程名即可 |

## 用户侧的交互对比

### 场景 1：切换课程表

| 方式 | 操作路径 | 耗时 |
|------|---------|------|
| 旧方案（点击即切换） | 点一次课程名 | 1 次点击 |
| **新方案（面板内切换）** | 点课程名 → 点「切换到该课程表」 | 2 次点击 |
| 长按切换（备选方案） | 长按课程名 | 1 次长按（但难发现） |

### 场景 2：重命名课程表

| 方式 | 操作路径 |
|------|---------|
| 旧方案（无入口） | 无法操作 |
| **新方案** | 点课程名 → 点「重命名」 |

### 场景 3：查看课程统计

| 方式 | 操作路径 |
|------|---------|
| 旧方案（无入口） | 无法操作 |
| **新方案** | 点课程名 → 点「统计」 |

## 与长按方案的对比

用户顾虑长按太隐蔽，这个顾虑**完全正确**。

| 维度 | 点开面板（推荐） | 长按 |
|------|--------------|------|
| **可发现性** | 点击有即时视觉反馈 | 没有视觉提示，用户想不到长按 |
| **平台支持** | 快应用原生支持 | 部分手环框架不支持 `longpress` |
| **误触风险** | 面板内操作需二次确认 | 长按计时容易被识别为滚动或双击 |
| **直觉匹配** | "点一下看详情"是通用范式 | 手环上没有长按的行业标准 |
| **功能扩展** | 面板内可以放多个操作 | 长按只能绑定一个动作 |
| **认知负担** | 低 — "点名称 → 看操作" | 高 — 用户需要记忆"长按=切换" |
| **切换速度** | 2 次点击 | 1 次长按（但前提是用户知道） |

**结论**：在智能穿戴设备上，**点击打开面板远远优于长按**。长按的学习成本太高，且缺乏平台标准的视觉提示。

## 需要评估的风险：「切换变慢」

这是唯一需要认真对待的缺点。分析两种典型用户画像：

### 画像 A：日常切换型用户

> 早上看今日课表 → 切换到明日课表看预习内容 → 切回今日课表

- 旧方案：3 次点击（每次 1 次）
- 新方案：6 次点击（每次 2 次）
- **额外耗时**：约 3 秒

### 画像 B：编辑型用户

> 新增课表 → 重命名 → 设置假期提醒 → 切换查看

- 旧方案：无法在课程表管理页完成这些操作（需要跳转其他页面）
- 新方案：全部在面板内完成，无需跳转
- **效率提升**：显著

### 权衡建议

如果需要兼顾快速切换，可以在面板的标题区增加一个直观的「当前课表标记」：

```
┌──────────────────────────┐
│  数学  ← 当前课表       │
│  12 门课程               │
│                          │
│  ┌────────────────────┐  │
│  │  切换到该课程表       │  │  ← 灰色禁用（因为是当前课表）
│  └────────────────────┘  │
│  ...                     │
└──────────────────────────┘

┌──────────────────────────┐
│  英语四级                  │
│  8 门课程                 │
│                          │
│  ┌────────────────────┐  │
│  │  切换到该课程表       │  │  ← 高亮可点击（不是当前课表）
│  └────────────────────┘  │
│  ...                     │
└──────────────────────────┘
```

这样用户打开非当前课表面板时，**第一个看到的就是切换按钮**，视觉引导明确。

## 我的建议：采用「点开即处理」方案

### 推荐理由

| 理由 | 说明 |
|------|------|
| **统一** | 所有屏型行为一致，不再区分胶囊/方屏 |
| **清晰** | 点击打开面板是点击操作的默认语义，用户不需要猜测 |
| **可扩展** | 面板内可以自由增减操作项，不需要修改列表结构 |
| **防误触** | 切换课表需要二次确认，不会因为屏幕小而误切 |
| **可发现性** | 优于长按，不需要教用户使用 |
| **代码简洁** | 列表项只需要 `onclick="openSheet($idx)"`，没有条件分支 |

### 需要做的改动

| 步骤 | 改动内容 | 状态 |
|------|---------|------|
| 1 | 列表模板：`.item-main` 移除，`.name` 绑定 `openSheet($idx)` | ✅ 已实现 |
| 2 | 面板模板：新增「切换到该课程表」按钮（含当前课表禁用态） | ✅ 已实现 |
| 3 | 面板逻辑：新增 `sheetSwitch()` 方法 | ✅ 已实现 |
| 4 | CSS：新增 `.sheet-switch-btn` / `.sheet-switch-btn-text` 样式 | ✅ 已实现 |
| 5 | 三点按钮：绑定 `openSheet($idx)`，胶囊屏隐藏 | ✅ 已实现 |
| 6 | 圆圈指示器：移除 `onclick`，仅保留视觉高亮功能 | ✅ 已实现 |

### 不改动部分

- `toggle()` 函数本身保持不变（只是从列表直接调用移到面板内调用）
- 面板的其他操作（重命名、复制、导出等）不变
- `stopBubble` 修复继续保持

## 总结

| 方案 | 可发现性 | 切换效率 | 编辑效率 | 平台兼容 | 推荐度 |
|------|---------|---------|---------|---------|-------|
| **点开面板（推荐）** | 高 | 中 | 高 | 高 | 强烈推荐 |
| 长按切换 | 低 | 高 | 低 | 中 | 不推荐 |
| 圆圈点切换 + 名字点面板 | 中 | 高 | 高 | 高 | 热区太小 |

**最终结论**：点击课程名打开面板、面板内切换——这个方案**适合手环场景**，解决了之前所有的痛点（空间不足、操作入口隐蔽、屏型差异），唯一代价是切换课表多一次点击，但换来的是操作明确、功能完整、用户无需学习。
