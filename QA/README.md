# QA 协作目录（用户体验官 UX Officer）

> 目的：让开发者 `git pull` 即可看到 AI 的 UX 巡检问题，无需切换分支或查看 PR。

## 目录结构
- `reports/`：UX 巡检报告。AI **只新增**，文件名 `UX-Report_YYYY-MM-DD_HHMM.md`，不修改/删除历史报告。
- `reply.md`：**开发者维护**的处理反馈，AI 只读。
- `README.md`：本协作约定（仅建立一次）。

## 谁写谁读（零冲突约定）
- AI（用户体验官）：只在 `QA/reports/` 新增报告；**绝不修改 `src/` 及 QA 目录下其它文件**。
- 开发者：只在 `reply.md` 按问题编号 `Uxx` 回填处理状态。
- 双方不写同一个文件 → 不产生代码冲突。

## 工作闭环
1. 开发者 `git pull`（停在 main 即可）直接看到 `QA/reports/` 最新报告。
2. 在 `reply.md` 把对应编号标为：`已修复` / `不修(原因)` / `重复(并入Ux)`。
3. AI 下次巡检先读 `reply.md` 与上一份报告：对「已修复」项复核关闭、对「明确不修」项不再重复报，并输出新增 / 已修复 / 遗留对照。

## 问题分级（用户视角优先，用户能直接感知的最重要）
- **P0** 用户操作直接失败 / 无法使用（保存没反应、数据丢失、白屏黑屏、进不去、误跳转）。
- **P1** 用户直接感知的错误或混乱（缺成功/失败提示、返回不刷新、显示错乱/截断、字小到看不见）。
- **P2** 可感知但不阻断的体验优化（间距、留白、行高、字号档位、占位文案）。
- **P3** 用户无感的内部工程问题（日志、临时文件、目录整洁、版本配置），报告末尾简列。

## 问题编号
稳定编号 `U` 系列长期延续（首次基线为 U1~U14），不随每份报告重置，便于在 `reply.md` 长期追踪。
